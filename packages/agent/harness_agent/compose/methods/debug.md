# Debug 方法（Compose 私有资产；任务失败后的重试注入）

上一轮实现失败了（见「上次失败原因」）。不要重复原做法，先诊断再修复：

## 步骤

1. 复现：运行失败场景或 focused 测试，确认失败是否可复现。
2. 定位：读取相关实现与测试，找到失败断言对应的代码路径；只读工具
   （read_file/grep/glob/lsp）优先，避免盲目改动。
3. 假设驱动：为最可能的根因写一个能证明/证伪的 focused 检查，先跑它。
4. 修复：用最小改动消除根因；若修复引入新问题，回到第 2 步。
5. 验证：运行任务声明的 verification_commands 与 focused 测试，如实
   记录 red_evidence（若本任务要求 TDD）与 focused_test_evidence。

## 规则

- 不许通过放宽断言、跳过测试或删除测试来“修复”。
- 每次只改一个假设；多个根因时按依赖顺序逐个修复。
- 无法在预算内修复时，在 remaining_issue 中写清根因、已尝试做法和
  最小可复现命令，供流程收敛为 blocked。
