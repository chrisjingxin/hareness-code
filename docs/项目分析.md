# Harness Code（za38-cli）项目分析

## 项目定位

Harness Code 是一个**面向企业研发场景的终端 Coding Agent（编程助手）**。用户通过终端界面与 AI 对话，AI 可以读写文件、执行命令、调用工具来完成编程任务。类似于 Claude Code / Codex 的开源企业版本。

当前版本：**0.1.0**（源码开发阶段，尚未发布安装包）

## 核心架构：双层进程

Harness Code 采用"Node 表现层 + Python Agent 内核"的双进程结构：

- **packages/cli/**（TypeScript + Bun + React + OpenTUI）：终端界面、参数解析、Python sidecar 生命周期管理
- **packages/agent/**（Python 3.11+ + deepagents + LangChain/LangGraph）：AI Agent 内核，负责模型调用、工具执行、Skill 加载、上下文管理与 Thread 持久化
- **packages/protocol/**（JSON Schema + 代码生成）：跨进程共享的 JSON-RPC 方法名与载荷类型定义

两端通过 stdio 上的 JSON-RPC v2 协议通信，单帧上限 8 MiB。协议唯一来源为 `packages/protocol/schema/v2.json`，生成的 TypeScript 和 Python 文件禁止手改。

## 三个包的分工

| 包 | 技术栈 | 职责 |
|---|---|---|
| packages/cli/ | TypeScript + Bun + React + OpenTUI | 终端界面、参数解析、Python sidecar 生命周期管理 |
| packages/agent/ | Python 3.11+ + deepagents + LangChain/LangGraph | AI Agent 内核：模型调用、工具执行、Skill、上下文管理、Thread 持久化 |
| packages/protocol/ | JSON Schema + 代码生成 | 跨进程共享的 JSON-RPC 方法名与载荷类型定义 |

## 关键功能特性

### TUI 交互界面

基于 OpenTUI/React 的终端 UI，支持 slash 命令体系（`/new`、`/model`、`/resume` 等），命令注册、补全、菜单和解析均由统一的 `CommandRegistry` 管理。Builtin 命令不可被覆盖，Skill/MCP/Plugin Loader 只能构造新的 catalog snapshot。

### 无头模式

支持 `--non-interactive` 批处理模式，适合脚本和 CI 使用。无头模式下不协商交互 capability，服务端遇到审批或提问会立即拒绝，属于协议层的安全兜底。

### 模型配置

OpenAI 兼容协议，支持多 Profile（fast/pro 等）、角色绑定（planner/executor/reviewer/tester/summarizer）。通过 `~/.harness/config.toml` 管理，密钥优先从环境变量读取。当前 Single Agent 仅将 executor 解析为实际 primary Runtime 模型。

### Session 持久化

基于 SQLite（`~/.harness/threads.sqlite3`）存储 Thread 历史与 LangGraph checkpoint，支持会话恢复。使用 `project_fingerprint`（SHA-256）索引，不存储原始项目路径。领域模型只有 project、thread 与 message 三层。

### 审批模式

支持 plan/default/auto-edit/yolo 四级审批策略，控制工具执行权限。`PlanModeMiddleware` 以白名单机制在工具执行前拦截，默认拒绝未知工具。default 模式拦截 execute/write_file/edit_file/delete/task。

### Skill 系统

四类来源：内置（`built_in_skills/`）、用户（`~/.harness/skills/`）、项目（`.harness/skills/`）、市场。启动时一次性扫描并建立不可变 catalog snapshot，新 thread 的 PromptEpoch 注入 Skill 元数据索引。

### 工作区安全边界

`WorkspaceBoundaryMiddleware` 强制文件工具只能访问工作区内的路径，防止通过符号链接或路径穿越逃逸。主 Agent 和 general-purpose 子 Agent 均注册该 guard。

### Runtime Pool

Profile 级别的 Agent 图复用与 LRU 淘汰，相同配置的 thread 共享 AgentRuntime。支持 `max_profiles`、`idle_ttl_seconds`、`close_timeout_seconds` 等配置。

### 上下文窗口管理

`PromptEpoch` 在首次运行时建立不可变前缀（核心策略、环境快照、Skill 索引、工具 schema），后续轮次只追加历史摘要和最近消息。`ContextWindowMiddleware` 在预算紧张时自动归档旧工具结果并生成结构化摘要。

### Shell 白名单

`ShellAllowListMiddleware` 以 POSIX shlex 解析命令，词法层禁止控制运算符、管道、重定向和子 Shell，解析失败一律 fail closed。

## 如何快速开始

### 前置条件

- Bun 1.2.19
- Python 3.11+
- uv（Python 包管理器）
- 企业网关 API Key

### 启动步骤

```bash
# 1. 安装 Python 依赖
cd packages/agent && uv sync --extra test && cd ../..

# 2. 创建配置目录并复制模板
mkdir -p ~/.harness
cp docs/user/examples/config.toml ~/.harness/config.toml

# 3. 设置 API Key 环境变量
export HARNESS_API_KEY='你的企业网关密钥'

# 4. 启动交互模式
bun run dev
```

### 配置模型

编辑 `~/.harness/config.toml`，修改以下关键字段：

```toml
[models.profiles.fast]
provider = "openai-compatible"
model = "your-model-name"
base_url = "https://your-gateway.example.internal/v1"
api_key_env = "HARNESS_API_KEY"
context_window_tokens = 128000
```

### 无头模式

```bash
bun run dev -- --non-interactive --message "解释当前目录的项目结构"
```

### 常用开发命令

```bash
bun run dev -- --help          # 查看 CLI 参数
bun run dev -- config show     # 查看当前脱敏配置
bun run test                   # 运行全部测试
bun run typecheck              # TypeScript 类型检查
bun run project:check          # 项目级完整性检查
bun run protocol:generate      # 重新生成协议代码
```

## 项目结构

```
hareness-code/
├── packages/
│   ├── cli/          # TypeScript 入口 + OpenTUI 表现层
│   │   ├── src/      # 源码（index.ts, args.ts, tui/）
│   │   └── tests/    # TS 测试
│   ├── agent/        # Python Agent 内核
│   │   ├── harness_agent/  # 源码（server.py, agent.py, providers/ 等）
│   │   └── tests/          # Python 测试
│   └── protocol/     # 跨进程协议定义
│       ├── schema/   # JSON Schema v2
│       └── src/      # 生成的 TS 类型
├── docs/
│   ├── user/         # 用户文档（快速开始、模型配置、交互使用等）
│   └── developer/    # 开发文档（架构总览、任务看板、ADR 等）
├── scripts/          # 项目管理脚本
└── package.json      # Bun workspace 根配置
```

## 开发规范要点

- TypeScript 使用 ESM、2 空格缩进；Python 使用 4 空格缩进
- 生产源码必须有中文文件说明和中文 JSDoc/docstring
- 协议变更必须同时修改 TypeScript 和 Python 两端
- 测试禁止使用真实模型凭据，使用 mock 模型或 mock HTTP 服务
- 版本号只能通过 `bun run version:set <SemVer>` 修改
- 提交前运行 `bun run project:check`、`bun run typecheck` 和 `bun run test`
- 禁止提交 API Key 和凭据到仓库
