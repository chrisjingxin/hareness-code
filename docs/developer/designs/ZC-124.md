# ZC-124：Web UI 工作台体验升级设计方案

原始任务：[ZC-124：统筹 Web UI 工作台体验升级与验收闭环](../tasks/ZC-124.md)

历史基础：[ZC-104](ZC-104.md)、[ZC-106](ZC-106.md)、[ZC-107](ZC-107.md)

最终验收：[ZC-105](../tasks/ZC-105.md)、[ZC-115](../tasks/ZC-115.md)

## 通俗问题说明

当前 Web 页面已经可以完成 Coding Agent 的主要操作，但布局和视觉注意力还没有完全服务“长时间观察 Agent、阅读代码、批准操作、继续输入”这一核心场景。

用户进入页面后应该始终先看到三件事：当前在做什么、Agent 刚做了什么、下一步自己能做什么。Sidebar、文件树、Model、Skill 和 MCP 都是辅助信息，不能在空间不足时挤掉对话与 Composer。

目标流程固定为：

```text
进入 Web 工作台
  → 先确认当前项目、Run 状态与可用输入
  → 阅读 User / Assistant / Tool / Interaction 的单一时间线
  → 需要时打开 Thread、文件或 Context Dock
  → 宽度不足时辅助区域变为互斥抽屉/覆盖层
  → 运行、失败、审批和新输出通过克制动效解释状态变化
```

本方案保留当前暖单色的质感，但用蓝色承担 selected、focus、active run 和 link，建立清晰而不过度装饰的开发者工作台。

## 已确认现状与证据

### 当前结构

- `WebApp` 组合 Topbar、WorkspaceSidebar、Timeline、InteractionForm、Composer、ContextDock 和 DialogHost。
- `WebInteractiveAdapter` 保存 theme、draft、Dock、Sidebar、Tool 展开、Interaction 草稿和 transient notice 等纯表现状态。
- Agent、Thread、Run、Catalog 和权限继续来自共享 `InteractiveSnapshot`，Web 不拥有第二套业务状态。
- `WorkspaceSidebar` 同时展示 Thread 和文件树，并支持横向/纵向 Pointer 拖动。
- `ContextDock` 包含 Code、Model、Skills、MCP、Status，Help 作为独立模式。

### 实测布局

使用当前生产组件和代表性工作台数据渲染得到：

| 视口 | 根 scrollWidth | Conversation 内容宽度 | 结论 |
| --- | ---: | ---: | --- |
| 1440×900 | 1440px | 约 672px（Dock 打开） | 可用，但外围列占比偏高 |
| 1280×800 | 1280px | 约 512px（Dock 打开） | 对话被明显挤压 |
| 390×844 | 1280px | 位于 x=304～816px | 主内容和 Composer 不可达 |

根因是 `.desktop-workspace` 的 `min-width: 1280px`，且当前 CSS 没有窄屏布局规则。

### 视觉和可访问性事实

- 暖骨白/炭黑视觉克制，适合长时间阅读，应保留为基础而非再次整套换肤。
- 浅色 `--muted: #787774` 在 `#f7f6f3` 上约 4.14:1，不适合 12px 必要文字；`--subtle` 只允许用于禁用或非文本装饰。
- “新建 Thread”使用全黑填充，比当前 Run 状态更醒目。
- User/Assistant 同时使用 author label 和 `U/H` avatar，身份表达重复。
- 连续 Tool 每项一张 40px+ 卡片，完成状态重复显示绿色文字，长 Run 的视觉噪声偏高。
- Sidebar/Dock resize handle 只有 `onPointerDown`，没有键盘、`aria-valuenow` 或复位操作。
- `Timeline` 会渲染全部可见 item；当前已有 memo，但没有真实长会话性能证据，不应先入为主引入 virtualization。

## 设计目标与非目标

### 目标

1. Conversation、Run 状态和 Composer 始终是第一视觉层级。
2. 1440px 保留高效三栏；空间下降时外围区域先降级，核心对话不被裁切。
3. Timeline 能快速区分用户意图、Agent 结论、Tool 活动和需要用户决策的 Interaction。
4. light/dark 使用同一语义 token、DOM 和状态结构。
5. 键盘、触控、200% zoom、reduced-motion 与鼠标操作具有同等可达性。
6. 动效解释状态，不制造等待、不改变布局边界、不干扰 streaming。

### 非目标

- 不改变 Agent 工作流、RPC、capability、Handoff 或安全策略。
- 不新增模型不存在的数据或 UI-only 假进度。
- 不复制 VS Code、Claude Code 或其它产品外观。
- 不用动画掩盖加载、错误或状态不确定性。
- 不为了桌面美观牺牲 320px reflow 和 200% zoom。

## 关键 invariant

- `InteractiveSnapshot` 是 Thread、Run、Timeline、Interaction、Catalog、Selection 和 capability 的唯一业务事实来源。
- Viewport、drawer、theme、Tool 展开和 focus restore 是 Web 表现状态，不进入 Protocol、SQLite 或 AgentHost。
- 辅助面板不得让列式 Conversation 可用内容宽度小于 640px；不足时必须切换 overlay/drawer。
- 页面根节点不得横向滚动；代码、表格、路径和 Tool 原始输出只在各自容器滚动。
- active Run、pending Interaction、readonly、leaving 和 connection error 的禁用原因继续来自现有 snapshot，不由 CSS 猜测。
- 不编造时间、耗时、百分比、文件 diff 或风险等级；只展示现有字段可证明的事实。
- 同一状态不得只依赖颜色；图标、文字或形状至少再提供一种区分。
- 历史恢复不播放批量入场动画；只有当前页面新追加的内容可以使用微动效。

## 信息架构

### Wide：≥1440px

```text
┌──────────────────────────── Topbar 52 ────────────────────────────┐
│ Brand/Project     Model · Approval       Run status   TUI · More │
├──────── Sidebar 280 ───────┬──── Conversation ≥640 ────┬─ Dock ─┤
│ New Thread (secondary)     │ Timeline                     │ Tabs  │
│ Thread list                │ Run / Interaction status     │ Code  │
│ ─ resize ─                 │ Composer                     │ ...   │
│ Files                      │                              │       │
└────────────────────────────┴──────────────────────────────┴───────┘
```

- Sidebar 默认 280px，可在 240～360px 内调整。
- Dock 默认 440px，可在 400～560px 内调整。
- Conversation 外轨最大 880px，正文段落最大 72ch。
- 如果用户把外围列拖到将 Conversation 压低于 640px，宽度变化必须被 clamp。

### Compact：1180～1439px

- Sidebar 可常驻；Dock 不作为第三列挤压 Conversation，而是从右侧覆盖或由用户主动关闭。
- 打开 Dock 时加轻量 scrim，但 Conversation 保持原位置，避免阅读列反复变宽变窄。
- Topbar 隐藏低优先级文字前缀；Model、Approval、Run 仍有可访问名称。

### Narrow：<1180px 或 200% zoom 后等效宽度

- 默认只显示 Conversation。
- Sidebar 与 Dock 使用互斥 overlay：打开一个会关闭另一个。
- <768px 时 Sidebar 宽 `min(92vw, 360px)`；Code Dock 使用全屏工作区，其他 Dock 使用右侧 sheet。
- <480px 时 Topbar 只保留项目名、Run 状态、Sidebar trigger 和 overflow；返回 TUI、主题、Model、Approval 进入菜单。
- Composer 使用 `env(safe-area-inset-bottom)`，textarea 字号至少 16px，发送/取消目标 44×44px。

## Web 表现状态与 interface

为保证响应式行为可以测试，viewport 与 drawer 归 Adapter，而不是散落在组件 local state：

```ts
export type WebViewportMode = "wide" | "compact" | "narrow"

export type WorkspaceSidebarState = {
  readonly open: boolean
  readonly widthPx: number
  readonly threadRatio: number
  readonly selectedPath: string | null
}

export type ContextDockState = {
  readonly open: boolean
  readonly presentation: "column" | "overlay" | "fullscreen"
  readonly activePanel: "code" | "models" | "skills" | "mcp" | "status" | "help"
  readonly widthPx: number
  // 现有 code 状态保持
}
```

新增/收敛的表现 intent：

```ts
type WebIntent =
  | { type: "viewport-set"; mode: WebViewportMode }
  | { type: "sidebar-open" }
  | { type: "sidebar-close" }
  | { type: "sidebar-width-change"; widthPx: number }
  | { type: "sidebar-thread-ratio-change"; ratio: number }
  | { type: "dock-open"; panel: ContextDockState["activePanel"] }
  | { type: "dock-close" }
  | { type: "dock-width-change"; widthPx: number }
  | { type: "quick-prompt-select"; value: string }
  | /* 现有 intent */
```

状态归一规则：

```text
viewport-set(wide)
  → Dock 可恢复 column；Sidebar 保留用户 open 状态

viewport-set(compact)
  → Dock 改 overlay；Conversation 宽度不改变

viewport-set(narrow)
  → Sidebar/Dock 最多一个 open；Dock 的 Code 为 fullscreen

sidebar-open(narrow)
  → 关闭 Dock → 打开 Sidebar → 移动焦点

dock-open(narrow)
  → 关闭 Sidebar → 打开 Dock → 移动焦点
```

非法宽度、ratio 或迟到 viewport 更新由 Adapter clamp/去重；不得导致业务 intent 或 Agent RPC。

## 视觉系统

### 色彩方向

采用“暖中性 + 冷蓝强调”，蓝色稀缺使用：

| 角色 | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#f7f6f3` | `#141310` | 主画布 |
| `--surface` | `#ffffff` | `#1b1a17` | 输入、卡片、chrome |
| `--surface-2` | `#f2f1ec` | `#23211d` | hover、次级区 |
| `--surface-3` | `#e9e7e1` | `#2c2a25` | code header、pressed |
| `--line` | `#e1e0da` | `#38352f` | 常规分隔 |
| `--line-strong` | `#c9c6bd` | `#565149` | 控件边界 |
| `--text` | `#211f1a` | `#f3f1ea` | 主文字 |
| `--text-soft` | `#4e4b44` | `#d0ccc2` | 正文次级 |
| `--muted` | `#65635e` | `#aaa69c` | 必要辅助文字 |
| `--subtle` | `#8d8981` | `#77736b` | disabled/装饰，非必要正文 |
| `--accent` | `#2563eb` | `#60a5fa` | selected、active、focus |
| `--accent-hover` | `#1d4ed8` | `#93c5fd` | hover/link |
| `--accent-soft` | `rgba(37,99,235,.08)` | `rgba(96,165,250,.12)` | selected surface |
| `--action` | `#181715` | `#f3f1ea` | 发送/主要确认 |
| `--success` | `#397047` | `#8fc39a` | 成功 |
| `--warning` | `#966600` | `#ddb76d` | 等待/警告 |
| `--danger` | `#a43733` | `#e6a49f` | 失败/取消 |

语义规则：

- 新建 Thread 使用 secondary/quiet，不占 `--action`。
- Send 与当前 Interaction 的唯一批准动作可以使用 `--action`。
- active Thread、selected Model、focus ring 和 running status 使用 `--accent`。
- completed Tool 默认使用 muted check，只有摘要或用户主动展开后显示完整状态。
- focus ring 固定 2px accent + 2px offset，不能使用与黑色按钮相同的炭黑 outline。

### 排版

- UI/正文：系统 sans stack；不加载远端字体。
- Brand：可保留 serif，仅用于品牌名和静态结束页标题。
- Code/command/path：系统 monospace stack。
- Assistant 正文 14px/1.65；中文长文保持 65～75 字符视觉行长。
- Tool/metadata 12～13px；必要文字对比度至少 4.5:1。
- 标题不使用全大写表达层级；`THREAD · N 项记录` 删除或由可读 Thread 标题替代。

### 空间和尺寸

| Token | Desktop | Narrow | 用途 |
| --- | ---: | ---: | --- |
| `--topbar-height` | 52px | 48px | 顶栏 |
| `--control-compact` | 30px | 44px | icon button |
| `--control-standard` | 34px | 44px | 普通按钮 |
| `--control-field` | 36px | 44px | input/select |
| `--radius-control` | 5px | 5px | 控件 |
| `--radius-surface` | 7px | 7px | 卡片/Composer |

整体继续使用 4/8px 节奏。结构边界使用 border；shadow 只给 overlay、menu、dialog，不给每一条完成 Tool。

## Topbar、Sidebar 与 Context Dock

### Topbar

从左到右固定为：

```text
项目 / 分支 → 弹性空间 → Model → Approval → Run 状态 → 返回 TUI → More
```

- Run 状态是右侧最高优先级；running/waiting/failed 除颜色外必须有文字。
- Model 与 Approval 是配置事实，不用填充主按钮样式。
- 1280px 以下按优先级把 Approval、Model、返回 TUI 收入 overflow，不允许顶栏横向裁切。
- “退出 Harness”保持 danger 文案，但不使用持续红色填充。

### Sidebar

- “新建 Thread”改为 secondary，保留 `+` 和快捷键提示。
- Thread 与 Files 在高视口继续上下分区；高度不足 700px 时改为 `Threads | Files` 切换，避免两个不可用小窗。
- active Thread 使用 accent-soft + 2px 左轨；hover 只用 surface-2。
- resize handle 的可见线仍为 1～4px，但 Pointer hit area 至少 8px；键盘可聚焦。

### Context Dock

- 删除通用标题与 tab 两行结构，合并为单行 tablist + close。
- `Code` 是默认第一 tab；其余 Model/Skills/MCP/Status 保持现有 capability 门禁。
- Wide 使用 column；Compact 使用 overlay；Narrow 下 Code fullscreen，其余为 sheet。
- overlay 打开后焦点进入 active panel，关闭后返回 trigger；桌面 column 不声明 modal。

## Timeline 与 Tool Activity

### 身份和阅读边

- Assistant：`Harness` author label + 内容，不再显示 `H` avatar。
- User：`你` author label + fit-content 的 accent-soft surface，不再显示 `U` avatar。
- System：独立 muted notice，不占角色轨。
- Tool/Interaction 与正文 leading edge 对齐，不再通过 37px avatar 空位缩进。

### Tool Group 纯投影

不改变 `InteractiveSnapshot.timeline`。Presentation 从相邻 item 派生：

```ts
type TimelineRenderItem =
  | { type: "message"; item: ConversationMessage }
  | { type: "tool-group"; runId: string; tools: readonly ToolCard[] }
  | { type: "interaction"; item: InteractionCard }
```

分组规则：

- 仅合并同一 `runId` 下连续 Tool；Message/Interaction 会断组。
- 1 个 Tool 仍显示单行 Tool。
- 2 个以上 completed Tool 默认显示“已完成 N 个操作”，展开后逐项显示。
- running/failed Tool 必须始终可见，不能被 completed 摘要隐藏。
- 展开状态仍由稳定 `runId + toolId/group key` 保存，历史恢复不自动展开。
- 缺少稳定 ID 或未知状态时退化为现有逐项渲染，不猜测合并。

## Run、Composer、空态和 Interaction

### Run 状态

Run 状态有两个同步视图：

- Topbar：全局状态，回答“页面现在是否在工作”。
- Composer 上方：当前动作，回答“用户现在能做什么”。

允许的文案只来自现有 activity/activeRun/interaction：`正在启动`、`正在运行`、`等待你的审批`、`正在取消`、`已完成`、`失败`。没有 duration 就不显示耗时，没有 total 就不显示百分比。

### Composer

- 始终与 Timeline 使用同一最大 880px 外轨。
- textarea 保持 React 单一 value owner；结构/主题/streaming rerender 不能丢 draft。
- active Run 时发送位置切换为 Cancel；textarea 可以继续编辑下一条草稿，但明确提示当前不可提交。
- Skill 和未来真实上下文使用可移除 chip；当前没有附件能力，不显示回形针。
- `/` 命令菜单、IME、Enter/Shift+Enter 和失败保留草稿语义不变。

### 空态

空 Thread 显示一行说明与三个 quick prompt：

- `解释当前项目结构`
- `检查未提交改动`
- `运行与当前改动相关的测试`

点击只写入 Composer，不自动提交，避免无意执行命令或消耗模型请求。连接只读、leaving 或 capability 不满足时 quick prompt 禁用并说明原因。

### Interaction

- pending Interaction 固定在 Composer 上方，不在 Timeline 重复。
- 审批卡按“操作摘要 → 目标/参数预览 → 风险说明（只有真实数据时）→ 决策”排序。
- 同一上下文只有一个 filled primary；拒绝为 secondary danger text，避免两个同权主按钮。
- pending Interaction 打开时焦点进入标题/首个控件；处理后返回 Composer 或原触发位置。

## 可访问性与键盘

- 页面首个焦点提供“跳到对话”和“跳到输入框”链接。
- Topbar → Sidebar → Timeline → Composer → Dock 的 DOM/Tab 顺序与视觉顺序一致；overlay 打开时才启用 focus trap。
- resize separator 增加 `tabIndex=0`、`aria-valuemin/max/now`：Arrow 每次 8px/2%，Shift+Arrow 每次 24px/5%，Home/End 到边界，双击恢复默认。
- 窄屏所有主要目标 ≥44×44px；桌面纯鼠标 icon 可 30px，但 focus ring 和 accessible name 完整。
- Timeline 使用 `role=log` 时只播报 additions；streaming token 不逐 token 朗读，Run status 使用单独 polite live region。
- 颜色不作为唯一状态；selected、disabled、expanded、running、failed 均有 ARIA state 和文案/图标。
- light/dark 的必要正文、小号 metadata 和图标分别验证 4.5:1/3:1。

## 动效规范

不新增动画库，使用 CSS transform/opacity 和现有 React 状态：

| 场景 | 时长 | 属性 | 规则 |
| --- | ---: | --- | --- |
| hover/focus 色彩 | 120～140ms | color/background/border | 不延迟点击反馈 |
| menu/command | 120～150ms | opacity + scale(.985→1) | origin 对齐 trigger |
| drawer/Dock overlay | 200～240ms | opacity + translate | 不动画 width/left |
| Tool 展开 | 160～200ms | chevron + 内容 fade | 保持 scroll anchor |
| 新消息 | 140～180ms | opacity + translateY(4px) | 仅本页新追加 item |
| running status | 1.4s | opacity | 只对状态点柔和呼吸 |

禁止：历史列表 stagger、背景光斑、磁性 cursor、持续 bounce、超过 500ms 的主流程动画。`prefers-reduced-motion: reduce` 下去掉位移、呼吸和 smooth scroll，只保留即时状态变化。

## 长会话与性能

实施顺序：

```text
先保留 memo 与稳定 key
  → 真实测量 500/1000 item + streaming
  → 定位 re-render / Markdown / highlight / layout 成本
  → 只有证据表明 DOM 规模是瓶颈时才引入 windowing
```

- 用户距离底部超过阈值时保持 scrollTop，不自动抢回底部；显示“有新输出”。
- 用户在底部时新输出跟随，但 Tool 展开/折叠不得改变是否自动跟随的判断。
- Markdown/CodeBlock 继续按已有缓存和降级边界工作。
- 性能任务必须记录 Profiler 或 Browser trace 结论；不得用“感觉更快”作为验收。

## 错误模式与降级

| 错误 | 可见行为 | 禁止行为 |
| --- | --- | --- |
| viewport 监听失败 | 默认 compact，核心对话可用 | 回退 1280px 固定布局 |
| Drawer focus target 消失 | 聚焦页面 main/Composer | 留下 body 外不可见焦点 |
| Tool 分组数据非法 | 逐项渲染原 Tool | 丢弃或重排 Timeline |
| 连接关闭 | 保留历史与 Tool 展开；Composer 只读并解释 | 清空 draft/页面 |
| 动效被禁用 | 立即完成状态切换 | 隐藏 loading/running 状态 |
| 长内容 | 局部容器滚动/折叠 | 扩大页面根宽度 |

## 测试方案

### 单元/DOM

- Adapter viewport 状态归一、互斥 drawer、clamp 和去重。
- Tool Group 分组、断组、running/failed 可见和降级。
- quick prompt 只填 draft，不提交 Controller。
- keyboard separator、Tab/Arrow/Home/End、Escape 优先级与 focus restore。
- reduced-motion class/media 行为和 semantic token 约束。

### Browser

固定视口：1440×900、1280×800、1024×768、390×844、320×720；另外测试 200% zoom。

每个 light/dark 至少覆盖：

- 空 Thread；
- 长 User/Assistant Markdown + code/table；
- 连续 completed Tool + running/failed Tool；
- pending approval/question；
- Code Dock 与其它 Dock；
- active Run cancel；
- connection closed/readonly；
- Sidebar/Dock drawer 和 Escape/focus restore。

几何断言：根无横向滚动、Composer 可见、主要 target 可点击、column Conversation ≥640px、局部 code/table 可横向滚动。

## 可观察验收

- 用户在所有目标视口打开 Web 后，不移动根页面即可看到 Conversation 和 Composer。
- 1280px 打开 Dock 时 Conversation 不再缩到约 512px，而是保持宽度并以 overlay 展示 Dock。
- 长 Run 的完成 Tool 被压缩，running/failed/approval 仍一眼可见。
- 新建 Thread 不再抢过当前 Run，Run 状态和下一步操作始终清楚。
- 键盘可以进入主内容、调整分隔条、打开/关闭抽屉、处理 Interaction 并回到 Composer。
- light/dark、reduced-motion、200% zoom 和 320px reflow 都通过自动化与截图验收。
