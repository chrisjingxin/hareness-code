# ZC-118 TUI/Web 思考摘要与运行进度设计

关联任务：[ZC-118](../tasks/ZC-118.md)

## 通俗问题说明

模型第一次返回正文或 Tool 之前可能等待较长时间。当前两个界面只在那之后才出现动态变化，用户无法区分“模型仍在运行”和“进程已经卡住”。部分模型还会返回供应商明确允许展示的 reasoning summary，但现有链路把这类 chunk 当成没有内容而丢弃。

目标是让用户在等待期间看到真实的运行阶段、活动时长和取消入口；如果模型明确提供公开摘要，再额外显示摘要。两条路径必须分开：摘要不是 assistant 正文，普通进度也不能伪造模型内部步骤。

## 已确认现状

- LangChain 版本锁定为 `langchain-core==1.4.8`、`langchain-openai==1.3.3`、`deepagents==0.6.8`。
- OpenAI Responses 的原始标准 block 形状为 `type=reasoning`，其公开摘要位于 `summary: [{ type: "summary_text", text: string }]`；`output_version="responses/v1"` 的 adapter 会把原始 Responses item 放进消息 content，而 provider translator 可能把它规范化成只含 `reasoning` 的 block，因此实现只信任原始 `summary` 容器。
- `ReasoningContentBlock.reasoning` 既可能表示 thought summary，也可能表示原始 reasoning 文本，不能仅凭该字段公开。
- Python Host 当前只把 `type=text` 组装为 `content.delta`；Interactive Core 的 Timeline 只有 message/tool/interaction；TUI/Web 都从同一个 snapshot 渲染。
- Transcript 捕获也只应继续读取安全的 text block；summary/progress 属于运行期视图状态。

## 目标流程与关键 invariant

```text
run.started
  → run.progress(preparing, elapsed_ms)
  → model chunk
      ├─ 安全 summary_text → reasoning.summary
      ├─ type=text          → content.delta
      └─ 无公开内容         → run.progress(model, elapsed_ms)
  → tool.started/delta/completed
  → run.completed/cancelled/failed
      → 清除 summary/progress，保留正常终态摘要
```

关键 invariant：

1. 只有消息原始 content 中的标准 `summary_text` block 才能产生 `reasoning.summary`；规范化后的 `reasoning` 标量、`encrypted_content`、`additional_kwargs`、未知字段、未知类型和混合未知摘要全部不公开。
2. `reasoning.summary` 不得进入 `content.delta`、assistant buffer、ThreadMessage、恢复历史或最终 assistant 正文。
3. `run.progress` 只表示 Host 已进入准备或模型流阶段；UI 不得把它翻译成未观测到的“正在读文件/分析代码”等具体步骤。
4. 事件按同一 Run 的 `sequence` 去重；重复/乱序帧不改变摘要，终态事件清空临时状态。
5. subgraph namespace 仍 fail closed；工具输出继续走 Tool 事件，不被 summary extractor 解释。
6. reasoning 配置属于 `ModelSettings` 和 `model_settings_fingerprint`；同一个 Profile 的运行身份必须包含该配置。

## 公开 interface 与错误模式

### Protocol

新增事件：

```text
run.progress
payload = { phase: "preparing" | "model", elapsed_ms: non-negative integer }

reasoning.summary
payload = { text: non-empty string }
```

两个事件沿用 v3 event envelope 和 sequence。摘要超出 Host 安全上限时在发送前截断，不发送原始大小或私有字段；空摘要、非法 block 和解析异常均静默跳过并只保留普通运行进度。进度/摘要不是持久化事件。

### Python Host

`_message_text()` 只接受显式 `type=text` block；存在 `content_blocks` 时不回退读取不透明对象，避免私有 reasoning 字段被误当正文。新增 extractor 只消费消息原始 content 中的标准 `summary` 列表，对 block/summary 的未知字段 fail closed，并对文本设上限。

### Interactive Core

`InteractiveState` 增加 `runProgress` 与 `reasoningSummary` 两个 nullable ephemeral 字段，`InteractiveSnapshot` 原样暴露给两个 adapter。新 Run 初始化为 `preparing/0`；接收 progress/summary 更新它们；任意终态、清空 Thread、恢复 Thread 或本地失败都会清除它们。

### 模型配置

`ModelSettings.reasoning` 为可选结构：`effort` 允许 `low|medium|high`，`summary` 允许 `auto|concise|detailed`。仅显式配置时向 `ChatOpenAI` 传 `reasoning` 和 `output_version="responses/v1"`。任何非法值在 config load 阶段抛 `ConfigError`；不配置时不发送 adapter 参数。

## 按依赖排序的实施步骤

1. 修改 `packages/protocol/schema/v3.json`，运行 `bun run protocol:generate`，再运行 `bun run protocol:check`。
2. 先加入 Python/TypeScript 红灯测试，覆盖 schema、Host translator、Core reducer 和两个 presenter。
3. 实现 Host 的 fail-closed extractor、progress/summary 事件与安全 transcript 读取。
4. 实现 Core ephemeral state、sequence/终态清理和 adapter snapshot parity。
5. 实现 TUI/Web 的运行态摘要、spinner、时长、取消可达性、ARIA live 与 reduced-motion。
6. 实现 ModelSettings 解析、adapter 参数和 fingerprint，并更新配置文档。
7. 运行 focused 检查，再运行 `bun run typecheck`、`bun run test`、`bun run project:check`，把结果写入任务。

## 可观察验收

- 仅有 reasoning-only chunk 时，Core/TUI/Web 出现运行状态或摘要；页面/终端不出现该 chunk 的 `reasoning` 原文。
- 标准公开 summary 显示在独立“思考摘要”区域，assistant 正文只包含 text block；重新打开 Thread 不恢复摘要。
- 没有 summary 或摘要形状不确定时，运行中仍显示 spinner、已运行时长、事实阶段和取消提示。
- 终态后临时摘要/进度消失，正常 run summary 保留；重复/乱序事件无重复内容。
- reduced-motion 下无强制动画；ARIA status/live 文案仍可被屏幕阅读器感知。
- `reasoning` 配置改变会改变 Profile fingerprint，未配置时 adapter 不携带该参数。

## 非范围

- 任何 raw CoT 或 encrypted reasoning 的 UI、日志、Transcript、Thread 持久化。
- Provider 私有字段的猜测性兼容和 `extra_body` 旁路。
- ZC-106 的协议/Core 设计和视觉主题迁移。
