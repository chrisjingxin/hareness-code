# 架构重构计划

本计划只依据 2026-07-28 的当前生产代码与测试，不承接历史 task 中尚未实现的产品需求。目标是先收紧现有模块的 interface 和 seam，再重新评估功能路线。

## 切分原则

- 每个任务围绕一个可独立验证的 deep module，不按文件或 RPC handler 拆分。
- transport、React、SQLite 和 TOML 只作为 adapter；领域状态转换必须有唯一所有者。
- 新测试只穿过目标 module 的 interface；完成迁移后删除穿透 private implementation 的旧测试。
- 不新增产品能力，不改变当前用户可见行为，不为未来仅有一个实现的方向预建 port。
