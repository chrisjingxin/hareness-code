# HC-146 修复审批反复弹窗

## 背景

用户在 AutoEdit 或 Auto 下跑一轮编码任务时，`execute` 会频繁弹出审批。即使已经点了「本项目允许」或「本会话允许」，下一条稍有不同的命令（换一个测试文件、换一个目录、`python -m pytest` 再跑一次）仍会再问。

对照 Qwen Code，问题不是「模式名字抄错了」，而是 Execute 变安静所依赖的三条腿没对齐：

1. **只读 Shell 快放只绑在 `default`。** `is_safe_command()` 能识别 `ls` / `cat` / 只读 `git status`，但预检写成 `approval_mode == "default"`。切到更自动的 AutoEdit / Auto 后，这些命令反而开始弹窗。
2. **批准经常写不出能复用的规则。** `python` / `node` / `bun` 落在裸根禁令里，`python -m pytest …` 批准后规则是空的。非解释器又用「第一个像单词的参数留下」，`ls packages` 变成只覆盖这个目录的死规则。
3. **Auto 的分类器默认没接上。** F4 在未配置 `[approval] classifier` 时恒为「回退人工审批」。用户以为 Auto 会自己判断 Execute，实际和 Default 差不多吵。

HC-117 已经在修第一代缺陷（规则末尾强制加 ` *` 导致匹配不上自己、三平台白名单、`approve_always` 改名）。本任务不重复那批工作，解决的是 HC-117 之后仍然高频出现的「模式更自动、Execute 却更吵，批准也记不住」。

需求已用 `mattpocock:grill-me` 确认，结论见下文。规格待本 Task 确认后再写。

## 用户最终得到什么

在 AutoEdit 下编码：

- `ls`、`cat`、`git status`、`git diff` 这类只读命令直接跑，不再弹窗。
- 工作区内普通文件删除和编辑一样自动执行；`.git`、`.github/workflows` 等敏感路径删除仍会问。
- 第一次跑 `python -m pytest tests/foo.py` 仍会问。点「本项目允许」后，换 `tests/bar.py` 不再问。
- 第一次 `ls packages` 若仍走到审批（例如带了白名单不认的参数），点允许后 `ls docs` 也不再问。
- `task`、`web_fetch` 仍每次问。有副作用的 Shell 第一次仍问。

在 Auto 下：

- 上面的只读快放和已保存规则仍然生效。
- 没命中规则的 Execute / Monitor / 删除 / 子 Agent / 联网，由分类器判断：明确无害就执行，明确危险就直接拒绝（不弹窗），拿不准或分类失败就弹窗。
- 没有单独配置分类器模型时，用这次 Run 的主模型做分类，不必先改配置才能用 Auto。

「本会话允许」仍只活在当前进程；「本项目允许」仍写入 `.harness/settings.json`，下次打开同一项目继续生效。

## grill-me 已确认决策

| 决策 | 结论 |
| --- | --- |
| 做到哪算修好 | 只读不再问 + 批准能记住 + Auto 默认接上分类器；AutoEdit 工作区内非敏感删除也自动放行 |
| 解释器规则有多宽 | 批准任意一条 python / node / bun 等解释器命令后，同类解释器调用都放行（覆盖面与 Qwen 的裸根规则相同） |
| 哪些命令可以记裸根 | **只有解释器**。`rm` / `curl` / `wget` / `docker` / `ssh` 仍禁止裸根规则，避免 `rm foo.txt` 放行 `rm -rf /` |
| 非解释器规则粒度 | 已知子命令表，对齐 Qwen：`ls packages` → 覆盖所有 `ls`；`git commit -m x` → 覆盖 `git commit …`；`npm install express` → 覆盖 `npm install …` |
| Auto 分类器用哪套模型 | 优先 `[approval] classifier`；没配或没 key 时用当前 Run 主模型。超时 / 解析失败回退弹窗，绝不因此自动放行 |
| 工具范围 | Shell（`execute` / `monitor`）+ Auto 过滤器里的删除 / 子 Agent / 联网；AutoEdit 额外让非敏感删除自动放行 |
| AutoEdit 还问什么 | 敏感删除、有副作用的 Shell（第一次）、子 Agent、联网 |

实现注记（行为已确认，存储格式由规格定，不必再问用户）：覆盖面对齐 Qwen，**不要**把自动生成规则改回末尾 ` *`。HC-117 约束 B 对含 `*` 的规则会拿整条命令跑底线，`git commit *` 会让 `git commit` 永远再弹窗。解释器记裸根前缀 `python`，其余记纯前缀 `git commit` / `ls`，匹配继续走词前缀；手写的 `Bash(git *)` 仍走 glob。

## 当前存在的问题

### 问题 1：切到 AutoEdit / Auto，只读 Execute 比 Default 更吵

`is_safe_command()` 与 `SAFE_GIT_SUBCOMMANDS` 已经能放行 `ls`、`git status`。预检和 `evaluate_permission` 的 L3.1 却只在 `default` 执行。AutoEdit 的 Execute 默认是 `ask`，Auto 的 F2 又不包含 Execute，于是 `git status` 在更自动的模式里反而弹窗。

Qwen 在任意模式下先做 AST 只读判定，只读命令根本不进确认框。

### 问题 2：批准解释器等于没批准

`BARE_ROOT_FORBIDDEN` 含 `python` / `node` / `bun` / `bash` 等。`python -m pytest tests/foo.py` 去掉开关后只剩裸根，生成侧返回空串，session 和项目配置都不写。用户点了「本项目允许」，下次换个文件再跑 pytest 仍弹窗，而且再点一次还是写不进去。

### 问题 3：第一个「子命令」把路径写进规则

`ls packages` → 规则 `ls packages`，`ls docs` 不命中。Coding Agent 大量「根命令 + 目录/目标」，批准一次只能覆盖那一个词。

Qwen 用已知子命令表：`ls` 没有子命令，规则覆盖所有 `ls`；`git` / `npm` / `docker` 才保留子命令。

### 问题 4：Auto 分类器是可选的，默认等于继续问人

未配置 `classifier` 时 F4 占位实现恒为 ask。文档虽然写了「判断不可用时回退确认」，但用户切到 Auto 的预期是「系统会自己判断」，不是「和 Default 一样每条 Execute 都问」。

### 问题 5：AutoEdit 删除仍每条都问

编辑在 AutoEdit 已自动放行，删除仍是 `ask`。用户确认：工作区内非敏感删除应与编辑同权；敏感路径仍问。

## 目标设计（通俗）

```text
工具调用
  → 越界 / deny 规则：不弹窗，按原逻辑拒绝
  → 敏感路径：所有非 yolo 模式仍弹窗
  → 只读 Shell（is_safe_command，且未触安全底线）：
        plan 除外的所有模式直接执行
  → 已保存 allow 规则命中：
        按前缀剩余部分跑安全底线；未触底线则执行
  → AutoEdit + 工作区内非敏感编辑/删除：直接执行
  → Auto + 未决调用：分类器（专用 profile 或当前主模型）
        allow / deny / 失败回退 ask
  → 其余：弹窗
        「本项目/本会话允许」按已知子命令表或解释器裸根前缀写规则
```

## 范围

- 预检与 `evaluate_permission`：只读 Shell 快放从「仅 default」扩到所有非 plan 模式（yolo 本来就不问；plan 仍拒绝 Execute）。
- 规则生成：解释器允许裸根前缀；其余改用已知子命令表；`rm` / `curl` / `docker` 等危险根仍禁止裸根。
- AutoEdit：工作区内非敏感 `delete_file` 与编辑一样自动放行；HITL 集合仍包含删除，以便敏感路径弹窗。
- Auto：分类器默认可用；优先配置的 classifier profile，否则用当前 Run 主模型构图分类器。`execute` / `monitor` / `delete_file` / `task` / `web_fetch` 未被规则或确定性过滤器裁决时走分类器。
- 分类失败、超时、输出无法解析：回退弹窗，不自动放行。
- 用户文档：写清各模式实际放行范围、解释器规则有多宽、Auto 未配 classifier 时会用主模型。
- 架构总览「审批模式」节：增量更新上述行为。

## 非范围

- 不把 AutoEdit 变成对 Shell 的 YOLO：有副作用的命令第一次仍问。
- 不改 plan / yolo 的语义，不放开工作区外路径。
- 不给 `rm` / `curl` / `wget` / `docker` / `ssh` 生成裸根规则。
- 不自动改写用户已有的 `.harness/settings.json`（沿用 HC-117 决策 6）。
- 不新增规则管理界面，批准时不强制预览将写入的规则。
- 不改审批按钮集合与文案。
- 不替代 HC-117 尚未收尾的工作（三平台白名单补齐、`approve_always` 改名若仍未合入，仍归 HC-117）。本任务覆盖并取代 HC-117 **决策 5** 的词分类启发式。
- 不为分类器新做一套独立计费或单独的用户可见「分类中」产品面；失败回退沿用现有弹窗。
