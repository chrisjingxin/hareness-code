# HC-165 会话撤销重做与快照还原

## 背景与问题

在长会话编码场景中，Agent 可能会在某一轮对话中出现偏离意图、编写错误代码或产生大量冗余文件的情况。当前 Harness Code 仅支持 `/new`（彻底开启新 Thread）和 `/compact`（上下文压缩），缺少回到历史特定回合的精细化容错能力。当某次回合写崩时，开发者不得不废弃整个会话重新开始，严重影响研发流畅度。

## 目标与范围

为 Harness Code 引入类似 Claude Code（`/rewind`）与 OpenCode（`revert` / `unrevert`）的会话与代码时光机能力，通过统一的 `/undo` 和 `/redo` 命令实现：

1. **历史回合选择器**：输入 `/undo`（或别名 `/rewind`、`/rollback`）弹出 `SearchPicker` 浮层，列出当前 Thread 历史上的所有 User Turns，展示 Prompt 摘要、相对时间及关联文件变更统计。
2. **三档还原选项**：
   - 同时回退代码与对话（Restore code and conversation）：截断对话上下文，并将磁盘代码还原至目标 Turn。
   - 仅回退对话（Restore conversation）：截断模型上下文，但保留当前磁盘文件。
   - 仅还原代码（Restore code）：仅还原磁盘代码至目标 Turn，保留对话记录。
3. **基于 Git 树隐式快照的代码还原**：在每轮 User Turn / Tool 运行前后，通过底层 Git plumbing（如 `git write-tree`）记录不可见的树对象快照，不污染用户 Git HEAD 分支与 commit log，并在回退时精确恢复。非 Git 仓库提示禁用代码回退或降级为纯对话回退。
4. **Undo / Redo 暂存状态机**：
   - 执行 `/undo` 后进入暂存回退态（Reverted State），在用户未发送新 Prompt 前，随时可通过 `/redo` 一键重做回最新状态。
   - 用户在回退态发送新 Prompt 时，正式触发 `cleanup` 物理截断旧分支，开启全新时间线，此时 `/redo` 自动失效。

## 验收标准

1. **命令注册与解析**：
   - Command Registry 正确声明 `/undo`（aliases: `rewind`, `rollback`）与 `/redo`；
   - `/redo` 在非暂存态时在 Slash 菜单中展示为 disabled，并说明原因；
   - `/undo` 在没有历史可回退时展示为 disabled。
2. **交互浮层与展示**：
   - 输入 `/undo` 弹出历史 Turn 选择器，支持键盘上下导航、搜索与 Enter 选择；
   - 选中 Turn 后展示该 Turn 预览、受影响文件列表统计（additions/deletions/files），并提供三档选项确认。
3. **Git 快照与还原**：
   - 在 Git 仓库下，选择还原代码能够秒级无损将修改过的文件恢复到目标快照状态（支持新增、修改与删除文件）；
   - 执行过程不产生无意义的 Git commit，不移动用户 HEAD。
4. **Redo 与新分支固化**：
   - 回退后未发新 Prompt 时，运行 `/redo` 能瞬间完整恢复历史与文件；
   - 发送新 Prompt 后，旧后续分支被持久化截断，`/redo` 正确置灰失效。

## 实施与 Review 结论

### 五维质量审查（agent-skills:code-review-and-quality）
1. **正确性 (Correctness)**：
   - 跨进程 JSON-RPC v3 方法（`threads.list_turns`、`threads.undo`、`threads.redo`）在 Python 与 TypeScript 两端强契约对齐。
   - `GitCheckpointService` 基于隔离 `GIT_INDEX_FILE` 创建树快照，不污染用户 HEAD 与 index；支持无初始 commit 的全新空 Git 仓库。
   - SQLite Schema v18 级联物理截断（`cleanup_thread_history_after_turn`）保证分叉点后旧数据干净清理。
   - `isReverted` 暂存状态机在 `startRun` 时自动重置，`/redo` 可用性状态精准切换。
2. **可读性与简洁性 (Readability & Simplicity)**：
   - 代码结构清晰，无多余 wrapper 与死代码；中文字段与 JSDoc 注释完备。
3. **架构分层 (Architecture)**：
   - 严格遵循 `Presentation 不直连 IPC，Application 不反向依赖 Presentation` 规则，通过 `architecture.test.ts` 强约束。
4. **安全性 (Security)**：
   - 路径解析使用 safe resolve，SQL 参数化查询绑定，无注入与路径穿越风险；Git 快照录制异常降级保护不阻塞主对话。
5. **性能 (Performance)**：
   - 依托 Git 底层 C plumbing，快照生成与还原均为毫秒级。
