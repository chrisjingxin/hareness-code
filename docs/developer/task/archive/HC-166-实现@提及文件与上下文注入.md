# HC-166 实现 @ 提及文件与上下文注入

需求已通过竞品深度调研（Claude Code、Codex 等）并与用户就 128k 企业级紧凑上下文预算达成一致确认（2026-09-01）。用户结果与验收以本文为准。

## 通俗说明

以前用户在终端输入消息时，如果要让 Agent 看某个文件，要么切到侧边栏文件树按 `@` 插入路径，要么自己手动手打路径；而且发送后 Agent 第一轮并不知道文件内容，必须先调用一次 `read_file` 读取文件，用户得白白多等几秒钟。

本任务打通完整的 `@` 文件提及闭环：

```text
在输入框打 @
  → TUI 与 Web 实时弹出纯路径菜单（固定高度、匹配高亮、计数与滚动）
  → 空查询从工作区根目录开始，可逐级进入目录定位文件
  → 按 Tab 或 Enter 补全路径（有空格自动加引号 @"path/my file.txt"，支持 #L10-50 行号）
  → 发送消息时，小文件（<10KB）或指定行号切片自动带上代码发给 Agent
  → 大文件自动变成轻量引用提示，不撑爆 128k 上下文
  → Agent 第一轮直接看到代码并开始回答，无需额外的 read_file 往返
```

## 当前问题

1. **输入框无法联想补全**：在输入框键入 `@` 没有任何反应，只有输入 `/` 才会弹出 Slash 命令菜单；
2. **缺乏即时代码感知（多一次 Tool Call 往返）**：消息中的 `@path` 只是纯文本，Agent 必须先执行 `read_file` 才能获取内容，产生 2~4 秒的额外延迟；
3. **缺少行号语法切片**：无法像主流工具一样指定 `@file#L20-50` 仅提取核心代码段；
4. **企业 128k 上下文保护缺失**：若用户提到大文件，缺乏大小门禁与黑名单过滤机制。

## 用户最终得到什么

1. **输入框即时 `@` 补全**：
   - 输入框中键入 `@` 立即弹出当前工作区文件候选列表；
   - 支持键盘 `↑`/`↓` 选择、`Tab`/`Enter` 确认补全、`Esc` 关闭；
   - 使用简洁的纯相对路径行，匹配字符高亮；候选很多时固定显示 8 行（矮终端 5 行），展示匹配计数并支持滚动与翻页；
   - 空查询只展示工作区根目录的第一层文件和目录，进入目录后再展示下一层；
   - 路径含空格时自动包裹引号（如 `@"docs/my spec.md"`），补全后自动在末尾追加空格方便继续打字。
2. **丰富的提及语法**：
   - 标准路径：`@packages/cli/src/index.ts`
   - 带空格路径：`@"src/my test file.ts"`
   - 精确行号切片：`@packages/cli/src/index.ts#L20-50` 或 `@src/app.tsx#L10`
3. **自适应的 128k 保守上下文预算注入**：
   - **小文件（< 10KB 且 < 300 行）或指定行号切片**：发送时自动提取文件内容，作为上下文块注入，Agent **首轮即可直接回答**；
   - **大文件（>= 10KB）或噪音/生成文件（.lock、.min.js、.map 等）**：自动降级为占位提示 `[Mentioned File: <path> (Size: X KB, too large to inline. Use read_file to inspect)]`，彻底杜绝爆上下文风险；
   - **单轮总上限控制**：单次消息内所有 `@file` 累计内联不超过 **20KB**（约 500 行代码 / ~4k-5k Tokens）。
4. **端到端安全防御**：
   - 自动校验路径合法性与是否在当前工作区内，防止 `../` 目录穿越逃逸；
   - 不存在的 `@` 字符串（如 `@username` 或普通文本）自动忽略，不影响正常提问。

## 已确认产品决策

1. **独立功能编号**：建立 `HC-166` 跟踪本功能，全套文档（Task/Spec/Plan/Todo/Research）保持同名同编号。
2. **分级内联预算策略**：单文件内联上限设为 **10KB**，单轮总内联预算设为 **20KB**，完美适配企业 128k 上下文约束。
3. **行号语法优先**：支持 `#L10-50` 切片提取，仅注入局部代码，最大限度节约 Token。
4. **共享核心实现**：提及解析、候选搜索、匹配范围与窗口导航逻辑放在 `packages/cli/src/presentation-shared/`，由 TUI 与 Web 端统一消费；文件读取与安全校验复用 `workspace/path-policy`。
5. **按可演示停点交付**：按规范一次只推进到可演示停点，不违规一次做完全部 Todo。
6. **显式切片源文件有界**：`#L` 切片允许读取大于 10KB 的文本文件，但源文件超过 16MiB 时在整体读取前降级为引用，避免少量行请求触发无界内存读取。

## 可演示停点规划

1. **停点 1（输入补全闭环）**：在 TUI 输入框中输入 `@` 弹出工作区文件候选浮层，键盘导航与 `Tab`/`Enter` 选中回填生效；
2. **停点 2（解析与内容切片提取）**：单元测试验证 `@path`、引号路径、`#L10-50` 行号提取与 10KB/20KB 预算门禁；
3. **停点 3（端到端 Prompt 注入）**：发送 `@file` 或 `@file#L10-20` 消息，Agent 首轮直接感知代码并回答，大文件降级占位。
4. **停点 4（双端大文件集菜单）**：TUI 与 Web 使用同一候选搜索结果；菜单固定显示 8 行（矮终端 5 行），展示 `当前位置/匹配总数`、候选池截断提示、匹配高亮和长路径省略，支持滚动、翻页与边界夹取；
5. **停点 5（双端目录下钻）**：空查询只展示根目录第一层；选中目录后可逐级进入或返回上级，选中文件仍按原语法回填。

## 范围

1. `presentation-shared` 下的 `@` 光标词法解析器、模糊匹配策略与提取器；
2. TUI 与 Web Composer 的 `MentionMenu` 状态机、固定窗口导航、目录下钻与选中回填；
3. `workspace` 下的提及文件安全读取与行号切片解析器（带 10KB/20KB 与黑名单门禁）；
4. `InteractiveController` / `runFeature` 提交时的上下文注入拼装；
5. 单元测试与用户文档更新（`docs/user/交互使用.md`）。

## 非范围

1. 不修改 Python Agent 核心交互协议或数据库 Schema；
2. 不在多轮压缩后把全文永久驻留历史（后续由 Compaction 按既有机制自动收敛）；
3. 暂不涉及网络 URL / 外部 Git 仓库的远程内联（仅限本地 Workspace 范围）。

## 质量审查结论（2026-09-02）

使用 `agent-skills:code-review-and-quality` 按正确性、可读性、架构、安全与性能五轴完成审查。审查发现并修复 3 项必须项：显式行号切片可能整体读取无界大文件、菜单关闭时仍重复扫描完整工作区、Markdown 附件内含三反引号时会提前闭合外层围栏。对应回归测试均已补齐。

- **正确性**：TUI/Web 的触发、搜索、目录下钻、回填与 Prompt 注入符合 Task/Spec；附件围栏现在严格长于正文最长反引号序列。
- **架构与可读性**：跨端算法保持在 `presentation-shared` 纯策略，文件系统读取留在 `workspace`，Adapter 只持有端内状态；未新增依赖、Python 协议或 SQLite 形状。
- **安全**：路径 realpath containment、UTF-8/二进制判定、10KB/20KB/300/500 门禁、黑名单和 16MiB 切片源上限均有自动化覆盖。
- **性能**：候选池上限 1000、工作区索引上限 20000；菜单不可见时发布共享空结果，不进入工作区扫描热路径。
- **结论**：Critical 0、未解决 Required 0；批准进入归档准备。
