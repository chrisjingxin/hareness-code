## 通俗说明

Compose 已经能按“理解 → 计划 → 构建 → 验证 → 评审”推进，但阶段内部现在像黑盒。用户只知道当前阶段，无法判断模型仍在处理、正在运行 Tool、等待审批，还是已经卡住。

本功能让 Compose 复用 Build 已有的实时执行链路，并在每条活动上补充 Stage、Task、Agent 和 attempt 归属。用户看到的是 Harness 已确认可公开的运行事实，不是隐藏思维或阶段 Agent 返回的内部 JSON。

```text
提交 Compose 请求
  → 显示当前 Stage、Agent 和耗时
  → 实时显示安全 Reasoning、Tool 与 Interaction
  → Runtime 校验内部结果并生成阶段摘要
  → 推进下一阶段
  → Thread 重开时恢复有界审计记录
```

## 用户最终得到什么

- TUI 和 Web 都能在当前执行位置看到 Compose 正在做什么，不再只显示静态阶段条。
- 模型状态、可公开 Reasoning、Tool start/result、Approval、Question 和阶段摘要按真实顺序展示。
- 每项活动都能回答属于哪个 Stage、Task、Agent 和 attempt；重试、fix loop 和双 Reviewer 不会串卡。
- 当前阶段默认展开，完成阶段默认折叠且可检查；失败、阻塞或取消不会清空已经发生的安全过程。
- Thread 重开后可恢复阶段、Task、Tool 终态、Verification 和 Review 摘要，但不会恢复 Reasoning、原始 Tool 内容或内部 artifact。

## 范围

- 把 Build 中的 LangGraph 流、Reasoning 翻译、Tool correlation、Interaction resume 和取消收敛为 Build/Compose 共用的 execution stream module。
- 为 Event 和 Interaction 增加严格、有界的 Compose activity scope，并使用真实 child execution provenance。
- Stage Agent 改为流式执行：安全事件实时发送，artifact 正文仅内部捕获，校验后由 Runtime 生成阶段摘要。
- Verify command、Builder task、两个 Reviewer、retry 和 fix loop 进入同一 scoped Timeline。
- Interactive Core 统一归组活动；TUI/Web 只负责共享状态的展示、折叠、滚动和焦点。
- 独立、有界地持久化 Compose 审计记录，并与根 Transcript 和模型 context 隔离。
- 补齐 Build 回归、Compose production-chain E2E、Protocol、恢复、双端展示和用户文档证据。

## 非范围

- 改变 HC-138 的 Stage 顺序、retry budget、artifact schema、Verification evidence 或双 Reviewer 判定。
- 展示或持久化隐藏 chain-of-thought、encrypted reasoning、未知 provider metadata、Prompt、ContextPack、artifact JSON、完整 Tool output、凭据或绝对用户路径。
- 把 Stage 临时正文或 activity history 写入根 Transcript、ContextProjector 或后续模型 context。
- 新增 Compose 专属日志页、第二套 Interactive Core，或让 TUI/Web 直接解释 Host Event。
- 通用 Workflow SDK、Plugin 自定义 Stage、跨进程 durable resume、自动 commit/push/PR 或远端 CI。

## 可观察验收

- Compose 任一模型阶段开始后，TUI/Web 立即显示正确 Stage、Task、Agent、运行状态和活动时长；没有公开 Reasoning 时也不会呈现空白等待。
- Tool 与 Interaction 保持 Host sequence；同名 Tool、重复 provider call ID、stage retry 和两个 Reviewer 不会互相覆盖。
- Child Tool 审批结束后恢复原 execution 和 checkpoint namespace，不重新创建 stage attempt。
- artifact JSON、Prompt、ContextPack 和隐藏思维不会出现在 wire、日志、Timeline、根 Transcript 或恢复记录；阶段摘要只来自已校验数据。
- 自动跟随底部时当前阶段可见；用户主动上滚时不被强制拉回；TUI/Web 的折叠、焦点、无障碍和终态语义一致。
- Thread reopen 按原顺序恢复有界阶段、Task、Tool 终态、Verification 与 Review 摘要；达到上限时明确显示截断，且恢复数据不进入模型 context。
- Build 的 event sequence、Timeline、审批、Transcript、恢复、取消和唯一终态与修改前一致。
- completed、failed、blocked、cancelled 和 terminal 后迟到事件均有 production-chain 回归测试；项目级构建、类型、测试和文档检查通过。
