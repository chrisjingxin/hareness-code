# HC-172 审批模式本轮生效

## 背景与用户结果

现在切换审批模式主要只改变 CLI 的下一轮选择；活动 Run 已编译的共享图和 Host 侧执行上下文仍拿着旧模式，用户无法可靠地判断当前任务是否已经收紧或放宽。这个任务把切换变成 Host 拥有的 Run 级操作：CLI 先请求服务端，服务端成功线性化后才改变本地显示，后续尚未决定的边界读取同一份新状态。

用户最终可以在当前任务继续运行时切换 `default`、`auto-edit`、`auto`、`yolo` 或 `plan`。活动 Run 的 owner 控制面切档与空闲/下一轮选择遵循同一用户控制语义，不额外要求 repository-level trust 状态；外部目录的独立 `WorkspaceBoundary`/`directory_trust` 流程仍约束文件工具和执行边界。已开始或已决定的调用不撤销；待下一次模型调用、HITL 预检、计划约束、AUTO 分类、目录信任和子代理门禁会看到新模式。失败时 UI 保持旧值，不会出现“看起来切换成功、服务端仍是旧策略”。

## 范围

1. 新增受控 `run.set_approval_mode` RPC、生成代码、能力声明、Host owner/control-lease 校验、Run 状态 revision 和稳定错误。
2. 让共享 AgentEngine 编译安全超集；在模型、工具、Plan、AUTO、目录信任和 delegation 决策边界动态读取当前 Run 模式。
3. 让 CLI Core 对活动 Run 走 RPC 成功后提交；空闲 Run 延续本地下一轮默认；待 Interaction、RPC 失败和终态保持拒绝/回滚。
4. 让 root、Inline child、Managed Plugin child 继承父 Run 当前模式并与自身最大权限求交，保留 HC-168 的串行审批恢复边界。
5. 补齐诊断、RuntimeState/compaction 快照、用户文档、架构文档和离线 focused/e2e 回归。

## 非范围

- 不重建或热替换共享 AgentEngine，不撤销已开始的模型/工具调用，不重放已发布内容。
- 不让 YOLO 绕过 deny、Capability、Policy、Workspace/Sandbox 或企业硬策略。
- 不修改 SQLite schema、审批 Interaction 的 cardinality 或 HC-168 的 `on_resume_consumed` 语义。
- 不使用真实模型、凭据、网络 MCP 或外部 Hook。
- 提交与推送仅在用户验收并明确授权后进行；实现已由 `b9c493a` 落地，本轮文档仅完成任务编号收口与生命周期归档。
