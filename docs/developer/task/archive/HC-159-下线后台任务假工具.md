# HC-159 下线后台任务假工具

## 需求确认结论（2026-08-21）

| 问题 | 结论 |
| --- | --- |
| KillShell 旧别名是否一并删除 | 一并删除；规则文件中的 KillShell 按未知工具 fail-closed 当作 EXECUTE 风险处理 |

## 问题（通俗说明）

模型目前能看到三个"后台任务"工具：

- `monitor(command, interval)`：自称在后台持续执行命令（如开发服务器）；
- `task_output(task_id)`：自称获取后台任务的输出；
- `task_stop(task_id)`：自称终止后台任务。

核查结论：这三个工具从未实现。`monitor` 只在一个内存字典里登记一行 `{"status": "running", "output": ""}` 就返回"后台任务已启动"，没有任何进程被执行；`task_output` 永远返回空输出；`task_stop` 只翻转字典里的一个标志位。它们会对模型谎报"任务已启动"，并在审批清单、风险分级、并发分类、规则 DSL、CLI 展示目录等策略面占着大量死配置。

本仓库架构约束（docs/developer/architecture/上下文管理改造需求.md）明确规定"不存在的后台任务能力不得伪造占位实现"，这三个工具违反该约束。

## 方案（通俗说明）

把三个工具连同所有接线整体下线，不留别名、不留空壳、不留死配置：

- 删除工具实现与注册：`harness_tools.py` 三个注册块、`tools_mode.py` 整个文件、`agent.py` 工具契约三条；
- 收敛策略面：审批 HITL 清单、ToolKind 风险映射、Shell 工具集合、委派工具集合、并发分类、规则 DSL 映射中移除三个名字；
- `KillShell` 旧别名一并删除（见需求确认结论）；
- CLI 展示目录移除 `monitor` 的图标/标签登记；
- 同步测试与用户文档。

## 范围边界

- 只删除这三个工具及其引用，不新增替代能力；
- 插件 Monitor 机制（plugins/runtime.py 的 MonitorDefinition/MonitorManager）是独立机制，保留不动；
- `task` 工具（子代理委派，同步返回结果）不受影响。

## 验收（可观察）

1. 活跃代码、测试、用户文档中 grep 不到三个工具名残留（架构/历史存档文档除外）；
2. packages/agent 与 packages/cli 测试全绿；
3. `create_harness_tools()` 返回集合不含三个工具名，有负向测试锁定；
4. docs/user/subagent.md 工具表从 20 项减为 17 项，docs/user/模型配置.md 低频工具名单同步。

## 非范围

- 不实现真正的后台任务能力（另行立项时复用插件 Monitor 机制）；
- 不清理其他历史工具面（如已由 HC-132 处理的 apply_patch）；
- 不改动跨进程协议与 SQLite 数据。
