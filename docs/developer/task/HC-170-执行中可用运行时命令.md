# HC-170 执行中可用运行时命令

需求已用 `grilling` 与用户确认（2026-09-08）。用户结果与验收以本文为准；后续 Spec 只能细化实现，不能扩大为 steer 或下一轮队列。

## 通俗说明

用户提交一条 prompt 后 Agent 开始干活，TUI 输入栏会失焦，只能按键取消；Web 虽能打字，提交会被直接丢掉。`/btw`、`/goal`、`/status` 这些本来就能在运行中执行的命令，因为输入面被锁死而用不了。

本任务打开执行中的输入栏，但**只放行运行时命令**，不把普通文字送进当前 Run，也不做「边跑边改口」。

```text
Agent 正在执行
  → 输入栏仍可打字
  → 运行时命令：立刻执行（本地查看 / 旁路问答 / 已规定会排队的控制面）
  → 普通文字、会新开 Run 或热切换绑定的命令：拒绝并留下草稿
  → Esc：只关浮层；没有浮层时提示取消键，不中止任务
  → TUI Ctrl+C / Web 停止按钮：取消当前任务，草稿保留
```

## 当前问题

1. TUI 在 `activeRun` 时把输入栏失焦，placeholder 写「Esc 中断」，用户无法输入任何斜杠命令。
2. Web Composer 执行中仍可打字，但 adapter 见到 `activeRun` 直接丢弃提交；且没有 BTW 呈现，`/btw` 即使提交成功也看不见。
3. 命令表已有 `requiresIdle`，`/btw`、`/goal`、`/status` 并未标必须空闲，但 Controller 对 `present` 一刀切拒绝，只读浮层也打不开。
4. `/goal` 写操作和 `/btw` 旁路在 Agent 侧已经能与主 Run 并存；卡点在交互层。
5. 输入一旦解锁，Esc 若仍同时「关浮层」和「取消任务」，关完 `/status` 再按一下就会误停长任务。

## 已确认产品决策

1. 第一版只放行运行时命令；普通 Enter 既不 steer 当前 Run，也不排到下一轮。
2. `/quit` 在干活时先确认「当前任务将被中止」，确认后再退出。
3. TUI 与 Web 共用同一张命令表；Web 补最小 BTW 面板，语义与 TUI `/btw` 一致。
4. 执行中的空参 `/goal`、`/plan-view` 用独立浮层，不占用审批/问答底部槽；空闲时现有 GoalDock / PlanDock 不改。
5. Esc 只关界面。取消任务：TUI 用 `Ctrl+C`（干活时一律中断并留草稿），Web 用停止按钮。无浮层时按 Esc 只提示正确取消方式，不中止任务。

## 用户最终得到什么

执行中可以打字、选命令、看状态、旁路提问、改目标控制面；不能把自然语言塞进正在跑的 Agent，也不能一按 Esc 就停掉任务。

### 执行中放行

| 输入 | 行为 |
| --- | --- |
| `/help` | 立刻本地说明 |
| `/status` | 立刻打开状态浮层 |
| `/btw <问题>` | 独立旁路问答，不写主 Transcript，不占主 Run |
| `/btw` 空参 | 用法提示，不调模型 |
| `/goal` 空参 | 独立浮层查看当前目标 |
| `/goal` 的 create/replace/edit/pause/resume/clear | 走已有 Goal 控制面；写操作排队到安全边界，不改当前 Run 冻结的 revision |
| `/plan` 空参 / `exit` / `<目标>` | 只改下一轮档位；running 时不新开规划 Run（保持现有 `/plan <目标>` 降级） |
| `/plan-view` | 有挂起计划审批则聚焦；否则独立浮层只读预览 |
| `/mcp` | 只读刷新/查看 |
| `/agents` | 只读 picker，选中即关闭，不派发 |
| `/teams`、`list`、`show`、`status` | 只读查询 |
| `/teams cancel <run-id>` | 请求取消该 Team Run |
| `/new` `/clear` | 现有确认框：确认后先取消再新建 |
| 未知 `/xxx` | 本地提示或建议，**不**送给模型 |
| `Shift+Tab` | 改下一轮审批档，不影响当前 Run |

### 执行中禁用（提示原因，草稿保留）

`/compact`、`/resume`（及别名）、`/undo`（及别名）、`/redo`、`/model`、`/web`、`/skills`、`/skill:<id>`、Plugin Command、`/new-work`、`/abandon`、`/teams generate`、`/teams run`、`!` Shell、普通文字、`//` 转义后的普通文字。

压缩中白名单仍只放 `/help`、`/status`、`/quit`，本任务不放宽。

### 取消与 Esc

- Esc：关 BTW / 状态 / Goal / Plan / 命令菜单 / 确认框。审批、问答 Dock 仍由现有 Interaction 处理。
- 没有可关的东西时 Esc 不取消任务，提示 TUI 用 `Ctrl+C`、Web 点停止。
- TUI 干活时 `Ctrl+C` 一律取消当前任务并保留草稿（不再先清空再取消）。空闲时 `Ctrl+C` 保持现状。
- Web 用现有停止按钮取消；Esc 不再取消 Run。
- 输入栏文案从「Esc 中断」改为实际取消方式。

## 范围

1. TUI 执行中保持输入栏可编辑、可提交命令；压缩中、断线、审批/问答 Dock 仍独占。
2. Web Composer 执行中允许提交运行时命令；补最小 BTW 面板。
3. Interactive Core 用命令能力表作为唯一运行态门禁；拆开 `present` 对只读浮层的一刀切 busy。
4. 按上表实现放行/禁用/确认；未知斜杠保持本地提示。
5. Esc 与取消键按「已确认产品决策」第 5 条分层；更新用户文档快捷键说明。
6. `/goal` 空参与 `/plan-view` 在执行中改为独立浮层；来了审批则关掉该浮层，把底部交给审批。

## 非范围

- 普通 Enter 注入当前 Run（steer）或排到下一 Run 的队列。
- 改空闲时 GoalDock / PlanDock。
- 放宽压缩中命令白名单。
- 运行中热切换当前 Run 的模型、工作模式或 Thread。
- 运行中武装 Skill、切入 Shell、Handoff 到 Web、压缩、撤销/重做。
- 新 JSON-RPC runtime_input 契约或 Agent mailbox。
- 为 Web BTW 单独做流式协议；与当前 TUI `/btw` 的请求-响应语义对齐即可。

## 可观察验收

1. 执行中 TUI 输入栏可聚焦打字；Web Composer 可打字并可提交放行命令。
2. 执行中 `/btw 问题` 弹出独立浮层并得到旁路回答；主 Run 继续；回答不出现在主时间线/Transcript。
3. 执行中 `/goal 改一下验收` 或 pause/resume/clear 被接受或提示已排队；当前 Run 不因此被取消或换模型。
4. 执行中空参 `/goal`、`/plan-view`、`/status` 打开独立浮层；Esc 关掉浮层后任务仍在跑。
5. 执行中发送「继续改测试」被拒绝，草稿还在；发送未知 `/foo` 只出现本地未知命令提示。
6. 执行中 `/model`、`/compact`、`/skills`、普通 Plugin Command 菜单显示禁用原因，提交后草稿仍在。
7. 执行中 `/quit` 弹出确认，取消确认则继续跑；确认后才退出。
8. 执行中 TUI 按 Esc（无浮层）不取消；`Ctrl+C` 取消且草稿仍在。Web 按 Esc 不取消，停止按钮取消。
9. 审批到来时，执行中打开的 Goal/Plan/状态浮层让位，底部交给审批 Dock。
10. `docs/user/交互使用.md` 写明执行中可输入、放行/禁用命令、Esc 与取消键的差别。
