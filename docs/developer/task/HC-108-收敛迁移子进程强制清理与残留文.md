## 背景

HC-107 将旧 schema 迁移放入可终止的独立子进程，避免不可中断的 `aiosqlite` worker
永久占用 Host。正常路径已经形成“超时 → terminate/kill → 确认 child 退出 → 按数据库事实恢复”的边界。

最终窄评审确认核心上下文连续性和 PromptEpoch 一次性迁移已经闭环，但强制清理的异常分支仍有
两个独立风险。用户决定不再阻断 HC-107 提交，将它们显式转入本任务；这不代表风险已经修复。

## 当前存在的问题

### 1. 强制终止或回收失败时可能释放迁移锁

当前 terminate、kill 和 reap 只处理部分进程异常。若出现权限错误、`wait`/`poll` 失败或最终
无法确认 child 已退出，异常会离开迁移流程；如果此时没有在释放文件锁前发布同一数据库的
持久/进程内 poison，后续 opener 可能进入，而未知 child 仍可能访问数据库。

### 2. SIGKILL 或 child crash 会留下临时文件

backup 与 restore 临时文件主要依赖 child 内 `finally` 清理。child 被 SIGKILL 或异常退出时，
这些文件可能残留。父进程尚未按受信命名、文件身份、数据库归属和完整性验证后进行有界清理，
也没有证明不会误删有效 backup、主库或攻击者放置的同名文件。

## 目标设计

```text
child timeout / crash
→ 父进程尝试 terminate
→ 有界等待
→ 必要时 kill
→ 有界 wait/reap
→ 无法证明 child 已退出：先发布 poison，再释放 migration lock，Host fail closed
→ 已证明退出：严格验证主库、migration state、verified backup
→ 只清理可证明属于本次 migration identity 的临时文件
→ 恢复或继续启动
```

poison 发布必须早于文件锁释放。任何异常路径都不得把“无法确认 child 已退出”解释为“child 已退出”。

## 实施步骤

1. 统一 terminate、kill、poll、wait 和 reap 的异常状态，覆盖权限错误、OS 错误、超时及未知结果。
2. 在持有 canonical database migration lock 时发布 poison；等待该锁的 opener 获取锁后必须再次检查。
3. 对无法回收的 child 保持 Host 失败关闭，记录不含路径和凭据的诊断；不得在线 restore。
4. 为 backup/restore 临时文件加入 migration identity 和受控目录边界，父进程只处理严格匹配的文件。
5. 启动清理先拒绝 symlink、非普通文件、错误 owner/权限和身份不匹配，再验证 SQLite 完整性与用途。
6. 已验证的 source backup、主库、WAL/SHM/journal 和无关文件永远不进入临时清理集合。
7. 增加 terminate、kill、wait、poll、reap 失败，以及 SIGKILL/crash 残留临时文件的回归测试。

## 范围

- legacy migration child 的强制终止、回收、poison 和临时文件生命周期。
- 同一数据库多 opener 的失败关闭边界。

## 非范围

- 不修改上下文压缩、Transcript、ContextProjector 或 PromptEpoch 迁移语义。
- 不扩展支持新的旧 schema 版本。
- 不删除无法证明归属的文件。

## 验收清单

- [x] terminate、kill、poll、wait 或 reap 任一失败时，进程内 poison 在 migration lock 释放前可见，durable marker 写失败也不解除门禁。
- [x] 等待 migration lock 的所有 opener 在获得锁后重新检查并失败关闭。
- [x] 无法证明 child 已退出时不执行 rollback、restore 或正常 open。
- [x] POSIX child crash/SIGKILL 后只清理严格归属于本次 migration identity 的临时文件。
- [x] POSIX symlink、身份不匹配、权限异常和恶意同名文件均失败关闭且不被删除。
- [x] verified backup、主库及其 WAL/SHM/journal 不会被临时清理误删。
- [x] 每个 attempt 的登记文件数量固定有界；已 reaped 时立即清理，`exit_unknown` 不承诺在线保留时间上界，只能在显式确认所有 worker 停止后离线幂等收敛。
- [ ] Windows 实现稳定 FileId adapter，并以真实 Windows runner 覆盖 identity replacement 与 cleanup；完成前旧库迁移返回 `CHECKPOINT_MIGRATION_FILE_IDENTITY_UNSUPPORTED`，不得宣告该平台完成验收。

## 平台边界

当前 ZC-108 的文件身份与真实进程测试证据仅覆盖 POSIX。Windows 的 `st_dev/st_ino`
不能替代稳定 FileId；为避免把未验证能力当作安全边界，现阶段 Windows 只对需要 ZC-108
attempt 的旧库迁移失败关闭。当前 schema 数据库的常规打开不受影响。
