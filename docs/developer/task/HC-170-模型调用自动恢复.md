# HC-170 模型调用自动恢复

## 背景与问题

OpenAI-compatible 网关可能先返回缺少 `name` 或 `id` 的畸形工具调用，随后在下一轮因 assistant/tool 历史不匹配返回 500。当前能力策略在缺少 ID 时把 `capability-policy` 写进 `ToolMessage`，会进一步制造孤儿结果；而 Build 没有把已有 `ManagedAgentExecutor` 的 provider retry seam 配上，SDK 的 `max_retries` 也无法处理“响应已返回但结构不可用”的情况。

## 用户最终得到什么

```text
模型返回 tool_calls
  → 模型输出保护在 ToolNode 前校验
  → 未公开输出的畸形响应不写 graph/checkpoint/Transcript，按同一预算重试
  → 合法调用缺少 ID 时由 assistant/tool 共用生成 ID
  → 正文/推理保持实时；已公开正文/推理后发生临时错误不自动重放，收敛为 `retryable=true` 的稳定终态，允许用户发起新 Run
  → 5xx/429/传输错误按 attempt 线性退避；400/鉴权/取消/策略拒绝立即结束
  → 成功继续当前 Run；预算耗尽只发一个稳定失败终态
```

用户可看到的是正常 Run 自动恢复；失败时得到稳定错误码、脱敏上游摘要和正确的 `retryable` 标记，而不是裸的 `Internal server error`。

## 范围

1. 新增职责单一的模型输出保护 middleware，提供同步与异步模型调用路径。
2. 将 `MALFORMED_TOOL_CALL`、5xx、429 和传输类临时错误接入 Managed executor 的既有重试、取消检查、`RunTimingLedger.retry_wait_ms` 与 `model.retry_scheduled/model.failed` 诊断。
3. 以 `ModelSettings.max_retries` 作为一次模型请求的重试次数；SDK 不再为同一请求额外重试，避免预算叠加。
4. 合法但无 ID 的调用在模型响应层补齐非空稳定 ID；能力策略拒绝只能复用该 ID，防御路径不得再生成 `capability-policy`。
5. Build 根 Run、Compose 主 Agent、Inline child 和 Managed Plugin 共用语义；失败尝试不得进入 canonical Transcript/checkpoint。

## 非范围

- 不新增 Protocol 字段、不修改公开 Run/Event shape。
- 不复制一套新的无限 HTTP retry；不改变用户的 `max_retries` 配置字段含义。
- 不把未知/未授权工具策略错误改成 provider retry。
- 不改变取消、审批拒绝、Compose/Team/Plugin 的既有终态与资源回收语义。
- 不使用真实模型、网络、API Key 或真实外部 Hook 验证。

## 可观察验收

- [x] guard 单测证明普通正文中的 literal `<tool_call>` 不会误判，结构化非法 name/args 会在 ToolNode 前稳定失败；合法缺 ID 生成非空 assistant ID。
- [x] 未公开正文/推理时 500 类 provider 错误与 `MALFORMED_TOOL_CALL` 在预算内重试；正文/推理已公开后不自动重放并收敛为 `PROVIDER_OUTPUT_INTERRUPTED`，终态 `retryable=true` 仅表示用户可发起新 Run；预算耗尽和 400 类错误分别收敛为稳定、脱敏且正确 `retryable` 的终态。
- [x] Build 根 Run 与 Inline child 各有离线纵向恢复用例；Inline 的 `MALFORMED_TOOL_CALL` 能穿过 delegation 回到父 executor。
- [x] retry 继续复用既有 attempt、取消、timing 和诊断 seam；已完成 Tool 批次仍即时可读，后续半条 assistant 可回滚。
- [x] 合法缺 ID 的 assistant tool call、ToolNode、ToolMessage 与下一轮请求全链路同 ID；unknown/unauthorized 原 ID 不触发 retry。
- [x] Compose/Managed Plugin/Team 的完整边界矩阵、架构文档和用户故障排查说明（阶段 4）。
