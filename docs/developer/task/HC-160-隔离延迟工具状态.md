# HC-160 隔离延迟工具状态

## 背景与问题

当前 `DeferredToolMiddleware`（位于 `deferred_tools.py`）将已 reveal 的工具保存在中间件实例的 `self._revealed` 集合中。
在生产环境中，`AgentHost` 使用共享的 `AgentEngine`（`shared_engine=True`）服务多个 Thread（会话）。由于图和中间件实例在多个 Thread 之间共享，Thread A 调用 `tool_search` 命中并 reveal 工具后，会直接修改共享中间件的 `_revealed` 集合。这导致：
1. **跨 Thread 状态泄漏**：Thread B 在未调用 `tool_search` 的情况下，其模型绑定工具中意外出现 Thread A reveal 的工具；
2. **Prompt Cache 不稳定**：共享工具列表被不同 Thread 频繁修改，破坏模型前缀缓存；
3. **Prompt 事实冲突**：System Prompt 说明工具默认未加载，但实际 tools 列表中已存在该工具。

## 目标与改动范围

1. 设计并实现 `ThreadDeferredToolStore`，在 Host 与 RunContext 层面按 `thread_id` 严格隔离 deferred 工具的 reveal 状态。
2. 重构 `DeferredToolMiddleware`，使其在模型调用（`wrap_model_call` / `awrap_model_call`）和工具执行（`wrap_tool_call` / `awrap_tool_call`）时均基于当前 `RunContext` 中的 Thread 身份读取与更新 reveal 状态。
3. 清理 `create_harness_tools` 中旧的全局 `reveal` 回调闭包，使工具保持无状态。
4. 补充跨 Thread 隔离性、同一 Thread 跨 Run 连贯性以及前缀稳定的测试用例。
