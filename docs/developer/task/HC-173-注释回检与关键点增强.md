# HC-173 注释回检与关键点增强

需求已与用户确认（2026-09-11）。本文与用户最新指示冲突时，以用户指示为准并回写本文。

## 通俗说明

代码即将迁移到内网继续开发，之后有大量人工审核和模型开发。迁移前的障碍有两个：

1. 现有注释很多是模型生成的：黑话堆叠（「读取不取得 Thread maintenance 锁」「返回持久权威投影」）、夹英文（「transport-neutral」）、复述代码。懂全系统的人能读懂，新人读着费劲。
2. 逻辑难懂、复杂、关键的地方（并发、状态转换、事务边界、审批安全边界）缺「为什么这么写」的说明。

本任务把已有注释按一把尺子回检改写，并在关键处补白话注释，让新同事和后续审核者只读代码就能上手。

## 已确认决策（2026-09-11，按时间顺序）

1. 按仓库完整流程走本文档链；改动不直接提交 master——多个子代理并行，各自在 git worktree 修改并提交到 `comments-*` 临时分支，用户逐个检查后合回。
2. 注释白话、简洁、人的视角；不自造名词；不追求覆盖率，只注释难懂/复杂/关键处。
3. 已有注释需要回检：黑话、复述、夹英文的改写或删除；与代码不符的修正；不确定是否过时的标注不硬改；已经白话简洁的不动。
4. 执行模式按用户指示用并行 worktree 替代 AGENTS.md 的串行停点交付；合并节奏由用户主导。
5. 风格样本（`threads/context_pressure.py` + `cli/src/ipc/client.ts`）已经用户确认（2026-09-11），作为全部执行者的风格基准。

## 范围

1. agent 包 `harness_agent/` 生产源码注释回检与关键点增强（Python docstring 与 `#` 注释）。
2. cli 包 `src/` 生产源码（TypeScript JSDoc 与 `//` 注释）同上；5 个缺头注释文件补文件说明。
3. protocol/src/index.ts 复查；生成文件不加注。
4. 每个执行单元跑 strip 等价校验 + 对应包测试，证明除注释外零代码变化。

## 非范围

- 测试文件、生成文件（generated.ts、validators.generated.ts、generated-syntax-parsers.ts、*.d.ts）、锁文件。
- 任何代码行为修改、重命名、格式调整。
- 追求 docstring/JSDoc 覆盖率 100%（AGENTS.md 第 247 行的公开 API docstring 要求按用户指示放宽为「关键处」，此偏差记录在案）。
- git push、改远端、改版本号。

## 可观察验收

1. 抽样任一被改文件：不读实现只读注释能说清「这段在干嘛、为什么这么写」。
2. 每个执行单元的 strip 等价校验输出全 OK；diff 中无代码行增删改。
3. 合回前后 pytest、bun test、typecheck 全绿；全部合完后 `bun run project:check` 通过。
4. 用户在各 worktree 审查并认可；不认可的 worktree 返工后重审。
