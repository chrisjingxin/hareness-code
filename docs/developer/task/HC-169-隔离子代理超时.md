# HC-169 隔离子代理超时

## 背景与问题

当前 `AgentDelegator` 已正确执行 300 秒硬 deadline：超时会取消实际 runner、把 child execution 收敛为失败并释放并发槽位。但是它随后抛出 `AgentDelegationError("DELEGATION_TIMEOUT")`，生产 `task` 工具没有在父子边界消费这个预期终态，异常会继续退出根 Agent 图，导致整个主 Run 显示“运行失败”。

用户需要的是：子代理超时只终止该子代理；主 Agent 明确收到“子代理已超时”的工具结果，并能继续当前 Run，而不是丢失本轮主对话。

## 用户最终得到什么

```text
子代理达到现有 deadline
  → 实际 child 被取消并回收资源
  → task 卡片显示失败及 DELEGATION_TIMEOUT
  → 主模型收到同一超时结果并继续下一轮
  → 主 Run 仍可正常完成
```

- 正在执行的 child 超时后，已产生的独立子时间线继续可查看。
- 排队中的委派超时后不会伪造一个从未启动的 child，也不会提供假的子时间线入口。
- 用户取消父 Run 时仍取消整个 Run；权限、目标、身份和未知执行错误仍保持失败关闭。

## 范围

1. 在主 Agent 的生产 `task` 工具边界精确消费 `DELEGATION_TIMEOUT`。
2. 将它转换为 `ToolMessage(status="error")`，内容包含稳定 `status=timed_out` 与 `error_code=DELEGATION_TIMEOUT`。
3. 保持现有 300 秒硬超时、排队计时、runner 取消、child 终态和资源释放机制不变。
4. 覆盖 Inline、Managed、排队超时和执行中超时的父对话恢复行为。
5. 更新用户文档与架构说明。

## 非范围

- 不修改 300 秒默认值，不增加用户可配置的子代理超时。
- 不改变 Compose Stage、Agent Team 或其他直接 `AgentDelegator` 调用方的失败语义。
- 不把普通 child 执行失败、权限错误、目标不存在或 Registry 错误改成可恢复结果。
- 不新增 Protocol 字段、RPC、后台子代理、恢复或 partial-result 汇总。
- 不把 child 的私有消息、思考或工具正文写入父 Transcript。
