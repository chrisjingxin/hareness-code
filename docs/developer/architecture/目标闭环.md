# 目标闭环

Build 用户可以把一件事设成跨 Run 持久的目标：先确认“怎样才算完成”，再让主 Agent 工作，由独立 grader 按当前验收条件检查。缺项时同一 Run 内返工；全部满足后由 Host 提交完成。目标跨 Run 和 Host 重启存在，但没有后台调度——没有用户动作时不会自动连开新 Run。

行为规格以 [HC-167](../spec/HC-167-目标闭环.md) 为准。本文只描述当前 canonical 路径，不保留旧斜杠命令或双形状。

## 职责边界

```text
CLI Interactive Core     Protocol v3.8          AgentHost / GoalStore
/goal、review、Timeline ── goal.* / run.start ── SQLite 真源 + Criteria/grader
TUI/Web 只渲染 snapshot     tagged RunInput        RubricMiddleware adapter
```

- CLI 不知道 SQLite 表、SDK 私有 rubric 事件或 Completion Guard CAS。
- DeepAgents adapter 不知道 TUI/Web。
- 持久层不解析 Slash Command。
- 一个 `project + thread` 最多一个 current accepted goal 和一个 pending proposal。

## 用户路径

```text
/goal <目标>
  → Criteria Agent 生成草案（大歧义先提问，小歧义写假设）
  → 人工审核：接受 / 编辑 / 驳回 / 取消
  → 接受后 SQLite 提交并自动启动 Build continuation
  → 普通 Build 消息继续同一 active goal
  → grader 只读验收
      needs_revision → 同一 Run 继续修改
      satisfied      → Completion Guard → complete
      failed/error/达到上限 → 本 Run 停止，goal 保持 active
```

`/goal` 只在 Build 暴露。Compose 隐藏；`/btw`、direct shell、proposal Run 不带 rubric。`/plan` 能看见目标但不 grading，批准进入实现后恢复验收。

remainder：空参 inspect；`edit` 修订；`pause` / `resume` / `clear`；其它非空文本无 goal 时 create、有 goal 时 replace。没有 `/goal model` 或 `/goal max-iterations`。

## 运行时判定

只有普通 active Build（含 `goal_continuation`）是 goal-backed：挂 `GoalRunBinding` 和 `RubricMiddleware`。Plan 约束、Compose、direct shell、proposal、paused/blocked/complete 都是 `goal_backed=false`。Build 仍可把 current goal 投影进 `goal.state` ContextBlock（用户数据，不是权限）。

blocked 后 `/goal resume` 或普通 Build 消息在受理前把状态改回 active，并把原因移到只投影一轮的 `prior_blocker`；写失败则用户消息不能开始。Run 终态清除 `prior_blocker`。

## 配置与权限

grader 与迭代上限在 `~/.harness/config.toml` 的 `[goal]`（`grader_model`、`max_iterations` 默认 3、范围 1～20），可由 `HARNESS_GOAL_GRADER_MODEL` / `HARNESS_GOAL_MAX_ITERATIONS` 覆盖。Run 受理时解析并冻结。inherit 等于该次实际主模型；独立 Profile 不可用时 `GOAL_GRADER_MODEL_UNAVAILABLE`，不回退。

Goal 不保存、不改变 approval mode。continuation 使用当前会话 Build 档位。Criteria 在所有模式下都必须人工确认。grader 工具是主 Agent 的只读子集，外加受控 `rerun_verification`；不生成 allow rule。

## 完成与历史

唯一 Completion Guard 在 SQLite 事务中校验：Run 正常完成、goal-backed、current 仍是绑定的 active revision/digest、无会使完成失效的 pending、当前 grading run 的完整 satisfied。任一条件失败只记 audit，不标 complete。

`threads.undo` 与 Goal 失效同一事务：撤销点之后的 evaluation 标 stale；complete 保守恢复 active。redo 只恢复会话/文件，不恢复 satisfied。
