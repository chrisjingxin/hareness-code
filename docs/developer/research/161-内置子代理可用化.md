# 161 竞品调研：内置子代理可用化

## 调研范围

本文服务 HC-161，仅检视以下两个本地竞品仓库的第一方源码、仓库内官方文档与测试，未使用网络二手资料。

- Qwen Code：`/Users/zhangjingxin/Code/OpenSource/qwen-code`，基准 commit `0d56e50b649e1d56f48218af402f1678688766d7`
- Oh My Pi：`/Users/zhangjingxin/Code/OpenSource/oh-my-pi`，基准 commit `45e12e5bb758198a920c6070e7e64cb33b21beac`

已确认的 HC-161 目标是：`general-purpose` 完整继承父 Run 的 ModelProfile 和审批边界；`explore` 仅允许 `ls/read_file/glob/grep/lsp`；两者共用冻结 RunContextSnapshot，但不继承父对话历史；同步 `task`、`depth=1`、`parallel=4`、可取消，并只回传最终结果。

## 核心结论

内置子代理真正可用不是“存在一份定义”，而是一条完整生产链：

```text
内置定义 → canonical 目录合并 → task/agent tool 对模型可见
        → 执行时再解析 → 独立子运行时 → 事件/审批/最终结果
```

Qwen Code 和 Oh My Pi 都不把 agent 名称做成静态 schema enum，而是在 tool description 中动态展示，并在执行前再校验。因此 HC-161 必须同时验证“目录可见”和“生产 graph 能执行”，不能只测 Registry 列表。

| 问题 | Qwen Code | Oh My Pi | HC-161 结论 |
|---|---|---|---|
| 内置角色 | `general-purpose`、`Explore` | 通用 `task`、探索 `scout` | 用单一 canonical catalog 同时驱动 `/agents`、tool 说明和执行解析 |
| 真实工具边界 | 显式 allowlist 会 fail closed，但 `Explore` 仍有 shell/web/skill | `scout` 的 read-only 主要是声明列表+提示词，运行时可带入扩展/MCP | `explore` 必须在执行器构建严格能力集，不得依赖 prompt 或“只读标签” |
| 审批 | 有 child Config/ToolRegistry 和审批事件 bridge，但默认会按模式放宽 | 父对 task 的一次审批是边界，child 默认 yolo | 借鉴 Qwen 的子配置+事件 bridge，不照搬两者的放宽策略 |
| 上下文 | 命名 agent 新会话；注入 QWEN.md/技能等环境事实 | 新 Session；传 cwd、skills、workspace tree/rules，但显式过滤 `AGENTS.md` | 新对话是正确方向；但 HC-161 必须传入同一冻结 AGENTS/skills/workspace snapshot |
| 模型 | 内置 agent 默认 inherit，`Explore` 可单独配置 | `task=@task`、`scout=@smol`，可回退父模型 | HC-161 不做子模型选择，两者都使用父 Run 冻结 ModelProfile |
| 生命周期 | 前台/后台、fork、resume、worktree，默认 depth 5、后台并发 10 | sync/batch/background/IRC/worktree，默认 depth 2、并发 32 | 只借鉴统一深度门、semaphore、AbortSignal 与 finally 清理；不引入异步管理面 |

## Qwen Code

`SubagentManager.listSubagents()` 在普通模式按 project → user → builtin → extension 合并去重，safe mode 只保留 builtin；项目或用户同名定义会覆盖 builtin。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/subagents/subagent-manager.ts:497-578`。

`AgentTool` 启动时立即放入 builtin 作为可用集，随后异步刷新合并目录，目录改变会触发 tool 重建；动态 description 向模型展示可用名称。`subagent_type` 仍是 string，调用前用缓存目录校验，miss 时再刷新一次。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/tools/agent/agent.ts:777-923`、`:925-973`、`:1033-1071`、`:1074-1122`。

这个 tool 确实进入了正式 ToolRegistry：Config 在为 subagent 构建 registry 时先排除 structured-output 和部分 control-plane/goal worker 工具，然后注册 `AgentTool`。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/config/config.ts:7863-7897`、`:7908-7939`、`:7979-7982`。

这条链有两个可借鉴点：

1. builtin 在异步 discovery 完成前也能立即进入生产 tool，不会出现“文件存在但首轮不可用”。
2. 同一目录同时驱动模型可见说明和执行校验，比平行维护 Registry、plan 工具、`.harness/agents` 更不容易出现虚假路径。

### 工具与审批边界

Qwen 的显式 allowlist 是执行边界，而不只是提示词：解析不到的工具名保留为“死的限制项”，不会回退到 `*`；子运行时的 `prepareTools()` 只从 allowlist 取 schema，然后再套用 control-plane 硬排除和 `disallowedTools`。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/subagents/subagent-manager.ts:1160-1216`、`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-core.ts:597-719`。

但 Qwen 的 `Explore` 不符合 HC-161 的严格只读定义：除 `read_file/grep/glob/ls/lsp` 外，它还拥有 `shell/web_fetch/skill`，并依靠 system prompt 要求 shell 只执行只读命令。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/subagents/builtin-agents.ts:48-103`。HC-161 只应借鉴 allowlist 的 fail-closed 实现，不应照搬其 `Explore` 工具表。

Qwen 最值得借鉴的权限细节是“重建子 ToolRegistry”：审批模式用原型委托产生 child Config，但重建 core tool instances，使 edit/write/read 绑定子 Config 和子 FileReadCache，避免沿用父工具实例而绕过子审批或 prior-read 约束。每个命名 agent 也会创建独立 FileReadCache/ToolRegistry，并在 dispose 中回收连接与 hook。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/tools/agent/agent.ts:517-573`、`:662-760`；`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/subagents/subagent-manager.ts:823-975`、`:977-1090`。

Qwen 不能直接提供 HC-161 的“完整继承父审批”语义：父处于 yolo/auto-edit/auto 时会直接覆盖子设置；默认信任目录会给子代理 auto-edit。`bubble` 仅在子运行时保持 Default，由后台路径把审批请求传到父 UI。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/tools/agent/agent.ts:431-495`。HC-161 可借鉴审批事件 bridge：子 `TOOL_WAITING_APPROVAL` 事件携带真实 tool confirmation details，父 UI 响应后调用 `event.respond()` 回填子 scheduler。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/tools/agent/agent.ts:1480-1674`。另一条 ACP 路径会在取消子审批时 abort 整个 Agent 调用，这不适合 HC-161 “拒绝作为 tool result 返回 child，让其调整”的语义。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/cli/src/acp-integration/session/SubAgentTracker.ts:204-295`、`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/cli/src/acp-integration/session/Session.ts:8407-8411`。

### 上下文、模型与生命周期

普通命名 agent 不继承父对话；仅显式 `fork` 才携带全部或最近父历史。这个边界也写入生产 tool description。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/tools/agent/agent.ts:951-973`。命名 agent 用新 AgentHeadless chat；没有 `initialMessages` 时创建新的 environment history，系统提示词追加 Config 中的 QWEN.md/输出语言等 context files 和 auto-memory，技能工具可用时还注入 available-skills reminder。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-core.ts:514-545`、`:578-595`、`:2281-2312`。

这证明“新对话不等于空环境”。HC-161 应让子代理拿到父 Run 创建时的同一冻结 workspace/AGENTS/skills/approval snapshot，但不应把父 message history 一并带入。

Qwen 对 `inherit` 不创建新 provider view，因此可沿用父模型；`Explore` 只在配置 `agents.builtin.exploreModel` 时覆盖。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/subagents/subagent-manager.ts:128-145`、`:1093-1150`。HC-161 应更窄：不允许子代理再解析配置或切换 provider，直接使用父 Run 已冻结的 ModelProfile。

Qwen 的 AgentHeadless 接受外部 AbortSignal，内部使用 child AbortController，并在 finally 中解除父信号联系；终态会产生 finish/error 事件、最终文本与执行统计。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-headless.ts:193-230`、`:243-300`、`:360-436`。它用同一 `spawnBlockReason()` 同时做 schema 隐藏和执行时防线，值得 HC-161 用于固定 `depth=1`。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-context.ts:145-180`、`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-core.ts:608-634`。

Qwen 的 `max_time` 主要在 reasoning loop 的轮次边界检查，不是能强制中断卡死 model/tool 的 wall-clock deadline。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/runtime/agent-core.ts:881-899`、`:947-952`、`:1111-1133`。HC-161 应由父 task 调度器持有 deadline 和 child AbortController，不应照搬该 loop-boundary timeout。

Qwen 默认最大子代理深度是 5，后台并发默认是 10，且同时支持后台、fork、resume、team 与 worktree；这些都超出 HC-161。证据：`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/config/config.ts:1450-1472`，`/Users/zhangjingxin/Code/OpenSource/qwen-code/packages/core/src/agents/background-tasks.ts:50-92`。

## HC-161 落地取舍

### 应借鉴

1. **一个 canonical catalog**：builtin 与 plugin 一起产生 `/agents` 列表、`task` tool 的模型可见说明和执行解析；执行前再以当前 Run snapshot 校验一次。
2. **双层防线**：不向 child schema 暴露不允许工具，执行器仍对 `depth=1`、工具 allowlist/dynamic deny 做强制校验，两层使用同一份策略计算。
3. **子运行时真隔离**：从父 RunContextSnapshot 派生子 runtime，但为其重建绑定子配置的 tool instances/审批上下文，不复用可能绑定父状态的缓存工具。
4. **新对话+同一环境快照**：子 agent 只收到 task prompt，不重放父 history；但系统上下文必须含同一 workspace facts、AGENTS、skills、approval 和 ModelProfile。
5. **审批事件 bridge**：`general-purpose` 的 task 启动先按父策略审批，子风险工具再按父同一 policy/dynamic deny 审批；UI 需同时标注 child 名称和真实 tool/diff，拒绝结果回到 child reasoning loop。`explore` 的 task 启动可自动通过，因为其实际 schema 只有五个只读工具。
6. **可证明的生命周期**：统一 `depth=1`门、Run 级 semaphore=4、父 cancellation token、可配置 timeout 和 finally 释放；同步 tool 仅将终态与最终文本返回父模型。

### 不应引入

- 不照搬 Qwen `Explore` 的 shell/web/skill，也不照搬 OMP 的 prompt-only/read-only-classifier 边界。
- 不照搬 Qwen 的默认 auto-edit/宽松父模式覆盖，也不照搬 OMP “批准 task 即授权 child yolo”。
- 不为 `general-purpose` 和 `explore` 增加单独 model alias；不从子运行时重新读取模型配置。
- 不过滤 AGENTS 指令，不继承父 conversation history。
- 不引入 background/batch/fork/resume/team/IRC/worktree/子代理自定义管理面；它们会改变当前已确认的同步 `task` 语义。
- 不保留旧 Registry、plan agent 或 `.harness/agents` 的 alias/fallback；未发版阶段应直接迁移调用方、测试和文档至单一路径。

### 对验收的直接启示

HC-161 的测试应把“真可用”拆为以下可观察事实：

1. 用生产 graph 启动 `general-purpose` 和 `explore`，不经过测试专用 Registry；`/agents` 同时看到 builtin 与 plugin。
2. 断言 `explore` 最终 model-visible schema 和 execution registry **都**只有 `ls/read_file/glob/grep/lsp`，并以反向用例证明 write/shell/network/MCP/custom/task 无法调用。
3. 覆盖父的 4 种审批模式、dynamic deny、用户拒绝回传，并校验 UI 审批请求中的 child/tool/diff 身份。
4. 证明两个 child 都使用父 Run 冻结 ModelProfile 和 RunContextSnapshot，且不带父 message history。
5. 覆盖 depth=1 拒绝嵌套、parallel=4 队列、排队取消/执行中取消、timeout 和 permit 无泄漏。
6. 保留一条使用真实 Harness 用户配置和 mock model 的 smoke，专门防止“单测可见，生产 tool schema 未注册”的回归。
