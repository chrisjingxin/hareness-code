# 156 竞品调研：TUI 选中复制

## 结论

MiMo Code 的主路径是“鼠标拖选文本后松开鼠标即复制”：OpenTUI renderer 必须已启用鼠标；根视图的 `onMouseUp` 调用统一的 `Selection.copy`。该 helper 仅在选区存在非空文本时写入剪贴板、立刻清除选区，并在异步复制成功后显示 `info` Toast；失败则交给 Toast 的 `error` 分支。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:75`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:1106`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/selection.ts:13`。

MiMo 将用户所说的 notice 命名为 Toast。复制成功文案为中文“已复制到剪贴板”，类型为 `info`；Toast 显示在右上角、默认 5 秒，且其 store 只保存一条 `currentToast`（新提示覆盖旧提示）。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/i18n/zh.ts:251`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/event.ts:33`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/toast.tsx:13`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/toast.tsx:52`。

## MiMo Code 事件流

```text
鼠标拖选可选择文本
  → OpenTUI renderer 保存 selection
  → 根 <box> 收到 onMouseUp
  → Selection.copy(renderer, toast, i18n 文案)
  → getSelectedText() 为空：直接返回，不提示
  → Clipboard.copy(text) 异步执行 + clearSelection()
  → 成功：Toast(info, “已复制到剪贴板”)
  → 失败：Toast(error, 错误文案)
```

- **触发前提**：`rendererConfig` 在非 plain terminal、未设 `MIMOCODE_DISABLE_MOUSE` 且配置 `mouse` 未显式关闭时开启 `enableMouseMovement` 与 `useMouse`。未满足时，鼠标选区链路不会可用。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:75`。

- **默认触发动作**：`MIMOCODE_EXPERIMENTAL_DISABLE_COPY_ON_SELECT` 为 false 时，应用根节点的 `onMouseUp` 调用 `Selection.copy`。该 flag 在未设置环境变量时只在 Windows 默认 true，因此 macOS/Linux 默认是“选中后松开即复制”。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/flag/flag.ts:35`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/flag/flag.ts:109`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:1106`。

- **选区与复制的边界**：`Selection.copy` 从 `renderer.getSelection()?.getSelectedText()` 获取文本；空选区返回 `false`，不调用剪贴板也不显示通知。非空时先发起异步复制、立刻 `clearSelection()`，成功后才显示 Toast。故视觉选区会先消失，成功 notice 反映复制 Promise 已完成。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/selection.ts:8`。

- **Windows/显式关闭自动复制时的回退**：同一 flag 为 true 时，`Ctrl+C` 复制当前选区并拦截按键，`Esc` 清除选区；右键优先复制现有选区，没有选区才把右键作为粘贴。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:281`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:1088`。

- **覆盖层避免重复触发**：Dialog 的内容容器单独处理 `onMouseUp`，默认模式下自行复制并 `stopPropagation()`，避免事件再传到根节点而重复复制/重复提示；Dialog Provider 也为默认模式绑定相同的选区复制回调。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/dialog.tsx:53`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/dialog.tsx:174`。

- **独立的 Console 选区通道**：renderer 的 console 配置将 `Ctrl+Y` 映射为 `copy-selection`，并设有 `onCopySelection`；应用层再次注册 callback 后，会对非空文本复制、显示同一 info Toast 并清除选区。这是控制台而非主 timeline 的附加入口。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:98`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:316`。

## 剪贴板与 notice 实现

- **剪贴板策略**：`Clipboard.copy` 先在 TTY stdout 写 OSC 52（包含 tmux/screen passthrough），再调用按平台选择的原生写入方法：macOS `osascript`、Linux Wayland `wl-copy` / X11 `xclip` / `xsel`、Windows PowerShell `Set-Clipboard`，最后回退 `clipboardy`。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/clipboard.ts:20`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/clipboard.ts:113`。

- **通知模型**：Toast event 的可用类型是 `info | success | warning | error`，可选 `title` 和 `duration`；复制成功始终传 `info`。渲染位置为绝对定位的 `top={2}`、`right={2}`、`zIndex={4000}`，按 variant 选择边框色。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/event.ts:33`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/selection.ts:17`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/toast.tsx:19`。

- **显示时机**：`Toast.show` 默认 duration 为 5000 ms；每次 show 会覆盖 `currentToast`、清理旧 timer，并在 timeout 后置空。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/toast.tsx:52`。

## 对 Harness Code 的可移植结论

1. **可直接复用的分层模式**：把“读取渲染器选区 → 调用 clipboard port → 清除选区 → 成功/失败 Toast”收敛为一个 presentation helper；根 TUI 与 Dialog/Picker 等浮层只调用它。该方式让复制无需进入 Python sidecar 或跨进程协议。MiMo 的收敛点见：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/selection.ts:13`。Harness 当前已有本地 clipboard helper 与 toast 队列，可作为接入点：`/Users/zhangjingxin/Code/MyRepo/harness-code/packages/cli/src/tui/platform/clipboard.ts:5`、`/Users/zhangjingxin/Code/MyRepo/harness-code/packages/cli/src/tui/application/adapter.ts:830`、`/Users/zhangjingxin/Code/MyRepo/harness-code/packages/cli/src/tui/presentation/toast.tsx:111`。

2. **推荐的首期交互**：保留 MiMo 的默认语义——仅当 `getSelectedText()` 非空时，在鼠标抬起后复制，成功提示“已复制到剪贴板”，失败提示“复制到系统剪贴板失败”；对浮层的 mouse-up 做 `stopPropagation` 或由共同根统一处理，二者只能选其一。触发逻辑依据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/app.tsx:1106`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/ui/dialog.tsx:53`。

3. **不可直接照搬：OpenTUI API 与版本**：MiMo 使用 `@opentui/core` / `@opentui/solid` 0.1.101，并直接依赖 `renderer.getSelection()`、`clearSelection()` 和 console 的 `onCopySelection`。Harness 使用 `@opentui/core` / `@opentui/react` 0.4.3，因此必须先用实际类型/API 验证等价的 selection 入口，不能直接复制 MiMo 的 Solid JSX 回调或 renderer 类型假设。MiMo 依赖证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/package.json:112`；Harness 依赖证据：`/Users/zhangjingxin/Code/MyRepo/harness-code/packages/cli/package.json:18`。

4. **不可直接照搬：成功语义**：MiMo 的 native clipboard 分支大量使用 `nothrow` 或吞掉进程错误，`Clipboard.copy` 仍可能 resolve，导致 success Toast 不能严格证明实际写入成功。Harness 现有 `copyToClipboard` 返回 boolean，更适合将通知严格绑定到真实结果。MiMo 证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/clipboard.ts:117`、`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/clipboard.ts:125`；Harness 证据：`/Users/zhangjingxin/Code/MyRepo/harness-code/packages/cli/src/tui/platform/clipboard.ts:5`。

5. **按需评估：OSC 52**：MiMo 的 OSC 52 解决 SSH/远端终端写本地剪贴板的问题，适合独立评估为后续增强；它会向 stdout 写控制序列，需结合 Harness 的 renderer 输出模式、终端兼容性与长度限制测试后再引入，不能在首期复制功能中无验证迁入。证据：`/Users/zhangjingxin/Code/OpenSource/MiMo-Code/packages/opencode/src/cli/cmd/tui/util/clipboard.ts:20`。
