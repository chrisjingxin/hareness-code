# 147-BTW 临时问答调研

日期：2026-08-14  
责任人：chrisjingxin  
关联功能：`/btw` 临时只读旁路问答（Side Question）

---

## 1. 要解决的问题

用户在终端交互会话（Build 模式或 Compose 模式）中，有时需要向 Agent 提出一个临时问题（例如：“这个报错是什么意思？”、“解释一下上面提到的概念”），但：
1. **不希望干扰主任务上下文**：问题与回答不应进入主会话的 Transcript、LangGraph 模型投影、SQLite 持久化或 Compose Work Item ledger，避免污染后续长会话上下文。
2. **不触发代码改动与副作用工具**：临时问答应当是严格只读的单轮回答（0 工具、1 轮直接回复）。
3. **交互轻量即焚**：在 TUI/Web 界面以临时浮层/面板或轻量块呈现，支持流式输出、滚动阅读、一键复制，按 `Esc` 或 `Enter` 即可随时关闭。

当前 Harness Code 在 Command Registry 中已预留 `assist.btw` 命令定义，但在 `command-dispatcher.ts` 及跨进程协议层尚未实现具体执行逻辑。

## 2. 证据范围与竞品方案分析

### 2.1 Oh My Pi (`/Users/zhangjingxin/Code/OpenSource/oh-my-pi`)

#### 核心实现
- **控制器**：`packages/coding-agent/src/modes/controllers/btw-controller.ts` (`BtwController`)
- **UI 呈现**：`packages/coding-agent/src/modes/components/btw-panel.ts` (`BtwPanelComponent`) 挂载于 `btwContainer`。
- **执行内核**：`session.runEphemeralTurn({ promptText, onTextDelta, signal })`。
- **提示词包装**：
  ```markdown
  <btw>
  This is an ephemeral side question for the current interactive session.
  Answer briefly and directly using the conversation context already provided.
  NEVER use tools.
  NEVER ask follow-up questions.
  Question:
  {{question}}
  </btw>
  ```
- **上下文与缓存设计**：
  - 调用 `buildEphemeralSnapshot` 抓取包含当前正在流式生成的半成品消息在内的完整会话快照。
  - 给 Provider 路由分配独立 lineage（如 `${sessionId}:side:${id}`），避免与主 Turn 状态冲突。
  - 强制禁用所有工具（`context.tools = []`）。
- **交互与快捷键**：
  - 空参数提示：`Usage: /btw <question>`。
  - 随时终止/关闭：`Esc` 键中止流并销毁面板。
  - 复制：`c` 键复制回答至剪贴板。
  - 分支提升：`b` 键可将 `/btw` 的问答提升（Branch）为会话主分支上的常规对话轮次（前提是当前主 Turn 未被修改且空闲）。

### 2.2 Claude Code (`/Users/zhangjingxin/Code/OpenSource/claude-code`)

#### 核心实现
- **命令入口**：`src/commands/btw/btw.tsx`
- **执行内核**：`src/utils/sideQuestion.ts` (`runSideQuestion`) 调用 `runForkedAgent`。
- **提示词包装**：使用 `<system-reminder>` 明确指出：轻量单轮 Agent、主 Agent 仍在工作未被中断、无任何可用工具、禁止后续轮次、不知道则直接说明。
- **缓存与优化**：
  - 复用 `getLastCacheSafeParams()`，确保 System Prompt、用户上下文的前缀字节完全一致，以最大化命中 Prompt Cache。
  - 单轮上限（`maxTurns: 1`）、`canUseTool: deny`。
  - `skipCacheWrite: true`：由于后续主请求不会共享 side question 的后缀，因此跳过写入缓存。
- **UI 交互**：
  - TUI Ink 组件 `BtwSideQuestion`：独立弹窗覆盖在主界面上方，支持 Spinner、流式/渲染 Markdown、上下滚动。
  - 快捷键：`Space`/`Enter`/`Esc`/`Ctrl+C`/`Ctrl+D` 均可快速关闭；`Up`/`Down` 滚动。

## 4. Harness Code 现有架构与落地分析

1. **协议层 (`packages/protocol`)**：
   - 现有的 `RunCoordinator` 和 `AgentHost` 负责受控执行。为了保持职责单一，可定义专用的 JSON-RPC 方法（如 `threads.side_question`）或由 `AgentHost` 提供轻量只读问答接口。
   - 请求载荷包含 `thread_id`、`question`、`model_profile_id`（可选）。
   - 响应通过流式 RPC 通知（`stream/text` 或专用 side event）或单次 JSON-RPC 结果返回。

2. **Python Agent 层 (`packages/agent`)**：
   - `SideAnswerPort` 已经在 `harness_agent.compose.work_item_engine` 中定义了类型契约：
     ```python
     class SideAnswerPort(Protocol):
         async def answer(self, *, thread_id: str, question: str) -> str:
             ...
     ```
   - 生产实现可直接复用 `ThreadPersistence` 读取当前 Thread 的历史消息，组装 `<system-reminder>` / `<btw>` prompt，通过当前激活的模型直连生成单轮回复，全程不调用任何 Tool，不写 Thread Store。

3. **CLI / TUI 交互层 (`packages/cli`)**：
   - `commandRegistry` 中已有 `assist.btw`。
   - `command-dispatcher.ts` 新增 `assist.btw` 处理：
     - 若未提供 `question`，返回 notice 提示用法；
     - 若提供了 `question`，派发 `btw.ask` 或执行 side question 请求。
   - TUI 视图层（`tui/presentation`）增加 `BtwModal` 或浮层组件，接收流式 token，渲染 Markdown，支持 `Esc`/`Enter` 关闭与 `c` 复制。
