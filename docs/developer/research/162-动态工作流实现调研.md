# 162 - 动态工作流实现调研

调研对象：deepagents 官方 CLI **dcode**（`libs/code`）与 **Qwen Code** 的动态工作流（Dynamic Workflow）能力。服务后续 HC Task「dynamic workflow」的 Spec 与架构设计，不替代 Task。

- dcode 源码：`/Users/zhangjingxin/Code/OpenSource/deepagents/`（下文 `MQ/` = `libs/partners/quickjs/langchain_quickjs/`，`dcode/` = `libs/code/deepagents_code/`）
- Qwen Code 源码：`/Users/zhangjingxin/Code/OpenSource/qwen-code/`（下文 `core/` = `packages/core/src/`）

## 0. 一页结论

**两边实现的是同一个功能**：让模型在运行时**现场编写一段 JavaScript 编排脚本**，脚本里用 `agent(prompt, opts)` 派发子 Agent、`parallel()/pipeline()` 做并发 fan-out、`Promise.all` 编排依赖关系，由一个**沙箱化的 JS 运行时**执行，脚本结果回填给模型。这就是"动态"的含义——工作流不是预定义的 DAG，而是模型按任务现场写出来的编排代码。

| | dcode | Qwen Code |
|---|---|---|
| 载体 | `langchain-quickjs` 中间件（deepagents 官方 partner 包），提供 `js_eval` 工具 | `WorkflowTool` + `agents/runtime/workflow-*` 体系（默认关闭，opt-in） |
| JS 执行宿主 | **QuickJS（wasm32）**，quickjs-rs PyPI 包，wasmtime 驱动 | **Node 内置 `node:vm`**（零外部沙箱依赖） |
| 子 Agent 桥接 | JS 内 `await task({...})` → 直接调 deepagents 的 task 工具（`BaseTool.arun`） | JS 内 `agent(prompt, opts)` → `WorkflowAgentDispatch` → AgentHeadless |
| 能力面 | 代码解释器 + PTC（`await tools.xxx()` 直调宿主工具）+ 子 Agent fan-out，一体三用 | 纯编排（子 Agent 只能派发，不能直调父工具） |
| 持久化/恢复 | REPL 全堆快照（bsdiff4 增量链 + HMAC 签名）存入 LangGraph state | journal.jsonl 前缀哈希缓存 + run snapshot 落盘（可断点续跑） |
| 治理 | 超时 5s/次、内存 64MiB、PTC 调用预算 256 次 | 并发窗 `min(16, cpus-2)`、1000 agent/run、token 预算、停滞看门狗、暂停/审批 |
| 与我们的距离 | **零距离**：Python + deepagents + LangChain/LangGraph，与我们同栈 | 距离远：TypeScript + node:vm，只能借鉴设计不能借代码 |

**对 harness-code 的推荐路线**：直接采用 `langchain-quickjs`（dcode 同款），它是 deepagents 0.7 生态的官方 partner 包，`CodeInterpreterMiddleware` 一行接入。真正要解决的是**版本升级**（见 §7）与 **CLI 侧呈现**（`js_eval` 展示 + 子 Agent fan-out 事件过协议）。

## 1. dcode：langchain-quickjs 中间件

### 1.1 定位与接线

`langchain-quickjs` 是 deepagents 官方 partner 包（`libs/partners/quickjs/`），定位是"给 Agent 一个持久化、沙箱化的 JavaScript REPL 工具"。动机（README「Why」）：N 次串行工具调用在"循环逐项调用、两路并发、调用间计算、跨 turn 复用中间态"场景下每次都要一次模型 round-trip；一个 REPL 把这些全部收进一次 `eval`。

dcode 接线（`dcode/agent.py:2895-2931`）：

```python
if enable_interpreter:
    from langchain_quickjs import CodeInterpreterMiddleware, PTCOption
    agent_middleware.append(CodeInterpreterMiddleware(
        tool_name="js_eval",
        timeout=settings.interpreter_timeout_seconds,
        memory_limit=settings.interpreter_memory_limit_mb * 1024 * 1024,
        max_ptc_calls=settings.interpreter_max_ptc_calls,
        max_result_chars=settings.interpreter_max_result_chars,
        ptc=ptc_option))
```

- 开关 `interpreter.enable_interpreter` **默认开启**（`dcode/config_manifest.py:70`），CLI `--no-interpreter` 可关（`dcode/main.py:2747`）；远程沙箱模式下禁用（本地特性）。
- PTC 预设默认 `"safe"` = 只读白名单 `{read_file, glob, grep}`（`dcode/config.py:2349`）；`"all"` 需显式确认（`dcode/agent.py:966-993`）。

构造参数全集（`MQ/middleware.py:241-255`）：`memory_limit=64MiB, timeout=5.0s, max_ptc_calls=256, tool_name="eval", max_result_chars=4000, capture_console=True, subagents=True, ptc=None, mode="thread", max_snapshot_bytes=memory_limit, snapshot_signing_key=None`。

### 1.2 REPL 语义与线程模型

- **每 `thread_id` 一个专属 OS 线程 + QuickJS Runtime + Context**（`MQ/_repl.py:1014-1027`）。quickjs-rs 对象不可跨线程（`!Send`），所有操作 marshal 到该 worker 线程（`_repl.py:380-386`）。重叠 eval 直接抛 `ConcurrentEvalError`（响亮失败，不排队）。
- **持久化三层 mode**：
  - `thread`（默认）：跨 turn 持久——turn 结束写全堆快照进 LangGraph state，下个 turn 恢复；
  - `turn`：同 turn 内多次 eval 共享 Context，turn 结束丢弃；
  - `call`：每次 eval 重建 Context。
- **顶层 let/const 存活的关键**：quickjs-rs 的 `SourceTransform.TOP_LEVEL_CONST_TO_VAR` 源码变换，把顶层词法声明改写为 `var` 挂到 global object（`_repl.py:1047-1051`）。这是纯 JS 层做不到的。
- **顶层 await**：`ctx.eval_handle_async(code)` 后若 `handle.is_promise()` 则 `await handle.await_promise(timeout)`；顶层 Promise 未决且无 host 工作在飞 → `DeadlockError`（`_repl.py:836-883`）。

### 1.3 沙箱边界

能力边界由两层保证：

1. **wasm32-wasip1 引擎**：QuickJS 编译为 wasm 跑在 wasmtime 里，**没有**文件、网络、真实时钟等系统调用面；
2. **只注册三个 host 面**：`console.log/warn/error`（捕获回传）、`task`（子 Agent 桥）、PTC 工具桥。Python 侧从未注册任何 I/O host 函数（`MQ/_repl.py:453-481, 616-654, 691-739`）。

限额与错误 wire format（模型可直接读，`MQ/_format.py:176-226`）：

```xml
<stdout>console 输出（独立截断）</stdout>
<result kind="handle">[Function] arity=2</result>   <!-- 不可 marshal 只给描述 -->
<error type="Timeout|OutOfMemory|Deadlock|PTCCallBudgetExceeded|TypeError">msg\nstack</error>
```

取消语义：`HostCancellationError` 重抛为 `asyncio.CancelledError`，LangGraph 取消可贯穿（`_repl.py:884-888`）。

### 1.4 PTC（programmatic tool calling）

Agent 自己的工具被桥接为 QuickJS **async host function**：JS 里 `await tools.readFile({...})` 直接拿到**已定型的原生值**（不是字符串化的 ToolMessage，`coerce_tool_output_for_ptc` 解包 Command/ToolMessage 信封并递归转换，`MQ/_format.py:93-135`）。实现要点：

- 调用在**父 LangGraph loop** 上执行 `tool.arun`（`run_coroutine_threadsafe`，`_repl.py:656-689`），并复刻 `ToolNode._inject_tool_args` 注入 ToolRuntime/InjectedState；
- 预算：每 eval 一个计数器，默认 256 次，超限 `<error type="PTCCallBudgetExceeded">`；
- `task` 不允许进 PTC（防混淆），`eval` 自身排除防递归（`MQ/_ptc.py:37-116`）。

### 1.5 子 Agent 派发（`await task({...})`）

- `task` 是顶层全局 async host 函数，**直接调用 deepagents 的 task 工具**（`task_tool.arun`），不经过 GraphInterrupt 挂起 REPL——若子 Agent 内部产生 GraphInterrupt（如审批请求），中断对象**原样穿透**让整个图中断，恢复时该 `js_eval` 调用整体重跑（`MQ/_subagent.py:191-272`、`_repl.py:637-638`）。
- **并发 fan-out**：JS 侧 `Promise.all([task(...), task(...)])` 天然并行；每个桥调用经 `run_coroutine_threadsafe` 到父 loop，硬上限每 REPL `Semaphore(32)`（`_repl.py:57, 443, 631`）；提示词建议每批约 10 个。
- **结构化输出**：`task({responseSchema})` 经 `config.configurable[SUBAGENT_RESPONSE_FORMAT_CONFIG_KEY] = AutoStrategy(schema)` 注入子 Agent，返回字符串 `json.loads` 后直接成为 JS 对象可参与后续计算（`_subagent.py:275-356`）。
- **流事件**：`SubagentStartEvent/CompleteEvent/ErrorEvent`（`type:"subagent"`、`phase:"start|complete|error"`、`id`、`eval_id`（外层 js_eval 的 tool_call_id，用于 fan-out 分组）、`label`、`duration_ms`）经 LangGraph **custom stream** 发出（`_subagent.py:55-154`）——CLI 靠这个画出实时 fan-out 面板。

### 1.6 快照与系统提示

- **全堆快照**：`ctx.create_snapshot()` 序列化整个 JS 堆（变量/函数/闭包/类），bsdiff4 增量链存入 state（经验上 1.4MB 堆 → 200B~1KB 补丁），可选 HMAC-SHA256 防篡改（`MQ/_snapshot.py`）。host 函数与进行中 Promise 不在快照内，恢复时重装。这意味着 **REPL 状态可跨进程恢复**（配合 checkpointer）。
- **系统提示注入**：每次模型调用按需追加三段（`MQ/_prompt.py`）：~15 行基础语义（沙箱/超时/内存/mode）、PTC 开启时的 TS 签名 API Reference（`tools.camel(input): Promise<T>`）、检测到 task 工具时的 ~227 行 `task()` 编排指南（含"用户说 workflow 时的行为指引"、批量 fan-out 示例、"先探索再派发"）。

### 1.7 dcode UI 侧（对我们 CLI 的参考）

- `js_eval` 输出被**结构性解析**后渲染：`<result>/<error>` 块锚定到输出末尾再解析，防止用户代码打印伪造标签（`dcode/tui/widgets/_js_eval_display.py:47-77`）；
- 子 Agent fan-out 按 `eval_id` 分组成 "phase"，停靠双栏实时面板（左 phase 列表 / 右子 Agent 表格，`dcode/tui/widgets/subagent_panel.py`）；
- 事件只接受主 Agent 命名空间、`type=="subagent"` 的 custom 事件，阻断嵌套子 Agent 事件上浮（`dcode/tui/textual_adapter.py:1139-1153`）。

## 2. Qwen Code：WorkflowTool 体系

### 2.1 架构与执行宿主

调用链：`WorkflowTool`（`core/tools/workflow/workflow.ts`）→ `WorkflowRunner.start`（预算/journal/registry/scheduler 装配）→ `WorkflowOrchestrator.run`（`countedDispatch` 统一漏斗）→ `workflow-sandbox.ts` 用 **`node:vm`** 执行脚本：

```ts
const wrapped = `(async () => {\n${script}\n})()`;
const result = new vm.Script(wrapped).runInContext(ctx, { timeout: 30_000 }); // 同步段
// 异步段由 30 分钟 WallClockWatchdog + abort controller 兜底
```

沙箱注入全局：`phase(title)`、`log(msg)`、`agent(prompt, opts)`、`parallel(thunks)`、`pipeline(items, ...stages)`、`workflow(nameOrRef, args)`（saved workflow 复用，仅顶层一层）、`args`、`budget`（只读）。**`Date.now`/`Math.random` 被替换为抛错版本**——保证脚本确定性以支撑 resume（`core/agents/runtime/workflow-sandbox.ts:977-997`）。

与 dcode 的本质差异：**qwen 的脚本只有"派发子 Agent"一个能力**（无 PTC——不能直调父工具）；dcode 的 REPL 是"代码解释器 + PTC + 子 Agent"三合一。

### 2.2 agent() 派发与结构化输出

- `WorkflowAgentDispatch = (prompt, opts) => Promise<string | object>`；生产实现包 AgentHeadless（无 UI 子 Agent 运行时），`opts`：`label/phase/schema/model/agentType/isolation`，未知 key 直接 throw（`workflow-sandbox.ts:1351-1363`）。
- `schema` 模式：为该次调用构建独立 ToolRegistry + 合成 `structured_output` 工具（AJV 校验），监听 TOOL_RESULT 事件捕获参数；2 次 nudge 后仍不调用 → 终止错误 `"subagent completed without calling StructuredOutput (after 2 in-conversation nudges)"`（`workflow-orchestrator.ts:1253-1281, 846-872`）。
- 跨 vm 边界值全部 `JSON.parse(JSON.stringify(...))` 复活，阻断宿主原型链逃逸（`args.constructor` 逃逸 PoC 有专门测试）。

### 2.3 治理层（dcode 没有而 qwen 多出来的部分）

- **并发窗**：共享一个 `WorkflowDispatchScheduler`，默认 `max(1, min(16, cpus-2))`，env 可覆盖，硬顶 64；限制作用在叶派发层防嵌套 fan-out 死锁（`workflow-orchestrator.ts:125-149`）。
- **agent 总量**：1000/run（env 可调、硬顶 10000）；**token 预算**：`QWEN_CODE_MAX_TOKENS_PER_WORKFLOW`，入口 + 槽位双重门禁（`workflow-budget.ts`）。
- **errors-as-data**：`parallel/pipeline` 用 `allSettled`，失败槽位填 `null` 位置对齐（`workflow-orchestrator.ts:1743-1798`）。
- **停滞看门狗**：60s 无进展且无工具在飞 → abort 单次派发，重试至 3 次；工具在飞时挂起计时（慢工具不算 stall）（`workflow-stall.ts`）。
- **暂停/恢复**：scheduler 三态机 + 墙钟看门狗同步暂停（暂停不烧时间预算）。
- **journal 断点续跑**：每次派发以 `sha256(prefixHash ‖ prompt ‖ canonicalOpts)` 为键写 `journal.jsonl`；`resumeFromRunId` 时前缀哈希命中直接回放缓存结果，首个 miss 后转 live——"重跑整个编排"降为"补跑差异后缀"（`workflow-journal.ts:109-121`）。前提是脚本确定性（Date/random 抛错）。
- **后台运行与审批**：`run_in_background` 独立 controller，完成后 `<task-notification>` 注入会话；run registry 管 pause/resume/cancel、per-phase token 归账、审批桥。

### 2.4 注册与提示

实验性 opt-in：settings `workflowsEnabled`（默认 false）+ env 三态开关（`core/config/config.ts:6616-6623`）；子 Agent 内排除 workflow 工具防递归。saved workflow 是 `<project>/.qwen/workflows/<name>.js`，同时被 `workflow('<name>')` 与 `/<name>` slash command 消费（执行时读文件、热更新；realpath 防目录穿越/symlink 逃逸）。给模型的说明完全承载在工具 description 里（scout-then-orchestrate 模式指引）。

### 3.1 dcode 路线（我们采用方向）——需核对的包

> ⚠️ 企业内网源核对清单（需要在内网环境执行）：`quickjs-rs`、`wasmtime`、`bsdiff4` 三个包名 + 版本区间。若企业源缺失 quickjs-rs，替代品（PyPI `quickjs`、`py-mini-racer`）均**缺** async host function / 堆快照 / 调用预算三件套，不可平替；届时只能走镜像同步申请。

### 3.2 qwen 路线依赖（仅参考）

零第三方沙箱依赖：`node:vm` + `node:async_hooks`（ALS）+ `node:crypto`；唯一相关 npm 依赖是已有的 `ajv`。这解释了它为何选 node:vm——TS 生态里没有现成的"可桥接 async 宿主函数的嵌入式 JS 引擎"，Node 自带 vm + JSON 复活是最务实选择。

## 5. 对 harness-code 的落点启示

1. **接入面极小**：`CodeInterpreterMiddleware` 作为 middleware 追加进 `harness_agent/runtime/agent.py` 的 middleware 链即可获得完整能力；`tool_name="js_eval"`、`ptc="safe"` 起步，`mode="thread"`。
2. **协议面要新增**：子 Agent fan-out 的 `type:"subagent"` custom stream 事件需过 JSON-RPC 到 CLI（对齐 dcode 的事件形状：`phase/id/eval_id/label/duration_ms`）；`js_eval` 工具调用的展示需要 CLI 侧解析 `<stdout>/<result>/<error>` wire format（照搬 dcode 的"锚定尾块防注入"解析策略）。
3. **审批穿透**：GraphInterrupt 原样穿透的语义意味着子 Agent 审批会中断整个 js_eval 调用并在恢复后重跑——这与我们现有的审批流语义要在 Spec 里对齐（自动批准模式下无感，人工批准模式下用户会看到 js_eval 重跑）。
4. **PTC 白名单**：沿用 dcode 的 `safe` 预设（只读工具）作为默认，写工具进白名单需要用户显式配置。
5. **qwen 值得借鉴但不照搬的部分**：token 预算双重门禁、停滞看门狗、journal 断点续跑属于"编排治理层"，可作为二阶段增强；我们一期用 dcode 同款（quickjs 侧的 timeout/内存/预算 + LangGraph checkpointer）已够。
6. **不需要自研沙箱**：quickjs-rs 的 wasm 隔离比 node:vm 强（无原型链逃逸面），langchain-quickjs 3200 行已把桥接/预算/事件/提示词做完，且与 deepagents task 工具直接兼容——这正是"基于 deepagents 所以重点参考 dcode"的验证。
