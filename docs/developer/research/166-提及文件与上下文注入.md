# 166-提及文件与上下文注入调研报告

## 一、 调研背景与问题

在 Coding Agent 交互过程中，用户经常需要指示 Agent 针对特定文件或某段代码展开工作（如 `@src/app.tsx 请帮我重构这段逻辑` 或 `@packages/cli/src/index.ts#L20-50`）。
目前 Harness Code 仅支持在 TUI 侧边栏文件树中选中文件后按 `@` 插入纯文本路径，尚未支持：
1. 输入框内键入 `@` 触发实时文件模糊联想与补全下拉菜单；
2. 提交消息时智能解析 `@file` 与行号切片（`#L10-50`），将符合预算门禁的文件内容自动内联至 Prompt，免除模型首轮额外的 `read_file` 工具调用往返；
3. 企业级 128k 小上下文窗口下的自适应降级（超大文件、二进制与生成文件转为轻量引用占位）。

## 三、 企业级 128k 上下文适配分析

在 128k（或更小）上下文窗口中，系统预置 + 历史记录通常已占用 40k~70k Tokens。因此必须实施**严格的保守预算控制**：

1. **单文件内联上限（Single File Budget）**：
   - 设为 **10KB**（或约 300 行）；超过该大小的文件不自动内联全文，自动降级为 `[Mentioned File: <path> (Size: X KB, too large to inline. Use read_file to inspect)]`。
2. **单轮总内联上限（Total Turn Budget）**：
   - 用户单次消息中若提及多个文件，总内联体积上限设为 **20KB**（约 500 行 / ~4k-5k Tokens），超过部分按出现顺序截断或转为引用。
3. **行号切片语法（Line Range Priority）**：
   - 优先支持 `@file#L10-50` 语法，仅读取并内联目标行区间（通常仅 100~300 Tokens），极大节约上下文。
4. **智能黑名单（Smart Blacklist）**：
   - 自动排除 `.lock`、`.min.js`、`.map`、`.svg`、图片/二进制等高噪音文件，无论其体积大小均不内联。

## 四、 Harness Code 落地架构设计

1. **表现共享层（`packages/cli/src/presentation-shared/`）**：
   - `mention-query-policy.ts`：纯函数解析光标处 `@` token、起止 offset 与查询词；
   - `mention-filter-policy.ts`：基于 `WorkspaceExplorer` 文件列表做模糊匹配与排序；
   - `mention-parse-policy.ts`：提取文本中的 `@path`、`@"path with spaces"` 与 `#L10-50` 行号。
2. **TUI 输入栏（`packages/cli/src/tui/presentation/input-bar.tsx` & `adapter.ts`）**：
   - 增加 `MentionMenu` 浮层组件（复用 `file-icons.ts` 图标与主题高亮）；
   - 支持键盘 `↑`/`↓` 选中、`Tab`/`Enter` 回填（带空格自动加引号并附带尾空格）、`Esc` 取消。
3. **内容安全与读取（`packages/cli/src/workspace/mention-resolver.ts`）**：
   - 基于 `resolveWithinRoot` 校验路径安全性（防止目录穿越逃逸）；
   - 读取文件或行号切片，应用 10KB 单文件 / 20KB 总预算门禁与智能黑名单；
   - 构造结构化上下文块（Attached Context）附加至提交给 Agent 的用户消息前。
4. **Agent 执行与感知（`packages/agent/` & `packages/cli/src/interactive/`）**：
   - 保留原始 Draft 记录在 UI 历史；
   - 模型首轮 Prompt 包含内联代码块，实现零延迟、零额外 Tool Call 的即时代码分析。

## 五、Grok Build @ 文件交互复核（2026-09-02）

### 1. 复核范围

- 一手源码：`/Users/zhangjingxin/Code/OpenSource/grok-build`
- 复核版本：`ba76b0a683fa52e4e60685017b85905451be17bc`
- 主要链路：`AtContext` 识别光标处 token → `FileSearchState` 异步检索与维护选中状态 → `render_dropdown` 绘制候选 → `PromptWidget` 回填为原子化文件引用。

### 2. 触发与关闭

1. `context::detect_with_drill` 从光标左侧寻找最近的 `@`，只有光标仍在该 token 内才激活。`@` 前一字符如果是字母、数字或下划线则不触发，因而 `user@example.com` 不会被当作文件搜索。空白、逗号、分号是 token 边界；查询只取 `@` 到光标之间的内容。证据：`crates/codegen/xai-grok-pager/src/views/file_search/context.rs:60-130`（`detect`、`detect_with_drill`）。
2. 输入只有 `@` 也会建立上下文；此时空查询返回工作区根目录的第一层文件和目录，不会一开始就把整棵树铺进弹窗。证据：`crates/codegen/xai-grok-pager/src/views/file_search/context.rs:166-170`；`crates/codegen/xai-grok-workspace/src/file_system/fuzzy.rs:139-157, 259-268`。
3. 新 token 出现时启动后台目录遍历并重置选中项、悬停项和滚动偏移；输入或移动光标后都会重算上下文。证据：`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:155-210`（`update_context`）。
4. `Esc` 清除上下文和候选；光标离开 token、接受文件，或开始操作已选的原子文件引用时也会关闭。证据：`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:199-217`（`clear_context`）；`crates/codegen/xai-grok-pager/src/views/prompt_widget/mod.rs:1410-1424, 1607-1609`。
5. `@!query` 是显式的“包含隐藏/被忽略文件”模式，切换后重新遍历并禁用 hidden、ignore 与 git-ignore 过滤。普通模式则遵循 `.gitignore`、全局 Git ignore 和 ignore 规则，不跟随符号链接，并排除 `.git`。证据：`crates/codegen/xai-grok-pager/src/views/file_search/context.rs:38-45`；`crates/codegen/xai-grok-workspace/src/file_system/fuzzy.rs:103-121, 407-418`。

### 3. 候选列表的信息结构

Grok Build 的默认候选行很克制：只显示相对路径，不显示文件图标、扩展名标签或第二行说明。

- 路径会移除开头的 `./`；候选内命中字符使用强调色。
- 当前选中行使用背景、粗体和左侧箭头；鼠标悬停使用另一层背景。
- 路径超出可用宽度时用 `…` 尾截断，不换行。
- 顶部分隔线右侧显示 `当前候选数/全部命中数`，返回上限时显示如 `1k+/N`。

证据：`crates/codegen/xai-grok-pager/src/views/file_search/dropdown.rs:22-23, 30-99, 115-237`（`MAX_DROPDOWN_ROWS`、`render_dropdown`、`render_fuzzy_item`）；`crates/codegen/xai-grok-pager/src/app/agent_view/render.rs:2702-2766`。

### 4. 文件很多时如何展示

1. **异步遍历**：文件树遍历与模糊匹配都在后台线程进行，UI 通过 poll 获取新快照；中间态的空结果不会覆盖旧结果，用 generation 拒绝过期结果，减少闪烁。证据：`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:219-250`（`poll`）；`crates/codegen/xai-grok-workspace/src/file_system/fuzzy.rs:388-456`。
2. **检索上限**：后台 matcher 最多保留 1000 个候选，但同时保留总命中数供 UI 显示；这是“返回集上限”，不是“工作区只索引 1000 个文件”。证据：`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:19-20, 61-68, 355-363`。
3. **检索排序**：使用 Nucleo 的 path 匹配配置、智能大小写和智能归一化；先以模糊分数排序并过滤过低分数，同分时优先路径更短、再按路径排序，最后截断到 top-K。证据：`crates/codegen/xai-grok-workspace/src/file_system/fuzzy.rs:56-79, 195-218, 245-350`（`set_query`、`get_top_k`）。
4. **可视窗口**：弹窗最多显示 8 行，超出后使用滚动条；键盘选中项移出可视区时自动调整 scroll offset。选中到顶/底时停住，不首尾循环。证据：`crates/codegen/xai-grok-pager/src/views/file_search/dropdown.rs:22-23, 41-99`；`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:253-281`。

### 6. 路径回填与已选文件反馈

1. 接受文件后，Grok Build 只替换当前 `@` token，回填格式为 `@relative/path`，如果 token 在输入末尾则追加一个空格。路径即使包含空格也不需要加引号，因为选中后会转为原子化 `KIND_FILE_REF` 元素。证据：`crates/codegen/xai-grok-pager/src/views/prompt_widget/mod.rs:1960-2008`。
2. 原子化元素的可见文本仍是 `@path`，但 `@` 是灰色、路径使用专用 path 颜色；附加行号后显示为 `@path:10-12`，分隔符与行号使用不同强度。它不是带文件图标的大型 chip。证据：`crates/codegen/xai-grok-pager/src/views/file_search/mod.rs:24-48`（`styled_file_ref`）；`crates/codegen/xai-grok-pager/src/views/prompt_widget/mod.rs:3431-3445`（`file_ref_display`）。
3. 回填被包在一个 undo group 中，一次撤销即可整体撤销提及。光标在已选元素内时不会重新触发 `@` 候选；在元素上按 `Enter` 可将其展开为普通可编辑文本。证据：`crates/codegen/xai-grok-pager/src/views/prompt_widget/mod.rs:1410-1424, 1996-2007, 2781-2801`。

### 7. 加载、空态与错误状态

Grok Build 在这部分的处理并不完整，不建议 Harness Code 照搬：

- `FileSearchState::is_visible` 要求既有 `@` 上下文又有非空结果，因而加载中和零命中都不显示面板，没有“正在索引”或“未找到文件”文案。证据：`crates/codegen/xai-grok-pager/src/views/file_search/state.rs:97-102`。
- 目录遍历中的单项读取错误会被跳过，不会出现可见错误。证据：`crates/codegen/xai-grok-workspace/src/file_system/fuzzy.rs:145-157, 170-181`。
- 行预览器读取文件失败时返回 `None`，调用方只取消 undo group，没有展示错误消息。证据：`crates/codegen/xai-grok-pager/src/views/file_search/line_viewer.rs:625-672`；`crates/codegen/xai-grok-pager/src/app/agent_view/viewer.rs:22-54`。

### 8. 对 Harness Code 交互方案的直接启示

#### 建议优先采用

1. **把弹窗收紧为单行路径列表**：保留路径、命中字符高亮、选中背景与必要的滚动条；不放文件图标和语言标签。
2. **文件多时使用“固定窗口 + 可滚动结果集”**：弹窗建议保持 8 行左右，显示 `已返回/总命中`，键盘选中项自动跟随滚动；后端候选上限可独立于可视行数。
3. **增加目录深入**：候选集同时包含文件和目录，`→` 进入目录，`Tab` / `Enter` 确认文件，比单纯对全路径进行前 15 项截断更适合大仓库。
4. **选中后使用原子化文件引用**：视觉上仍是紧凑的 `@path`，但编辑、删除、撤销、提交解析都把它当作一个整体，以便可靠支持空格路径和多个提及。
5. **保留现有文件安全和上下文预算规则**：Grok Build 的弹窗交互可以参考，但 HC-166 已实现的路径越界检查、二进制识别、10KB/300 行单文件门禁和 20KB 单轮预算不应因交互改造而放宽。

#### 建议改良后采用

1. Grok Build 的无感加载/无结果状态容易让用户误以为 `@` 失效。Harness Code 应保持弹窗框架，显式显示“正在扫描工作区…”、“未找到匹配文件”和“结果已截断，请继续输入”。
2. 不建议首轮就引入 Grok Build 的行预览器、`@!` 隐藏模式与全部 Emacs/Vim 导航键。这些都是独立的交互范围，应在基础文件搜索、滚动和原子回填稳定后再评估。
