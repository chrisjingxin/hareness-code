# TUI 右侧侧边栏（Sidebar）与文件树预览可行性调研

## 1. 调研背景与诉求

当前 Harness Code 的终端界面（TUI）为全宽单列流式布局，顶部为会话主时间线（Timeline），底部为输入栏（InputBar）及审批/问答/目录信任等 Dock。随着项目功能丰富，用户希望在 TUI 中增加右侧 Sidebar，以提供更直观的环境状态与快速文件操作能力：

1. **运行态与环境信息**：展示当前 Context（Token 消耗、百分比、TPS、花费）、当前工作目录（CWD）、MCP 服务器连接状态等。
2. **工作区文件树与快速预览**：快速浏览工作目录下的文件树结构，支持展开/折叠，并可点击或按键快速预览文件内容。
3. **响应式终端适配**：仅在终端达到一定宽度尺寸（如宽屏）下默认显示，窄屏下可折叠或以浮层/抽屉形式呼出，保证主会话区域的可读性。

## 2. 竞品实现深度剖析（以 MiMo-Code 为核心）

我们在本地源码库 `/Users/zhangjingxin/Code/OpenSource/MiMo-Code` 中对 MiMo Code 的 TUI 侧边栏实现进行了完整溯源和代码走查：

### 2.1 响应式尺寸适配与显示策略

在 `packages/opencode/src/cli/cmd/tui/routes/session/index.tsx` 中：

```tsx
// 1. 宽屏断点：终端宽度 > 120 列判定为 wide
const wide = createMemo(() => dimensions().width > 120)

// 2. 侧边栏可见性判定：
// - 子 Agent 或非主会话不显示
// - sidebarOpen() 手动打开时显示
// - sidebar() 配置为 "auto" 且当前为宽屏 wide() 时自动显示
const sidebarVisible = createMemo(() => {
  if (session()?.parentID) return false
  if (currentAgentID() !== "main") return false
  if (sidebarOpen()) return true
  if (sidebar() === "auto" && wide()) return true
  return false
})

// 3. 主内容区宽度动态扣减：
const contentWidth = createMemo(() => dimensions().width - (sidebarVisible() ? 42 : 0) - 4)
```

**双模式渲染机制**：
- **宽屏并排模式（`wide === true`）**：Sidebar 作为 Flex 布局的右侧固定列渲染（宽度固定为 42 列，高度 100%），左侧主内容区 `flexGrow={1}` 自适应填满剩余空间。
- **窄屏抽屉/Overlay 模式（`wide === false`）**：当用户在窄屏下主动触发打开侧边栏时，Sidebar 被放置在一个 `position="absolute"`、全屏半透明黑色遮罩（`RGBA.fromInts(0, 0, 0, 70)`）、右对齐（`alignItems="flex-end"`）的浮层中，形成右侧抽屉效果。
- **交互与快捷键**：通过 `<leader>b` 或 `Ctrl+X B` 切换侧边栏的展开与收起状态，状态通过本地 KV 存储持久化（`auto` / `hide`）。

### 2.2 侧边栏内容插槽体系（Plugin/Slot 机制）

在 `packages/opencode/src/cli/cmd/tui/routes/session/sidebar.tsx` 中，Sidebar 采用了分层 Slot 设计：
- `sidebar_title`：会话标题、Session ID、Workspace 状态指示灯（如 connected 绿点）、分享链接。
- `sidebar_content`：多模块垂直堆叠区域，通过插件系统按 `order` 顺序渲染。
- `sidebar_footer`：应用版本号及状态。

### 2.3 核心模块的具体实现

| 模块 | 实现文件 | 数据源与呈现逻辑 |
| :--- | :--- | :--- |
| **Context** | `sidebar/context.tsx` (order: 100) | 统计最后一条 Assistant 消息的 tokens（输入、输出、推理、缓存命中），计算 Context 窗口占比（`percent% used`）；计算实时 TPS（流式计算/完成结算）及累计花费（`$ spent`）。 |

## 3. Harness Code 现有架构契合度分析

### 3.1 表现层与 UI 架构
- **渲染框架**：Harness Code 基于 `@opentui/react` + OpenTUI 核心（`createCliRenderer`），具备完整的 Flexbox 布局引擎（`<box>`）、滚动容器（`<scrollbox>`）、文本格式化（`<text>`）以及鼠标事件支持（`useMouse: true`）。
- **状态驱动模式**：TUI 表现层通过 React `useSyncExternalStore` 订阅 `TuiAdapter` 的快照（`TuiAdapterSnapshot`），所有状态单向流动，天然适合在 Snapshot 中新增 `sidebar` 相关表现状态。

## 4. 「工作区文件树与文件快速预览」技术设计方案

### 4.1 文件树数据获取与性能优化（Lazy Tree）

在企业级代码仓库中，文件数量可达数万至数十万，**绝不能在启动时进行全量深层遍历**。
- **按需加载（Lazy Loading）**：
  - 初始仅读取工作区根目录（depth = 1）的文件和目录列表。
  - 只有当用户展开某个文件夹时，才异步读取该子目录的条目并插入树节点中。
- **智能忽略规则（Gitignore Aware）**：
  - 默认加载并解析工作区的 `.gitignore`，过滤 `node_modules`、`.git`、`dist`、`__pycache__`、`.venv` 等无关大目录。
  - 避免无效渲染与内存膨胀。
- **平铺视图映射（Flat List Projection）**：
  - 将树形展开状态映射为一维可视行列表（Virtual Array），包含 `{ path, name, isDir, depth, expanded, level }`。
  - 配合 OpenTUI 的 `<scrollbox>` 进行轻量滚动渲染。

### 4.2 交互与焦点控制模型（Keyboard & Mouse）

在终端 TUI 下，必须处理好**主输入框**与**侧边栏文件树**之间的按键冲突：

```
[模式 A：聊天输入模式（默认）]
- Focus 在底部 InputBar
- 键盘输入正常打字
- 快捷键 F2 / Ctrl+B / Tab 切换焦点到 Sidebar

[模式 B：Sidebar 浏览模式]
- Focus 切换至 Sidebar 文件树
- ↑ / ↓ ：在文件树中上下移动光标
- → / Enter（在目录上）：展开目录
- ← / Enter（在展开的目录上）：折叠目录
- Enter / Space（在文件上）：打开「文件快速预览浮层」
- @ 快捷键：将当前选中的文件相对路径插入到聊天输入框并切回输入模式
- Esc / Tab：退出 Sidebar 浏览，焦点返还 InputBar
- 鼠标支持：支持鼠标直接点击目录展开/折叠，点击文件直接触发预览
```

### 4.3 文件快速预览（Quick Look Preview Modal）

由于侧边栏宽度有限（通常 36~42 列），直接在侧边栏狭窄区域内看代码体验极差，因此建议采用**浮层式快速预览**：

```
+-----------------------------------------------------------------------------+
| 文件预览: packages/cli/src/tui/app.tsx                         [Esc / q 关闭] |
|-----------------------------------------------------------------------------|
| 1: /** OpenTUI 表现 adapter：把终端输入映射为 TuiIntent... */                   |
| 2:                                                                          |
| 3: import { createCliRenderer, type KeyEvent } from "@opentui/core"         |
| 4: import { createRoot, useKeyboard } from "@opentui/react"                 |
| 5: ...                                                                      |
|                                                                             |
|                                                                             |
|                                                                             |
|-----------------------------------------------------------------------------|
| 快捷键: [↑/↓] 滚动行  [PgUp/PgDn] 翻页  [@] 引用到输入框  [q/Esc] 关闭        |
+-----------------------------------------------------------------------------+
```

- **高亮渲染**：复用 Harness Code 现有的 Tree-sitter / OpenTUI 语法高亮解析器（`registerCommonSyntaxParsers`）。
- **大小限制与二进制保护**：对大于 1MB 的文件或二进制文件（如图片/音视频/可执行文件）提示「文件过大或为二进制文件，暂不支持文本预览」，防止 TUI 内存崩溃。

## 5. 建议的分期实施路线（Phased Implementation）

为符合项目「小步迭代、可演示停点」原则，建议将该功能拆分为两个清晰的阶段：

### 第一阶段：基础侧边栏与环境状态（Context / CWD / MCP）
1. **布局与尺寸适配**：
   - 增加终端尺寸断点判断（`width > 120` 自动分栏，`<= 120` 抽屉模式）。
   - 增加快捷键（如 `Ctrl+B` 或全局命令）切换侧边栏开/关。
2. **环境状态小部件**：
   - 渲染 CWD（格式化路径）。
   - 渲染 Context（Token 统计、百分比进度条、TPS）。
   - 渲染 MCP 服务器连接状态列表（带状态灯）。

### 第二阶段：工作区文件树与文件快速预览
1. **文件树数据与懒加载组件**：
   - 实现带有 `.gitignore` 过滤的本地轻量目录扫描与懒加载。
   - 渲染树形组件（`▶`/`▼` 文件夹折叠与文件图标）。
2. **焦点切换与导航交互**：
   - 实现 `Tab` / `F2` 焦点切换机制。
   - 支持键盘光标导航与鼠标点击。
3. **文件预览弹窗（Preview Modal）**：
   - 实现语法高亮代码预览浮层。
   - 支持上下滚动与一键 `@` 引用文件路径到输入框。
