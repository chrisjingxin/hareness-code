## 使用规则

- 按 WP1～WP15 的依赖顺序执行；Plan 明确允许并行的 module 才可由多个执行 Thread 并行推进。
- 每个工作包使用 `agent-skills:test-driven-development`：先提交能证明目标行为缺失的失败测试，再写最小实现，最后重构。
- Compose Activity 固定绑定 Spec 中的内置角色；本任务不得加入 Plugin Agent 自动选择、推荐或隐式路由。
- 不得保留 HC-138 旧阶段路由的 alias、fallback、双写或兼容分支。生产入口切换前允许新 module 未接线，切换后旧 canonical path 必须删除。
- 若实现需要改变公开 interface、Protocol、SQLite 数据形状、生命周期、命令可见性、恢复/错误语义或权限边界，停止执行并先修订 Task、Spec、Plan、Todo。
- 每个工作包的动作、focused tests 和完成信号全部满足后才勾选；检查点未通过不得进入下一阶段。
