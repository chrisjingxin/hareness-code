# Slash Command 体系实施设计

## 定位与边界

Slash Command 是交互式 Harness TUI 的功能入口，而不是面向脚本的命令行子命令树。它以少量稳定的顶层命令打开 OpenTUI 的 Picker、Manager、Viewer、Dialog 或执行明确的 Action；CLI Subcommand 与 JSON-RPC 则分别服务自动化和跨进程通信，三者复用底层服务但不共享文本语法。

```text
Slash Command → Command Registry → Dispatcher → CommandResult → TUI Adapter
                                      │
                                      └→ Domain Service / JSON-RPC
```

`packages/cli/src/tui/commands.ts` 的不可变 Command Registry 统一驱动帮助、补全、菜单、解析、capability 可见性与未知命令建议。`command-dispatcher.ts` 中的 Builtin Handler 只返回 `CommandResult`；当前根组件仍适配 RPC、React 状态、Picker/Dialog 和部分多步工作流。

`packages/cli/src/tui/overlays.tsx` 提供两项可复用基础：`SearchPicker<T>` 统一遮罩、尺寸、窄终端降级、搜索焦点、加载/错误/空态、滚动与 Enter 选择；调用方只提供稳定键和领域行渲染。`DialogShell` 复用同一浮层骨架，并接收确认、取消和可选内容。Skill、Thread 和 Model 选择器复用该 interface；浮层关闭后，在允许输入的状态下延后一 tick 恢复 Composer 焦点。

`/model [query]` 要求 `models.read` 且在 active Run/Interaction 中禁用。Picker 消费 `models.list` 的脱敏 catalog、当前 `thread_selection` 与最近实际绑定；确认后立即更新 TUI 的 `ThreadExecutionSelection.primary_profile`，每次 `run.start` 都携带 `model_selection`。若协商 `config.write`，Picker 还会在保存态执行 `config.details → config.preview → config.commit`，只提交 `models.default_profile`；失败不回滚当前 Thread 选择。`run.started` 返回实际 primary 模型后再校准状态栏，`/new` 清除选择并采用已同步的默认值。

## 交互约定

- Picker：`/model`、`/resume`、`/skills`。
- Viewer/Manager：`/mcp`、`/status`、`/version`、`/help`。
- Dialog：`/new`、`/compact`。
- Action：`/web`、`/quit`。

Registry 只声明当前已接入命令。尚未实现的交互入口记录在 [新功能候选](新功能候选.md)，不能提前进入帮助、补全或 capability。

`/new` 为创建新 thread 的 canonical 名称，`/clear` 保留为别名；活动 run 下会先打开确认 Dialog，确认后才发起取消。`/force-clear` 仅在一个兼容周期内提示迁移到 `/new`，不会再形成第二套取消/清理流程。`/resume` 的别名为 `/continue` 和 `/threads`。不向用户展示内部 `thread_id`。

## 命令契约

每项命令必须拥有稳定 ID、canonical 名称、别名、来源、类别、展示类型、参数提示、所需 capability、thread/空闲状态要求、安全确认策略和执行器。执行器只返回结构化 `CommandResult`，例如 `open-picker`、`open-manager`、`open-viewer`、`open-dialog`、`rpc`、`notice`、`submit-prompt` 或 `exit`；TUI 根组件只负责将结果映射为界面动作。

Registry 在生成菜单、帮助和补全前统一计算可用性：缺少协商 capability 时隐藏；当前状态不满足时显示禁用原因；执行中的 run 不允许切换 Profile、恢复其他 thread 或进行破坏性操作。命令名称大小写不敏感，参数原文保持不变；未知 `/command` 显示建议而不能发送给模型，`//text` 是向模型发送以 `/` 开头文本的转义方式。

## 状态与安全限制

- 已启动 Run 的模型和 Runtime Profile 不可变，不能在运行中热切换。空闲 Thread 的 `/model` 可以更新下一次 Run 的主模型，并自动尝试更新后续新 Thread 的 `models.default_profile`；两条路径独立失败，服务端在 `run.start` 重新解析并写入独立的实际绑定。
- `/compact` 仍遵守现有最近轮次、节省率、归档和隔离规则。
- MCP 和 Skill 视图不得显示凭据、完整敏感 URL、Prompt 或原始大工具结果。

## 当前来源

Builtin 命令不能被覆盖。Skill catalog 以 `/skill:<canonical-id>` 形式提供动态 Prompt 入口，短名称只在全局唯一时可调用。当前不加载 MCP Prompt、Plugin Command 或 Prompt Template。

运行中不监听文件变化。catalog 只在 sidecar 启动时建立快照；没有对应 capability 或可信来源时，命令必须隐藏或拒绝。

## 架构收敛

```text
Command Registry / Parser
  → Dispatcher / CommandResult
  → TUI 状态与工作流 module
  → React/OpenTUI adapter
```

当前架构任务只深化 TUI 状态与命令工作流，不新增命令，见 [ZC-090](tasks/ZC-090.md)。
