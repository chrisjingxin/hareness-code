# HC-171 审批模式本轮生效实施计划

关联任务：[HC-171](../task/HC-171-审批模式本轮生效.md) · 规格：[HC-171 Spec](../spec/HC-171-审批模式本轮生效.md) · 清单：[HC-171 Todo](../todo/HC-171-审批模式本轮生效.md)

## 通俗方案

把审批模式从“CLI 选择值”提升为 Host 运行表中的一个小型、带 revision 的 Run 状态。共享图只编译一次，但每个关键决策边界通过 `RunContext` 读这个状态；CLI 只有拿到服务端确认才改显示。这样可以同时满足活动 Run 生效、无回溯、子代理求交和硬策略优先级。

版本决策：本任务在尚未正式发布的 canonical Protocol v3.8 内直接加入方法，保持 `min_minor=8`，不升 v3.9。原因是当前仓库没有外部兼容承诺，v3.8 仍可整体生成；低于 minor 8 的连接由既有版本门禁拒绝，避免静默消费未知 RPC。

## 阶段 1：RED 与协议基础

1. 先添加 Protocol/Host/CLI 的失败测试：不存在的 `run.set_approval_mode`、活动 Run 仍只改本地、Host 状态缺失/非 owner/待交互错误。
2. 修改唯一 schema，加入 operation、capability、error codes 和 params/result；运行 canonical generator/check，迁移 TS/Python 类型和 fixture。
3. 在 `RunCoordinator` 增加 `ApprovalModeState`、pending Interaction 集合和锁内 set seam；Host 注册 handler、control lease 和 stable error mapping。

## 阶段 2：CLI 线性提交（可演示停点）

1. `AgentClient`、`AgentClientGateway`、`AgentGateway` 增加 set RPC；`RunFeature` 活动路径 await RPC，成功才提交 actual mode/revision，失败保持旧值。
2. 保留 idle next-Run 覆盖和 pending Interaction busy；更新 `/plan`、Shift+Tab、Web dropdown 的异步路由与错误结果。
3. 完成 CLI focused tests：idle/active、server failure rollback、pending busy、mode cycle/set、plan restore。

可演示停点：用内存 Gateway 运行 CLI focused case，观察活动 Run 在 `default → yolo` 后 snapshot 变化；注入 RPC 失败时 snapshot 仍为 `default`，并能看到调用顺序和 stable rejection。完成后更新 Todo/handoff 并暂停。

## 阶段 3：共享 AgentEngine 动态边界

1. `RunContext` 增加共享状态和 current-mode helper；模型 prompt、Plan middleware、RuntimeState/compaction 使用实际值。
2. 让 HITL 使用安全超集；AUTO middleware、classifier、destructive guard 和 workspace trust 在每次边界按 current mode no-op/启用。
3. 让 Inline/Managed child 继承同一状态并按 child maximum 求交；保留 HC-168 resume cardinality 和正在执行调用不回滚。
4. 补 fake model/工具纵向用例：新 prompt、未决工具新模式、已决定工具不回溯、Plan/AUTO/目录信任动态行为。

## 阶段 4：边界收尾与文档

1. 补 cancel/terminal race、control/owner、invalid identity、pending plan/approval/question/directory trust、classifier unavailable fail-closed；directory trust 只作为已存在 Interaction 的 busy 条件，不作为活动切档的项目门禁。
2. 更新用户交互/安全沙箱文档和架构总览，记录审计事件与 revision 语义。
3. 按 Todo 运行 focused、protocol generate/check、typecheck、CLI Bun、Agent pytest、project check、diff check；只记录无关宿主权限/过期任务阻塞，不扩大范围。

## 本轮实施结果（2026-09-10）

- 阶段 3 已落地：`RunContext` 共享 Host-owned mode/revision，模型提示、HITL 超集、Plan hard deny、AUTO classifier/破坏性守卫、Workspace trust、RuntimeState/compaction 都在决策边界读取当前事实；不重建共享 AgentEngine。
- Inline/Managed child 已按父当前档位与角色/Plugin 最大档位求交；`general-purpose` 在父 `default` 下保留 `auto-edit` 角色默认例外，Plan constraint、deny、Capability、Sandbox 仍不可绕过；HC-168 的恢复消费边界未改变。
- 阶段 4 已补齐：活动切档的 cancel/terminal/pending/owner/identity/revision 竞态、v3.8/minor gate、脱敏 mode-change 诊断，以及用户/子代理/架构文档；外部目录工具仍由独立 `WorkspaceBoundary`/`directory_trust` 流程约束。
- 第二轮验收修复：共享 `SafetyClassifier` 的缓存和 reject streak 按 `(thread_id, run_id, execution_id)` 隔离，模型后处理、HITL 预检和执行守卫保持同一调用的一次分类；CLI 同一活动 Run 的模式 RPC 串行提交，Plan 恢复读取最后一个服务端确认档位。
- 详细命令结果以 Todo 停点证据和 Task `test_evidence` 为准；本轮仍不提交、不推送、不归档，待 review 与用户验收。

## 真实依赖顺序

Schema → generated contract → Coordinator state/handler → client port → Core submission → dynamic RunContext/guards → child/runtime snapshots → docs and regression. 不重建共享图，不把 UI 本地状态当作服务端事实。
