## 已锁定的做法（不在实现时重开）

1. **光标词法与过滤（Presentation Shared）**：
   - 提取逻辑与模糊匹配纯函数放置在 `packages/cli/src/presentation-shared/`（TUI 与 Web 共用，无 Node/React 依赖）；
   - 文件数据源直接复用 `WorkspaceExplorer` 已有的工作区文件列表（`rows: WorkspaceTreeRow[]`），不重复遍历磁盘。
2. **128k 上下文保守门禁**：
   - 单文件内联上限固定为 **10KB**（或 300 行）；
   - 单轮总内联预算固定为 **20KB**（或 500 行）；
   - 超过阈值或命中黑名单（`.lock`、`.min.js`、`.map`、图片/二进制等）一律降级为 `[Mentioned File: ... too large to inline]` 占位；
   - 显式行号切片（`#L10-50`）仅内联指定行代码。
3. **安全不变量**：
   - 必须通过 `resolveWithinRoot` 校验，坚决拦截任何逃逸工作区的非法路径；
   - 不存在的 `@` 文本（如 `@username`）静默忽略，不抛错不中断。

## 停点 1 — 输入框 @ 补全菜单与键盘交互闭环

**改什么：**
1. 在 `packages/cli/src/presentation-shared/` 新建：
   - `mention-query-policy.ts`：解析光标处 `@` 触发状态、查询词 `query` 与替换范围 `[start, end]`；
   - `mention-filter-policy.ts`：基于文件名与相对路径做模糊匹配、排序；初始版本限制返回 Top 15，停点 4 扩展为带总数与截断信息的 1000 项候选池。
2. 在 `packages/cli/src/tui/presentation/input-bar.tsx` 新增 `<MentionMenu />` 组件：
   - 渲染简洁的纯相对路径列表；
   - 定位在输入框上方（与 `<CommandMenu />` 视觉风格一致）。
3. 在 `packages/cli/src/tui/application/adapter.ts` 与 `types.ts` 增加 `MentionMenuState`：
   - `updateDraft` 时检测 `@` 补全触发；
   - 处理 `mention-menu-select` 意图，将选中的文件相对路径回填到草稿（带空格自动包裹引号 `@"path"`，并在末尾追加空格）；
   - 支持键盘 `↑`/`↓` 选择、`Tab`/`Enter` 选中、`Esc` 取消。

**为什么：** 用户能直接在界面上看见并使用 `@` 补全，打通前端交互第一公里。

**怎么验证：**
```text
cd packages/cli && bun test tests/presentation-shared/mention-query-policy.test.ts tests/presentation-shared/mention-filter-policy.test.ts tests/tui/adapter-mention.test.ts
```
断言：光标在 `@` 词后正确触发；模糊搜索能搜出目标文件；带空格路径自动包裹引号并追加空格；Esc 退出补全。

**可演示：** 运行 `bun run dev`，在输入框打 `@`，立即弹出工作区文件候选列表；上下键切换、按 `Tab` 即可完成路径补全。

## 停点 2 — 提及提取与切片安全解析器（含 128k 门禁）

**改什么：**
1. 在 `packages/cli/src/presentation-shared/` 新建 `mention-parse-policy.ts`：
   - 提取文本中的所有 `@path`、`@"path with spaces"` 以及 `#L10-50` 行号切片。
2. 在 `packages/cli/src/workspace/` 新建 `mention-resolver.ts`：
   - 调用 `resolveWithinRoot` 防御路径穿越；
   - 读取小文件全文或提取指定行号切片（支持超出行数自动夹取）；
   - 应用单文件 10KB / 单轮总计 20KB 预算门禁；
   - 应用黑名单过滤（`.lock`, `.min.js`, `.map`, `.svg`, 二进制等）；
   - 构造结构化 `[Attached Context: ...]` 代码块与降级占位符。

**为什么：** 保证提取逻辑的精确性与 128k 上下文绝对安全，避免大文件拖垮模型。

**怎么验证：**
```text
cd packages/cli && bun test tests/presentation-shared/mention-parse-policy.test.ts tests/workspace/mention-resolver.test.ts
```
断言：常规小文件正确生成内联代码块；`#L10-50` 精确切片；超 10KB 降级占位；黑名单文件降级占位；`../../` 越界路径被安全拦截。

## 停点 3 — 端到端 Prompt 注入与 Agent 即时感知

**改什么：**
1. 在 `packages/cli/src/interactive/controller.ts` 的 `handleSubmit` 流程中：
   - 在向 Agent 提交 Prompt 前调用 `mentionResolver.resolveMentions(message)`；
   - 将生成的 `contextBlock` 与用户原始消息组合为发送给 Agent 的最终 Prompt；
   - 用户 Draft 历史与 UI Timeline 仍展示用户手打的原始消息。
2. 更新用户文档 `docs/user/交互使用.md`（补充 `@` 提及文件与 `#L10-50` 行号语法说明）；
3. 检视并增量更新 `docs/developer/architecture/架构总览.md`。

**为什么：** 完成完整功能交付，Agent 零等待即时感知代码。

**怎么验证：**
```text
cd packages/cli && bun test tests/interactive/controller-mention.test.ts
bun run typecheck
```
断言：提交含 `@file` 的消息后，Agent 接收到的首轮 Prompt 包含 Attached Context；UI 历史保留用户原消息；端到端无类型与运行时报错。

**可演示：** 运行 `bun run dev`，输入 `@packages/cli/src/index.ts#L1-20 请解释这几行代码`，Agent 第一轮直接基于代码进行解答，无任何多余的 `read_file` 工具调用。

## 停点 4 — TUI 与 Web 大文件集候选菜单

**依赖：** 停点 1 的补全状态机与停点 3 的端到端链路已可用。

**改什么：**
1. 把共享过滤函数升级为结构化搜索结果：最多保留 1000 项候选，同时返回真实匹配总数、是否截断和每项匹配范围；新增共享的选中索引/窗口纯函数。
2. TUI 菜单标准显示 8 行，矮终端显示 5 行；Web 菜单显示 8 行。两端统一支持边界夹取、PageUp/PageDown、滚动跟随与 `当前位置/匹配总数`。
3. 两端都使用纯路径行、匹配高亮和长路径省略，并显示加载中、无匹配、扫描受限及候选池截断状态。
4. Web UI 通过内部 UI contract 接收 `WorkspaceTreeState.allEntries`；增加 @ 菜单状态、键盘/鼠标选择和文本回填，不改变跨进程 Protocol。

**验证：**
```text
cd packages/cli && bun test tests/presentation-shared/mention-filter-policy.test.ts tests/presentation-shared/mention-window-policy.test.ts tests/tui/adapter-mention.test.ts tests/tui/presentation/mention-menu.test.ts tests/web/application/adapter.test.ts tests/web/presentation/composer.test.tsx
bun run typecheck
```

**可演示：** 分别运行 TUI 与 Web UI，在文件很多的仓库输入 `@app`；两端最多显示一页候选，方向键、翻页和鼠标滚动可浏览，底部计数反映完整匹配数，长路径不撑破菜单。

## 停点 5 — TUI 与 Web 目录下钻

**依赖：** 停点 4 的共享候选结果与窗口导航稳定。

**改什么：**
1. 空查询只计算当前目录的直接子项，根目录作为初始层；文件与目录使用纯路径文本区分，不恢复装饰性语言图标。
2. 两端支持 `Right`/`Tab`/`Enter` 进入目录、`Left` 返回上级、鼠标点击目录，并在底部展示浏览路径；仅文件执行草稿回填。
3. 输入非空查询时回到全工作区文件搜索；清空查询时回到当前目录层级。

**验证：** 两端覆盖根目录初始列表、连续进入两层、返回上级、目录不回填、文件正常回填和空目录状态。

**可演示：** 在 TUI 与 Web 输入单独的 `@`，从根目录逐层进入 `packages/cli/src`，选择文件后路径准确回填。
