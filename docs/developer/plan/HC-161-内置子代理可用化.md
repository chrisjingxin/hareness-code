# HC-161 内置子代理可用化实施计划

关联任务：[HC-161](../task/HC-161-内置子代理可用化.md)  
规格：[HC-161 Spec](../spec/HC-161-内置子代理可用化.md)  
清单：[HC-161 Todo](../todo/HC-161-内置子代理可用化.md)

不新增范围。实现一次只做到下一个可演示停点，勾选本段 Todo 后停下。

## 通俗怎么拆

先让用户在 `/agents` 和 `task` 里看见 `explore`，并且真能只读搜代码。  
再改 `general-purpose` 的审批：派出后工作区普通写入不再一路弹窗，跑命令仍问，卡片带上子代理名。  
最后把并发排队、取消、超时做实，拆掉旧 Registry 和假文档。

```text
停点 1  /agents 与 task 能派出 explore（只读可跑）
  │
停点 2  general-purpose 按 auto-edit 少打断，execute 仍问
  │
停点 3  并发/取消/超时、拆旧路径、用户与架构文档
```

跨 protocol / agent / CLI 的同一行为留在同一步，不按包横着切。

## 已锁定的做法（不在实现时重开）

- 单一 Dispatch Catalog：builtin + 已启用 Plugin；同时驱动 `/agents`、`task` 说明、执行解析。
- 两个内置角色 Inline；Plugin 仍 Managed。
- `explore` 五工具机械只读；Forced exclusions 对两个内置角色都生效。
- 审批：child 不得比父更松；仅父 `default` + builtin `general-purpose` 内部升到 `auto-edit`。不是 child yolo。
- Plugin 要 Interaction 仍 fail closed；定义不能放宽审批。
- 新对话 + 冻结父 ModelProfile / 工作区 / AGENTS；不继承父 history。`general-purpose` 继承 Skill 索引与 MCP；`explore` 两者都不带。
- 深度 1、并发 4 排队、硬超时 300s、FIFO Interaction 队列。
- 删除 `subagents.py` Registry、`plan` 内置、`.harness/agents` 文档路径，不留兼容。

## 停点 1 — 目录可见，explore 真能跑

**改什么：** 内置角色定义（中文 description / 系统提示词 / 工具上限）写入 agent 包，由 `AgentCatalog` 在启动时先放入 builtin、再合并 Plugin。协议 `agentSummary` 增加 `kind`、`tools`。`/agents` 列出两个内置和 Plugin，标明来源与工具边界。生产 `task` 的模型可见名单与 Delegator 解析同一份。为 `explore` 编译独立 Inline 子图：只含五只读工具（Host 无 `lsp` 实现则省略）、新对话、冻结工作区与 AGENTS；不注入 Skill 索引、不挂 MCP、不注册 `tool_search`。`general-purpose` 继续可派发，套 Forced exclusions，并继承父 Skill 索引与 MCP。本停点不改 GP 的 HITL 松紧。

**为什么：** 用户现在最大的断裂是「文档有 explore，调用却目标不存在」。先把第二条真实生产路径接上。

**怎么验证：**

```text
bun run protocol:generate && bun run protocol:check
cd packages/agent && .venv/bin/python -m pytest -q tests/runtime tests/host/test_server.py tests/test_agent_delegation.py
cd packages/cli && bun test tests/interactive/commands.test.ts tests/ipc
```

断言：`agents.list` 含 `general-purpose` 与 `explore`；生产构图的 `task` 能 invoke `explore` 并只暴露只读工具；伪造 `write_file`/`execute` 拒绝；Plugin 同名不能覆盖内置 ID。

**可演示：** `bun run dev`，输入 `/agents`，应弹出只读浏览浮层，看到 `general-purpose` 和 `explore`（及已启用 Plugin）。对主 Agent 说「用 explore 找出 task 工具在哪定义」，应返回路径/符号，且不弹写文件审批、不改仓库。

## 停点 2 — GP 少打断，命令仍问

**改什么：** 按 Spec 8.1 计算 child 有效审批模式。父 `default` 时 `general-purpose` 内部按 `auto-edit` 构图（工作区非敏感写/改/删不弹窗，有界活动仍进时间线）。`execute`、敏感路径、目录信任走现有 Interaction，请求带 `agent_id` / `execution_id`。派出 `task` 在 `default` 下仍审批，卡片写明可改工作区、普通写入不再问、命令仍问。CLI/Web：Interaction DTO 带 `agentId`，Dock 标题标明子代理；`pendingInteraction` 改为 FIFO 队列，禁止替换丢弃。Plugin 不套用 auto-edit 放宽，Interaction 仍 fail closed。

**为什么：** 停点 1 之后 GP 仍可能「批过 task 就内部不审批」或「每次写文件再问」。这一步把产品语义做对。

**怎么验证：** focused：父 default 下 child 写工作区文件不产生 `interaction.approval`，`execute` 会产生且 `agent_id=general-purpose`；父 plan 下 child 写文件仍硬拒绝；deny rule 仍拦截；新 Interaction 入队不 fail-close 旧 `ask_user`。CLI/Web 相关测试覆盖队列与标题。

**可演示：** `bun run dev`，审批模式 default。让主 Agent 派 `general-purpose` 改一个普通文件：派出时弹一次（若当前会对 `task` 审批），确认后文件改动不再弹窗。再派它执行一条 shell：应弹出「子代理 general-purpose 需要审批」，拒绝后主对话还在，子代理能改方案。子代理内部过程时间线见 HC-162，本停点主时间线只保留派出卡片。

## 停点 3 — 生命周期、拆旧、文档

**改什么：** `AgentDelegator` 并发从「超额拒绝」改为许可排队，硬上限 4（Policy 只能更严）。排队中与执行中均可被父取消；300s 硬超时取消实际 child；所有终态 `finally` 释放许可。删除 `runtime/subagents.py` 发现/Registry/`plan`、`_create_default_subagents` 后备，并迁移只为它们存在的测试。改用户文档与架构 5.4–5.5 节。补生产 graph 双目标离线 E2E，以及真实用户配置 + mock 模型的开发 smoke。

**为什么：** 目录和审批已经可看；没有排队/取消/拆假文档，功能仍不像完整产品。

**怎么验证：**

```text

rg -n "AgentRegistry|BUILTIN_AGENTS|\\.harness/agents" packages docs --glob '!docs/developer/task/**' --glob '!docs/developer/spec/HC-161*' --glob '!docs/developer/plan/HC-161*' --glob '!docs/developer/todo/HC-161*'
bun run project:check && bun run typecheck
```

生产代码与用户文档不得再宣传 `.harness/agents` 或内置 `plan` 子代理。

**可演示：** `/agents` 与 `docs/user/subagent.md` 只谈两个内置 + Plugin。连续派出超过 4 个 child 时第 5 个等待而不是立刻失败；取消父 Run 后排队与执行中的 child 都停。explore / general-purpose 都能从生产 `task` 跑通。
