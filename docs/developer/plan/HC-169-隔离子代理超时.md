# HC-169 隔离子代理超时实施计划

关联任务：[HC-169](../task/HC-169-隔离子代理超时.md)

规格：[HC-169 Spec](../spec/HC-169-隔离子代理超时.md)

清单：[HC-169 Todo](../todo/HC-169-隔离子代理超时.md)

本任务只有一个可演示停点。实现不得修改 hard deadline 或扩大到其它 delegation 错误。

## 通俗方案

底层继续像现在一样在超时时真正停掉子代理；只在主 Agent 的 `task` 边界把超时异常变成一条带错误状态的工具结果。这样派出卡仍明确显示失败，主模型也知道稳定错误码，但根图能进入下一轮继续回答。

## 停点 1：子代理超时，主对话继续

### 1. 先建立失败测试

- 在 delegation 测试中补齐执行中 timeout：证明 runner 被取消、child 为 failed、slot 可复用。
- 在 Middleware 测试中证明只有 `DELEGATION_TIMEOUT` 转为 `ToolMessage(status="error")`。
- 在生产 Agent/Host 纵向测试中让 fake task 超时，断言主模型收到 ToolMessage 后继续生成最终回答，根 Run 完成。
- 在 CLI 既有投影测试中加入 `is_error=true` 的 task 结果与后续 assistant，断言 TUI/Web 可见。

### 2. 最小实现

- 在 `DelegationContextMiddleware` 增加一个私有、确定性的 timeout ToolMessage renderer。
- `awrap_tool_call` 仅捕获 `AgentDelegationError` 且只在 `code == "DELEGATION_TIMEOUT"` 时返回该 ToolMessage；其他异常原样抛出。
- 如同步 wrapper 没有生产 timeout 路径，不为测试制造平行实现；只保证现有同步 fail-closed 不被放宽。

### 3. 回归与文档

- 验证父取消、策略拒绝、目标不存在、Compose/Team 语义未变。
- 更新 `docs/user/subagent.md`，说明超时卡片失败但主对话继续。
- 在 `docs/developer/architecture/架构总览.md` 的子代理生命周期处增量写明 Tool 级隔离边界。
- 更新 Task/Todo 证据和 `tmp/handoff.md`，停止等待验收；不提交、不推送、不归档。

### 可演示结果

离线纵向用例展示同一时间线顺序：派出卡运行 → 派出卡失败并显示 `DELEGATION_TIMEOUT` → 主 Agent 后续回复 → `run.completed`。正在执行后超时的派出卡仍能进入原 child timeline；排队超时不显示虚假入口。
