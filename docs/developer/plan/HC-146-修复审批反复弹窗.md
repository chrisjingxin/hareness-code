## 3. 工作包细则

### WP1：Shell 只读安全命令快放与 AutoEdit 删除放行
**目标**：消除在更自动的模式（`auto-edit` / `auto`）下只读 Execute 命令反而更吵的问题，并让 `auto-edit` 模式下的工作区内普通文件删除与编辑同权免弹窗。

**主要改动**：
- `packages/agent/harness_agent/policy/approval_policy.py`：`evaluate_permission` 中 L3.1 只读 Shell 快放条件由 `approval_mode == "default"` 调整为 `approval_mode != "plan"`。
- `packages/agent/harness_agent/runtime/agent.py`：`_make_approval_preflight` 中同步放宽 L3.1 门控为 `approval_mode != "plan"`；并在 `auto-edit` 模式下将工作区内非敏感文件操作放行扩展至 `ToolKind.DELETE`。
- `packages/agent/tests/policy/test_approval_policy.py` & `packages/agent/tests/runtime/test_agent.py`：新增/扩充测试用例。

**验收标准**：
- [ ] `auto-edit` 模式下 `ls`, `cat`, `git status`, `git diff` 无弹窗直接执行。
- [ ] `auto` 模式下只读安全 Shell 命令无弹窗直接执行。
- [ ] `auto-edit` 模式下删除工作区内普通文件无弹窗直接执行；删除 `.git/config` 依然弹窗。
- [ ] `plan` 模式依然严格拒绝 Execute 命令。

**可演示停点 1**：
在 `auto-edit` 或 `auto` 模式下，运行只读命令（如 `git status`、`ls`）或删除普通文件，无需点击审批直接完成执行；删除敏感路径仍会弹出确认。

---

### WP2：解释器裸根规则与已知子命令表
**目标**：使「本项目允许」/「本会话允许」对解释器调用（`python -m pytest` 等）沉淀有效规则，并防止普通操作数/路径被误固化进子命令规则中。

**主要改动**：
- `packages/agent/harness_agent/policy/bash_parser.py`：
  - 定义 `INTERPRETER_ROOTS`（`python`, `node`, `bun`, `pytest` 等）与 `KNOWN_SUBCOMMANDS`（`git`, `npm`, `docker`, `kubectl` 等）。
  - 将解释器从 `BARE_ROOT_FORBIDDEN` 移出，仅保留 `rm`, `del`, `curl`, `wget`, `docker`, `ssh` 等高危命令。
  - 重构 `extract_command_rule`：
    - 解释器命令生成裸根规则（允许裸根前缀匹配）；
    - 无子命令命令（`ls`, `cat` 等）生成根命令规则，丢弃后续操作数；
    - 有子命令命令仅在 token 命中 `KNOWN_SUBCOMMANDS` 时保留子命令（含 `run`/`exec` 转发保留）。
- `packages/agent/tests/policy/test_bash_parser.py`：补充参数化测试。

**验收标准**：
- [ ] `python -m pytest tests/foo.py` 生成 `python`（或 `python -m pytest`），再次执行 `python -m pytest tests/bar.py` 成功命中规则。
- [ ] `ls packages` 生成规则 `ls`，再次执行 `ls docs` 成功命中规则。
- [ ] `git commit -m x` 生成 `git commit`；`npm install express` 生成 `npm install`；`npm run build` 生成 `npm run build`。
- [ ] `rm foo.txt` 生成空串 `""`，不产生裸根规则，`rm -rf /` 依然弹窗。

**可演示停点 2**：
对 `python -m pytest tests/test_a.py` 选择「本项目允许」后，再次执行 `python -m pytest tests/test_b.py` 不再弹窗直接放行。

### WP3：Auto 模式分类器默认接通主模型
**目标**：在用户未单独配置专用 classifier 时，Auto 模式默认使用当前 Run 的主模型作为安全分类器，实现开箱即用的 AI 自动判断。

**主要改动**：
- `packages/agent/harness_agent/host/agent_host.py`：
  - 在 `create_harness_agent` 组装阶段，当 `approval_mode == "auto"` 且 `spec.execution.approval_classifier` 未指定或不可用时，使用当前 Run 的主模型实例构造 `SafetyClassifier(model)`。
- `packages/agent/tests/host/` 或 `packages/agent/tests/policy/`：新增测试覆盖未配 classifier profile 时的主模型分类与超时/失败安全回退。

**验收标准**：
- [ ] 未配置 `[approval] classifier` 时，Auto 模式下的普通 Execute 命令由主模型进行分类判断。
- [ ] 配置了专用 profile 时，优先使用该 profile，不误用主模型。
- [ ] 分类器超时、API 失败或输出格式不合法时，安全回退至人工审批弹窗（Fail-Closed）。

**可演示停点 3**：
在默认配置（无专用 classifier）下切换到 Auto 模式执行未在白名单中的无害命令，命令自动通过主模型分类放行并执行。
