### 阶段一：跨进程契约与 Command Registry 接入

**目标**：在 Protocol 层定义 `threads.list_turns`、`threads.undo`、`threads.redo` 契约，并在 CLI `CommandRegistry` 中注册 `/undo` 与 `/redo` 命令及别名解析。

1. **Protocol 扩展** (`packages/protocol`)：
   - 增加 `ThreadsListTurnsParams`、`ThreadsListTurnsResult`、`TurnSummary` 数据形状；
   - 增加 `ThreadsUndoParams`、`ThreadsUndoResult`、`ThreadsRedoParams`、`ThreadsRedoResult` 定义；
   - 在 `Method` 枚举中增加 `THREADS_LIST_TURNS`、`THREADS_UNDO`、`THREADS_REDO` 常量。
2. **Command Registry 与菜单策略** (`packages/cli/src/interactive/commands.ts`)：
   - 声明 `thread.undo`（aliases: `rewind`, `rollback`）与 `thread.redo`；
   - 扩展 `CommandContext` 与 `availability` 逻辑：当处于 Reverted 暂存态时高亮 `/redo`，非暂存态时置灰禁用 `/redo`。

> **🎯 可演示停点 1（命令注册生效）**：
> - 运行 `bun run dev`，在 TUI 中输入 `/`，菜单中可见 `/undo`（及其别名 `/rewind`、`/rollback`），输入 `/redo` 可见当前禁用原因提示。

### 阶段二：Python 后端 Git Checkpoint 录制与快照恢复

**目标**：在 Python Sidecar 中建立基于 Git plumbing 的 Checkpoint 机制，实现根据 Turn ID 获取文件改动统计以及将工作区安全还原至指定快照。

1. **Git Checkpoint 录制与索引** (`packages/agent/harness_agent/threads/`)：
   - 实现 `GitCheckpointService`：通过 `git write-tree` 在 Run 启动与结束时计算当前树哈希（Tree OID）；
   - 在 SQLite / Thread 存储中记录 `(thread_id, turn_id, run_id, tree_oid, created_at)` 索引。
2. **Undo / Redo 消息截断与还原执行器**：
   - 实现 `threads.list_turns` RPC 派发器：返回当前 Thread 的所有历史回合、Prompt 摘要及各 Turn 对应的变更文件数；
   - 实现 `threads.undo`：根据模式（`both` / `conversation` / `code`）恢复 Git 树（`git read-tree` + `git checkout-index`）并将 Thread 内部活跃游标回拨，标记进入 Reverted 暂存态；
   - 实现 `threads.redo`：恢复被撤销前的最新状态；
   - 实现 `run.start` 前置的 `cleanup`：若在 Reverted 态下启动新 Run，永久删除旧分支。

> **🎯 可演示停点 2（后端能力单测全通）**：
> - 运行 pytest 针对 Git Checkpoint 录制、代码文件无损恢复、纯对话截断、以及发新消息时物理清理进行端到端断言。

### 阶段三：CLI 核心交互状态机与 Dispatcher 联动

**目标**：在 TypeScript Interactive Core 中接入 Undo / Redo 语义操作（Semantic Operations），并在 `InteractiveController` 中驱动 Sidecar RPC。

1. **Dispatcher 扩展** (`packages/cli/src/interactive/command-dispatcher.ts`)：
   - 增加 `request-undo` 与 `request-redo` 语义动作；
   - 拦截 `/undo` 并触发 `present` 打开历史回合选择器。
2. **Controller 状态机驱动** (`packages/cli/src/interactive/controller.ts`)：
   - 维护 `threadRevertState`（记录当前是否处于 Reverted 暂存态及目标 Turn）；
   - 实现 `handleUndoConfirm(turnId, mode)`：调用 `agentGateway.undoThread`，更新 Timeline 渲染视图；
   - 实现 `handleRedo()`：调用 `agentGateway.redoThread`，恢复完整历史；
   - 在用户提交新 Prompt 触发 `run.start` 时，同步重置 `threadRevertState`。

> **🎯 可演示停点 3（Controller 状态流转验证）**：
> - 运行 `cd packages/cli && bun test`，通过针对 Controller 的单元测试验证状态机流转（正常 -> Undo -> Redo -> 新 Prompt 截断）。

### 阶段四：TUI 浮层展示与全链路端到端集成

**目标**：在 OpenTUI 表现层实现历史回合选择浮层（`SearchPicker`）与确认对话框（`DialogShell`），完成视觉与交互全链路闭环。

1. **`UndoPicker` 历史回合选择器** (`packages/cli/src/tui/presentation/`)：
   - 接入 `SearchPicker` 展示 Turn 列表（倒序显示 Turn 编号、Prompt 摘要、时间标签和改动文件统计标签）；
   - 支持键盘 `↑`/`↓` 快速导航与实时搜索过滤。
2. **`UndoConfirmDialog` 二次确认浮层**：
   - 选中 Turn 后展示两行 Prompt 详情及改动概览；
   - 提供 `both` / `conversation` / `code` 键盘焦点单选器；
   - 非 Git 仓库自动将代码还原选项置灰并显示警告说明。
3. **通知与状态栏联动**：
   - 执行 Undo 后，右上角 Toast 弹出通知：`已回退至 Turn N（输入 /redo 可恢复）`；
   - 状态栏即时刷新。

> **🎯 可演示停点 4（完整交互验收）**：
> - 运行 `bun run dev`，在真实长会话中进行多轮问答与代码修改，输入 `/undo` 挑选历史回合回退，观察代码与对话同步还原，输入 `/redo` 恢复原状，输入新消息开启新分支。
