# HC-172 清理死代码与重复实现实施计划

关联：[Task](../task/HC-172-清理死代码与重复实现.md) · [Spec](../spec/HC-172-清理死代码与重复实现.md) · [Todo](../todo/HC-172-清理死代码与重复实现.md)

不新增范围。实现严格按 Todo 执行，一次只推进到下一个可演示停点；每到停点必须更新 Todo 证据与 `tmp/handoff.md`，然后停下等用户验收。未经用户要求不得继续下一停点。

「本任务明确不做」见 Todo 冻结清单；Plan 步骤不得引用那些路径作为本编号的改动。

## 通俗怎么拆

先把确定没人走的代码和撒谎文档拿掉，仓库立刻变干净、行为不变。再把两套还在跑的重复类型合成一套。合并比删除风险高，所以放后面，且各自可验证。

```text
停点 1  删死代码 + 拆兼容别名 + 改过期文档
  │
停点 2  合并 Skill 运行时 + 合并资源租约
```

不按 `cli / protocol / agent` 水平分层硬拆。停点 1 的 CLI 别名和 Python 死代码可以同一停点交付，因为都是「删符号、改 import、测仍绿」。

## 已确认的代码事实

- 生产 Compose 入口是 `ComposeRunAdapter` → `ComposeSession.execute_turn`。`ComposeWorkflow(` 只出现在测试的 `inspect.getsource`。
- `ComposeWorkItemEngine(` 只出现在 compose 测试，**归属 HC-155，本计划不删**。
- Host 同时 `import` `plugin_skills` 与 `skills.SkillCatalogManager`。
- `agent_engine.py` 同时 import `resource_lifecycle` 与 `resource_ownership`；两套 `ResourceScope` 枚举值分别为 `engine` 与 `agent-engine`。
- `createInteractiveController`：`options.gateway ?? options.agent ?? createFallbackNoopGateway()`。
- TUI `file-icons.ts` 仅被自身测试引用，**归属 HC-152，本计划不删**。
- `thread_persistence.py` 前半是迁移仪式，**归属 HC-108，本计划不拆、不删**。

## 架构决策

- **删除优于包装。** 去掉死模块后不留 `compat.py` 或 re-export。
- **合并时选被 Host 生产路径使用的那一份当 canonical。** Skill 以 `plugin_skills` 的运行时 catalog 为准，把 `SkillCatalogManager` / 市场安装收进去；资源租约以 Host 已用的 `SharedResourceOwner` 为准，把 lifecycle 的 handle/lease 语义并入，而不是再包第三层。
- **测试目录可以保留假 gateway。** 禁止生产 `controller.ts` 默认构造它。
- **文档只改与本停点删除/合并直接相关的撒谎处。** 不借机重写架构总览里 Compose Work Item 段落（那是 HC-155 的文档债）。

## 依赖顺序

```text
1. 删除 ComposeWorkflow 栈及其只服务它的测试
   ↓
2. 删除 CLI 生产 noop / 别名 / agent-port 转发；测试改走内存 gateway
   ↓
3. 删除过时 eval、重复 red 测试、docs 迁移脚本、撒谎文档
   ↓
4. 停点 1 可演示
   ↓
5. 合并 Skill 模块 + 迁移 import
   ↓
6. 合并资源租约 + 统一 ResourceScope
   ↓
7. 停点 2 可演示
```

5 与 6 无互相依赖，但都改 Host/runtime 启动路径，同一停点串行交付，避免两套半合并状态。

## 停点 1 — 死代码、别名、文档

**改什么：** 删除 `compose/workflow.py`、`state_machine.py`、`context_pack.py`、`threads/compose_artifact_store.py` 以及只覆盖它们的测试。删除 `agent-port.ts`、生产路径对 `createFallbackNoopGateway` 的默认调用、`InteractiveScheduler` / `InteractiveResult` / `options.agent`。删除 `semantic-tone.ts`（若仍无生产引用）。删除 `evaluations/zc133/`、`test_hc166_plugin_management_red.py`、`scripts/project/migrate-docs-layout.ts`。删除或改写 `docs/项目分析.md`、`docs/Harness-Code-项目深度分析.md`、根 `tasks/`、`架构重构计划.md` 的过期「当前待办」。

**为什么：** 不碰仍在跑的重复类型，先拿掉确定的噪音，diff 可审、可回滚。

**怎么验证：** 见 Todo 停点 1。`rg` 负向断言 + focused tests + `bun run typecheck`。

**用户怎么看：** 开发者打开仓库：`ComposeWorkflow` 搜不到；`bun run dev` 进 TUI 发一条 Build 消息、切 Compose 走现有 Session 路径，行为与改前相同。无需新 UI。

## 停点 2 — 合并 Skill 与资源租约

**改什么：** 一个 `SkillRegistry` 定义点；`SkillCatalogManager` 与市场安装迁到同一模块；删掉第二份 `SkillMarketplaceProvider` 拷贝。一套 `ResourceScope` + owner/lease；`agent_engine.py` / MCP / execution pool 只依赖这一处。

**为什么：** 这两处是「两套都在跑」的重复，删一半会断生产路径，必须迁 import 再删。

**用户怎么看：** `bun run dev` 列出 Skill、启停 Skill、跑一次带工具的 Run；资源关闭路径由 focused tests 覆盖。界面无新能力。
