# HC-170 执行中可用运行时命令实施计划

关联：[Task](../task/HC-170-执行中可用运行时命令.md) · [Spec](../spec/HC-170-执行中可用运行时命令.md) · [Todo](../todo/HC-170-执行中可用运行时命令.md) · [Research](../research/170-运行时输入调研.md)

不新增范围。实现严格按 Todo 执行，一次只推进到下一个可演示停点；每到停点必须更新 Todo 证据与 `tmp/handoff.md`，然后停下等用户验收。未经用户要求不得继续下一停点。

## 通俗怎么拆

先让干活时输入栏能打字、本地命令能跑、Esc 不会误停任务。再接上用户最初要的 `/btw` 和 `/goal`（含 Web BTW 和执行中查看浮层）。最后补齐其余放行命令、`/quit` 确认和文档。

```text
停点 1  执行中能打字 + 本地命令 + Esc 不取消
  │
停点 2  /btw 并行（含 Web 面板）+ /goal 控制面与查看浮层
  │
停点 3  其余放行命令 + /quit 确认 + 用户/架构文档
```

停点按用户能看见的行为切，不按 `cli/tui/web` 横切。同一停点里 Core 门禁和两端呈现必须一起通，否则用户仍会感觉「一端能用一端不能」。

## 已确认的代码事实

- 命令可用性已经集中在 `CommandRegistry.availability`；`requiresIdle` 会在 running 时禁用。`CommandSafety.allowedDuringRun` 从未被读取，按 Spec 删除并改为 `runtime?: "allowed" | "blocked"`，缺省 blocked。
- `/skills`、`/new-work`、`/abandon` 目前没有 `requiresIdle`，执行中会被误放行；必须在停点 1 标 `blocked`。
- TUI 失焦：`input-bar.tsx` 的 `focused={(!busy || awaitingQuestion)}`，`busy = activeRun || compacting`。
- TUI Esc：`shortcuts.ts` 在无浮层且 `activeRun` 时返回 `cancel-run`。`Ctrl+C` 有草稿时先 `clear-draft`。
- Web：textarea 执行中并未 disabled，但 `adapter.submit()` 见到 `activeRun` 直接 return；`composer.tsx` 与 `web-app.tsx` 两处 Esc 都会 `cancel-run`。停止按钮已存在。
- Controller `applyCommandResult` 对任意 `present` 在 running 时拒绝，所以 `/status`、`/agents` 即使 Registry 放行也打不开。
- Dispatcher 对 disabled 命令返回 notice 且 `accepted`，adapter 会清草稿。Spec 要求改为 `rejected` 才能留草稿。
- `/btw` 的 `side-question` 效果 TUI 已实现；Web `handleInteractiveResult` 没有该分支。
- 空参 `/goal` 走 `openGoalViewer` → Interaction DTO → GoalDock，会占底部槽。执行中要改成 Adapter overlay。
- `run.start` 受理后即返回，sidecar 读循环空闲，`threads.side_question` / `goal.*` / `run.cancel` 执行中可并发。本任务不改 Python mailbox。
- 压缩中白名单已在 `blocksPendingOperation`：只放 `system.help` / `system.status` / `system.quit`。不放宽。

## 架构决策

- **能力表只放 Registry。** Adapter 禁止再写「running 就不能 submit」。
- **失败关闭。** 未标 `runtime: "allowed"` 的命令执行中禁用。
- **禁用 = rejected。** 只有这样草稿才不会被 `accepted` 清掉。
- **Esc 与取消拆键。** 停点 1 必须同时改，不能先解锁输入却仍用 Esc 取消。
- **查看浮层属于 Adapter。** Core 仍返回 inspect 语义；TUI/Web 在 `activeRun` 时画 overlay，空闲仍用 GoalDock/PlanDock。

## 依赖顺序

```text
1. Registry policy + Controller 提交路由 + present 白名单
   ↓
2. TUI 焦点/文案 + TUI/Web 键盘仲裁 + Web 不再丢弃 submit
   ↓
3. 停点 1 可演示
   ↓
4. Web BTW 面板 + 执行中 Goal/Plan 查看 overlay + 审批让位
   ↓
5. 停点 2 可演示
   ↓
6. 其余 allowed 命令、/quit 确认、文档
   ↓
7. 停点 3 可演示
```

1 与 2 必须在同一停点交付：只改 Core 用户仍不能在 TUI 打字；只改焦点不改路由，普通文字会撞上含糊的 startRun busy。

## 停点 1 — 执行中能打字、本地命令能跑、Esc 不误杀

**改什么：** Registry 写入 Spec 5.1/5.2 的 `runtime`；`availability` 在 running 时对非 allowed 禁用。Controller：禁用命令 `rejected` 留草稿；普通文字/`//` running 时 `rejected` 稳定中文；`present status|agents` 放行。TUI 执行中输入栏保持焦点，placeholder 改为 Ctrl+C。TUI/Web Esc 不再 cancel-run；无浮层 Esc 只提示。TUI 执行中 `Ctrl+C` 无论有无草稿都取消并留草稿。Web `submit()` 把 draft 交给 Core。

**为什么：** 这是用户能感知的最小闭环，并且先消掉 Esc 误触。

**怎么验证：**

```text
cd packages/cli && bun test tests/interactive/commands.test.ts tests/interactive/controller*.test.ts tests/tui/application/shortcuts.test.ts tests/web/presentation/composer.test.ts tests/web/application/adapter.test.ts
```

（以 Todo 里实际测试文件名为准。）

**用户怎么看：** `bun run dev` 发一条会跑一会儿的 prompt。执行中输入栏可打字。`/status` 打开浮层，Esc 关掉后任务仍在跑。输入「继续」被拒绝且字还在。无浮层再按 Esc 任务不停，提示用 Ctrl+C。Ctrl+C 才停，输入还在。Web 同样：能提交 `/status`，Esc 不停，点停止才停。

## 停点 2 — `/btw` 与 `/goal`

**改什么：** Web 解释 `side-question`，做最小 BTW 面板（loading/ready/error、Esc 关闭、复制）。执行中空参 `/goal`、无挂起审批时的 `/plan-view` 打开独立 overlay，不进 GoalDock/PlanDock。`pendingInteraction` 变为审批类时关闭这些 overlay（含 Status/BTW）。Goal 写操作继续既有 queued，补一条 running 时提交的 focused test。

**为什么：** 这是开这个 Task 的直接原因。

**用户怎么看：** 执行中 `/btw 这个报错是什么意思`，TUI 与 Web 都弹出旁路面板，主任务继续，主时间线不出现这轮问答。`/goal` 打开查看浮层，Esc 关掉后还在跑。再 `/goal pause`，看到已排队或已应用提示，当前 Run 不中止。若 Agent 弹出审批，查看浮层消失，底部变成审批。

## 停点 3 — 其余命令、退出确认、文档

**改什么：** `/plan` 保持 running 降级；`/mcp` 只读；`/agents` picker；`/teams` 查询与 cancel 放行，`generate`/`run` 拒绝留草稿；`/quit` running 时 confirmation。更新 `docs/user/交互使用.md` 快捷键与 Slash 说明，以及 `斜杠命令体系.md`「执行中不允许」那句改为指向能力表。

**用户怎么看：** 执行中 `/agents` 能打开只读列表；`/teams generate …` 被拒绝且草稿还在；`/quit` 先问是否中止，选否继续跑。用户文档写明 Esc 与 Ctrl+C/停止的差别。

## 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| OpenTUI 输入栏获焦后吞掉 Ctrl+C | 无法取消 | shortcut 层继续优先于 textarea；补 shortcut 测试 |
| 禁用命令若仍 `accepted` | 草稿被清 | 停点 1 先改 rejected |
| Goal overlay 与 GoalDock 两套 UI | 空闲行为回归 | overlay 仅 `activeRun`；空闲路径不改；审批让位单测 |
| Web Esc 两处监听 | 漏改一处仍会取消 | composer 与 web-app 各补测试 |
| `/teams` 整命令 allowed 但子命令要拒 | 菜单看起来能点 | Dispatcher 按子命令拒绝，文案与 blocked 相同 |
