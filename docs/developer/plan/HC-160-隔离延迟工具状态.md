# HC-160 隔离延迟工具状态 实施计划

## 1. 计划概述

按真实依赖关系，从底层存储到运行时上下文、再到中间件拦截与主机集成，分阶段实施。

## 2. 实施步骤

### 阶段 1：实现 `ThreadDeferredToolStore` 与 `RunContext` 字段扩展
- 在 `packages/agent/harness_agent/threads/deferred_store.py` 中实现 `ThreadDeferredToolStore`。
- 在 `RunContext` 中增加 `deferred_tool_store` 字段。
- 编写 `ThreadDeferredToolStore` 单元测试，验证按 Thread 隔离、空名过滤、不可变快照返回与 TTL/淘汰。

### 阶段 2：重构 `DeferredToolMiddleware`
- 移除 `DeferredToolMiddleware` 上的共享可变 `self._revealed`。
- 改造 `wrap_model_call` / `awrap_model_call`：按当前 `runtime` 中的 `RunContext` 与 `thread_id` 读取 `revealed` 工具集。
- 增加 `wrap_tool_call` / `awrap_tool_call`：拦截 `tool_search` 工具调用结果并自动记录到当前 Thread 的 store 中。
- 保持单测兼容：提供基于 fallback store 的无 context 降级支持。

### 阶段 3：清理 `harness_tools.py` 与 `agent.py` 装配
- 移除 `create_harness_tools` 中的 `reveal` 闭包参数依赖。
- 在 `AgentHost` 中实例化 `self._deferred_tool_store = ThreadDeferredToolStore()`，并在构造 `RunContext` 时注入。
- 在 `create_za38_agent` / `create_harness_agent` 中完成中间件挂载。

### 阶段 4：编写测试验证跨 Thread 隔离与完整回归
- 编写跨 Thread 共享 AgentEngine 测试：验证 Thread A 搜索 reveal 工具后，Thread B 无法看到该工具。
- 验证同一 Thread 多轮对话中 reveal 工具的连续性。
- 运行全部 Python 测试，确保全部通过。
