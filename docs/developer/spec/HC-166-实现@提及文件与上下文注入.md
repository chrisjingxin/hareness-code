## 1. 目标与概述

在 Harness Code 终端（TUI）、Web UI 与交互核心中建立完整的 `@` 文件提及与上下文智能注入链路：
1. **输入联想**：两种界面的输入框键入 `@` 都触发当前工作区文件补全菜单，共享搜索与窗口导航语义，支持大文件集浏览、键盘选中与自动引号回填；
2. **语法支持**：支持普通路径 `@path/to/file`、带空格路径 `@"path with spaces/file.txt"` 以及精确行号切片 `@file.ts#L10-50`；
3. **上下文智能注入**：发送消息时解析有效 `@` 引用，按企业 128k 保守预算门禁（单文件 10KB、单轮总计 20KB）智能内联文件正文/切片或降级为轻量占位，实现 Agent 首轮推理直接感知目标代码。

## 2. 核心数据流与架构分层

```text
[用户在输入框键入 @query]
       ↓ (光标位置与文本)
[packages/cli/src/presentation-shared/mention-query-policy.ts]
       ↓ (提取 query，计算替换区间 [start, end])
[packages/cli/src/presentation-shared/mention-filter-policy.ts]

[TUI InputBar / Web Composer: <MentionMenu />]
       ↓ (用户按 Tab / Enter / 点击)
[TUI / Web application adapter: onSelectMention]
       ↓ (替换 @query 为补全路径，若有空格加引号，末尾追加空格)
[用户点击发送 Enter: input.submit]
       ↓ (提交原始 draft)
[packages/cli/src/workspace/mention-resolver.ts]
       ↓ (extractMentions → path-policy 安全校验 → 读取内容/切片 → 10KB/20KB 预算门禁)

       ↓ (拼装 Attached Context Block 到 message 前部，或直接注入)
[Python Agent 运行时 (harness_agent)]
       ↓ (首轮即感知文件内容，零额外 read_file 往返)
```

## 3. 语法与词法解析规则

### 3.1 光标触发规则（`mention-query-policy.ts`）
- **触发条件**：光标左侧紧邻 `@<query>`，且 `@` 前面为行首 `^` 或空白字符 `\s`（避免邮箱 `abc@domain.com` 误触）；
- **激活与提取**：
  - 输入 `hello @in`（光标在末尾）→ 激活，`searchQuery = "in"`，`tokenRange = [6, 9]`；
  - 输入 `hello @"my fi` → 激活，`searchQuery = "my fi"`，`tokenRange = [6, 13]`；
  - 若光标前为普通单词无 `@`（如 `hello world`）→ 未激活。

### 3.2 提交时提及提取规则（`mention-parse-policy.ts`）
1. **带引号路径**：
   - 正则：`/(?:^|\s)@"([^"]+)"/g`
   - 示例：`@"docs/my plan.md"` → 提取 `docs/my plan.md`
2. **普通路径**：
   - 正则：`/(?:^|\s)@([^\s"']+)/g`
   - 示例：`@src/app.tsx` → 提取 `src/app.tsx`
3. **行号切片语法**：
   - 格式：`path#L<start>-<end>` 或 `path#L<start>`
   - 示例：`@packages/cli/src/index.ts#L20-50` → 提取路径 `packages/cli/src/index.ts`，`lineStart: 20`，`lineEnd: 50`
   - 示例：`@src/app.tsx#L10` → 提取路径 `src/app.tsx`，`lineStart: 10`，`lineEnd: 10`

## 4. 128k 上下文保守预算与降级门禁

为保障在企业 128k 上下文下的绝对安全性，设置以下三级门禁（在 `mention-resolver.ts` 中执行）：

| 门禁项 | 限制值 | 超限 / 命中动作 |
|---|---|---|
| **单文件内联上限** | `10 * 1024` 字节（10KB）或 300 行 | 降级为 `[Mentioned File: <path> (Size: X KB, too large to inline. Use read_file to inspect)]` |
| **单轮总内联预算** | `20 * 1024` 字节（20KB）或 500 行 | 多个提及累计超限时，后续文件自动降级为占位提示 |
| **智能黑名单** | `.lock`, `.min.js`, `.map`, `.svg`, `.png`, `.jpg`, `.woff`, `.wasm`, 二进制 | 无论大小一律降级为占位提示 |
| **显式行号切片** | 单切片不超过 300 行且不超过 10KB | 按指定行精确切片并内联（如 `#L20-50` 仅 31 行） |
| **切片源文件上限** | `16 * 1024 * 1024` 字节（16MiB） | 超限时在整体读取前降级为占位提示，避免少量行请求触发无界内存读取 |

## 5. 公共 Interface 与类型定义

## 7. TUI 与 Web 表现层及键盘交互规范

1. **菜单渲染与定位**：
   - 当 `mentionMenu.visible === true` 时，在 TUI 输入框或 Web Composer 上方渲染 `<MentionMenu />`；
   - 沿用各端现有命令菜单的容器语义，但候选行只展示相对路径，不展示文件类型图标；
   - 标准视口固定显示 8 行；TUI 可用终端高度不足 19 行时显示 5 行；不足一页不补空行；
   - 长路径在可用宽度内省略，查询命中的字符范围高亮；底部展示 `当前位置/匹配总数`，候选超过 1000 条时显示截断提示；
   - 加载中、无匹配、工作区扫描受限均给出明确状态，不以空白菜单代替反馈。
2. **键盘导航**：
   - `↑` / `k`：选中上一项；到达首项后保持在首项；
   - `↓` / `j`：选中下一项；
   - `PageUp` / `PageDown`：按当前可见行数翻页，选中索引夹取到有效范围，窗口随选中项移动；
   - `Tab` / `Enter`：确认选中项，回填文本：
     - 若路径含空格，替换为 `@"path with spaces"`；
     - 若无空格，替换为 `@path/to/file`；
     - 回填后在末尾追加一个空格，光标移至末尾；
     - 关闭补全菜单；
   - `Esc`：关闭补全菜单，保留当前输入。
3. **互斥不变量**：
   - `CommandMenu`（`/` 触发）与 `MentionMenu`（`@` 触发）互斥，同一时刻最多展示一个菜单。

### 7.1 大文件集候选契约（停点 4）

1. 候选数据优先使用 `WorkspaceTreeState.allEntries`，缺失时才使用当前 `rows`；搜索和目录浏览不在渲染组件中重复遍历文件系统。
2. 搜索函数返回最多 1000 个排序候选，同时保留未截断的 `totalMatches`；界面只切出当前窗口，不把截断误报为“只有 1000 个匹配”。
3. TUI 与 Web 的选中索引、窗口起点、翻页和边界行为由同一组无框架依赖的纯函数计算。
4. 本停点继续只返回可直接回填的文件候选；空查询目录浏览与目录项选择在停点 5 启用，避免目录出现在尚不可操作的列表中。

### 7.2 目录下钻契约（停点 5）

1. 空查询展示当前目录的第一层文件和目录，初始目录为工作区根目录；不一次铺平整棵树。
2. `Right`、`Tab`、`Enter` 或鼠标点击进入选中的目录，`Left` 返回上级并重新选中刚离开的目录；目录不会被回填到草稿，菜单底部显示当前浏览路径。
3. 选中文件时沿用原有 `@path` / `@"path with spaces"` 回填规则；输入查询词时恢复对完整文件快照的模糊搜索。

## 8. 安全与路径不变量 (Path Invariants)

1. **工作区逃逸拦截**：
   - 所有提取到的路径均通过 `resolveWithinRoot(workspaceRoot, path)` 校验；
   - 任何企图访问 `../../etc/passwd` 或工作区外的路径一律判定为无效，不触发文件读取与内联。
2. **不存在路径静默忽略**：
   - 文本中的 `@someone`、`@todo` 等非文件字符串，在 `stat` 失败后直接忽略，不报错、不中断消息发送。
3. **只读安全性**：
   - 上下文注入纯粹为只读文件操作，不产生任何文件系统副作用。
