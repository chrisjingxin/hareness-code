# HC-162 子代理时间线规格

关联任务：[HC-162](../task/HC-162-子代理时间线.md)  
上游：[HC-161](../task/HC-161-内置子代理可用化.md) 规格 9.2（父时间线不铺 child 工具过程）  
交互参考：MiMo Code 派出卡可点、进入 actor 切片、Main 返回；不照搬独立 session、peer、token 费用条。

用户结果与验收以 Task 为准。本文只规定行为、公开 interface、错误语义和 invariant。

## 1. 通俗目标

现在点开派出卡片，只能看到任务说明和最终结论。子代理在里面读文件、跑命令、思考，主时间线什么都没有；等到超时只剩一句 `DELEGATION_TIMEOUT`。

做完之后：

- 主时间线仍然只有现有派出卡片（谁接手、任务、结论），不会多出一串子代理的 `read_file` / `execute`。
- 点那张卡片，TUI 和 Web 都进入该子代理自己的时间线，能看见它的思考和工具，运行中会跟着刷。
- 只能看，不能在子视图里接着说话。Esc 或返回回到主对话。
- 审批还在主会话底部 FIFO，进子视图也不会把审批卡弄丢。

主模型下一轮仍然看不到子代理中间过程。`task` 回给主模型的仍是最终文本或错误码。

## 2. 已确认假设

来自已确认 Task，Spec 不得改写：

1. 新开 HC-162，不并进 HC-161 停点 3。
2. TUI 与 Web 同一套交互。
3. 主 Agent 继续用现有派出卡片；子代理时间线不在主 Agent 上显示。
4. 子代理时间线只能查看。
5. 先做 HC-162，HC-161 停点 3 后做。

本任务补进、与 Task 不冲突的实现假设：

- 协议事件信封已经有 `execution_id` / `parent_execution_id` / `agent_id`。本任务用它们区分父子，不新开一套 Event type。
- 子代理过程事件进入当前 Thread 的 Interactive Core 状态，供 UI 投影；**不写入父 Transcript**，不进入主模型下一轮上下文。本任务不新做 SQLite 子时间线表，也不保证 `threads.open` 恢复后还能点进历史子过程。
- 任何经 `AgentDelegator` 派出的 child（内置 Inline 与 Plugin Managed）只要发出带 child 身份的事件，都可以点进查看。Plugin 审批 fail-closed 语义不变。
- 子视图里审批 Dock 仍挂在主会话：用户在子时间线里也能处理「子代理 {id} 需要审批」。

## 3. 术语

```text
Parent timeline
└─ 主 Agent 时间线。只含用户消息、主 Agent 文本/思考、主 Agent 工具（含 task 派出卡片）、主会话 Interaction。

Child timeline
└─ 某一个 child execution 的时间线。含该子代理的思考、工具、文本。由 envelope.execution_id 过滤。

Dispatch card
└─ 主时间线上现有的 task 派出卡片。绑定 child_execution_id 后可点进去。

Child route
└─ 表现层只读路由：正在查看哪一个 child execution。不是新的 JSON-RPC 方法，也不是新 Thread。
```

## 4. 模块与 seam

| 模块 | 职责 | 调用方必须知道的 interface | 依赖 |
|---|---|---|---|
| child-stream | 子图不再闷跑 `ainvoke`；按现有 `tool.*` / `reasoning.delta` / `content.delta` 往 Host 流，信封带 child 身份 | 输入 DelegateAgent + child graph，输出与父 Run 同一类 Event | 已有 ExecutionStream、Delegator |
| dispatch-binding | 把父 `task` 工具调用绑到刚创建的 child execution | 父 tool_call_id → child_execution_id + child_agent_id | child-stream |
| timeline-scope | 按 execution 切时间线：父视图丢掉 child 项，子视图只留该 execution | `scopeTimeline(items, executionId)` | Interactive Core |
| child-route | TUI/Web 同一套进入/返回：点派出卡进入，Esc/返回回父 | present `child-timeline` + executionId；只读 | timeline-scope |

深度：Host 和 Delegator 的调用方只看见「child 开始流事件」和「task 卡片带上 child id」。切时间线、点卡片、禁输入都藏在 CLI。禁止再为子代理发明第二条 Event 总线或独立 Thread。

## 5. 顶层流程

```text
主模型调用 task
  → 父时间线出现派出卡片（status=running，尚不可进入）
  → Delegator 创建 child execution
  → 在该 task 的 tool.delta 写入 child_execution_id / child_agent_id
  → 派出卡片可点
  → child 用 ExecutionStream 跑图（不是 ainvoke）
      每条 reasoning / tool / content 事件：
        execution_id = child
        parent_execution_id = parent
        agent_id = 角色
  → CLI 把这些项放进同一条 timeline 数组，但父视图按 root 过滤
  → 用户点派出卡 → child-route 切到该 execution_id
  → 子视图只读渲染该切片，运行中继续追加
  → Esc/返回 → 回到父视图，卡片仍在
  → child 结束：task 工具结果仍是最终文本或 DELEGATION_* 错误
  → 父 Transcript 只记录父侧（派出卡结论），不记录 child 工具正文
```

## 6. 协议

### 6.1 信封（已有，必须填）

child 过程事件使用现有 `eventBase`：

| 字段 | child 过程事件 | 父 `task` 工具事件 |
|---|---|---|
| `execution_id` | child execution id | 父 execution id |
| `parent_execution_id` | 父 execution id | 缺省或父的父 |
| `agent_id` | `general-purpose` / `explore` / Plugin id | 主 Agent（可缺省） |
| `type` | 现有 `reasoning.delta` / `tool.started` / `tool.delta` / `tool.completed` / `content.delta` | 现有 `tool.*` |

禁止为子代理新增 `subagent.*` Event type。

### 6.2 派出绑定（本任务新增字段）

在 `tool.delta` payload 增加可选：

```text
child_execution_id: string
child_agent_id: string
```

仅父 `task` 工具在 child execution 创建成功后写一次。非法或缺字段时该派出卡保持不可进入，不得猜测绑到别的 child。

`bun run protocol:generate` 后 TS/Python 两端同时拥有这两个字段。未发版，不做兼容别名。

### 6.3 不新增 RPC

没有 `subagent.open` / `child.watch`。进入子时间线是 CLI 本地 present。观察者 Connection（`threads.watch`）若收到带 child 身份的事件，用同一套过滤；本任务不单独做 WebSocket 专用协议。

## 7. 运行时

### 7.1 流，不闷跑

Inline child 必须走与父 Run 同类的 ExecutionStream（或等价 astream 投影），禁止 `graph.ainvoke` 把过程吞掉。Managed Plugin child 若当前也是一次性返回，同样改为可投影过程事件；做不到时该派出卡不可进入，不得把 Plugin 失败伪装成空时间线成功。

取消、现有 300s 超时、`DELEGATION_TIMEOUT` 语义不变。超时前已发出的 child 事件留在 Interactive Core，仍可点进查看。

### 7.2 Transcript 隔离

```text
输入：一条即将持久化的事件
  → 若 execution_id 不是父 Run 的 root execution → 不写入父 Transcript
  → 主模型下一轮 ContextProjector 只读父 Transcript
  → Interactive Core 仍保留该事件，供本进程内子时间线
```

`task` 的 tool result 仍只含最终文本或稳定错误码（`DELEGATION_TIMEOUT` 等）。

### 7.3 审批

Child HITL 继续走 Host Interaction，`agent_id` / `execution_id` 已有。FIFO 与「子代理 {id} 需要审批」标题不变。Child route 不得把 Interaction 藏起来，也不得要求用户先回到父视图才能点批准。

## 8. 表现层

TUI 与 Web 共用 `timeline-scope` 和同一套 Intent，禁止各写一套过滤规则。

### 8.1 父视图

- 时间线过滤：`execution_id` 缺省或等于父 root 的项才渲染。
- `task` 派出卡片继续用现有任务/结论布局。
- 已绑定 `childExecutionId` 的卡片可点（指针/Enter，具体键位与现有工具卡一致，TUI 另支持鼠标）。
- 未绑定或 child 从未发出过程事件：可点但进入后是空态（「还没有过程」），不得报错崩 UI。

### 8.2 子视图

- 只渲染 `execution_id === childExecutionId` 的思考、工具、文本。
- 工具渲染复用现有 Renderer（文件、命令、Markdown 等），不把 JSON 当默认正文。
- Composer / 发送消息 / 切换 Agent 禁用。滚动、展开工具、复制、返回可用。
- 明确返回：TUI `Esc`（无浮层时）或底栏「返回」；Web 返回按钮或等价。返回后滚动位置尽量留在那张派出卡附近，不做硬性像素验收。
- 多个 child：点哪张卡进哪条。本任务不做 MiMo 式 Prev/Next 循环（非范围，以免扩大交互）。

### 8.3 空态与终态

| 状态 | 子视图 |
|---|---|
| 刚绑定、尚无事件 | 「子代理刚开始」类短空态 |
| 运行中 | 实时追加 |
| 成功 | 过程 + 与派出卡结论一致的最终文本可出现在子视图末尾 |
| 超时/失败 | 保留已有过程，末尾可见失败/超时，不清空 |

## 9. 公开 interface（建议形状，名称可按邻近风格微调）

### 9.1 协议

`toolDeltaPayload` 增加可选 `child_execution_id`、`child_agent_id`。

### 9.2 CLI Interactive Core

```ts
type ToolCard = {
  // 现有字段…
  childExecutionId?: string
  childAgentId?: string
}

function scopeTimeline(
  items: readonly TimelineItem[],
  executionId: "root" | string,
): readonly TimelineItem[]

type PresentTarget =
  | { type: "child-timeline"; executionId: string; agentId?: string }
  // 现有 target…
```

`scopeTimeline("root")` 供父视图；`scopeTimeline(childId)` 供子视图。测试只打这条纯函数和 reducer 绑定，不测像素。

### 9.3 Intent

```text
open-child-timeline { executionId }
leave-child-timeline
```

Web/TUI Adapter 都实现。只读：在 child route 下拦截 send/submit。

## 10. 错误语义

| 情况 | 行为 |
|---|---|
| child 事件缺 `execution_id` | 视为父事件，禁止出现在子视图；不得丢弃 |
| `child_execution_id` 指向未知 id | 卡片不可进入或进入空态，不绑到其他 child |
| 两个 task 并发 | 各自 tool_call_id 绑定，禁止按 agent_id 抢绑 |
| Plugin child 无过程流 | 可进入空态；不得把父工具误显示成该 Plugin 的过程 |
| 子视图下用户按 Enter 发消息 | 忽略发送，不创建新 Run |

## 11. Invariant

1. 父视图时间线不含 child `execution_id` 的工具/思考/文本项。
2. 父 Transcript 与主模型上下文不含 child 过程正文。
3. 子视图不含父 root 的消息和其它 child 的项。
4. 绑定是 `task` tool_call_id → 一个 child execution，一对一。
5. 子视图只读。
6. 审批 FIFO 与 child route 正交：进子视图不 fail-close、不替换当前 Interaction。

## 12. 可观察验收

与 Task 验收一致，补协议级：

- 派出后，父 Event 流里能看到带 child `execution_id` 的 `tool.started`（子代理自己的工具），同时父时间线 UI 不渲染它们。
- 对应 `task` 的 `tool.delta` 含 `child_execution_id`。
- TUI/Web：点卡进入、Esc/返回离开、运行中追加、双卡不串。
- 进子视图时弹出的 child 审批仍可处理。

## 13. 非范围

与 Task 非范围相同。另外：

- 不做 MiMo Prev/Next 子代理循环、token/费用底栏、独立 child Thread。
- 不做历史 Thread 恢复后的子过程重建。
- 不改 300s 超时时长，不把超时改成可配置。

## 14. 测试策略

- Protocol：payload 字段生成与校验。
- Agent：Inline child 发出带身份的 tool 事件；父 Transcript 不含这些事件；`task` 绑定字段存在；ainvoke 路径删除或不再用于生产 child。
- CLI：`scopeTimeline`；reducer 写入 `childExecutionId`；父视图过滤；open/leave child-timeline；child route 下不 dispatch send。
- TUI focused：点派出卡后帧里出现子代理工具名，返回后消失在父帧、派出卡仍在。
- Web focused：同一套 Intent 与过滤。
- 禁止真实模型凭据。
