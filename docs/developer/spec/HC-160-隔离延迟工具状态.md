# HC-160 隔离延迟工具状态 规格说明

## 1. 目标与设计原则

- **链接 Task**：[HC-160 隔离延迟工具状态](../task/HC-160-隔离延迟工具状态.md)
- **单一事实源**：Thread 的 reveal 状态由 `ThreadDeferredToolStore` 管理，生命周期绑定 Host 与 Thread 维度；`RunContext` 负责在单次 Run 中传递上下文。
- **无全局/实例单例状态**：`DeferredToolMiddleware` 实例本身不持有跨 Thread 的可变 `_revealed` 集合。
- **中间件闭环**：`tool_search` 工具本身是无状态函数；中间件在 `wrap_tool_call` / `awrap_tool_call` 层解析 `tool_search` 的返回结果并向当前 Thread 登记 reveal 工具。

## 2. 接口与核心契约

### 2.1 `ThreadDeferredToolStore`
```python
class ThreadDeferredToolStore:
    """按 Thread 隔离并受容量保护的 deferred 工具 reveal 内存存储。"""

    def __init__(
        self,
        *,
        max_threads: int = 1024,
        ttl_seconds: float = 24 * 3600.0,
    ) -> None: ...

    def reveal(self, thread_id: str, names: Sequence[str]) -> frozenset[str]: ...
    def get_revealed(self, thread_id: str) -> frozenset[str]: ...
    def clear(self, thread_id: str) -> None: ...
```

### 2.2 `RunContext`
在 `RunContext` 中增加 `deferred_tool_store: ThreadDeferredToolStore | None = field(default=None, repr=False)`。
当在共享图内运行时，通过 `require_run_context(runtime)` 取得当前 Run 的 `thread_id` 及绑定的 `deferred_tool_store`。

### 2.3 `DeferredToolMiddleware`
- 移除实例属性 `self._revealed: set[str]`；
- 保留可选的 `fallback_store: ThreadDeferredToolStore` 用于无 `RunContext` 的单机/测试场景；
- 在 `wrap_model_call` / `awrap_model_call` 中：
  1. 通过 `request.runtime` 获取 `RunContext`；
  2. 获取当前 Thread 的已 reveal 工具集合；
  3. 计算 `visible_tools = [tool for tool in tools if tool.name in resident or tool.name in revealed]`；
  4. 传递 `request.override(tools=visible_tools)` 给下一层。
- 在 `wrap_tool_call` / `awrap_tool_call` 中：
  1. 若 `request.tool_call.get("name") == "tool_search"`，等待底层 handler 执行完毕；
  2. 解析工具返回值中的 `results` 列表，提取命中的工具名；
  3. 将命中的工具名登记到当前 Thread 的 `deferred_tool_store`。

### 2.4 `create_harness_tools`
- 移除闭包参数 `reveal: Callable[[Sequence[str]], None] | None` 依赖，工具本身只负责检索并返回 candidates。

## 3. 关键不变量 (Invariants)

1. **Thread 隔离不变量**：对任意两个不同的 Thread A 和 Thread B，Thread A 在任何时刻 reveal 的任何工具，绝不会在 Thread B 的模型请求可见工具列表中出现。
2. **Thread 连续性不变量**：在同一个 Thread 中，Run 1 搜索 reveal 的工具，在 Run 2 以及后续该 Thread 的 Run 中默认保持可见。
3. **Fail-Closed 与兼容性**：在没有 `RunContext` 的简单单图/单测调用中，中间件安全降级至局部 fallback store，保证既有简单测试无需额外配置。
