# HC-169 隔离子代理超时规格

关联任务：[HC-169](../task/HC-169-隔离子代理超时.md)

上游：[HC-161](../task/HC-161-内置子代理可用化.md)、[HC-162](../task/archive/HC-162-子代理时间线.md)

用户结果与验收以 Task 为准。本文锁定行为、错误语义和实现 seam；Plan/Todo 不得扩大范围。

## 1. 现状

`AgentDelegator.execute()` 负责 deadline、取消、child execution 终态和资源释放。执行中 timeout 会取消并等待 runner，把 child 记为 `failed`，然后抛出 `AgentDelegationError("DELEGATION_TIMEOUT")`；排队 deadline 耗尽也抛出同一稳定码。

生产 `task` 由 DeepAgents 调用 CompiledSubAgent runnable。`DelegationContextMiddleware` 当前只绑定父 RunContext 和 tool call ID，不处理终态异常，因此 timeout 会离开 ToolNode 并使根 Run 失败。

## 2. 目标流程

```text
task handler
  → AgentDelegator.execute
      → deadline 到期
      → cancel + await runner
      → child failed + release slot
      → raise AgentDelegationError(DELEGATION_TIMEOUT)
  → DelegationContextMiddleware 精确捕获
  → 返回 ToolMessage(status="error", tool_call_id=父 task call id)
  → ExecutionStream 发 TOOL_COMPLETED(is_error=true)
  → 主模型收到错误工具结果并继续下一轮
  → 根 Run 可 run.completed
```

## 3. 唯一转换边界

转换只能发生在 `DelegationContextMiddleware` 的 `task` Tool wrapper：

- 它已经拥有可信的 `tool_call_id`，可以生成合法 ToolMessage。
- 它只影响主 Agent 的 `task` 调用，不改变 Compose/Team 对 `AgentDelegator` 的直接消费。
- `ToolMessage.status="error"` 表达“这次 task 没成功”，但返回对象本身不会终止根图。

禁止在 `RunCoordinator` 全局吞错；禁止把 `AgentDelegator` 所有 timeout 改成成功；禁止仅靠匹配异常字符串。

## 4. ToolMessage 契约

`content` 使用固定、有界、无秘密的文本：

```text
子代理未在执行时限内完成，已终止。

- status: timed_out
- error_code: DELEGATION_TIMEOUT
- 主对话仍可继续；请根据已有信息决定是否缩小任务后重试。
```

要求：

- `tool_call_id` 必须来自当前受控 `task` 请求。
- `status` 必须为 `error`，使现有 ExecutionStream/CLI 投影为失败卡片。
- 不包含任务正文、文件路径、异常正文、模型输出、凭据或内部 traceback。
- 不伪造 partial result；超时前过程只留在已有 child timeline。

## 5. 错误分类

| 终态 | `task` 边界 | 根 Run |
| --- | --- | --- |
| child completed | 现有成功 ToolMessage | 继续 |
| `DELEGATION_TIMEOUT` | error ToolMessage | 继续 |
| 父 `CancelledError` | 原样传播 | cancelled |
| 权限/目标/深度/身份错误 | 原样传播 | fail closed |
| 未知 child/Registry/运行时错误 | 原样传播 | 保持现状 |

如果 timeout 与父取消竞态，父取消不得被包装成可恢复 timeout。

## 6. 排队与执行中 timeout

- 排队 timeout：没有 child 被 accept/start，不发 `child_execution_id`；父卡片只有任务与超时结论。
- 执行中 timeout：child binding 已发出；runner 被取消，Registry 记为 `failed`，原 child timeline 保留且仍可进入。
- 两种情况向主模型提供相同稳定码，当前不新增 `queue_timeout` wire 变体。

## 7. Invariant

1. 硬 timeout、取消和 slot/lease 回收行为不变。
2. child timeout 是 Tool 级错误，不是根 Run 终止条件。
3. 只有精确稳定码 `DELEGATION_TIMEOUT` 可被转换。
4. ToolMessage 的 `is_error` 必须在 TUI/Web 显示为失败；“父 Run 继续”不能伪装成 child 成功。
5. 父 Transcript 只保存 task 的有界超时结果，不吸收 child 私有过程。
6. Compose/Team 不经过该转换边界。

## 8. 测试规格

- Middleware：timeout → error ToolMessage；其它 `AgentDelegationError`、`CancelledError` 原样传播。
- Delegator：执行中 timeout 取消 runner、child failed、slot 可复用；排队 timeout 不启动 child。
- 生产 Agent 纵向：fake model 首轮调用 task，timeout 后第二轮读取 ToolMessage 并返回正文。
- Host：同一 Run 发出失败的 `tool.completed`、后续 `content.delta` 和 `run.completed`，无 `run.failed`。
- CLI：同一事件序列在 TUI/Web 显示失败派出卡、超时结论和后续主回复。
- Compose/Team：既有 timeout 失败测试继续通过。
