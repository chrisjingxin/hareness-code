# HC-170 模型调用自动恢复规格

关联任务：[HC-170](../task/HC-170-模型调用自动恢复.md)

用户结果与验收以 Task 为准。本文锁定行为、错误语义和 seam；Plan/Todo 不得扩大范围。

## 1. 现状与目标

`ManagedAgentExecutor._execute_round_with_retry()` 包住一次 LangGraph stream round，能够记录 `model.started`、`model.failed`、`model.retry_scheduled`，并把等待记入 timing；Build/Compose/child request 现在都从冻结的 Profile 设置得到 provider retry policy。模型 middleware 在 ToolNode 前阻断畸形 `AIMessage.tool_calls`，直接摘要、`/btw` 和分类器等 executor 外调用也复用同一策略 owner。

## 2. 唯一执行流程

```text
model middleware handler
  → 取得 ModelResponse/AIMessage
  → 校验每个 AIMessage.tool_calls
  → 合法：规范化缺失 ID 后返回
  → 畸形：抛 MALFORMED_TOOL_CALL（不返回 graph message）
  → ManagedAgentExecutor 或 direct-call helper 按同一 ProviderRetryPolicy 重试
  → ToolNode、assistant/tool checkpoint 与 Transcript 只接收已确认的完整调用；安全的
    content/reasoning signal 可在模型仍输出时实时投影
```

HTTP/传输异常也在同一 retry loop 中处理。`ChatOpenAI` 的 SDK retry 设为 0；配置的 `ModelSettings.max_retries` 转为 executor 的总 attempt budget（初始调用 + max_retries 次重试），从而只有一个 owner。
正文和 reasoning signal 在 chunk 到达时实时投影；tool signal 等模型节点确认后再投影。
若临时 provider 错误发生在正文/reasoning 已经通过 Ports 公开之后，stream 抛出稳定
`PROVIDER_OUTPUT_INTERRUPTED`，不再次执行该模型回合；已公开的正文/reasoning signal 保留一次，未提交的
capture/session 回滚。工具 signal 在模型调用确认前不会公开，因此这一阶段的失败仍可丢弃并按预算重试。
只有尚未公开正文/reasoning 的失败 attempt 才能按预算自动重试；`PROVIDER_OUTPUT_INTERRUPTED` 仍带
`retryable=true`，只表示用户可修复 provider 后发起新的 Run，不表示当前模型回合会自动重放。

## 3. 模型输出保护接口

新增 `ModelOutputGuardMiddleware`（内部 module）：

- `wrap_model_call` 和 `awrap_model_call` 均调用下一个 handler 一次并校验返回值。
- `ModelResponse.result` 中出现 `AIMessage.invalid_tool_calls`、tool call 不是 mapping、name 不是非空字符串、args 不是 mapping，抛出 `MalformedToolCallError(code="MALFORMED_TOOL_CALL")`。
- 合法 name/args 但 id 缺失时，在 assistant `AIMessage` 返回前补齐一个本响应生命周期内稳定、非空的 ID；不得只改 ToolMessage。
- 具有原始非空 ID 的合法调用原样保留；未知/未授权 name 仍属于合法结构，不在该 middleware 拒绝。
- 普通正文中的 literal `<tool_call>` 不参与 substring 判错；只有结构化 invalid tool call 或字段不满足 contract 才进入 `MALFORMED_TOOL_CALL`。
- handler 的异常原样抛出，不由 middleware 自己重试。

## 4. 重试分类与预算

`BoundedProviderRetry` 是唯一策略实现，供 Build、Compose 和 Managed Plugin 复用：

| 异常类别 | 是否重试 | 说明 |
| --- | --- | --- |
| `MALFORMED_TOOL_CALL` | 条件 | 尚未公开正文/reasoning 时丢弃整个未可信 response 并重试；已有公开正文/reasoning 时收敛为 `PROVIDER_OUTPUT_INTERRUPTED`，终态 `retryable=true` |
| HTTP 429 | 条件 | 尚未公开正文/reasoning 时优先使用 `Retry-After`；无该头时按 attempt 线性退避并封顶 |
| HTTP 500–599 | 条件 | 尚未公开正文/reasoning 时按 attempt 线性、上限退避 |
| 连接/读取超时、连接断开等 transport error | 是 | 仅在 attempt budget 内 |
| 已公开正文/reasoning 后的临时错误 | 否 | 不自动重放模型回合，返回 `PROVIDER_OUTPUT_INTERRUPTED` 且 `retryable=true`；该标记只供用户发起新的 Run，避免重复显示 |
| HTTP 400、401、403、确定性参数错误 | 否 | 立即失败 |
| `CancelledError`、Run cancel、审批拒绝 | 否 | 原样保持取消/拒绝语义 |
| Capability/策略 ToolMessage error | 否 | 是合法模型调用后的业务结果，不进入 provider retry |

`attempt` 从 1 开始；`attempt < max_attempts` 才允许重试。预算耗尽时 executor 抛稳定 `ManagedAgentExecutionError`/RunError，保留安全摘要，不重复发终态。

executor 外的直接模型调用只能通过 `run_with_provider_retry`（同步路径为 sync helper）执行：
`ContextCompactor`、`/btw` side question、AUTO 分类器和 evaluation runner 使用配置的
bounded policy；没有配置来源的嵌入式 classifier 明确使用单次 attempt。模型工厂的 SDK
`max_retries` 固定为 0，防止 direct helper 与 SDK 双重重试。

## 5. ID 与策略不变量

1. 一个 assistant tool call 与其所有 ToolMessage 只能使用同一个非空 ID。
2. Capability policy、workspace boundary、approval policy 不得在缺失 ID 时伪造 fallback ID；缺失 ID 只能在模型输出保护层修复，防御性路径稳定失败。
3. 未授权/未注册工具只要结构合法，使用原 ID 返回 `ToolMessage(status="error")`；主模型可继续，且不增加 provider attempt。
4. 尚未公开模型 signal 的重试前清理当前 stream/session 的临时正文、tool 映射、pending assistant capture 和 usage 增量；该失败 attempt 不产生 wire signal、ToolMessage 或 Transcript 记录。
5. content/reasoning signal 保持实时；tool signal 按 model-call 确认边界提交。已公开正文/reasoning 后的临时失败不得自动重放，返回 `PROVIDER_OUTPUT_INTERRUPTED` 且 `retryable=true`；该标记只表示用户可发起新的 Run，已公开 signal 最多出现一次。
6. 失败模型 attempt 的 Build capture 和 checkpoint 事实仍回滚；已完成 Tool 边界的 canonical 事实保留并可读取。
7. 生成的 retry 诊断只含稳定 code、attempt、round、duration、wait 和脱敏上游类型/摘要，不含 prompt、工具参数、literal tool-call 文本、凭据或 traceback。

## 6. 运行时复用

- Build 根 Run 和 Compose 通过 RunPreparation 冻结 `max_retries`，构造同一 `BoundedProviderRetry`。
- Inline child 和 Managed Plugin 从 resolved agent spec 的 `model_settings.max_retries` 构造同一策略；其 child observer 仍只投影允许的子事件。
- middleware 装配到根图和 Inline child 图；不引入第二套子代理或 HTTP retry loop。
- 不修改 Protocol、SQLite schema、Interaction cardinality、Compose/Team direct delegation 语义。

## 7. 测试规格

- middleware 单测：同步/异步畸形 name/id、ID 生成与合法未知工具；失败响应不返回。
- executor 单测：MALFORMED_TOOL_CALL、5xx、429/Retry-After、transport、预算、取消、确定性错误；断言 timing/diagnostic 和错误摘要脱敏。
- stream/Transcript 纵向：失败响应无 visible signal、pending transcript 或 checkpoint 事实；第二次合法响应正常完成。
- Build root 与 Inline child 各一个 fake model vertical case；未知/未授权工具不 retry。
- Host 终态与 Compose/Managed Plugin/Team 边界回归通过；Team 只收敛成员稳定错误，不创建第二个 provider retry owner。
