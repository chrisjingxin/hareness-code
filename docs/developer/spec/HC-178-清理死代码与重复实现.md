# HC-178 清理死代码与重复实现规格

关联任务：[HC-178](../task/HC-178-清理死代码与重复实现.md)  
全局架构：[架构总览](../architecture/架构总览.md)

用户结果与验收以 Task 为准。本文只规定行为不变式、公开 interface 收敛、错误语义和删除/合并边界；不规定实施步骤。Plan / Todo 必须与本文同名，且不得把 Task 非范围做成范围。

## 1. 通俗目标

生产路径只保留一套 Compose 编排入口（现有 `ComposeSession`）、一套 Skill 注册、一套资源租约。死代码、兼容别名和撒谎文档删掉或改对。用户操作与协议形状不变。

```text
输入：当前仓库里「看起来像能力、实际无生产调用方」或「两套同名类型」
  → 判断：是否属于 HC-155 / HC-152 / HC-108，或是否改变用户行为
  → 执行：无主则删除或合并；有主则写进 Todo 冻结清单，本任务不改
  → 输出：更短的生产树 + 仍绿的 focused tests + 与代码一致的开发文档
```

## 2. 已确认假设

来自已确认 Task，Spec 不得改写：

1. 零用户可感知行为变化。
2. 不改 JSON-RPC、SQLite schema、公开 CLI 命令、错误码。
3. Work Item 引擎不在本任务删除。
4. TUI `file-icons.ts` 不在本任务删除或接线。
5. 迁移仪式与 `thread_persistence.py` 拆分不在本任务。
6. 不拆 `AgentHost` / `settings.py` / 两端 adapter。
7. Todo 必须带「明确不做」冻结清单，执行 Agent 不得勾选推进。

本 Spec 补齐的实现口径：

8. 「生产路径」指 `harness_agent/` 与 `packages/cli/src/` 中能被 `AgentHost` / `runTui` / Web composition root 到达的代码；仅被同文件测试引用视为死代码。
9. 合并重复类型时删除其中一份定义，迁移全部 import，不留 alias 或 re-export。
10. 删除模块时同步删除只为它存在的测试；跨切测试里对死符号的 import 改为活路径或删用例。

## 3. Capability Map 与 module seam

Module ID 是职责标签，不要求同名目录，也不拆成多份 Spec。

| Module ID | 职责 | 外部 interface | 依赖 |
|---|---|---|---|
| `dead-compose-workflow` | 删除 HC-138 五阶段 `ComposeWorkflow` 栈 | 生产不再出现 `ComposeWorkflow` / `ComposeStateMachine` | 无 |
| `dead-cli-shims` | 删除生产 noop gateway 与 Interactive 兼容别名 | `createInteractiveController({ gateway })` 为唯一构造 | 无 |
| `skill-registry` | 单一 `SkillRegistry` 定义与 import | Host / runtime / virtual files 只依赖这一处 | 无 |
| `resource-lease` | 单一共享资源 owner+lease | AgentEngine / MCP / execution pool 只依赖这一处 | 无 |
| `stale-docs` | 删除或改写与代码不符的过程文档 | 开发者打开文档看到的是当前路径 | 上述完成后再改架构表述 |

依赖：

```text
dead-compose-workflow
dead-cli-shims
        ↓（可并行）
skill-registry
resource-lease
        ↓
stale-docs
```

深度要求：

- 调用方不知道曾经存在第二份 `SkillRegistry` 或第二份 `ResourceScope`。
- 测试不得再从兼容路径 import 已删符号。
- 不把「方便以后再接回」的 Protocol / Factory 留在生产模块里，除非它仍有生产 adapter（`RemoteSandboxFactory` 明确不做，仍留）。

## 4. 公开 interface

本任务**不新增**公开 interface。只收敛内部构造与 import。

| 现状 | 目标 |
| --- | --- |
| `createInteractiveController({ gateway?, agent?, runtime?, baseRuntime? })` | 只接受 `gateway` 与 `baseRuntime`（或文档化的现行 canonical 名，二选一，禁止双写） |
| `createFallbackNoopGateway()` 被 Controller 默认调用 | 生产构造必须传入真实 `AgentGateway`；函数若保留，仅测试目录使用 |
| `from harness_agent.extensions.skills import SkillRegistry` 与 `plugin_skills.SkillRegistry` 并存 | 单一模块导出 `SkillRegistry` / `LoadedSkill` / `SkillError` |
| `resource_lifecycle.ResourceScope` 与 `resource_ownership.ResourceScope` 并存 | 单一枚举；`ENGINE` / `agent-engine` 只留一个值 |
| `packages/cli/src/interactive/agent-port.ts` 别名转发 | 删除文件；调用方改 import canonical 名 |

## 5. 状态与错误语义

- 不改变 Run / Thread / Interaction / Plugin 的状态机。
- 不改变任何 JSON-RPC 错误码。
- 构造 `InteractiveController` 时若缺少 `gateway`：TypeScript 类型上即为必填；测试用内存 gateway，不用生产 noop。
- 合并资源租约后，关闭顺序与「borrower 未放完不得 close」的 fail-closed 语义必须保持。

## 6. 关键 invariant

1. **单一事实源：** 每个领域类型（`SkillRegistry`、`ResourceScope`、Compose 编排入口）在生产代码里只有一个定义点。
2. **无兼容 shim：** 删除后不得用 `TypeAlias`、re-export、`options.agent ?? options.gateway` 把旧名接回来。
3. **有主的死代码不动：** 属于 HC-155 / HC-152 / HC-108 的路径，本任务 git diff 不得出现。
4. **测试跟符号走：** 删生产符号则删或改对应测试；禁止留红测试或 skip 充数。
5. **冻结清单不可执行：** Todo「明确不做」不是待办 checkbox，不能在本任务被勾成完成。

## 7. 可观察验收

1. `rg ComposeWorkflow packages/agent/harness_agent` 无命中。
2. `rg "class SkillRegistry" packages/agent/harness_agent` 只命中一个文件。
3. `rg "class ResourceScope" packages/agent/harness_agent` 只命中一个文件。
4. `rg createFallbackNoopGateway packages/cli/src` 不在 `controller.ts` 的生产构造路径上。
5. `rg options\\.agent packages/cli/src` 无命中。
6. 根目录不再有作为过程文档的 `tasks/plan.md` / `tasks/todo.md`（或文件头标明已废止并指向 `docs/developer/`）。
7. focused tests 见 Plan/Todo；`bun run typecheck` 通过。
