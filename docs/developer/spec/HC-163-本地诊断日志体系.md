# HC-163 本地诊断日志体系规格

关联任务：[HC-163](../task/HC-163-本地诊断日志体系.md)  
架构入口：[架构总览](../architecture/架构总览.md)、[配置架构](../architecture/配置架构.md)

用户结果与验收以 Task 为准。本文只规定已确认行为、模块边界、公开 interface、错误语义、性能口径和 invariant。本轮修订人读投影与叙事目录后，同名 Plan / Todo 必须对齐再继续实现。

## 1. 通俗目标

现在 Harness 有一些分散的「诊断」：CLI 有少量同步 JSONL，Python 有自由文本 `logging`，Run 事件和 SQLite 又各自保存业务事实。它们既无法拼成一次完整执行，也不适合直接扩大到热路径。

改完后，代码在真正掌握生命周期的地方继续用普通 logger 写法：

```ts
runLog.info("run.completed", {
  outcome: "completed",
  duration_ms: 8421,
  input_tokens: 12000,
  output_tokens: 530,
})
```

```python
run_log.info(
    "run.completed",
    outcome="completed",
    duration_ms=8421,
    input_tokens=12000,
    output_tokens=530,
)
```

调用方不管文件、轮转或线程；底层完成：

```text
log.debug/info/warn/error
  → 验证事件与字段白名单
  → 补全已绑定的执行 context
  → 脱敏、限长、编码
  → 有界异步队列
  → 后台 writer 写进程独立 JSONL
```

用户通过 `harness logs` 离线查最近 Thread，通过 `harness logs --thread` 看一条对话的**中文友好视图**（准备、各次 Run 章节、失败点、最近一轮过程树、慢项），不是事件名流水账。`harness logs --run` 只放大其中一次 Run；`--flat` 把选中范围改成逐事件中文表格。JSONL 仍是机器存储；`--json` 仍是英文结构化结果。默认输出有界；平铺或 JSON 长结果用 opaque cursor 续页，树形视图不按 event 拆页。

## 2. 已确认决策

1. 一次交付「统一基础设施 + 核心链路事件 + `harness logs --thread` / `--run`」，不只换 logger。
2. TUI、无头模式、实际启动 Agent 的管理命令、Build、Compose、root/child Agent、Plugin、MCP 和 Tool 都在覆盖范围内。
3. 默认记录 INFO/WARN/ERROR；DEBUG 必须可用，但 DEBUG 也不记录业务正文与秘密。
4. 使用 `[diagnostics].level` 持久配置，`HARNESS_LOG_LEVEL` 临时覆盖。不复用为未来远程遥测保留的 `[telemetry]`。
5. CLI 和 Agent 各写自己的文件，但使用同一份跨语言契约；查询时合并，不让两个进程共写文件。
6. 记录路径只做有界入队，不同步写盘。拥塞时先丢 DEBUG、再丢 INFO，为 WARN/ERROR 预留容量。
7. 当前只复用已有 ID 和技术排序字段；不引入 `session_id` / `trace_id` / `span_id`。
8. `harness logs` 只读日志文件，不启动 sidecar、不读 SQLite、不因查询再写日志。
9. 日志目录固定为用户目录下 `.harness/logs`；不双写、不迁移 `~/.harness/debug`，不开放任意日志目录。
10. macOS、Linux、Windows 是同一交付边界；文件占用、路径和权限行为不以 POSIX 假设代替验证。
11. 人读主入口是 `harness logs`（列 Thread）和 `harness logs --thread`（一条对话的中文树形/表格）。`--run` 只放大其中一轮；`--flat` 是逐事件中文表格，和 `--json` 共用 snapshot cursor。树形 human 不按 event cursor 拆页。JSONL 事件名与 `--json` 保持英文契约；不给 JSONL 加自由 `message`，不做 `--follow` / stderr 镜像。
12. 人类稳定身份进 fields：MCP 用配置 catalog 名，Skill 用 catalog id，Hook 用 plugin_id + 事件名，子代理/阶段用 agent_id。fingerprint 可留作关联，human 视图不展示。
13. 叙事完整性优先于事件名全量展示。默认过程树只投影「Agent 知道什么 / 做了什么 / 为何失败或变慢」的章节；`logging.*`、普通 `ipc.request.*`、`persistence.operation.*` 仍落盘，默认不画进树。

## 3. 诊断问题与术语

第一版必须能稳定回答这些问题：

1. 这条 Thread 里各次 Run 的结果如何？最近一次为什么完成、失败、取消或未完成？失败落在哪一步？
2. 时间花在 Model、Tool、Runtime、Context、Persistence、IPC，还是用户 Interaction / retry 等待？慢项是哪几步？
3. 连了哪些 MCP、调了哪个 MCP 工具、执行了哪些 Hook、实际读了哪些 Skill、做了哪种压缩（自动/手动/溢出）？这些步骤发生在哪一次 Run？
4. 子代理或 Compose 阶段如何嵌套在某次 Run 里？
5. 日志 writer、队列、Runtime Pool 或 transport 是否发生降级、丢弃或异常关闭？（`--json` 或 `--event logging` 可见；默认过程树不展开）
6. 能否在不记录业务正文的前提下，关联 CLI / Agent / root execution / child execution？

```text
Diagnostic Event
└─ 一条可删除的本地观察记录。不是 JSON-RPC 业务 Event，不参与恢复。

Diagnostic Log
└─ 调用方使用的 debug/info/warn/error interface，只接受契约事件。

Log context
└─ 通过 child() 绑定的 project/thread/run/execution 等已有身份。

Active segment
└─ writer 正在打开的 `.active.jsonl`；retention 绝不删除或重命名。

Closed segment
└─ writer 已关闭并去掉 `.active` 后缀的 `.jsonl`；可参与 retention。

Snapshot cursor
└─ 包含首页文件水位、过滤指纹和上次排序位置的 opaque token，不是 offset。
```

## 4. 模块与 seam

一项功能只维护本文这一份 Spec。下表是内部模块边界，不是平行文档树。

| 模块 | 职责 | 调用方必须知道的 interface | 依赖 |
|---|---|---|---|
| `diagnostic-log-contract` | 定义 envelope、事件名、级别和每事件字段白名单；生成 TS/Python 类型与 validator | 给定 level + event + fields，能否形成 v1 记录 | 无 |
| `diagnostic-log-runtime` | 提供常规 `log.*`、context 绑定、脱敏、有界队列、后台 writer、轮转与 retention | `child()` + `debug/info/warn/error()` 是非阻塞调用；`close()` 只在生命周期边界有界等待 | contract |
| `diagnostic-log-integration` | 现有生命周期 owner 在其真实开始、终态和失败边界调用 `log.*`；这是接入职责，不是新的集中目录 | 只知道自己的事件与字段，不知道队列/文件 | runtime |
| `diagnostic-log-query` | 离线发现文件、安全解析、按 Thread 或 Run 合并（含过程级无 id 事件）、过滤；默认投影中文树形，`--flat` 投影逐事件中文表格，`--json` 投影英文契约；cursor 只承载平铺事件分页 | `listThreads(query)` / `queryThread(query)` / `queryRun(query)`；不启动 Agent | contract |

深度原则：

- 不建立名为 `execution-instrumentation` 的第二套打点框架。
- 「日志接入点」分布在已有 Run/Model/Tool/Persistence/IPC owner 内，但事件名、字段和级别不分散定义。
- 业务层不得直接 import writer、queue 或 JSONL encoder。
- `harness logs` 只依赖 query + contract，不依赖 runtime，因此查询不会产生新日志。

## 6. `diagnostic-log-contract`

### 6.1 契约版本

Diagnostic Log 契约与 JSON-RPC v3 分开版本化，首版为 `schema_version = 1`。它不进入 `EVENT_TYPES`，不通过 stdio 传输。

每次契约生成同步产生：

- TypeScript event/field 类型、运行时 validator 和 schema digest。
- Python TypedDict/dataclass 或等价类型、运行时 validator 和同一 digest。
- 跨语言 fixture：任一端产生的 v1 记录，另一端必须接受；多字段、错类型、超长必须一致拒绝。

Schema 和事件 `fields` 使用 `additionalProperties: false`。日志不接受任意 `Record<string, unknown>` 或自由 `message`。

### 6.2 Envelope

JSONL 每行一条 UTF-8 JSON object，结构固定为：

```json
{
  "schema_version": 1,
  "timestamp_ms": 1787800000123,
  "level": "info",
  "event": "run.completed",
  "component": "agent",
  "process": {
    "pid": 41230,
    "started_at_ms": 1787799999000,
    "record_sequence": 42
  },
  "project_fingerprint": "<64 lowercase hex>",
  "thread_id": "<optional existing id>",
  "run_id": "<optional existing id>",
  "execution_id": "<optional existing id>",
  "parent_execution_id": "<optional existing id>",
  "agent_id": "<optional existing id>",
  "tool_call_id": "<optional existing id>",
  "event_id": "<optional existing id>",
  "event_sequence": 17,
  "activity_id": "<optional existing id>",
  "rpc_request_id": "<optional existing JSON-RPC id>",
  "fields": {
    "outcome": "completed",
    "duration_ms": 8421
  }
}
```

| 字段 | 规则 |
|---|---|
| `timestamp_ms` | 调用 `log.*` 时的 UTC wall clock，只用于合并展示，不用于跨进程耗时计算。 |
| `process.record_sequence` | 进程内从 1 递增，在入队前分配。即使中间记录被丢弃，也不回退或复用。 |
| `component` | 仅 `cli` / `agent`。Plugin、MCP 和 child Agent 通过事件 + 已有身份表达，不变成第三个 writer component。 |
| `project_fingerprint` | SHA-256（lowercase hex）。输入为平台 API 规范化/解析后的 workspace 路径；原始绝对路径绝不落日志。TS/Python 用共享 fixture 验证算法。 |
| 关联 ID | 只在真实存在时记录。不用空串、`unknown` 或随机新 ID 补齐。 |
| `rpc_request_id` | 仅 IPC 操作边界使用；它是已有 JSON-RPC request id，不是 Trace ID。 |
| `fields` | 按 event 定义的字段白名单；不存在为 DEBUG 特例开放的 `extra` 字典。 |

单条编码后最大 8 KiB（含换行）。输入中可变长安全字段必须在各自契约上限内先截断；仍超限时整条拒绝，记入 `record_too_large` 丢弃计数，不把未验证的半条 JSON 写入文件。

### 6.3 级别语义

| 级别 | 用途 | 典型事件 |
|---|---|---|
| `debug` | 可选内部状态、决策、资源快照；不包含业务正文 | retry 计划、pool 快照、context 策略选择 |
| `info` | 正常生命周期边界和关键耗时 | process/run/model/tool/persistence 完成 |
| `warn` | 已降级或已恢复的异常，用户取消、可重试失败、丢日志 | retry、`logging.dropped`、run cancelled |
| `error` | 未恢复的系统/契约错误或终态失败 | run failed、writer failed、不可恢复 IPC 错误 |

每个事件在 contract 中定义允许级别。TypeScript 在类型上限制；Python 在运行时验证。错误的 level/event/fields 组合不得把异常抛回业务路径：记录 `contract_violation` 计数，并在 writer 可用时合并成一条无原值的 `logging.contract_violation`。测试 adapter 必须能断言计数为零。

### 6.4 错误字段

失败事件只允许：

```text
error_code       稳定业务/边界错误码
error_type       异常类型名，最大 120 字符
retryable        boolean
failure_stage    契约枚举
stack_frames     DEBUG 可选，最多 20 帧，每帧只有 module/function/line
summary_code     有限枚举，不是 exception message
```

Stack frame 不带源码行、绝对文件名或异常原文。如果只有不可安全输出的第三方 message，保留 `error_type` + 边界定义的 `summary_code`。

## 7. `diagnostic-log-runtime`

### 7.1 窄 interface

TypeScript 概念形状：

```ts
interface DiagnosticLog {
  child(context: DiagnosticContext): DiagnosticLog
  debug<E extends DebugEvent>(event: E, fields: DiagnosticFields<E>): void
  info<E extends InfoEvent>(event: E, fields: DiagnosticFields<E>): void
  warn<E extends WarnEvent>(event: E, fields: DiagnosticFields<E>): void
  error<E extends ErrorEvent>(event: E, fields: DiagnosticFields<E>): void
}

interface DiagnosticLogLifecycle {
  reconfigure(settings: EffectiveDiagnosticSettings): void
  close(): Promise<DiagnosticCloseResult>
}
```

Python 提供对等的 `DiagnosticLog.child()` / `debug()` / `info()` / `warn()` / `error()`。Factory 返回 log 和 lifecycle/controller；普通业务模块只拿 log，只有进程 composition root 拿 lifecycle。

`child()` 返回不可变 context logger：子 context 只能增加或用更具体的已有身份覆盖同名字段。不允许 fields 再提供 envelope 关联字段，避免同一事件两个 `run_id`。

### 7.2 非阻塞与有界队列

`debug/info/warn/error` 在调用线程内只执行：级别判断、契约验证、脱敏/限长、补 context、序列化到内存 byte buffer、入队。不打开/关闭/轮转文件，不 `await` 磁盘，不写 stdout/stderr。

每个进程只有一个 writer 和一个队列：

- 总队列上限为 4096 条或 8 MiB，任一先到即视为满。
- 其中至少 128 条且 256 KiB 只为 WARN/ERROR 保留，DEBUG/INFO 不得使用。
- 普通容量满时：新 DEBUG 直接丢弃；新 INFO 先淘汰最旧待写 DEBUG，无 DEBUG 则丢弃 INFO。
- WARN/ERROR 先使用保留容量；全部容量满时依次淘汰最旧 DEBUG、INFO。连保留容量也耗尽时，只增加有界 emergency 计数，不阻塞等待。
- 保留下来的记录仍按 `process.record_sequence` 顺序写入，不因优先级改变时间线。

拥塞恢复后，writer 生成一条合并 `logging.dropped` WARN，字段为级别、原因和数量的有界计数，不为每条丢弃再产生日志。`logging.dropped` 不能通过普通入队路径递归生成自己。

### 7.3 Writer 生命周期

```text
进程启动
  → 解析日志 root 与 bootstrap settings
  → 安全创建目录
  → 以 exclusive-create 打开本进程 active segment
  → 启动单 writer worker
  → log.* 只入队
  → writer 批量追加完整 JSONL
  → 达到单文件上限：关闭 active → rename closed → 再打开新 active
  → 定期/轮转后回收已关闭文件
  → 进程终止：有界 drain → 关闭 → rename closed
```

- 常规 flush 周期不作为 durability 承诺；突然崩溃可丢失尾部尚未落盘记录。Diagnostic Log 不是业务事实源。
- 正常关闭最多等待 2 秒；超时后丢弃剩余队列并关闭主进程生命周期，不无限卡住退出。
- writer 不可用或持续写失败时进入 disabled，不反复尝试每条日志。后台生命周期最多向 stderr 写一条固定、无业务值的安全错误码；Agent stdout 永远不受影响。
- 日志失败不能改变 Run、RPC、Tool 或主进程终态。

### 7.4 文件布局、轮转与 retention

Canonical root：

```text
macOS/Linux: <home>/.harness/logs/
Windows:     %USERPROFILE%\.harness\logs\
```

用户目录必须通过 Node/Python 平台 API 获取，不读取 shell 字符串展开 `~`。文件布局：

```text
logs/
└─ 2026-08-27/
   ├─ cli-1787800000123-41230-0001.active.jsonl
   ├─ cli-1787800000123-41230-0000.jsonl
   ├─ agent-1787800000456-41231-0000.jsonl
   └─ agent-1787800000456-41231-0001.active.jsonl
```

- 文件名只包含 `component`、`process.started_at_ms`、PID 和 segment 序号；不包含 workspace/thread/run/user 文本。同名时 exclusive-create 递增 segment，不覆盖。
- 单文件上限默认 16 MiB。轮转先关闭句柄，再去掉 `.active` 后缀；此顺序必须在 Windows 成立。
- retention 默认保留 14 天，closed segments 目标总量不超过 200 MiB。先删除超时 closed，再按最旧 closed 删到容量内。
- retention 只匹配受控相对路径和严格文件名，不跟随越出 root 的 symlink。单文件失败记计数后继续，不中断 writer。
- retention 绝不删除/重命名 `.active.jsonl`。进程崩溃可留下一个 orphan active；不依赖 PID 枚举、inode、`flock` 或猜测它已不活跃来删除。
- 因 active/orphan 安全例外，root 实际占用可暂时超过 200 MiB；retention 会计入它们的大小并继续删除可删 closed，但绝不为了硬压容量破坏 active 安全。`harness logs` 报告 orphan candidate 数量/字节，本任务不自动删除它们。

POSIX 创建目录 `0700`、文件 `0600`，并对既有对象复核 mode；不能在群组/其他用户可读时继续写。Windows 依赖用户 Profile 目录的 ACL 继承与 runtime 可提供的用户边界；用户文档必须准确说明不将 `0600` mode bit 视为 Windows ACL 保证。如安全边界无法建立，logger 降级 disabled，Harness 主功能继续。

## 8. 配置与启动

### 8.1 TOML 与环境变量

```toml
[diagnostics]
level = "info"
retention_days = 14
max_total_mib = 200
max_file_mib = 16
```

| 字段 | 默认 | 允许值 |
|---|---:|---|
| `level` | `info` | `debug` / `info` / `warn` / `error` |
| `retention_days` | `14` | 1..365 整数 |
| `max_total_mib` | `200` | 16..4096 整数 |
| `max_file_mib` | `16` | 1..256 整数，且不大于 `max_total_mib` |

`HARNESS_LOG_LEVEL` 只覆盖 level，不覆盖保留与容量。优先级：

```text
HARNESS_LOG_LEVEL > [diagnostics].level > info
```

`[diagnostics]` 加入 ConfigManifest implemented section。通过 `config.preview/commit` 的修改标记 `applies_to = restart`；当前不实现双进程热更新。非法值按现有配置错误语义拒绝，但日志 bootstrap 仍以默认/环境 level 启动，不因业务配置失败失去启动诊断。

### 8.2 CLI/Agent 启动对齐

CLI 不引入第二套 TOML parser。启动流程：

```text
CLI 解析 argv
  ├─ 若为 harness logs → 直接 query，不创建 runtime，不启动 sidecar
  └─ 其他实际启动 Agent 的命令
      → CLI 用 env/default 启动 bootstrap DiagnosticLog
      → 启动 Agent
      → Agent 直接用 Python canonical config + env 启动自己的 DiagnosticLog
      → initialize result 返回脱敏 effective diagnostics settings
      → CLI lifecycle.reconfigure，同一 writer/同一 active segment 继续使用
```

JSON-RPC v3 `InitializeResult` 新增 required `diagnostics`：

```ts
type EffectiveDiagnostics = {
  level: "debug" | "info" | "warn" | "error"
  retention_days: number
  max_total_mib: number
  max_file_mib: number
}
```

这是未发版内部契约的 canonical 修改：直接生成 TS/Python 两端，不保留旧形状 fallback。Agent 返回的 `connection.project.id` 也必须在所有命令中是实际 workspace fingerprint，不再因未打开 Thread SQLite 而返回 `"echo"`。计算 fingerprint 不得触发 SQLite 创建/迁移。

Agent 在 initialize 之前的记录已使用真实 Python settings；CLI 在 initialize 失败时保留 bootstrap level，确保启动失败仍可观察。

## 9. 日志接入与事件目录

### 9.1 Canonical owner

| 范围 | 谁写 | 不得由谁猜测 |
|---|---|---|
| CLI process/sidecar | CLI composition root 与 process manager | TUI/Web 视图 |
| IPC client request | `AgentClient` / transport 请求边界 | Run controller |
| IPC server handler | `AgentHost` dispatcher 边界 | Python stdout encoder |
| Run 受理/终态 | `RunCoordinator` | UI 看到 `run.completed` 后反推 |
| Runtime acquire/release | `ManagedAgentExecutor` / pool owner | Model 调用层 |
| Context 建立/压缩 | Context lifecycle owner | Run 总耗时差值 |
| Model round/attempt | 实际 provider 调用边界 | stream consumer |
| Tool 执行 | 实际 tool invocation 边界 | JSON-RPC `tool.completed` 投影 |
| Persistence | ThreadPersistence 稳定公开操作边界 | SQL adapter/每条 statement |
| MCP 连接 | MCP connection owner | 不可信子进程 stdout；不得只记 fingerprint 不记 catalog 名 |
| MCP 工具调用 | 与普通 Tool 同一 invocation 边界，`tool_kind=mcp` 且带 `server_name` | 平行的 `mcp.tool.*` |
| Skill 读取 | 虚拟后端成功读 SKILL.md/资源的 owner | 从 `read_file` 参数或路径反推 |
| Hook 执行 | HookRunner `_invoke` 开始/终态 | 拦截或重定向 Hook/LSP/Monitor 协议流 |
| Catalog 绑定 | Run 受理处，本 Run 实际生效的 Skill/MCP/Plugin 快照 | TUI catalog 刷新 |
| Execution 开场/收场 | child stream / Compose stage owner | UI 时间线反推 |

Model 和 Tool 日志覆盖 root、内置 child 和 Plugin child：通过 `execution_id` / `parent_execution_id` / `agent_id` 区分，不为三种 Agent 复制三套事件。MCP tool 走通用 `tool.*`，另加 `server_name`；MCP 连接生命周期另记 `mcp.connection.*`。Hook 记执行边界，不把 stdout/stderr/payload 写入 Diagnostic Log。

### 9.2 v1 核心事件

事件字段在 schema 中逐个定义；下表是 v1 必须存在的目录。可空数值用 `null`，不伪造成 0。

| `ipc.request.failed` | warn/error | side、method、duration_ms、error fields |
| `ipc.transport.closed` | info/warn/error | side、outcome、pending_requests |
| `run.started` | info | mode、resumed、approval_mode、model_profile_id |
| `run.completed` | info | outcome、duration_ms、active_ms、interaction_wait_ms、retry_wait_ms、first_visible_activity_ms、usage |

| `execution.started` | info | kind（root/child/compose_stage）、agent_id |

| `execution.failed` | warn/error | kind、agent_id、duration_ms、error fields |
| `model.started` | info/debug | model_round、provider_attempt、profile_id |
| `model.completed` | info | model_round、provider_attempt、duration_ms、provider_first_chunk_ms、usage、finish_reason |

| `model.failed` | warn/error | model_round、provider_attempt、duration_ms、error fields |

| `tool.completed` | info | 同上 + outcome、duration_ms、result_bytes、truncated |

`server_name`、`skill_id`、`plugin_id`、`agent_id`、`tool_name` 只允许已解析的 catalog / 配置名，最大 120 字符。`server_fingerprint` 仍是 MCP canonical id 的不可逆 hash，供关联，human 视图不展示。不记 URL、command、args、headers/env、Skill/Hook/Tool 正文或路径。

### 9.3 Python 普通 logging 与 stderr

- Harness 生产代码中已有关键 `logging.getLogger()` 调用迁移到类型化 `DiagnosticLog`；不把 format string 直接写入 JSONL。
- 为 `harness_agent.*` 提供一个受控 stdlib `logging.Handler` adapter，只映射 module、level、exception type 和脱敏 stack，绝不调用 `record.getMessage()` 进入 Diagnostic Log。重要行为仍必须迁移为具名事件，adapter 不是永久自由文本通道。
- 不自动收集所有第三方 logger 原文。Provider/Tool/MCP 的错误在 Harness 边界捕获，用稳定 error fields 记录。
- CLI 对 sidecar stderr 必须持续 drain，不再无上限累积。日志只记 bytes/lines/truncated 计数，不复制原文。退出错误引导用户查看 Agent 日志，不在 CLI 再重放不可信 stderr。
- Plugin Hook/LSP/Monitor 的专用 stdout 协议不属于日志，不拦截、不重定向到 Diagnostic Log。Agent stdout 继续只有换行分隔 JSON-RPC。HookRunner 必须在 `_invoke` 边界写 `hook.*`；这与「不劫持协议流」同时成立，禁止用「不拦截 stdout」省略生命周期事件。

## 10. 性能计时口径

所有 `duration_ms` 使用同一进程内 monotonic clock 的开始/结束差，转为非负整数毫秒。不用两条 `timestamp_ms` 相减得到跨进程耗时。

| 指标 | 开始 | 结束 | 不包含/说明 |
|---|---|---|---|
| Run `duration_ms` | preparation 与 persistence acceptance 完成，Host 真正受理 Run | 终态确定 | 总 wall time，包含受理后的所有等待；不把受理前准备静默计入 Run |
| Run `active_ms` | 每段实际 Runtime/Context/Model/Tool/Persistence 作业开始 | 对应作业结束 | 取该 Run 下 root/child 所有主动执行区间的并集时长，排除 interaction/retry sleep；并发 child 重叠区间只计一次 |
| `interaction_wait_ms` | Interaction 发出 | resolved/rejected/cancelled | 用户思考时间不计入 Model/Tool duration |
| `retry_wait_ms` | 开始实际 backoff sleep | sleep 结束/被取消 | 不包含失败 attempt 本身 |
| `provider_first_chunk_ms` | provider attempt 真正 dispatch | 首个有效 assistant/reasoning/tool-call chunk | 无有效 chunk 为 null；不把连接心跳当首包 |
| `first_visible_activity_ms` | Run 被 Host 受理 | 首个 UI 可投影的 content/reasoning/tool/interaction 活动 | 纯内部 progress/log 不算 |
| Model `duration_ms` | 单个 provider attempt dispatch | attempt 成功/失败/取消 | 每个 `model_round + provider_attempt` 独立 |
| Tool `duration_ms` | 审批完成后真正进入 handler | handler result/error/cancel | 审批等待归 interaction |
| Runtime acquire | 申请 profile | 返回可用 runtime/失败 | 分拆 `queue_ms`、`build_ms`，命中复用时 build=0 |
| Persistence | 公开领域操作进入 | commit/返回/失败 | 不记每条 SQL；operation 枚举 |
| IPC client | frame 交给 transport | response/error/transport close | `run.start` 只到 accepted，不代替 Run duration |
| IPC server | validated request 进入 handler | handler result/error | client/server 分别记 `side` |

Run 的 `active_ms`、`interaction_wait_ms`、`retry_wait_ms` 是解释维度，不承诺三者与并发 child 的各段 duration 简单相加等于总耗时。人类视图明确标注重叠和 wall/active 差别，不制造伪精确。

Usage 字段为 `input_tokens` / `output_tokens` / `cached_input_tokens`，未提供时为 `null`，不用 0 表示未知。Model 事件保存 attempt 级 usage，Run 终态保存已知汇总；两者不互相覆盖。

## 11. 隐私与脱敏 invariant

以下内容在 debug/info/warn/error 任何级别都禁止：

- Prompt、Assistant/Reasoning 正文、源码、文件内容、完整 Tool 参数/结果。
- 完整 shell command/args、工作区绝对路径、用户主目录、URL query、HTTP Header/cookie。
- API key、token、password、credential、环境变量名值对、MCP env/header。
- JSON-RPC raw frame、stdio 原文、第三方 stdout/stderr 原文、SQL statement 及 bind values。
- 任意 exception message 或包含原始输入的 `repr` / `str(error)`。

允许的是：不可逆 fingerprint、catalog 中的安全 ID/名称、稳定错误码/类型、boolean/count/bytes/duration/token usage、约束枚举、不包含路径的脱敏 stack frame。

契约白名单是第一道边界，runtime 还必须做二次防护：拒绝敏感 key pattern、控制字符、过长字符串和非有限数值。二次防护不允许把未知字段「尽量 sanitize 后写入」；未知字段整条视为 contract violation。

## 12. `harness logs` 查询契约

### 12.1 命令形状

```text
harness logs [--json]
             [--limit N]

harness logs --thread <thread-id-or-prefix>
             [--level debug|info|warn|error]
             [--event <event-or-namespace>]
             [--component cli|agent]
             [--limit N]
             [--flat]
             [--cursor <opaque-token>]
             [--json]

harness logs --run <run-id-or-prefix>
             [--level debug|info|warn|error]
             [--event <event-or-namespace>]
             [--component cli|agent]
             [--limit N]
             [--flat]
             [--cursor <opaque-token>]
             [--json]
```

行为：

- 无 `--thread` / `--run`：默认当前 workspace，按最后一条日志时间列出最近 20 个 Thread；`--limit` 可调整 1..1000。不读 SQLite，Thread 标题不可得，只展示 `thread_id` 安全前缀。
- `--thread`：接受完整 ID 或唯一前缀。无匹配返回 `THREAD_NOT_FOUND`；多匹配返回 `THREAD_PREFIX_AMBIGUOUS` 和有界候选前缀。这是人读主视图。
- `--run`：接受完整 ID 或唯一前缀。无匹配返回 `RUN_NOT_FOUND`；多匹配返回 `RUN_PREFIX_AMBIGUOUS`。只放大该次 Run，不替代 `--thread`。
- `--flat`：只与 `--thread` 或 `--run` 一起使用，把默认树形 human 投影切换为逐事件中文表格；不与 `--json` 同时使用。
- `--thread` 与 `--run` 互斥，同时出现返回 `THREAD_RUN_CONFLICT`。
- `--level` 是最低级别，顺序 `debug < info < warn < error`；未给出时最低为 `info`。
- `--event tool` 匹配 `tool.*`；`--event tool.failed` 只匹配完整事件名。不接受 glob/regex。
- `--component` 仅 `cli` / `agent`。不同种类过滤按 AND 组合。
- 第一页默认最多 200 条；`--limit` 最大 1000。完整 stdout（包含 header/footer/JSON metadata）编码后不得超过 256 KiB，输出器必须减少完整 events/flat rows 以保持完整文本/合法 JSON，不得按字节硬切。不提供 `--all`。
- `--cursor` 只允许出现在 `--flat` 或 `--json` 的 Thread/Run 查询。树形 human 视图被条数或字节上限截断时，记录块显示匹配数/已显示数，并给出切换到同选择器、同过滤条件 `--flat` 的命令，不生成 cursor。
- 带 `--cursor` 时选择器（thread 或 run）和过滤参数必须与 cursor 绑定值一致。`--limit` 可调小/调大到 1000，不影响过滤指纹；`--flat` 与 `--json` 可以复用同一 token，因为 cursor 绑定事件 snapshot 而不绑定表现格式。
- `logs` 命令本身不支持 `--config`，不需要 Python 配置。它使用固定 log root 和当前 `--cwd`/进程 cwd 的 fingerprint；如需查另一工作区，使用 `--cwd PATH`。

### 12.2 发现与安全解析

Query 只枚举 log root 下符合严格日期目录 + segment 文件名的普通文件，拒绝越出 root 的 symlink/非普通文件。同时可读 closed 和 active segment，但：

- 首页打开时记下每个文件的字节水位；只读到该水位，不追随后续追加。
- 水位末尾不是换行的半条 JSON 记为 `partial_line_count`，跳过而不报整体失败。
- 单条坏 JSON、契约错误分别计 `malformed_count` / `invalid_count`。不支持的 schema 计 `unsupported_schema_count`，不猜测未知字段。
- 这些计数出现在 human footer 和 JSON metadata，但 query 不把它们写回 Diagnostic Log。

合并排序键固定为：

```text
(timestamp_ms,
 component,
 process.started_at_ms,
 process.pid,
 process.record_sequence,
 source_relative_path,
 source_byte_offset)
```

`record_sequence` 保证进程内顺序；跨进程只能按 wall clock 最佳合并。查询不伪称 CLI/Agent 时钟绝对同步，也不用此排序键计算 duration。

### 12.2.1 关联范围

只按 `run_id` / `thread_id` 过滤会丢掉 initialize 阶段的 MCP 连接等过程级事件。

`--thread` 必须合并：

1. 所有 `thread_id` 匹配该 Thread 的事件（含其中每一次 Run 与子 execution）。
2. **参与过该 Thread 的进程**（至少有一条带该 `thread_id` 的事件，身份为 `component` + `process.pid` + `process.started_at_ms`）里、没有 `thread_id` 也没有 `run_id`、时间戳落在该进程 `process.started` 与 `process.stopped`（若尚未停止则到 snapshot 水位）之间的过程级事件，至少包括：`ipc.initialize.*`、`mcp.connection.*`、`process.stopped`、`logging.stopped`。

同一 CLI/Agent 进程若服务过多个 Thread，这些过程级事件可以出现在每个相关 Thread 视图的「准备」里；不假装每个 Thread 各自重新连接了 MCP。

`--run` 必须合并：

1. 所有 `run_id` 匹配该 Run 的事件。
2. 同一进程里、没有 `run_id`、落在该进程起止之间的过程级事件（同上列表）。`--run` 视图把它们挂在这次放大的「准备」下，便于单独看一轮时仍能看到 MCP。

过滤 `--event` / `--level` / `--component` 在合并之后生效。`--json` 包含同一批事件。

### 12.3 Flat 与 Cursor

`--flat` 按合并排序键逐事件输出；每行独立，不建立父子关系，因此分页不会产生残缺树。宽终端使用 `时间 / 级别 / 来源 / EVENT / 详情 / 耗时` 单行表格，窄终端降级为「时间 + 级别 + 来源 + EVENT」和缩进详情两行。原始 event 名用于精确过滤与排障；详情只由 event + 白名单 fields 生成中文短句，不输出自由 message、原始 JSON、绝对路径或 fingerprint。状态必须保留文字，不能只靠颜色。

示例：

```text
HARNESS LOGS · FLAT
Run       e5c255ea-549f-4a71-a066-fd0234d46481
筛选      INFO+ · 全部组件 · 全部事件

时间          级别   来源   EVENT                       详情                    耗时
14:32:11.204  INFO   agent  run.started                 构建 · 开始                 -
14:32:20.830  INFO   agent  model.completed             回合 #1 · 尝试 #1 · 完成  8.61s
14:32:25.842  ERROR  agent  tool.failed                 MCP github.list_issues…  5.00s

记录
共 437 条 · 已显示 200 条 · 已截断

下一页
harness logs --run e5c255ea-... --flat --limit 200 --cursor <opaque-token>
```

Cursor 是 base64url 编码的版本化、严格验证 token，结构不是公开 API，也不是安全凭据。它绑定：

- cursor 版本和 Diagnostic Log schema 版本。
- `project_fingerprint`、选择器（完整 `thread_id` 或完整 `run_id`，互斥）、规范化过滤指纹。
- 首页发现的受控相对文件名与各自字节水位。
- 已返回的最后一个完整排序键和各源读取位置。

验证规则：

| 情况 | 结果 |
|---|---|
| token 不可解码/超大/字段错误 | `INVALID_CURSOR` |
| Thread/Run 选择器、workspace 或过滤不同 | `CURSOR_MISMATCH` |
| snapshot 文件被 retention 删除、缩小或替换 | `CURSOR_EXPIRED` |
| snapshot 之后文件增长/新建 segment | 忽略新部分，继续原 snapshot |
| 继续页出现上一页记录 | contract/test failure，不允许客户端自行去重 |

Cursor 内的文件名必须再次经过 root containment 和命名白名单，不允许伪造 token 读取任意文件。

### 12.4 Human 输出

默认文本视图是给人看的中文友好投影，不是事件名流水账。JSONL 事件名、fields 名和 `--json` 保持英文。身份（MCP 名、Skill id、工具名、plugin_id、错误码）保持原名，不翻译成另一套 id。MCP、Skill、Hook、Plugin、token 等术语保留英文。

标签由固定中文映射表从 `event` + 白名单 fields 投影，不打印原始 JSON、fingerprint、绝对路径或不可信 message。

终端布局遵循以下 invariant：

- 单列信息架构固定为「产品头 → 摘要 → 失败点（可选）→ 过程 → 慢项 → 记录」，不靠随机空格或事件顺序形成层级。
- 表格按 terminal cell 宽度计算，中文/全角字符占两格，不能用 JavaScript 字符串长度直接 `padEnd`。
- human 输出读取终端列数并限制在 48–120 列；每行不得超过可用列宽，过长安全名使用 `…` 截断。列表在不足 60 列时降级为每 Thread 两行摘要。
- 状态始终保留「完成 / 失败 / 取消」文字，不得只用 ANSI 颜色区分；管道和无色终端仍能完整理解。

#### 列表

`harness logs` 每个 Thread 至少展示：最后活动时间、Thread ID 安全前缀、运行次数、最近一次 Run 的模式与结果、最近一次总耗时。

```text
HARNESS LOGS
最近 Thread · 2

最后活动          THREAD        次数  模式  结果      耗时
2026-08-27 12:01  ab12cd           3  构建  失败     15.8s
2026-08-27 11:40  9f12ab           1  编排  完成     4.20s

提示  harness logs --thread <prefix> 查看详情
```

#### `--thread` 主视图

按顺序输出，允许省略空块：

1. **摘要**：Thread 前缀、运行次数、最近结果。
2. **失败点**：该 Thread 合并时间线中最后一条 ERROR（种类 + 名字 + 稳定错误码 + 耗时 + 所属 Run 前缀）。无 ERROR 则整块省略。
3. **准备**：过程级 MCP / initialize / 目录，挂在 Thread 根上，不属于某一 Run。
4. **各次 Run**：按时间顺序列出。更早的 Run **折叠为一行**（时间、Run 前缀、模式、结果、耗时）。**只展开最近一次 Run** 的过程树（上下文/压缩/模型回合/Skill/Hook/工具/子代理/阶段）。
5. **慢项表**：展开的那次 Run（及准备阶段）中带正数 `duration_ms`、已有明确中文名字且代表实际工作的事件，按耗时降序至多 5 条；排除 `logging.*` / `process.*`、Run 终态汇总、Runtime release 等控制事件，避免总计与明细重复或出现「步骤 0ms」；一条都没有则省略。

```text
HARNESS LOGS
Thread    ab12cd
概览      3 次运行 · 最近失败

失败点
位置      MCP 工具 github.list_issues
原因      TIMEOUT

过程
├─ 准备
│  └─ MCP github               HTTP · 3 工具 · 已连接    3.80s
├─ Run 01  9f12ab30            构建 · 完成               4.20s
├─ Run 02  c0ffee00            构建 · 完成               8.10s
└─ Run 03  e5c255ea            构建 · 失败               15.8s
   ├─ 上下文                   80 消息 · 11430 token      120ms
   ├─ 模型回合 #1 / 尝试 #1    完成                       8.60s
   └─ MCP 工具 github.list…    失败 · TIMEOUT             5.00s

耗时      项目
   8.60s  模型回合 #1 / 尝试 #1
   5.00s  MCP 工具 github.list_issues

查看      更早的运行已折叠 · harness logs --run <run-prefix>
```

折叠行必须能让人知道那一轮的结果和耗时；不把旧 Run 的工具/模型细节画进默认树。查看旧轮过程使用 `--run`。

#### `--run` 放大镜

结构为单次 Run 四块（摘要表、失败点、过程树、慢项），树根是该 Run；准备阶段仍可挂该进程的 MCP 连接。页脚可给回 Thread：`所属 Thread：harness logs --thread <prefix>`。

过程树嵌套规则：

- 无 `thread_id`/`run_id` 的过程级 MCP/initialize 挂在「准备」。
- `catalog.bound` 挂在对应 Run 下。
- `tool` / `hook` / `skill.read` / `interaction` 挂在对应 `model_round`；缺 round 则挂在当前 Run 根下。
- `execution.kind=child|compose_stage` 及其 `execution_id` 下的事件再下一层，中文为「子代理」或「阶段」。
- 默认**不**把 `logging.*`、`ipc.request.*`、`persistence.operation.*`、`runtime.pool_snapshot` 画进树；`--json` 与 `--event` 仍能取到。
- 树节点文案示例：已连接 / 完成 / 失败 / 允许 / 拒绝 / 开始 / 已构建 / 读取 / 自动压缩 / 手动压缩 / 溢出压缩。

树形截断时「记录」块必须显示匹配数和已显示数，并给出保留当前选择器与 filters 的可复制 `--flat` 命令；不得生成下一页 cursor 或从父子节点中间续页。

Windows/macOS/Linux 使用同一套 Unicode 树形字符（`├─` / `│` / `└─`）；不因平台改成事件名 dump。

「记录」块在 discovery/parser 的诊断计数非零时，必须用中文显示损坏 JSON、无效记录、不支持版本、不完整末行和未正常关闭文件；计数全为零时省略该行。

### 12.5 JSON 输出

`--json` 输出一个版本化 object，不是无界 JSONL dump：

```json
{
  "query_schema_version": 1,
  "project_fingerprint": "...",
  "thread_id": "...",
  "run_id": "...",
  "filters": {
    "minimum_level": "info",
    "event": null,
    "component": null
  },
  "summary": {
    "outcome": "completed",
    "duration_ms": 8421,
    "active_ms": 7010,
    "interaction_wait_ms": 0,
    "retry_wait_ms": 1000
  },
  "events": [],
  "matched_count": 437,
  "returned_count": 200,
  "truncated": true,
  "next_cursor": "...",
  "diagnostics": {
    "malformed_count": 0,
    "invalid_count": 0,
    "unsupported_schema_count": 0,
    "partial_line_count": 1,
    "orphan_active_count": 0,
    "orphan_active_bytes": 0
  }
}
```

`events` 是已验证 Diagnostic Event 的受控查询投影，保留稳定 envelope/fields；不加入源文件绝对路径。该形状与 event v1 同由 `diagnostic-log-contract` 生成和验证。

列表查询的 JSON 以 Thread 为行，不展开过程事件。`--thread` 的 `summary` 含 `run_count`、最近 `outcome`，以及有界 `runs` 数组（每项 `run_id` / `outcome` / `duration_ms`，按时间序）。`--run` 的 `summary` 仍是单次 Run 的耗时口径。`thread_id` 与 `run_id` 按当前选择器出现，未选择的为省略而非空串。

### 12.6 命令错误与 exit code

| 情况 | stdout/stderr | exit code |
|---|---|---:|
| 目录不存在/当前 workspace 无日志 | 空列表或 JSON 空结果，非错误；human 用中文说明本工作区暂无日志 | 0 |
| Thread/Run 无匹配/前缀歧义 | `THREAD_NOT_FOUND` / `RUN_NOT_FOUND` / `THREAD_PREFIX_AMBIGUOUS` / `RUN_PREFIX_AMBIGUOUS`；human 用中文有界说明 | 2 |
| 同时指定 `--thread` 与 `--run` | `THREAD_RUN_CONFLICT` | 2 |
| 参数、filter、cursor 无效/过期 | 稳定 code；human 用中文可操作说明 | 2 |
| 日志 root 完全不可读 | `LOG_ROOT_UNREADABLE`；human 中文说明 | 1 |
| 单文件/单行损坏 | 继续输出可用结果，footer/metadata 计数 | 0 |

JSON 错误也使用稳定 object：`{"query_schema_version":1,"error":{"code":"..."}}`，code 保持英文；不把 stack trace 或本地路径写到 stdout。默认文本错误说明用中文。

## 13. 错误和降级语义

| 失败点 | 行为 |
|---|---|
| home/root 不可用 | runtime 返回 disabled log；主流程继续；生命周期最多写一条固定 stderr code |
| queue 满 | 按 DEBUG → INFO 策略丢弃；有界统计；不阻塞 |
| 单条记录契约错误 | 丢弃该条；记 contract violation；不抛回业务 |
| append 部分失败 | 不重写可能已写的半条；关闭 segment，writer disabled；query 跳过半行 |
| rotation rename 失败 | 关闭句柄，该 segment 保持 active 命名；尝试打开新 segment；失败则 disabled |
| retention delete 失败 | 继续其它 closed 文件；不碰 active；不中断 writer |
| close flush 超时 | 返回 timed_out 结果，主进程继续退出 |
| query 遇到未知 schema | 计数并跳过；不将未知形状当 v1 |

## 14. Invariant

1. Agent stdout 只有 JSON-RPC；CLI stdout 只有用户/命令输出。`log.*` 不写两者。
2. 日志写入的成功或失败不能改变业务结果。
3. 业务热路径没有同步文件 I/O，队列与单记录都有界。
4. 两个进程不共写同一 segment；retention 不处理 active segment。
5. JSONL 每条先通过版本化契约；没有自由 extra/message 逃生口。
6. DEBUG 只增加事件，不减少脱敏、字段白名单或大小限制。
7. Diagnostic Log 不进 SQLite，不参与恢复、幂等、配置裁决或 Run 终态。
8. 耗时由 owner 在 monotonic clock 边界计算，不由查询器用 wall timestamp 猜。
9. `harness logs` 完全离线、默认当前 workspace、输出有界、自身不产生日志。
10. Cursor 只服务 `--flat` / `--json` 的平铺事件，绑定首页 snapshot，续页不混入新记录、不用数字 offset、不访问 root 外文件；树形 human 不按 event cursor 拆页。
11. 未通过红线脱敏测试时，功能不得以「调试更方便」为由放行。
12. macOS/Linux/Windows 共用行为契约；仅权限 adapter 允许按平台表达真实能力。

## 15. 代码风格

- TypeScript 和 Python 事件名使用相同 `namespace.terminal_state` 字符串、snake_case fields 和同一 enum value。
- 生产调用只写 `log.info("event", fields)` 这类常规 logger 语义；不在业务代码里手工组 envelope/JSON。
- `child()` 在生命周期身份建立处创建一次，不在每条 event 反复拷贝 ID。
- 终态使用成对事件和 `try/finally`，不只记 started 不记 completed/failed/cancelled/released。
- 事件不写 prose `message`；需要解释的原因加入稳定 `reason_code` 枚举。human 中文句子只存在于 query 投影映射表，不写回 JSONL。
- 类、公开方法、并发/轮转/平台边界按仓库要求写中文 JSDoc/docstring，说明意图。
- 无新依赖为默认选择；若 Plan 证明三平台必须引入文件锁/ACL 库，先回写 Spec 并征得用户确认。

## 16. 测试策略

### 16.1 Contract

- 生成器 deterministic check：schema digest、TS/Python 产物、fixture 没有 drift。
- 每个 event 有最小有效 fixture；级别不匹配、多字段、错类型、NaN/Infinity、超长和敏感 key 有反例。
- TS 生成记录由 Python 验证，Python 生成记录由 TS 验证。

### 16.2 Runtime

- 用 fake clock、fake home、fake/slow/failing writer 验证非阻塞、排序、批量、flush timeout 和 disabled 降级。
- 队列压测覆盖数量/字节双上限、DEBUG → INFO 淘汰、WARN/ERROR 保留和 `logging.dropped` 不递归。
- 轮转测试确认先 close 再 rename；retention 只删 closed，active/orphan 不动；部分失败不阻断主流程。
- POSIX 定向验证 `0700/0600`；Windows 定向验证 path API、已打开 active 不被 retention 触碰、close-before-rename。

### 16.3 Integration

- CLI：TUI、noninteractive、config/skills/plugins 等实际启动 Agent 的命令都创建日志；`logs` 命令不启动 Agent/不创建日志。
- IPC：initialize、普通请求、错误、transport close 有两侧定向测试，stdout 协议纯净。
- Agent：用 mock model/tool/MCP 覆盖 Build、Compose、root、内置 child、Plugin child、Skill 读取、Hook、重试、Interaction、取消、失败和资源释放。
- 性能：fake monotonic clock 精确验证 wall/active/interaction/retry/first chunk/first visible 口径，并发 child 不被错误累加。
- stderr：大量 sidecar stderr 不造成无界内存，日志不含原文，正常/异常退出均 drain。

### 16.4 Query

- 完整 Thread/Run ID、唯一/歧义前缀、`--thread` 与 `--run` 互斥、workspace 隔离、level/event/component AND 过滤。
- `--thread` 列出各次 Run 且默认只展开最近一次过程树；`--run` 放大单次。过程级 MCP 出现在准备层，human 树展示 `server_name` 而不是 fingerprint。
- 200 条/256 KiB 双上限、`--limit` 1..1000、flat/JSON metadata 一致；树形截断引导切换 flat。
- human 默认视图含中文摘要、过程树、失败点/慢项（可空省略）；不得把 `mcp.connection.completed` 这类事件名当作默认展示。
- `--json` 仍为英文契约 object，events 含 envelope/fields，不含中文投影句。
- `--flat` / `--json` cursor snapshot 期间追加、新 segment、过滤改变、文件被删/缩小/替换、不重不漏；树形 + cursor 稳定拒绝。
- active 半行、坏 JSON、无效 v1、未知 schema、symlink/path traversal 和无权限 root。
- `harness logs` 运行前后文件数不增，用 mock process launcher 断言 sidecar 没有启动，用 SQLite spy 断言没有打开。

### 16.5 脱敏红线

用唯一 canary 同时注入 Prompt、Assistant、source、tool args/result、command、absolute path、protocol frame、header、env、secret、exception message 和 stderr；在 INFO 与 DEBUG 两次运行后，扫描所有 CLI/Agent JSONL 与 `harness logs --json`，任一 canary 出现即测试失败。

### 16.6 验证命令

Plan 按停点细化 focused test；整任务至少包含：

```bash
bun run protocol:generate
bun run protocol:check
cd packages/cli && bun test
cd packages/agent && .venv/bin/python -m pytest -q
bun run typecheck
bun run project:check
bun run test
```

macOS、Linux、Windows 需要 CI matrix 或等价的可复现 runner 证据。某项受 sandbox 宿主能力限制时，按仓库规范记录跳过原因，不把权限失败冒充代码缺陷。

## 17. 可演示验收对应

Plan 必须以真实用户可见结果划分停点，不按 CLI/Protocol/Agent 水平分层。Spec 预期最少有以下纵向能力，具体停点数由 Plan 依依赖确定：

1. 运行一次简单命令，CLI/Agent 产生跨语言可验证、异步有界、三平台安全的 process/initialize 日志。
2. 运行 mock Build/Compose/child/MCP 链路，用日志能解释终态与耗时，DEBUG 红线扫描通过。
3. `harness logs` 中文列表最近 Thread；`--thread` 中文树能看出各次 Run、MCP 名、最近一轮的压缩/失败点/慢项，`--run` 可放大某一轮；`--json` 仍可机器分析；过滤/上限/坏记录行为可见。
4. 带 Skill 读取、Hook、子代理或 Compose 阶段的最近 Run，过程树按层级出现对应章节。
5. 造一条超长 Run，用 `--flat --cursor` 稳定翻页；默认树形不被拆开，同时追加日志不改变 snapshot。

## 18. 边界

### Always

- 修改 event/schema 同时再生成并验证 TS/Python 两端。
- 在生命周期 owner 记录开始/终态/失败，耗时用 monotonic clock。
- 用字段白名单与 canary 扫描证明脱敏，不依赖 code review 猜测。
- 保持 stdout 协议/用户输出纯净，保持日志失败不阻断主流程。
- 在三大操作系统验证路径、轮转、active 文件和查询行为。

### Ask first

- 为日志引入新三方依赖、原生扩展、系统服务或平台专用权限。
- 改变默认保留/容量、单页限制、脱敏边界、cursor 快照语义或公开配置字段。
- 实现自动 orphan active 删除，因为这需要新的跨进程活性证据。
- 让 `harness logs` 读取 SQLite、启动 Agent、上传数据或访问 log root 外文件。

### Never

- 不记录 Prompt/源码/Tool payload/command/绝对工作区路径/raw frame/header/env/secret/原始 stderr。
- 不在 Agent stdout 或 CLI 用户 stdout 打日志，不在热路径同步写盘。
- 不用日志作为恢复、幂等、裁决或业务终态依据。
- 不引入 Trace/Span/session、远程 telemetry、OTLP、Perfetto/Chrome Trace、`harness doctor`、自定义日志目录或无界 `--all`。
- 不删除/重命名 active segment，不为了 POSIX 测试通过而声称 Windows 权限/文件占用已验证。
- 不把默认 human 视图做成英文事件名 dump；不加自由 `message` 字段；不实现 `--follow` 或把诊断镜像到 TUI/stdout。
- 不以 Hook/LSP/Monitor 协议流原文换取「更好排障」。

## 19. 非范围

与 Task 一致：不做远程遥测、Trace/Span、SQLite 性能字段、原文诊断包、`harness doctor`、自定义日志目录、无界查询、旧目录迁移/双写/自动清理。不做 `--follow`、stderr 镜像、JSONL 自由 `message`。不默认展开 Thread 内全部历史 Run 的过程细节。

本轮是对已确认 Spec 的增量修订（人读投影与叙事目录）。同名 Plan / Todo 必须随后对齐；实现阶段仍按 Plan 的下一个可演示停点交付。
