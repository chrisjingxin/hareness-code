用户结果与验收以 Task 为准。本文只规定行为、公开 interface、状态、错误语义和 invariant；不规定实施步骤。后续 Plan/Todo 必须与本文同名，且不能扩大为 steer 或下一轮队列。

## 1. 通俗目标

Agent 干活时，用户仍能在输入栏打字并执行**运行时命令**（查看状态、旁路提问、改目标控制面）。普通文字不能塞进正在跑的任务。Esc 只关浮层；取消任务用 TUI 的 `Ctrl+C` 或 Web 的停止按钮。

```text
用户提交 prompt
  → Agent 执行，输入栏保持可编辑
  → 输入以 / 开头
        ├─ 运行时命令 → 立刻执行
        ├─ 禁用命令 → 提示原因，草稿留下
        └─ 未知 /xxx → 本地建议，不送给模型
  → 普通文字 / //转义 → 拒绝，草稿留下
  → Esc → 只关浮层；无浮层则提示取消方式
  → TUI Ctrl+C / Web 停止按钮 → 取消当前任务，草稿留下
```

## 2. 已确认假设

来自已确认 Task，Spec 不得改写：

1. 第一版只放行运行时命令；普通 Enter 既不注入当前 Run，也不排到下一 Run。
2. TUI 与 Web 共用同一张命令表；Web 补最小 BTW 面板，语义与当前 TUI `/btw` 一致（请求-响应，不新做流式协议）。
3. `/quit` 在干活时先确认再退出。
4. 执行中空参 `/goal`、`/plan-view` 用独立浮层，不占审批/问答底部槽；空闲时 GoalDock / PlanDock 不改。
5. Esc 只关界面。TUI 干活时 `Ctrl+C` 一律取消并留草稿；Web 用停止按钮；无浮层 Esc 只提示，不取消。
6. 压缩中白名单仍只放 `/help`、`/status`、`/quit`，本任务不放宽。
7. 不新增 JSON-RPC runtime_input，不改 Agent mailbox。`/btw` 继续 `threads.side_question`；`/goal` 写操作继续既有 queued 语义。
8. 未在能力表标记为执行中可运行的命令，执行中一律禁用（失败关闭）。

## 3. Capability Map 与 module seam

Module ID 是职责标签，不要求同名目录，也不拆成多份 Spec。

| Module ID | 职责 | 外部 interface | 依赖 |
|---|---|---|---|
| `runtime-command-policy` | 命令在 idle / running / compacting 下的可用性与禁用原因 | Registry `availability` + runtime policy | 无 |
| `runtime-submit-router` | 执行中提交：斜杠走 Dispatcher，普通文字拒绝并留草稿 | `input.submit` / `command.execute` 的 IntentOutcome | `runtime-command-policy` |
| `runtime-key-arbitration` | Esc 只关浮层；取消任务换键；提示文案 | TUI shortcut 与 Web keyboard intent | 无 |
| `runtime-inspect-overlay` | 执行中空参 `/goal`、`/plan-view` 的独立浮层；审批到来时让位 | Adapter overlay snapshot，不进入 Interaction Dock | `runtime-submit-router` |
| `runtime-web-btw` | Web 最小 BTW 面板，复用既有 side-question 效果 | 与 TUI 相同的 `side-question` PresentationEffect | `runtime-submit-router` |

依赖只能沿下列方向：

```text
runtime-command-policy
        ↓
runtime-submit-router
        ↓
runtime-inspect-overlay
runtime-web-btw

runtime-key-arbitration   （与上列并行，不依赖 submit）
```

深度要求：TUI/Web 不得各自计算「这条命令能不能在 running 时跑」。Adapter 只解释 snapshot 里的 `availability` 和 PresentationEffect。子命令差异（`/teams generate`、`/plan <目标>`）留在 Dispatcher，不泄漏到表现层。

## 4. 术语

```text
运行时命令
└─ 执行中允许立刻处理的 Slash Command：本地查看、旁路问答、已规定会排队的控制面、带确认的生命周期。

执行中 / running
└─ InteractiveSnapshot.activeRun 非空。压缩中不是执行中。

独占底部槽
└─ 审批 / 目录信任 / 问答 / 计划审批 / Goal 审核（GoalDock）。与输入栏互斥。

独立浮层
└─ 盖在时间线之上，不替换输入栏。键盘在打开时由浮层消费；关闭后焦点回输入栏。

未知斜杠
└─ 以单个 / 开头、Registry 无法解析的输入。只产生本地 notice，永不 startRun。
```

## 5. 运行时命令能力表

这是执行中放行/禁用的唯一事实源。菜单、手输、Web 提交都读 Registry，不在页面里写 `if (running)`。

删除未使用的 `allowedDuringRun?: boolean`。改为显式 policy：

```typescript
/** 命令在主 Run 进行中的策略；缺省视为 blocked（失败关闭）。 */
export type CommandRuntimePolicy = "allowed" | "blocked"

export type CommandSafety = {
  runtime?: CommandRuntimePolicy
  confirmation?: "never" | "when-running" | "always"
}
```

`CommandRegistry.availability` 在 `context.activeRun === true` 时：

1. 仍先处理 capability / workMode / thread / workItem / reverted。
2. `requirements.requiresIdle === true` 或 `safety.runtime !== "allowed"` → `{ state: "disabled", reason: "当前任务结束后可用" }`。
3. 否则 `available`。

压缩中（`pendingOperation` / activity compacting）保持现有白名单：只允许 `system.help`、`system.status`、`system.quit` 的 `command.execute`；其余失败关闭。压缩中的 `/quit` 不要求「中止当前任务」确认（没有可中止的 Run）。

### 5.1 执行中 allowed

| ID | 名称 | confirmation | 执行中行为 |
|---|---|---|---|
| `system.help` | `/help` | never | 本地 help notice |
| `system.status` | `/status` | never | 打开 Status 浮层；必须允许 `present: status` |
| `assist.btw` | `/btw` | never | 有问题 → `side-question`；空参 → 用法 notice |
| `goal.manage` | `/goal` | never | 空参 → 执行中独立浮层；写操作走既有 Goal 控制面（可 queued） |
| `approval.plan` | `/plan` | never | 空参/`exit` 只改下一轮档位；带目标且 running 时只切档、不 `submit-prompt`（保持现有降级） |
| `approval.plan-view` | `/plan-view` | never | 有挂起计划审批则聚焦；否则执行中独立浮层只读 |
| `mcp.manage` | `/mcp` | never | 只读刷新 catalog；增删 MCP 的独立 intent 仍 busy 拒绝 |
| `agents.list` | `/agents` | never | 只读 picker；选中即关闭，不派发。必须允许 `present: agents` |
| `teams.manage` | `/teams` | never | `list/show/status/cancel` 立刻 RPC；`generate`/`run` 在 Dispatcher 拒绝，notice「当前任务结束后可用」，草稿保留 |
| `thread.new` | `/new` `/clear` | when-running | 现有确认框；确认后先取消再新建 |
| `system.quit` | `/quit` `/q` | when-running | **新增**：running 时确认「当前任务将被中止」；取消确认则继续跑 |

未知斜杠不是 Registry 项，但执行中路径与空闲相同：`unknownCommandNotice`，accepted，不 startRun。

`Shift+Tab` 不是 Slash Command，执行中仍可改下一轮审批档（现有行为）。

### 5.2 执行中 blocked

菜单显示禁用原因；手输或提交返回同一句 `/{name} 暂不可用：当前任务结束后可用。`；**草稿必须保留**（`input.submit` 为 `rejected`，adapter 不得 `clearDraft`）。

| ID | 名称 | 现有标记 |
|---|---|---|
| `context.compact` | `/compact` | `requiresIdle` |
| `thread.resume` | `/resume` `/continue` `/threads` | `requiresIdle` |
| `thread.undo` | `/undo` `/rewind` `/rollback` | `requiresIdle` |
| `thread.redo` | `/redo` | `requiresIdle` |
| `model.select` | `/model` `/models` | `requiresIdle` |
| `host.web` | `/web` | `requiresIdle` |
| `skills.open` | `/skills` | 本任务标 `runtime: blocked` |
| Skill 菜单项 `/skill:<id>` | 武装下一轮 Skill | 执行中不可选；提示任务结束后可用 |
| Plugin Command | 本质 `submit-prompt` | 已有 `requiresIdle` |
| `compose.new-work` | `/new-work` | 本任务标 `runtime: blocked` |
| `compose.abandon` | `/abandon` | 本任务标 `runtime: blocked` |

`/teams generate`、`/teams run` 不是独立 Registry 项，由 Dispatcher 在 running 时拒绝。

`!` Shell：执行中禁止切入；若因竞态已在 Shell，Esc 先退回 chat，不取消任务；Shell 提交按普通文字拒绝。

普通文字与 `//` 转义文本：`rejected`，`code: "busy"`，稳定中文：`当前任务进行中，完成后发送，或用 Ctrl+C 中断后再发送。`（Web 末句改为「或点停止中断后再发送。」）

### 5.3 `present` 不再一刀切

Controller 今日对任意 `present` 在 `activeRun` 时拒绝。改为：

```text
present.target 属于 { status, agents } → 执行中允许
其余 present（models, skills, threads, undo）→ 仍 busy 拒绝
```

`/mcp` 不走 `present`，保持刷新 catalog。`/help` 走 notice。Goal / plan-view 不走 `present`，见第 8 节。

## 6. 提交路由

唯一入口仍是 `input.submit` 与 `command.execute`。表现层不得在 Adapter 里因 `activeRun` 直接 `return` 掉整次提交。

```text
handleSubmit(raw)
  → 解析 Slash
      命令 → dispatchSlashCommand（availability 已含 running）
             rejected/disabled notice 时 outcome.status = accepted（notice）或 rejected（禁用且须留草稿）
      未知 → notice，accepted，不清草稿也可清（未知命令 accepted 后可清；禁用命令必须留）
      转义或普通文字
          running 或 compacting → rejected busy，留草稿
          否则 startRun
```

禁用命令的手输：Dispatcher 已返回 notice 且 `accepted` 的现状会清草稿。本任务改为：**availability.state === "disabled" 时 IntentOutcome 为 rejected**，adapter 只展示 `outcome.message`，不清草稿。未知命令仍 accepted + notice，可清草稿（与空闲一致）。

菜单选中：

- `disabled` → 提示原因，留草稿，不执行。
- 执行中 `available` 且无必填参数 → 立刻 `command.execute`（与今日 TUI running 半截路径一致）。
- 执行中 `available` 但用户还要补参数（如 `/btw`、`/goal pause`）→ 用户手输完整行再 Enter；菜单点选 `/btw` 空参则用法 notice，可接受。

`submit-prompt` 在 `activeRun` 时必须 rejected（`startRun` 已有 busy）。任何漏标的命令撞上这条也不得新开 Run。

## 7. 键盘与取消

### 7.1 Esc 只关界面

优先级（高 → 低），命中即停：

1. 确认 Dialog、Undo Dialog
2. BTW / Status / 执行中 Goal 查看 / 执行中 Plan 查看
3. 命令菜单、提及菜单、只读 picker
4. 子时间线 → 退回主对话（现有）
5. Shell 模式 → 退回 chat（现有）
6. 审批 / 问答 / 计划审批 / Goal 审核 Dock → 仍由 Interaction 自己处理（shortcut 返回 `none`）
7. **执行中且无以上浮层：不取消任务**；TUI toast/notice「中断请用 Ctrl+C」；Web toast/notice「中断请点停止」
8. 空闲无草稿 → 现有 clear-selected-skill

禁止：执行中无浮层时 `escape` → `cancel-run`。Web `web-app.tsx` 全局 Esc 链和 Composer `Escape && activeRun` 都必须去掉取消。

### 7.2 取消任务

| 端 | 动作 | 草稿 |
|---|---|---|
| TUI 执行中 | `Ctrl+C` **无论是否有草稿** | 保留 |
| TUI 空闲 | 保持现状：有草稿则清空，无草稿则退出 | — |
| TUI Windows 有选区 | 仍优先复制选区，不取消 | — |
| Web 执行中 | 停止按钮 | 保留 |
| Web 执行中 Esc | 不取消 | 保留 |

`/quit` running：发 `request-confirmation`（新 confirmationId，如 `quit-while-running`）。确认 → `request-exit`（宿主退出过程会拆掉 sidecar，等于中止）；取消确认 → 继续跑。不得在未确认时 `request-exit`。

### 7.3 文案

TUI/Web 执行中 placeholder 与进度提示不得再写「Esc 中断 / Esc 可中断」。

- TUI：`正在执行；Ctrl+C 中断`
- Web：`正在执行；点停止中断`

用户文档快捷键表同步：Esc = 关闭浮层或菜单；执行中取消 = Ctrl+C / 停止按钮。

## 8. 执行中独立浮层

### 8.1 空参 `/goal`

空闲：保持 GoalDock（只读 viewer）。  
执行中：Adapter 打开独立浮层，展示与今日 Goal 只读投影相同的 objective / criteria / status / revision；**不**写入 `interaction`，不占底部槽。

Esc / Enter / q 关闭浮层，焦点回输入栏，Run 继续。

### 8.2 `/plan-view`

有挂起 `interaction.plan`：仍 `focus-plan`（底部本就是计划审批）。  
执行中且无挂起计划审批：独立浮层展示计划正文；关闭键同上。  
空闲且无挂起：可保持今日 PlanDock / 现有 viewer。

### 8.3 审批让位

`pendingInteraction` 变为审批 / 目录信任 / 问答 / 计划审批 / Goal 审核时：

1. 关闭执行中 Goal/Plan/Status/BTW 浮层（BTW 请求按今日语义丢弃响应）。
2. 底部交给对应 Dock。
3. 不得让查看浮层挡住 Interaction。

Status 浮层今日已是 overlay；执行中允许打开，同样在 Interaction 到来时关闭。

### 8.4 Web BTW

Web Adapter 解释既有 `side-question` 效果，维护与 TUI 同构的面板状态：`loading | ready | error`、问题、回答、关闭、复制。不写主 Transcript。Esc 关面板。空参用法 notice 与 TUI 相同。

## 9. 输入栏焦点

TUI `InputBar`：`activeRun` **不再**导致失焦。失焦条件只剩：压缩中、picker/独占 Dock 打开、页面不该输入。

Web：去掉 `submit()` 里 `Boolean(interactive.activeRun)` 的整段丢弃。改为把 draft 交给共享 Core；由第 6 节路由决定 accepted / rejected。`composedDisabled` 仍包含 leaving、断线、submitting、compacting。

独占底部槽打开时两端都不得把输入栏当提交面（现有 BottomArea 互斥保持）。

## 10. 错误语义

| 情况 | IntentOutcome | 草稿 |
|---|---|---|
| 普通文字执行中 | `rejected` `busy` 中文提示 | 保留 |
| 禁用命令 | `rejected` `busy` `/{name} 暂不可用：当前任务结束后可用。` | 保留 |
| `/teams generate\|run` 执行中 | 同上 | 保留 |
| `submit-prompt` 撞上 activeRun | `rejected` `busy` | 保留 |
| 未知斜杠 | `accepted` + notice | 可清空（与空闲一致） |
| `/btw` 空参 | `accepted` + 用法 notice | 可清空 |
| `/quit` 未确认 | 打开 confirmation，accepted | 可清空命令行 |
| 取消 Run 成功 | `accepted` | **必须保留** |
| side-question 失败 | BTW 面板 error，主 Run 不受影响 | — |

不得把禁用命令或普通文字当模型消息追加到 Transcript。

## 11. Invariants

1. 一条用户提交要么成为运行时命令副作用，要么被拒绝留在草稿，要么（空闲时）成为新 Run；执行中不得 `startRun`。
2. `/btw` 不写 Transcript、SQLite、Goal rubric、Compose ledger；不占用主 Run abort controller。
3. `/goal` 写操作不取消当前 Run，不修改该 Run 已冻结的 revision。
4. Esc 在执行中无浮层时副作用为零（仅提示），不得 `run.cancel`。
5. 执行中 `Ctrl+C`（TUI）或停止按钮（Web）取消后草稿与取消前一致。
6. 命令能不能跑只由 Registry + Dispatcher 决定；TUI 与 Web 结果相同。
7. 未标 `runtime: "allowed"` 且未 `requiresIdle` 的新命令，执行中默认禁用。
8. 审批 Dock 的优先级高于一切查看浮层。

## 12. 测试策略

包：`packages/cli` 的 focused tests。禁止真实模型。

| 层 | 覆盖 |
|---|---|
| Registry | running 时 allowed/blocked/requiresIdle 的 availability；Plugin 仍 disabled |
| Dispatcher | `/teams generate\|run` running 拒绝；`/plan <目标>` running 不 submit-prompt；`/quit` 产生 when-running confirmation |
| Controller | 普通文字 running → rejected 留草稿语义；`present status/agents` 允许；`present models` 拒绝；`input.submit` `/status` accepted |
| TUI shortcut | 无浮层 Esc ≠ cancel-run；有草稿 Ctrl+C = cancel-run；浮层 Esc = 关闭 |
| Web keyboard | Esc ≠ cancel-run；submit 在 activeRun 时仍派发 Core；停止按钮仍 cancel |
| Adapter | 执行中空参 `/goal` 打开 overlay 而非 GoalDock；pending 审批时 overlay 关闭 |

## 13. 非范围

- steer / follow-up 队列、`expected_run_id`、mailbox
- 改空闲 GoalDock / PlanDock
- 放宽压缩中白名单
- 运行中热切换模型、工作模式、Thread
- 运行中武装 Skill、切入 Shell、Handoff、压缩、undo/redo
- 新的 side_question 流式协议
- 为 Web BTW 做与 TUI 不同的持久化或工具权限

## 14. 可观察验收

与 Task 验收 1–10 条一一对应。Spec 不新增产品范围。实现完成前必须更新 `docs/user/交互使用.md` 快捷键与 Slash 说明，以及 `斜杠命令体系.md` 中「执行中的 run 不允许…」那一句：改为指向本能力表，而不是整栏禁用输入。
