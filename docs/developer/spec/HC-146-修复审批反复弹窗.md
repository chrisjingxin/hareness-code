# HC-146: 修复审批反复弹窗 —— 规格说明书 (Spec)

> 原始任务：[HC-146](../task/archive/HC-146-修复审批反复弹窗.md)

---

## 1. 通俗说明与问题背景

### 现状与问题
用户在 `auto-edit` 或 `auto` 模式下进行编码工作时，遇到频繁弹出的工具审批窗口（尤其是 `execute` 命令与 `delete_file`）。即使点击了「本项目允许」或「本会话允许」，稍有变化的后续命令依然会反复弹窗：
1. **只读 Shell 快放仅限 Default 模式**：`ls`、`cat`、`git status`、`git diff` 等只读安全命令在 Default 模式下能被 L3.1 白名单自动放行，但在更自动化的 `auto-edit` 与 `auto` 模式下，预检代码只对 `approval_mode == "default"` 开放该快放，导致在更自动的模式下只读命令反而频繁弹窗。
2. **批准解释器等于没批准（生成空规则）**：`python`、`node`、`bun` 等解释器被放入了 `BARE_ROOT_FORBIDDEN` 裸根禁令中。当用户对 `python -m pytest tests/foo.py` 点击「本项目允许」时，解析器在遇到开关 `-m` 截断后只剩裸根 `python`，触发禁令返回空规则 `""`，导致没有规则被保存，下次换测试文件执行时继续弹窗。
3. **启发式子命令把普通操作数/路径固化进规则**：解析器使用 `^[A-Za-z][A-Za-z0-9_-]*$` 正则来猜测子命令，把 `ls packages` 中的 `packages` 误当成子命令，生成了 `ls packages` 这一死规则，后续执行 `ls docs` 无法命中。
4. **Auto 模式分类器未默认接通主模型**：用户未在配置文件中专门指定 `[approval] classifier` 时，Host 不会实例化 `classifier`，F4 层直接返回 `ask` 占位，导致 Auto 模式对每条未决 Execute 命令都弹窗，未达到「AI 自动判断」的预期。
5. **AutoEdit 下工作区内非敏感删除仍每条都问**：AutoEdit 模式下文件编辑会自动执行，但文件删除（`delete_file`）仍被当作 `ask` 处理，即使删除的是普通临时文件也会打断用户。

### 改造后的预期变化
- 在 `auto-edit` 与 `auto` 模式下，所有只读安全命令（`ls`、`cat`、`git status`、`git diff` 等）直接执行，不再弹窗。
- 工作区内非敏感的普通文件删除在 `auto-edit` 模式下与编辑同权，直接执行；敏感路径删除（如 `.git/config`、`.github/workflows/`）依然强制弹窗。
- 对解释器命令（`python -m pytest tests/foo.py`、`bun test` 等）选择「本项目允许」后，沉淀解释器根规则，后续执行不同测试文件不再弹窗；同时安全底线依然守卫剩余参数。
- 非解释器命令按已知子命令表提取规则（`ls packages` 生成 `ls`，`git commit -m x` 生成 `git commit`）。
- Auto 模式在未单独配置专用 classifier 时，默认使用当前 Run 的主模型作为安全分类器；分类失败或超时时安全回退人工弹窗，绝不自动放行。

## 2. 目标与非目标

### 目标
1. 将 Shell 安全命令快放（L3.1）从 `approval_mode == "default"` 扩展到除 `plan` 外的所有模式（即 `approval_mode != "plan"`）。
2. 将解释器根（`python`, `python3`, `node`, `bun`, `deno`, `ruby`, `perl`, `php`, `bash`, `sh`, `zsh`, `powershell`, `pwsh`, `cmd`）移出 `BARE_ROOT_FORBIDDEN`，允许生成裸根前缀规则；危险根命令（`rm`, `del`, `mv`, `cp`, `chmod`, `dd`, `curl`, `wget`, `ssh`, `docker` 等）依然严格禁止生成裸根规则。
3. 引入已知子命令表机制（对齐成熟竞品实现），对于没有子命令的工具（`ls`, `cat`, `echo`, `touch` 等）丢弃位置参数生成根规则；对于有已知子命令的工具（`git`, `npm`, `docker`, `kubectl` 等）仅保留有效子命令。
4. Auto 模式分类器（`SafetyClassifier`）默认可用：未配置 `[approval] classifier` 时，自动采用当前 Run 的主模型（`model`）实例进行初始化。
5. AutoEdit 模式在工作区内非敏感路径上对 `delete_file`（`ToolKind.DELETE`）自动放行。
6. 补齐对应单元测试与集成测试，并更新用户文档与架构文档。

### 非目标
1. 不把 AutoEdit 变成对 Shell 命令的 YOLO 模式：有副作用的 Shell 命令第一次执行时依然需要审批。
2. 不修改 `plan` 与 `yolo` 的核心语义：`plan` 模式依然拒绝所有写与执行操作；`yolo` 模式依然免除全部弹窗。
3. 不为 `rm`、`del`、`curl`、`wget`、`docker`、`ssh` 等危险根命令开放裸根规则。
4. 不修改用户的 `.harness/settings.json` 历史存量数据，不强制前端弹窗预览生成的规则。
5. 不修改跨进程协议中的审批选项与 TUI/Web 按钮文案。

## 3. 详细架构设计与流程

### 3.1 权限决策与预检流水线

```text
工具调用 (tool_name, tool_args)
  │
  ├─► [1] 工作区边界越界 / L2 deny 规则: 直接拒绝 (fail closed / deny)
  │
  ├─► [2] L3 只读工具 (read_file, ls, glob, grep, lsp 等): 自动放行 (allow)
  │
  ├─► [3] L3.1 只读 Shell 安全白名单 (is_safe_command):
  │         条件: approval_mode != "plan" 且 tool_name == "execute"
  │         逐段检查 is_safe_command && 未触及安全底线 ──► 自动放行 (allow)
  │
  ├─► [4] L3.5 敏感路径保护 (requires_safety_check):
  │         所有非 yolo 模式 ──► 强制审批 (ask)
  │
  ├─► [5] L4 已保存 allow 规则匹配 (evaluate_tool_rules):
  │         命中 allow 且通过剩余参数安全底线检查 ──► 自动放行 (allow)
  │
  ├─► [6] auto-edit 模式工作区内文件操作:
  │         tool_name 为 write_file / edit_file / delete_file
  │         且非敏感路径 ──► 自动放行 (allow)
  │
  ├─► [7] auto 模式 F4 LLM 分类器 (AutoClassifierMiddleware):
  │         优先使用配置的 classifier profile，未配置则使用当前主模型
  │         分类结论为 allow ──► 自动放行 (allow)
  │         分类结论为 deny ──► 硬拦截 (deny)
  │         分类结论为 ask / 超时 / 异常 ──► 回退人工审批 (ask)
  │
  └─► [8] 其余场景:
            触发人工审批弹窗 (ask)
            用户若选择「本项目允许」或「本会话允许」:
              → 解释器生成裸根规则 (如 python, pytest, node)
              → 已知子命令工具生成子命令前缀规则 (如 git commit, npm run build)
              → 无子命令工具生成根规则 (如 ls)
              → 危险命令拒绝生成裸根规则 (如 rm foo.txt 不生成规则)
```

## 4. 关键模块接口与改动规格

### 4.1 `packages/agent/harness_agent/policy/approval_policy.py` & `agent.py`
#### L3.1 只读 Shell 快放放宽
- **变更前**：
  ```python
  if tool_name == "execute" and approval_mode == "default":
  ```
- **变更后**：
  ```python
  if tool_name == "execute" and approval_mode != "plan":
  ```
- **语义保证**：`plan` 模式由 `PlanModeMiddleware` 严格拦截，不进入 L3.1；`yolo` 模式本身不产生审批；`default`、`auto-edit` 和 `auto` 模式均享受只读命令（`ls`, `cat`, `git status`, `git diff`, `pwd` 等）免弹窗。

#### AutoEdit 模式放行 `delete_file`
- **变更前**：
  ```python
  if approval_mode == "auto-edit" and get_tool_kind(tool_name) is ToolKind.EDIT:
      return False
  ```
- **变更后**：
  ```python
  if approval_mode == "auto-edit" and get_tool_kind(tool_name) in (ToolKind.EDIT, ToolKind.DELETE):
      return False
  ```
- **敏感路径保障**：前序的 `sensitive = requires_safety_check(tool_name, tool_args)` 处于此分支之前，如果目标属于受保护文件（如 `.git/*`、`.github/workflows/*`）依然会触发 `return True` 弹出确认。

#### `extract_command_rule` 提取规则行为矩阵：
1. **解释器命令**：
   - 如果根属于 `INTERPRETER_ROOTS`（例如 `python`、`node`、`bun`、`pytest`）：
     - 若后跟 `-m <module>`（如 `python -m pytest tests/foo.py`），生成 `python -m pytest` 或根规则 `python`；
     - 若后跟脚本名或参数，生成 `python` / `node` 裸根规则；
     - 允许裸根规则作为前缀匹配生效。
2. **已知带子命令的工具**：
   - 检查 `tokens[1]` 是否在 `KNOWN_SUBCOMMANDS.get(root, set())` 中：
     - 若是子命令：保留 `root + token[1]`（例如 `git commit -m ...` → `git commit`，`npm install ...` → `npm install`）；
     - 若子命令属于转发类（`run`, `exec`, `x`, `dlx`）且紧随其后有非 flag 词（如 `npm run build`），进一步保留为 `npm run build`；
     - 若第 2 个 token 不是已知子命令（例如 `git` 后面跟了个未识别的参数），则仅保留 `root`（或在安全允许下处理）。
3. **无子命令的标准命令**：
   - 如 `ls`, `cat`, `echo`, `mkdir`, `grep`, `dir`, `type`：
     - 其后的任何参数或路径不当作子命令，直接生成根前缀规则（如 `ls packages` → `ls`，`dir /b foo` → `dir`）。
4. **危险命令防护**：
   - 如 `rm foo.txt`，经处理后只剩裸根 `rm`，因 `rm` 属于 `BARE_ROOT_FORBIDDEN`，返回空串 `""`，不生成规则。

### 4.3 `packages/agent/harness_agent/host/agent_host.py`
#### Auto 模式分类器默认接通主模型
- **变更前**：
  ```python
  classifier = None
  if approval_mode == "auto" and spec.execution.approval_classifier:
      classifier = self._build_approval_classifier(spec.execution.approval_classifier)
  ```
- **变更后**：
  ```python
  classifier = None
  if approval_mode == "auto":
      if spec.execution.approval_classifier:
          classifier = self._build_approval_classifier(spec.execution.approval_classifier)
      if classifier is None and model is not None:
          from harness_agent.policy.classifier import SafetyClassifier
          classifier = SafetyClassifier(model)
  ```
- **行为保证**：
  - 用户配置了专用 profile 且有效时，优先使用专用 profile；
  - 用户未配置或 profile 无效时，无缝回退到当前 Run 的主模型实例；
  - 构造出的 `SafetyClassifier` 传入 `create_harness_agent`，进而注册 `AutoClassifierMiddleware`；
  - 分类失败或超时时，`SafetyClassifier` 内部捕获异常并返回 `("ask", "classification failed/timeout")`，安全回退人工审批。

## 5. 关键 Invariants

1. **Fail-Closed 原则**：分类器在超时、API 错误、网络中断或格式无法解析时，必须严格返回 `ask` 触发审批弹窗，任何异常绝不能导致命令静默放行。
2. **底线不可绕过**：即使命令命中了已保存的 allow 规则或白名单，`evaluate_safety_floors` 与 `allow_remainder_triggers_floor` 依然会对命令的危险副作用（如写重定向 `>`、破坏性底线）进行守卫。
3. **敏感路径强制审批**：任何针对受保护路径（`.git/*`、`.github/workflows/*` 等）的写与删除，在非 `yolo` 模式下恒为 `ask`。
4. **规则自匹配保证**：由 `extract_command_rule(cmd)` 生成的非空规则，在下次执行完全相同的 `cmd` 时必须能通过 `matches_command_prefix` 成功匹配。
5. **单会话与跨会话作用域隔离**：「本会话允许」保存在内存 `session_rules` 中；「本项目允许」持久化在 `<workspace>/.harness/settings.json` 中，两端契约明确。

## 6. 验收标准与验证矩阵

| 测试用例 | 预期行为 |
| :--- | :--- |
| `auto-edit` 下执行 `ls` / `git status` / `git diff` | 无审批弹窗，直接执行成功 |
| `auto` 下执行 `ls` / `cat README.md` | 无审批弹窗，直接执行成功 |
| `auto-edit` 下删除工作区内 `temp.txt` | 无审批弹窗，直接执行成功 |
| `auto-edit` 下删除 `.git/config` | 弹出审批确认窗口 |
| 对 `python -m pytest tests/test_a.py` 选「本项目允许」后，再执行 `python -m pytest tests/test_b.py` | 第一次弹窗并写入规则；第二次不再弹窗直接执行 |
| 对 `ls packages` 选「本项目允许」后，再执行 `ls docs` | 第一次弹窗写入 `ls` 规则；第二次不再弹窗直接执行 |
| 对 `git commit -m "msg"` 选「本项目允许」后，再执行 `git commit --amend` | 第一次弹窗写入 `git commit` 规则；第二次不再弹窗直接执行 |
| 对 `rm foo.txt` 批准执行 | 不生成 `rm` 规则；后续执行 `rm -rf /` 依然弹窗 |
| 未配置 classifier 时在 `auto` 模式执行自定义命令 | 调用主模型进行分类；无害命令自动执行，破坏性命令拒绝，拿不准/失败时弹窗 |
| 配置了专用 classifier 时在 `auto` 模式执行 | 使用专用 profile 的分类器模型进行分类 |
