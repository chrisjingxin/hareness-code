## 背景

当前暖单色基础具有良好的长期阅读质感，但黑色被同时用于新建 Thread、发送、选中和 focus，无法明确区分“主要操作”和“当前状态”。旧 ZC-106 的蓝色大方向与当前 CSS 也没有形成新的单一事实来源。

## 当前存在的问题

- 浅色 muted 小字对比度不足；dark 的 subtle 也不适合必要 metadata。
- 新建 Thread 使用全黑填充，持续压过 Conversation 和 Run 状态。
- selected Thread/Model、focus、running 与普通强调没有统一蓝色语义。
- Context Dock 使用“标题行 + tab 行”两层 chrome，空间和边界重复。
- 26/32/36px 控件尺寸仍有任意混用，窄屏尺寸尚未由统一 token 表达。

## 目标设计

```text
semantic token
  → light/dark 映射
  → chrome / content / action / state 各用固定角色
  → 组件不再写临时 raw color 和任意尺寸
```

完整色值、字体、尺寸和组件层级以 [ZC-124 设计](../designs/ZC-124.md)“视觉系统”及“Topbar、Sidebar 与 Context Dock”为准。

## 实施步骤

1. 清理 `styles.css` 中重复的 `:root`/light token，建立唯一 light/dark semantic token 表。
2. 将必要 muted 文本、focus、selected、running、primary action 分配到新的语义色。
3. 统一 compact/standard/field、radius、icon 和间距 token；组件只引用用途 token。
4. 调整 Topbar：Run status 提升、Model/Approval 保持次级、返回/overflow 保持可达。
5. 调整 Sidebar：新建 Thread 变为 secondary；active Thread 使用 blue accent rail/surface。
6. 合并 Context Dock header/tab，保持 Code/Model/Skills/MCP/Status 的 capability 与键盘语义。
7. 增加 token、class 唯一来源、对比度和结构 focused tests；更新 Web 用户视觉说明。

## 范围

- `packages/cli/src/web/presentation/styles.css`。
- `web-app.tsx`、`workspace-sidebar/`、`context-dock/` 的 chrome 结构。
- 对应 Web presentation tests 和用户文档。

## 非范围

- 不实现响应式抽屉或 viewport state（ZC-126）。
- 不改 Timeline/Tool 内容结构（ZC-127）。
- 不改变 Protocol、Controller、Handoff 或主题持久化策略。
- 不引入字体、动画或 UI framework 依赖。

## 验收清单

- [ ] warm neutral + blue accent 在 light/dark 中一致生效，selected/focus/running 可区分。
- [ ] 所有必要小字和控件图标满足对比度要求，disabled/decorative 与必要文字 token 分离。
- [ ] 新建 Thread 不再是页面最强主按钮，Send/Interaction primary 保持唯一主动作。
- [ ] Context Dock 只保留一层 header/tab chrome，现有 tab 与 Help 行为不回归。
- [ ] CSS 不依赖同一组件的后置覆盖才能正确显示。
- [ ] focused tests、`bun run build`、`bun run typecheck` 通过。
