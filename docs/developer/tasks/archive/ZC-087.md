## 背景

当前 MCP 已经不是预留接口：AgentHost 初始化时读取配置、建立 `McpConnectionManager`，AgentEngine 构建时把 MCP 工具注入 Agent graph，Protocol 也提供 `mcp.status`、`mcp.add` 和 `mcp.remove`。

仓库同时已有 `ConfigChangeService`，负责用户配置的来源校验、managed lock、revision、preview、原子写入和脱敏审计。模型默认值等受控修改已经走这条 seam。

但 MCP 管理是在另一条路径上后加的：

```text
mcp.add/remove RPC
  → server.py 参数解析
  → AgentHost 自己组装配置并热增删

（改造前）ConfigChangeService
  ── 没有参与
```

## 当前存在的问题

### 1. MCP 绕过唯一配置写入 seam

`AgentHost._handle_mcp_add()` 和 `_handle_mcp_remove()` 曾自己组装 MCP 配置并调用独立写入逻辑。该路径没有复用：

- 配置来源限制；
- revision/CAS；
- managed lock；
-完整 `load_config()` 校验；
- `ConfigChangeAudit`；
- 显式 `--config` 与测试注入的 home/path 语义。

因此仓库实际有两套配置变更规则。

### 2. Server handler 拥有配置领域逻辑

`_handle_mcp_add()` 负责名称正则、transport 必填字段、重复检查、TOML DTO 构造、运行时 DTO 构造和操作顺序。Protocol adapter 不只是 wire 转换，而是 MCP 配置变更的主要 implementation。

### 3. 持久化配置、连接状态和 AgentEngine 身份来自不同快照

- `mcp_config_writer.py` 直接读取文件。
- `ConfigChangeService` 有自己的配置文档与 revision。
- `McpConnectionManager` 保存一份可变 config 列表。
- AgentEngineProfile 在 Run 开始时重新从 `Za38Config.mcp_servers` 计算指纹。

一次 add/remove 后，这些副本依赖调用顺序碰巧一致，没有一个不可变 snapshot 表示“当前 Host 认可的 MCP 配置”。

### 4. MCP 指纹不足以识别真实运行差异

`mcp_config_fingerprint()` 当前只包含 server name 和 transport。下面这些变化不会改变 AgentEngineProfile：

- stdio command；
- args；
- URL；
- Header/环境变量引用名称；
- timeout 等运行参数。

AgentEnginePool 因此可能复用按旧 MCP 工具目录构建的 graph。

### 5. 失败语义不明确

当前顺序是“先写配置，再热连接”。连接失败时配置已经保留，但这不是由 module 明确定义的状态转换；删除时也没有统一描述持久化成功、运行时断开失败和下一次重启之间的关系。

## 为什么现在要修改

- MCP 已经进入真实 Agent graph 和 `/mcp` 用户路径，配置与 AgentEngine 身份不一致会直接造成错误工具集合。
- 多 Connection Host 中，CLI 与 Web 可能同时触发管理操作；没有统一锁与 revision 会出现 lost update。
- Run lifecycle 重构必须把 AgentEngine 输入视为稳定 snapshot，不能继续从可变 manager 和文件分别取值。
- `ConfigChangeService` 已存在并经过测试，复用它比维护第二个 writer 更小、更安全。

## 目标设计

### 唯一变更 seam

MCP 变更必须进入现有配置变更 module。可以在 `ConfigChangeService` 上增加领域化操作，或让其接受类型化 MCP change；不得再保留独立通用 writer。

```text
mcp.add/remove adapter
  → ConfigChangeService
      ├─ 来源 / lock / 校验
      ├─ 锁内 read-modify-write
      ├─ revision / 原子提交 / audit
      └─ 产出 McpConfigSnapshot
                    ├→ McpConnectionManager
                    └→ AgentEngineProfile builder
```

### 不可变 MCP snapshot

建议结果类型至少包含：

- 按 server name 稳定排序的已校验 server 定义；
- snapshot digest；
- 配置 revision；
- 不含凭据值的 AgentEngine identity；
- 面向状态展示的脱敏摘要。

snapshot 的 AgentEngine identity 必须包含会改变连接或工具目录的字段：transport、command/URL、args、非秘密参数和环境变量/认证 Header 的引用名称。真实环境变量值、token 和认证 Header 值不能进入 digest、日志或 SQLite。

### 明确状态转换

- 写入校验或原子提交失败：旧配置、旧 snapshot、旧连接和旧 AgentEngine 全部保持不变。
- 写入成功但新连接失败：新配置与新 snapshot 成为事实，manager 记录 failed 状态；不得回滚到旧文件。后续 Run 不得复用旧 fingerprint 的 AgentEngine。
- 删除写入成功：新 snapshot 立即排除该 server；即使资源关闭报告失败，也不能把旧 server 重新声明为有效配置。
- 现有 AgentEngine 按旧 snapshot 完成或排空；新 Run 只能使用新 snapshot 对应的 AgentEngineProfile。

## 实施步骤

1. 将 MCP server 的结构校验和规范化从 Server handler 收进配置 module，复用现有 `McpServerConfig` 或建立不可变等价类型。
2. 为 `ConfigChangeService` 增加锁内 MCP add/remove 操作，复用 revision、完整配置校验、原子写入和 audit。
3. 构建 `McpConfigSnapshot`，分离“用于连接的运行时值”和“用于 identity 的脱敏值”。
4. 扩充 `mcp_config_fingerprint()`，让所有影响运行行为的非秘密字段参与 canonical digest。
5. 让 AgentHost 只保存当前 snapshot；`McpConnectionManager` 与 AgentEngineProfile builder 都从它更新。
6. 删除旧的 MCP 专属写入路径（当前分支已不存在该文件），把行为测试集中到配置变更 module interface。
7. 增加并发 add/remove、revision conflict、managed lock、写盘失败、连接失败、AgentEngineProfile 变化和秘密不泄漏测试。

## 范围

- 删除 `mcp_config_writer.py` 的独立 TOML 写入路径，把 MCP 变更纳入现有 `ConfigChangeService`。
- 从规范化配置构建不可变 MCP snapshot；指纹覆盖 transport、command/URL、args 和环境变量名称，不包含秘密值。
- MCP live manager 与 AgentEngineProfile 只消费 snapshot，不分别解释 TOML。
- 明确“持久化成功后刷新 live runtime”的顺序和失败回滚/诊断语义。

## 非范围

- 不新增 HTTP/SSE、OAuth、项目信任或 MCP 管理界面。
- 不改变 Protocol operation 名称或 capability。
- 不引入 Web framework 或新的配置格式。

## 实现结果

- `ConfigChangeService` 新增 `read_mcp_snapshot()`，MCP add/remove 在同一文件锁内完成来源、managed lock、必填 revision、CAS、规范化、完整配置校验、原子写入和审计。
- `McpServerConfig` 负责协议/TOML 映射的唯一规范化入口；`McpConfigSnapshot` 深度冻结服务器映射和脱敏 AgentEngine identity。指纹包含连接形状、参数、引用名称和超时；环境变量值、认证 Header 值和认证 query 值均不进入身份。
- `AgentHost` 只编排 typed MCP config、snapshot 和 Manager；`McpConnectionManager.apply_snapshot()` 与 AgentEngine build spec 使用同一 snapshot。写入成功但连接失败时保留新配置并返回 failed/skipped 状态，旧 AgentEngine 不承接后续新 Run。
- 未修改 JSON-RPC v3、SQLite schema、TUI、版本号和配置格式；旧的独立 MCP writer 路径在当前分支不存在。

## 验收清单

- [x] MCP 只有一个可信配置写入 seam。
- [x] revision conflict、managed lock 和写盘失败不会改变 live runtime。
- [x] snapshot 指纹对运行相关字段敏感，对秘密值不可逆。
- [x] 写入成功但连接失败时，持久化事实、运行状态和下次 Run 行为一致且可诊断。
- [x] 同一旧 AgentEngine 不会在 MCP snapshot 变化后承接新 Run。
- [x] Server handler 只编排 module 结果，不直接编辑 TOML。
