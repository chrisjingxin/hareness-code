## 背景

一次用户请求是一个 `Run`，一个 Agent 为完成一项任务经历的完整模型循环是一个
`AgentExecution`；模型调用、工具调用和 delegation 只是 execution 内的操作。

当前 Run 已有完整生命周期，但它只暴露 Run ID。`RunContext` 只有模糊的 Agent role，事件
也只能归属到 Thread/Run，因此未来出现子 Agent 时无法回答“哪个 Agent 在执行、谁是父执行、
当前状态是什么”。

最终方案把能力分为两种执行策略：可信短期 worker 使用 `Inline`，根 Agent、独立角色和
Plugin 使用 `Managed`。两种策略首先共用身份、Policy、事件、usage 和取消语义；独立
AgentEngine、checkpoint、PromptEpoch 和恢复状态不在本阶段提前引入。

## 当前存在的问题

### 1. Run 与 AgentExecution 没有明确分层

`RunCoordinator` 直接调用根图，`RunContext` 没有 execution ID、父执行 ID、Agent ID 和执行
模式。后续 delegation 只能把子图事件错误地归到父 Run。

### 2. 终态和取消没有执行树语义

当前只有 Run 终态，没有可复用的 execution 状态转换和 Run seal 规则。未来子执行若并发或
等待用户交互，不能由一个小接口统一收敛。

### 3. Protocol event 缺少执行归属

事件 envelope 只有 `thread_id` 和 `run_id`。即使 DeepAgents 提供子图 namespace，Harness
也无法把它映射成稳定的 AgentExecution 身份。

## 为什么现在要修改

- ZC-091 已提供角色级 `ResolvedAgentSpec` 和 AgentEngine 身份，Run 可以在受理阶段生成根
  execution 的模型、Policy 和 Profile 事实。
- ZC-096 接入 delegation 前，必须先有一个不依赖 SQLite 表结构的执行树 seam。
- 先完成轻量身份可以解决事件、取消和状态边界，同时避免为当前没有独立恢复需求的 Inline
  worker 支付完整持久化复杂度。

## 目标设计

```text
Run
└─ AgentExecution
   ├─ Model / Tool operation
   └─ Delegation operation
      └─ Child AgentExecution
```

核心值对象：

- `ExecutionRef`：`thread_id`、`run_id`、`execution_id` 和父 execution ID；提供 root ID 与
  Managed namespace builder。
- `AgentExecutionBinding`：冻结 Agent、模式、深度、模型/Policy/Profile 事实，只允许更新
  状态、时间和 usage。
- `AgentExecutionRegistry`：提供 `accept/start/finalize/cancel_run/seal_run` seam，按
  `(thread_id, run_id)` 隔离进程内执行树；Run 封口后由 Coordinator 释放该短期记录，历史幂等仍由
  `ThreadPersistence` 负责。

根执行路径：

```text
run.start
  → RunCoordinator 创建 root-<run_id>
  → Registry accept/start
  → RunContext 携带 execution 身份
  → 所有事件携带 execution_id/agent_id
  → Run 终态映射到 root execution
  → Registry seal
```

## 实施步骤

1. 在 `execution_binding.py` 增加 `ExecutionRef`、`ExecutionMode`、`ExecutionStatus` 和
   `AgentExecutionBinding`，校验父子深度与不可变身份。
2. 新增 `agent_execution.py`，实现进程内 `AgentExecutionRegistry`；父 Run 取消时将所有
   未终结 execution 置为 cancelled，存在未收敛 execution 时禁止 seal。
3. 让 `RunCoordinator` 为每个根 Run 登记 Managed root execution，并让 `RunContext` 携带
   execution ID、Agent ID、父执行 ID 和模式。
4. 扩展 v3 event envelope 的可选执行归属字段，保持旧客户端只读 `thread_id/run_id` 的
   行为不变；不把每个模型/工具调用持久化成 Step。
5. 后续由 ZC-096 决定 Inline/Managed 子执行的实际 delegation；Managed 状态持久化、
   checkpoint/PromptEpoch 隔离在该集成阶段按真实需求接入。

## 范围

- 轻量 AgentExecution 身份、父子关系和状态机。
- 根 Run 的 registry 接入、取消传播和 Run seal。
- RunContext 与事件 envelope 的 execution/agent 归属。
- 为后续 Inline/Managed delegation 提供内部 seam。

## 非范围

- 不实现 DeepAgents `task` 的 delegation dispatcher。
- 不新增 Step/Invocation 数据表或完整事件存储。
- 不为 Inline worker 建立独立 AgentEngine lease、checkpoint、PromptEpoch 或恢复。
- 不实现 Plugin、Team、mailbox、任务 DAG 或长期后台 Agent。
- 不改变现有 Thread 单 active root Run 规则。

## 验收清单

- [x] 根 Agent 有稳定 `root-<run_id>` execution ID 和 `agent_id=main`。
- [x] `AgentExecutionBinding` 的身份字段不可被状态转换修改。
- [x] 非法状态转换、未知父 execution 和冲突重复 ID 会 fail closed。
- [x] 父 Run 取消会使所有未终结 execution 收敛到 cancelled。
- [x] Run seal 后不能追加或修改 execution。
- [x] Python/TypeScript event contract 可以传递 execution 和 agent 归属。
