## 背景

Web UI 已经具备 Thread、对话、Tool、Interaction、Composer、文件树和 Context Dock 等核心能力。ZC-106/ZC-107 完成了前两轮主题、Composer 和代码展示改造，但当前实现继续演进后，任务文档中的蓝色设计目标、实际暖单色 CSS 和响应式行为已经不再一致。

本任务是新的上层体验任务。它不把所有改动塞进一个分支，而是固定共同设计与依赖顺序，再把实现拆成可认领的子任务。

## 当前存在的问题

- `.desktop-workspace` 强制 `min-width: 1280px`，390px 实测仍按 1280px 排版，主对话和 Composer 位于屏外。
- 1280px 同时打开 Sidebar 和 Context Dock 时，中央对话内容宽度只剩约 512px，外围工具挤压了核心任务。
- 高对比“新建 Thread”和重复 Tool 卡比当前 Run 状态更醒目，长期 Coding Agent 使用时注意力顺序错误。
- User/Assistant 同时显示名称和单字母 avatar；连续 Tool 逐条占卡，长会话噪声偏高。
- 浅色小号 muted 文本对比度不足，拖动分隔条只支持 Pointer，没有键盘调整语义。
- 现有动效只有通用 hover、spinner 和 cursor，缺少面板、Tool 状态和新输出的统一规则。
- 旧任务没有拆解者、上层任务和定期复核信息，无法判断视觉任务间的覆盖关系。

## 为什么现在要修改

ZC-105/ZC-115 即将建立最终 Browser E2E 和验收基线。若先对当前失效的窄屏布局和过时视觉目标固化截图，后续会再次重建基线。应先由本任务确认最终体验，再用既有验收任务关闭产品与架构证据。

## 目标设计

```text
暖中性色画布 + 蓝色交互强调
  → 以 Conversation / Run 为视觉中心
  → Sidebar 与 Context Dock 按可用宽度降级
  → Timeline 把连续 Tool 压缩为可扫读 Activity
  → Composer 始终可达并解释当前可执行动作
  → 键盘、缩放、窄屏和 reduced-motion 行为一致
```

完整 token、断点、状态、interface、动效和错误语义见 [ZC-124 设计方案](../designs/ZC-124.md)。

## 任务拆解

| 顺序 | 子任务 | 交付边界 |
| --- | --- | --- |
| 1 | ZC-125 | 统一 semantic token、品牌/顶栏/Sidebar/Context Dock 的视觉层级 |
| 2 | ZC-126 | 建立 wide/compact/narrow 三档响应式与抽屉/覆盖层行为 |
| 3 | ZC-127 | 收敛 Timeline 身份表达，并把连续 Tool 投影为 Activity Group |
| 4 | ZC-128 | 强化 Run 状态、Composer、空态和 Interaction 决策层级 |
| 5 | ZC-129 | 补齐键盘、焦点、对比度、触控目标和可访问分隔条 |
| 6 | ZC-130 | 落地功能性动效、长会话性能测量和滚动稳定性 |
| 7 | ZC-105 | 在最终 UI 上建立真实 Browser 双主题、多视口与主要工作流证据 |
| 8 | ZC-115 | 完成最终架构验收矩阵和 TUI/Web 连续性闭环 |

上述顺序是依赖顺序，不表示所有任务必须由同一 Agent 认领。ZC-127 与 ZC-128 在 ZC-125/ZC-126 合并后可并行；ZC-129/ZC-130 是跨组件收敛任务，必须等待核心结构稳定。

## 实施步骤

1. 由 ZC-125 建立新的 token 和 chrome 层级，删除与新基线冲突的旧视觉规则。
2. 由 ZC-126 收敛 DOM 骨架和 viewport 状态，保证 Conversation 最小宽度与窄屏可达性。
3. 由 ZC-127/ZC-128 分别优化历史阅读流和当前执行流，不改变 Interactive Core 业务事实。
4. 由 ZC-129 对完整页面做键盘与可访问性复核，补齐 Pointer-only seam。
5. 由 ZC-130 在稳定结构上加动效、测量长会话，并只在证据表明需要时引入 windowing。
6. 更新 Web 用户文档，由 ZC-105/ZC-115 固化最终 Browser、Handoff 和架构证据。

## 范围

- `packages/cli/src/web/application/adapter.ts` 的纯表现状态与 intent。
- `packages/cli/src/web/presentation/` 的结构、组件和 CSS。
- 必要的 `presentation-shared` 纯展示策略，不改变 Agent 业务语义。
- Web presentation/adapter/Browser E2E、视觉截图与可访问性验证。
- 相关用户、设计和架构文档。

## 非范围

- 不改变 Protocol、Python AgentHost、RunCoordinator、Handoff 安全边界或 ControlLease。
- 不新增附件、消息编辑、远端图片、代码执行或新的 Agent 能力。
- 不引入 CSS framework、CSS-in-JS、GSAP、远端字体或远端视觉资产。
- 不伪造 DTO 中不存在的时间、duration、进度百分比或风险等级。
- 不把 TUI 改造成相同 DOM 视觉；只保持语义和工作流一致。
