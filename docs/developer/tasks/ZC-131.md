## 背景

当前 DeepAgents 内置 `write_file` 已经只创建文件，`edit_file` 也会做精确唯一匹配；因此
整改不能建立在“所有现有写工具都会盲覆盖”的错误前提上。真正确定的高危路径是 Harness
自研 `apply_patch`：它只按 hunk 行号切片，不验证 old/context 是否等于当前文件。

此外，当前“必须先 read 再 edit”主要通过 prompt 约束，没有按 Thread 绑定模型实际读过的
文件版本和区间。共享 AgentEngine、外部 IDE 修改和远端 backend 会进一步放大弱模型误用
工具的风险。

## 用户结果

```text
模型定位并局部读取
  → Harness 记录这个 Thread 看过的文件版本和行
  → 模型表达“把刚才版本的这些行改成什么”
  → Harness 校验、展示 diff、审批、比较并提交
  → 返回实际落盘后的新版本和局部结果
```

模型可以因为参数、版本或范围错误而失败，但 Harness 不能在证据不一致时猜测目标位置。

完整决策、接口、错误语义和退出条件见 [ZC-131 设计方案](../designs/ZC-131.md)。

## 实施计划

1. 先移除不校验原文的 `apply_patch`，确保后续开发期间也不存在已知静默误写入口；通过工具
   catalog、Policy 和模型 schema 测试验证入口已消失。
2. 用固定 fixture 比较弱模型可理解的编辑表达，选择 exact-string + prior-read 作为唯一接口；
   任何真实模型结果变化先更新同 ID Design，再调整实现。
3. 建立唯一文件工具接管 seam、ThreadSnapshotStore 和本地/远端文本 adapter，让主 Agent、
   inline child 与 declarative child 共用同一执行路径。
4. 纵向实现 read/create/edit/delete：从虚拟路径进入，校验 Snapshot、已读范围和内容版本，
   生成审批 diff，再 compare-and-replace，最后重读实际内容并返回新 Snapshot。
5. 收敛工程边界：保留 BOM/换行/权限，Notebook 与 non-text 只读，CAS 不可证明时拒绝；
   diagnostics 和指标必须有界、去敏且不改变提交结果。
6. 运行生产路径回归、项目检查和真实企业弱模型评测；只有安全门槛、完成率、文档和版本影响
   全部闭环后才完成本 Task。

## 共同 invariant

- Snapshot 至少绑定 Thread、canonical path、backend identity、完整内容强 hash 和已读行。
- 修改只允许覆盖 Snapshot 中模型实际见过的源行；虚拟 `/.harness/` 始终只读。
- 同一调用所有 edit 先完整预检，任一失败则零写入。
- Policy/Approval 是授权边界，Snapshot 是一致性边界；两者不能互相替代。
- 批准后的文件版本发生变化时，旧批准失效并返回冲突。
- 远端 backend 无安全 compare-and-replace 能力时拒绝编辑，不退化为盲写。
- commit 后重新读取实际内容，新 Snapshot 不得基于“准备写入但实际未落盘”的文本。
- 首版不做 fuzzy/stale recovery、自动 formatter 或跨文件事务。

## 范围

- `packages/agent/harness_agent/runtime/` 的 Agent/FileTools 装配和 Run/Thread context 接入。
- `packages/agent/harness_agent/tools/` 的文件工具、Snapshot 和 mutation service。
- `packages/agent/harness_agent/policy/` 的工具名、风险、审批描述和并发接入。
- 本地/远端 backend adapter、Python 测试、弱模型 opt-in 评测脚本和固定 fixtures。
- 必要的 TUI/Web 工具展示适配，但不改变 JSON-RPC v3 业务协议。
- 用户、架构、设计和任务文档。

## 非范围

- 不实现跨文件原子事务、rollback journal、文件移动或目录删除。
- 不引入 hashline/fuzzy anchor 或第二次模型调用纠正 edit。
- 不自动 formatter，不编辑 Notebook/二进制/图片/PDF。
- 不把 Snapshot 持久化到工作区、SQLite 或 Transcript。
- 不新增兼容 alias、旧 schema fallback 或按模型并存两套文件工具。
