## 范围

- 仅在出现固定编排需求后，定义 `AgentWorkflow` 文件资产和版本；步骤按 Agent ID 引用 catalog，不创建 RoleDefinition、PersonaDefinition 或新的 Thread/Run 核心对象。
- 初版仅支持显式顺序步骤（例如 Planner → Executor），结构化交接必须通过目标 Agent 的 input/output contract 校验、长度限制与来源标识；交接数据属于 Run/Checkpoint 状态而非 Runtime 实例。
- Workflow 中每个 execution 复用 ZC-082/ZC-015 的模型解析、Policy 交集、取消、审批、RuntimePool 和 execution tree；不允许 Workflow 节点以内联 Prompt、Provider、模型或权限绕过 AgentDefinition。

## 非范围

- 不替换主 Agent 动态 delegation；Single Agent 保持隐式 root，不要求用户配置 Workflow。
- 不实现并行 worker、Agent 间自由通信、持久 mailbox、TeamScheduler、任意 DAG、无限递归子 Agent 或自治提权。
- 不修改远端子 Agent 的端点协议。

## 验收清单

- Workflow 定义/步骤/交接契约变化形成新 Runtime Profile，旧 Runtime 仍按现有 lease、TTL/LRU 规则释放。
- 单 Agent 默认路径和动态 delegation 的协议、工具调用、线程恢复和测试行为不变。
- Planner 输出只能以校验过的结构化交接进入 Executor；取消、拒绝审批、计划失败和执行失败均有明确 execution 终态且不串 thread。
- Agent 默认模型、Thread override、Policy 交集、调用顺序和 checkpoint 恢复均有 mock 集成测试。
