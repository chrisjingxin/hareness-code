## 背景

ADR 已定义 `RunExecutionBinding.executions[]`：每个 Agent execution 保存父子关系、Agent、实际模型、有效 Policy、深度和终态。

当前生产持久化主要围绕根 Agent：

- Run 开始时记录 primary model；
- PromptEpoch 主要按 Thread 保存；
- Context artifact、summary 和 checkpoint 主要通过 Thread namespace 路由；
- Deep Agents 默认子 Agent 是一次性内部 worker，没有进入 Harness 的执行事实。

多张角色图可以共享编译对象，但绝不能共享同一份可变执行状态。

## 当前存在的问题

### 1. Thread ID 不能唯一标识 Agent execution

同一个 Run 可以两次调用 Executor，也可以并行调用 Reviewer。只用 `thread_id` 会让消息、PromptEpoch、摘要和恢复位置发生碰撞。

### 2. 子 Agent 的模型和 Policy 没有进入历史事实

即使 Planner 使用 pro、Executor 使用 fast，当前历史主要只能回答根 Agent 使用了什么，不能审计某个子执行当时是否具有 write 权限。

### 3. PromptEpoch 和 Skill 快照仍偏根 Agent

不同角色的 Prompt、Skill 子集、工具说明和上下文窗口不同。复用 Thread PromptEpoch 会把根 Agent 规则注入子 Agent，或让角色配置变更后无法正确恢复。

### 4. 终态和取消缺少执行树语义

根 Run 取消后，子 execution 应全部收敛；一个子 Agent 失败是否终止父 Agent也需要显式结果。当前 Run lifecycle 只拥有根级状态。

## 为什么现在要修改

- ZC-088 和 ZC-089 会分别提供生命周期持久化 seam 与 RunCoordinator，适合在其上增加 execution，而不是让 delegation 直接操作表。
- ZC-091 会提供角色级 AgentEngine 身份；历史事实必须消费同一个解析结果。
- 在动态 delegation 前完成 namespace，可以避免上线后迁移已经存在的子 Agent checkpoint。

## 目标设计

一次 Run 的执行树：

```text
RunExecutionBinding
└─ exec-root
   ├─ exec-planner
   ├─ exec-executor-1
   └─ exec-reviewer
```

每个 execution 启动前固化：

- `execution_id`
- `parent_execution_id`
- `agent_id`
- AgentEngine/Profile key
- 实际 Model binding
- EffectivePolicy ID 与指纹
- Prompt/Skill/Tool view 指纹
- depth

可变字段只允许状态转换：

```text
pending → running → completed | failed | cancelled
```

状态 namespace 至少区分：

```text
project / thread / run / execution
```

具体 SQLite 表和 LangGraph `checkpoint_ns` 可以由实现决定，但外部 module 只能使用类型化 execution ref。

## 实施步骤

1. 扩展 ZC-086 的类型化 RunExecutionBinding，使其支持追加 AgentExecutionBinding 和更新终态。
2. 在 ZC-088 的生命周期持久化 interface 增加 accept/start/finalize execution 操作，并保证幂等与合法状态转换。
3. 定义 `ExecutionRef` 和 namespace builder，禁止调用方手写 thread/checkpoint key。
4. 让 PromptEpoch、Context artifact/summary/state 和 Deep Agents checkpoint 按 execution 路由。
5. 明确根 Agent 的兼容映射，使旧 Thread 仍能恢复为单一 root execution。
6. 在 ZC-089 RunCoordinator 中加入子 execution 注册、取消传播和 Run seal 前收敛检查。
7. 增加同角色重复派发、不同角色并行、子执行失败、父取消、进程恢复和损坏 namespace 测试。

## 范围

- 建立 Run 内 Agent execution 的类型、状态机、持久化和 namespace。
- 让 PromptEpoch、上下文压缩和 checkpoint 支持角色级隔离。
- 旧单 Agent Run 继续可读，不回填不存在的历史模型或 Policy。
- 为后续 delegation 提供内部 interface，不增加用户操作。

## 非范围

- 不实现 Agent 调度、Team mailbox 或任务 DAG。
- 不保存完整 Prompt、凭据或原始 Policy 到 Run binding。
- 不让子 Agent 拥有独立于父 Run 的无限期后台生命周期。
- 不改变现有 Thread 单 active root Run 规则。

## 验收清单

- [ ] 每个 Agent execution 有稳定 ID、父子关系和不可变模型/Policy 事实。
- [ ] 相同角色被调用两次时 checkpoint、PromptEpoch 和 Context 不会碰撞。
- [ ] 父 Run 取消会使所有未终结子 execution 收敛到 cancelled。
- [ ] Run 终态后不能追加或修改 execution。
- [ ] 旧单 Agent Thread 可以恢复，未知历史事实明确标记 unknown/legacy。
- [ ] 所有持久化操作通过生命周期 interface，不向 RunCoordinator 暴露表结构。
