## 背景

Harness Code 的 TUI 和 Web 共用 Interactive Core。Agent Host 从 LangChain 流事件产生 JSON-RPC v3 事件，Core 再把事件折叠为两个界面共用的 snapshot。当前协议只有 assistant 正文、Tool、Interaction 和终态事件，没有“运行中进展”或“公开思考摘要”的领域语义。

## 当前存在的问题

- `RunCoordinator._message_text()` 只读取 `type=text`，reasoning-only chunk 在 `_translate_stream_event()` 中被直接丢弃；首个正文或 Tool 事件前用户看不到变化。
- TUI 在 `starting/running` 时隐藏 spinner，Web 的状态文案和状态点是静态的；共享状态已有 `run.started`，但没有可感知的持续反馈。
- LangChain/OpenAI adapter 的标准 Responses block 可以携带 `reasoning` 的公开 `summary_text`，但当前 `ModelSettings` 没有 reasoning 配置，也没有安全的 fail-closed 提取器。
- 不能把原始 reasoning、`encrypted_content`、`additional_kwargs` 或未知供应商载荷当作 assistant 正文或 Transcript；当前没有独立协议事件承载公开摘要。

## 为什么现在要修改

首个模型事件可能延迟很久，当前 UI 会让用户误以为进程卡死，也没有明确的取消入口反馈。直接显示 reasoning 字段又会越过模型供应商的公开边界，产生泄露 Chain of Thought 的安全风险。本任务独立于 ZC-106：ZC-106 只负责表现层的通用视觉细节，不改变本任务新增的 Protocol/Core 语义。

## 目标设计

```text
LangChain 标准 content block
  → fail-closed 提取公开 summary_text
  → reasoning.summary / run.progress
  → InteractiveState 的 ephemeral 字段
  → TUI 与 Web 共用运行状态、摘要和取消提示
```

新增两个独立事件：

- `reasoning.summary`：只承载已经被 adapter 以 `summary_text` 明确标识为公开的文本；不伪装成 `content.delta`，不写入 assistant message 或 canonical Transcript。仅在当前 Run 中显示，终态清理。
- `run.progress`：只承载事实阶段（`preparing` 或 `model`）与非负活动时长；没有摘要时也能驱动运行状态，UI 不能据此虚构具体执行步骤。

安全 invariant：只有消息原始 Responses block 中 `type=reasoning`、`summary` 是由 `type=summary_text` 和字符串 `text` 组成的标准列表、且不存在加密/未知字段时才公开摘要；标准 adapter 规范化后的标量 `reasoning`、`additional_kwargs`、未知 block 和供应商私有载荷全部 fail closed。摘要和进度不参与 Thread 恢复与 Transcript 持久化。

模型配置在 canonical `ModelSettings` / AgentEngine Profile fingerprint 中保存显式 reasoning 选项，adapter 通过 `reasoning` 和 `output_version="responses/v1"` 传递，不使用 `extra_body` 绕过 Profile 身份。

## 实施步骤

1. 在 canonical Protocol schema 增加两个 payload 和事件，运行生成脚本，同步 Python mirror、TypeScript 类型、validator、fixture，并补协议契约测试。
2. 在 Python Host 增加安全 summary 提取与 progress 翻译；保留正文、Tool、subgraph、取消和终态语义，补 reasoning-only、text+summary、未知/加密、乱序/重复边界测试。
3. 在 Interactive Core 增加只运行期存在的 progress/summary state，按 sequence 去重并在终态清理；补 reducer、Timeline Feature 和 TUI/Web adapter parity 测试。
4. 调整 TUI/Web 的运行态展示：从 `run.started` 起显示 spinner、事实阶段、活动时长、可取消提示和公开摘要；加入 ARIA live/status、键盘可达取消入口与 reduced-motion 样式测试。
5. 在模型配置解析、adapter 构造和 Profile fingerprint 中接入显式 reasoning 选项；补合法/非法配置、传参和身份变化测试。
6. 更新用户交互/配置文档、架构说明、任务证据，运行 focused 与项目级检查。

## 范围

- Agent → Protocol → Interactive Core → TUI/Web 的公开 summary 和事实运行进度。
- 当前锁定版 `langchain-core`/`langchain-openai` 的标准 Responses content block。
- reasoning 配置的解析、adapter 传递和 Profile 身份。
- 运行期展示、取消反馈、可访问性和跨端 parity。

## 非范围

- 原始 Chain of Thought、加密 reasoning、`additional_kwargs` 或供应商私有载荷的展示/持久化。
- 修改 ZC-106 的 Protocol/Core 范围或重构其视觉主题。
- 将摘要写入 Thread 历史、恢复数据或 canonical assistant Transcript。
- 新增供应商 adapter、跨平台安装包或生产发布流程。
