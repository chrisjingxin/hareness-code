## 范围

- 按 ZC-081 的 `ThreadExecutionSelection` 与 `RunExecutionBinding` 契约实现模型切换 MVP：只含当前根/主 Agent 的 `primary_profile`。`/model <profile>` 在空闲 Thread 打开既有 Picker；用户确认后仅更新 TUI 的待下次 Run 选择和状态栏，不发起独立的 `models.switch` RPC，也不直接改写 TOML。
- 协议升级到新的 minor，并通过 capability 协商开放 `models.select`：新客户端每次 `run.start` 发送 `model_selection: { primary_profile }`；保留 `model_profile` 作为旧 minor 客户端“新 Thread 首次选择”的兼容别名。`models.list(thread_id)` 返回当前可恢复选择和只读的最近实际绑定；`run.started` 返回本次实际 primary 模型、来源和 Runtime Profile 摘要，作为 TUI 的权威校准值。
- 在服务端将当前 `ModelRouter.bind_thread()` 的“首次冻结”拆为“每次 Run 解析”。当前 Single Agent 仍使用既有 `executor` 角色作为 physical primary，不实现 Agent/Role 定向覆盖、Planner/Executor Team 或新的 Provider 配置模型。
- 新增按 `(project_fingerprint, thread_id, run_id)` 记录的 `RunExecutionBinding` 持久化：保存请求选择、脱敏实际 primary 绑定、来源、Runtime Profile Key 摘要和时间；首条消息索引与本 Run 绑定必须同事务写入。恢复 Thread 时读取最后一条成功受理的选择；旧 `harness_thread_model_bindings` 仅作为 v5 及以前 Thread 的只读回退，不再为新 Run 写入或阻止切换。
- 解除 `harness_thread_runtime_profiles` 对模型切换的不可变约束：Runtime Profile 仍以实际模型配置计算并去重保存，但不再作为 Thread 的永久 Profile。删除“任一 Thread 选择变化就 DRAIN 前一个 `_default_profile_key` Runtime”的全局驱逐；RuntimePool 只按既有 lease、TTL、LRU 和容量规则回收空闲 Runtime。
- TUI 以明确的“当前 Thread 下一次使用”和“本 Run 实际使用”状态替换 `pendingModelProfile`/“待新 Thread”语义。恢复、`/new`、Picker 取消、不可用模型、`run.start` 拒绝、窄终端和焦点恢复必须保持状态一致；旧 minor 或缺少 `models.select` 时保留现有“仅新 Thread”兼容行为。

## 非范围

- 不实现运行中的模型热替换；活动 Run、审批、问答、压缩和取消收敛期间 `/model` 必须禁用。
- 不把裸 `/model` 视为修改全局默认配置；“同时设为后续新 Thread 默认”由 ZC-079 在 ZC-071 配置写服务之上单独实现。
- 不实现 `agent:<id>`/角色级模型覆盖、AgentDefinition、ExecutionPolicy、动态 Subagent 派发、固定 Agent Team、Workflow 或任意模型自动路由。
- 不引入 ProviderDefinition、JSON 模型目录、新厂商 SDK、模型市场、远端配置同步，亦不修改 endpoint、Header、API Key、Role mapping 或其他非模型选择字段。

## 验收清单

- 当前空闲 Thread 在 `/model fast`、下一轮 `/model pro` 后均保持同一 Thread ID；每次后续 Run 的实际 executor/primary 与选择一致，历史 Run 的实际模型不随之后的切换重写。
- 新建 Thread、已运行 Thread、重启后的恢复 Thread 和 v5 legacy Thread 分别按“请求选择 → 最近 Run 选择 → legacy 绑定 → 配置默认”的顺序解析；配置已删除的 Profile、不可用凭据和能力不足均明确失败且不产生新的选择/绑定记录。
- 相同 `run_id` 的重试不产生第二条消息、第二条 Run 绑定或第二个后台 Run；冲突重试给出稳定错误。SQLite 迁移、事务回滚和损坏历史记录均 fail closed，所有 DTO、日志和表记录不含 endpoint、Header、API Key、环境变量名或完整 Prompt。
- 多 Thread 使用 Fast/Pro 时可并存、复用正确 Runtime；Thread A 的切换不 DRAIN 或中断 Thread B 正在使用的 Runtime，既有 lease/run 完成后再由 TTL/LRU/容量策略回收。
- Python 覆盖 ModelRouter、ThreadStore 迁移/恢复/幂等、RuntimeProfile/RuntimePool 和 run.started 事件；TypeScript 覆盖协议协商、每次 `run.start` 参数、现有 Thread Picker、状态栏校准、失败回退、恢复及窄终端焦点。完成协议生成与契约测试，并通过项目级检查。
