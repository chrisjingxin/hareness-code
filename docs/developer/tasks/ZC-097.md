## 背景

Planner → Executor → Reviewer 这类顺序调用可以由 ZC-096 的层级 delegation 完成，不需要 Agent Team。

只有出现以下需求时才需要 Team：

- 多个成员长期并行；
- 显式任务依赖；
- 成员可以被独立取消或重试；
- Team 需要统一预算、并行上限和终态；
- 进程重启后仍要恢复尚未完成的成员任务。

AgentEnginePool 只负责“给定角色 Profile，取得可执行图”，不能承担 Team 的任务编排。

## 当前存在的问题

### 1. 没有 Team 状态所有者

当前 RunCoordinator 管理根 Run，Deep Agents task 管理一次性子调用，但没有 module 统一拥有成员、任务依赖和总体终态。

### 2. 并行 Agent 的取消和失败规则未定义

一个成员失败时是停止全部、继续无关任务还是重试，不能由各 Agent Prompt 自行决定。

### 3. 共享工作区容易产生写冲突

即使 ZC-094 提供底层调度，Team 仍要决定哪些任务允许并行、哪些必须等待，以及何时使用独立 worktree。

### 4. mailbox 容易演变成第二套 Thread

如果没有明确边界，成员消息、用户消息、任务状态和 Agent checkpoint 会互相复制，形成难以恢复的多套事实来源。

## 为什么现在要修改

本任务优先级为 P1，必须在 ZC-096 完成并证明层级 delegation 不足后实施。先立项是为了固定边界，防止 Team 能力被顺手塞入 AgentEnginePool、RunCoordinator 或 ThreadPersistence 的现有接口。

## 目标设计

建立 Run-scoped `TeamCoordinator`：

```text
TeamCoordinator
├─ TeamPlan：任务与依赖
├─ MemberExecution：引用 AgentExecutionBinding
├─ maxParallelism / budget
├─ cancellation / failure policy
└─ Team terminal state
        ↓
AgentDelegator
        ↓
AgentEnginePool
```

MVP 只支持固定 Team 定义和有向无环任务依赖：

```text
plan → execute → review
          └────→ test
```

Team 状态保存任务和 execution 引用，不复制成员完整消息或 checkpoint。成员之间通过结构化 task input/result 传递信息；是否增加 mailbox 必须由后续真实需求证明。

## 实施步骤

1. 用产品场景确认层级 delegation 无法满足的最小 Team 行为；若没有该场景，保持任务待认领。
2. 定义 TeamDefinition、TeamRun、TeamTask、依赖和失败策略；拒绝循环依赖。
3. 建立 TeamCoordinator 状态机和持久化 seam，Team terminal state 必须唯一。
4. 通过 AgentDelegator 启动成员，不直接构建或持有角色图。
5. 接入 maxParallelism、全局/父级 Policy、WorkspaceExecutionScheduler 和总预算。
6. 定义父 Run、Team 与成员 execution 的取消传播顺序。
7. 支持进程恢复后重建任务状态；running 但无法确认的成员按明确规则失败或重试，不重复写入。
8. 增加顺序 DAG、只读并行、写入串行、成员失败、父取消、恢复和预算耗尽测试。

## 范围

- 一个 Run 内的固定 Team 和显式任务 DAG。
- Team 通过 ZC-096 派发成员，成员仍使用角色级 AgentEngine。
- 统一并行、取消、失败和终态规则。
- 结构化 task/result 传递，不默认实现自由聊天。

## 非范围

- 不实现开放式 peer-to-peer 社交 Agent。
- 不实现跨 Host、跨用户或无限期后台 Team。
- 不实现动态共识、投票、拍卖式任务分配或自动组织重构。
- 不实现 mailbox，除非实施前有无法由 task/result 满足的真实场景并新增 ADR。

## 验收清单

- [ ] TeamCoordinator 不拥有或缓存编译图，只通过 AgentDelegator 使用 AgentEnginePool。
- [ ] 固定任务 DAG 可恢复，循环依赖在受理前被拒绝。
- [ ] 只读成员可以在限制内并行，写成员服从工作区调度。
- [ ] 父 Run 取消会收敛所有 Team task 和 Agent execution。
- [ ] 每个 Team 恰好一个终态，成员失败策略可观察且可测试。
- [ ] Team 状态不复制成员消息、checkpoint、PromptEpoch 或 AgentEngine 配置。
- [ ] 没有真实 mailbox 需求时不增加 mailbox abstraction。
