## 服务的用户结果

弱模型只需要使用一套短、明确的文件工具，并且不能通过猜路径、猜行号或复用旧版本绕过
“先读当前内容再修改”的边界。

## 前置条件

- ZC-133 已选择 `snapshot_id + old_string + new_string` exact-string 作为当前唯一生产 schema，并把默认 read limit 和输出上限写回 ZC-131 设计。
- ZC-134 已提供唯一 tool seam、ThreadSnapshotStore 和 backend adapter contract。

如果任一条件不满足，本任务不得自行补决策。

## 实施步骤

1. 实现 canonical `read_file`：读取完整内容 identity，向模型只返回请求窗口、普通源行号、
   Snapshot ID、shown/total lines；相同内容重复读取合并 seen ranges。
2. 明确空文件、超长行、offset/limit 超界、最大字节、UTF-8/BOM/CRLF/LF、末尾换行和
   multimodal/Notebook 的返回语义；视觉分段编号不得成为可编辑源行号。
3. 实现 create-only `write_file`：目标存在返回 `FILE_ALREADY_EXISTS`；成功后返回实际内容
   Snapshot 和首个局部窗口。
4. 实现评测胜出的 `edit_file(file_path, snapshot_id, old_string, new_string)`：校验
   Snapshot scope/hash、唯一 exact match、其完整源行属于 seen range、no-op 和内容上限；
   任一校验失败零写入。
5. 实现 `delete_file(snapshot_id)`：复用相同 scope/hash 校验并保持 DELETE 风险审批；成功后
   使该路径 Snapshot 失效。
6. 返回 ZC-131 定义的稳定 JSON error code 和唯一 `next_action`，控制消息长度并避免把源码
   内容写入日志。
7. 同步 `_BUILTIN_TOOL_SHAPES`、schema fingerprint、Capability/Policy、风险/并发分类、
   deferred tool、主/子 Agent prompt 和工具展示。
8. 删除旧 `replace_all`、range/`edits[]` 候选 schema、兼容转换和第二 `delete_file` 测试/注册
   入口；当前未正式发版，不保留 legacy alias。
9. 更新交互使用和故障排查，说明 Snapshot 过期/stale 后局部重读，不暴露内部 hash。

## 明确不修改

- 不在本任务实现 diff 审批增强和本地原子 writer 细节（ZC-136），但必须继续经过现有
  Capability/Approval，不能形成未授权写入中间态。
- 不自动 formatter/LSP，不做 stale recovery。
- 不支持跨文件 batch、移动或目录删除。

## 验收清单

- [x] 每种模型/主子 Agent 只看到一套最终 schema。
- [x] 未读、stale、跨作用域、非唯一或找不到的 exact-string edit 均返回正确 code 且字节不变。
- [x] 局部 read 只进入局部 context，但完整内容 identity 正确。
- [x] write/create、edit/modify、delete 的职责不可互换。
- [x] 旧 schema、转换、alias 和 fallback 已删除。
- [x] focused、runtime、policy、Thread isolation tests 通过。

## 实施记录

- `SnapshotFileToolContract` 已接管主 Agent、declarative 子 Agent 和 inline worker 的
  `read_file`、`write_file`、`edit_file`、`delete_file`。`edit_file` 只接受
  `file_path + snapshot_id + old_string + new_string`，并在当前版本、唯一匹配和已读范围全部
  验证后才 compare-and-replace；`delete_file` 需要完整读取且会失效同路径 Snapshot。
- 已删除旧 direct `delete_file` 模块/注册和 legacy contract；工作区外文件调用不再有审批后的
  直写旁路。
- `bun run test` 在允许 loopback 后只剩非本任务的 Web bundle 环境失败：Bun 把 worktree
  `node_modules`/workspace symlink 的多个 `.js` 路径读取成目录（`EISDIR`）。因此本任务保持
  `进行中`，不在未修复该环境前调用 `task:complete`。
