## 背景

ZC-106 已把 Web 工作台切换为蓝色深浅主题，并建立 260px Thread 栏、54px 顶栏、880px 中央阅读列、可选 372px 工作台和移动端抽屉。真实页面已经具备目标设计的主骨架，但用户提供的实现截图与原始浅色/深色 HTML 稿仍有明显差异，并且核心输入流程在真实浏览器中不可用。

当前问题不是一次普通的颜色调整：Composer 无法输入会阻断整个 Web 对话；代码块没有 TUI 已具备的语法高亮；Timeline 的空 Assistant 行、角色标识和控件尺寸又让实际页面显得松散、错位。需要在建立最终 Browser E2E 基线前完成一次有明确规格的可用性与视觉收敛。

## 已确认问题

### P0：Composer 无法输入和发送

- 用户在真实 Web Thread 中无法在 textarea 输入文字，也无法发送消息。
- `Composer` 同时使用 React `value={draft}` 和 `useLayoutEffect` 直接写 `textarea.value`，输入值存在两个 owner。
- `draft-change` 由 Adapter 延迟到下一 animation frame 发布；受控输入在真实 DOM 事件返回时仍可能拿到旧 snapshot。
- 当前 DOM 测试因 Happy DOM 与 React 19 事件委托问题，直接调用 React handler，未走浏览器原生 `input` / composition / click / form submit 链路，因此现有“可输入”测试不能覆盖现场故障。

### P1：Web fenced code 没有语法高亮

- `markdown.tsx` 只输出 `<code data-language>` 和纯文本；所有 token 使用同一前景色。
- TUI 已通过 Tree-sitter 和随 CLI 分发的本地 WASM/query 资产高亮 Markdown fenced code。
- CLI 已锁定 `web-tree-sitter@0.25.10`，但 Web bundle、静态路由、CSP、Worker 和 React renderer 尚未接入这些资产。

### P1：实际 UI 与 HTML 设计稿仍未收敛

- 27px Assistant avatar 内渲染完整 `Harness` 文本，发生溢出；截图中角色文字压到消息正文和 Tool 行上。
- 非流式空 Assistant message 仍占据 Timeline 行；连续 Tool 调用因此被空角色行分隔，形成大面积无意义留白。
- Sidebar 比设计稿多出 `THREADS / Thread` 两级标题，挤压首屏 Thread 内容。
- 短 User 消息使用整行蓝色 surface；Assistant 正文可铺满 880px，长文阅读行长和视觉权重偏大。
- 当前发送按钮为带文字的 72×34px 主按钮，与 HTML 稿中的紧凑 icon action 差异明显；32px icon button、桌面表单按钮和移动端触控目标也缺少统一尺寸层级。
- Brand mark 使用实心蓝底，meta chip 依赖文字前缀，和 HTML 稿的轻量 brand surface、图标 + 值布局不一致。
- Markdown 代码、表格和正文共用相近密度，代码块缺少语言标识、复制动作和高亮加载/降级状态。

## 目标流程

```text
真实键盘/IME/点击
  → React 原生 textarea/form 事件
  → WebIntent（草稿立即发布，提交只读取 Adapter 当前草稿）
  → InteractiveController
  → run.start / 错误反馈
  → 草稿按结果清空或保留

Markdown fenced code
  → 校验语言与大小
  → 本地 Worker 按需加载 Tree-sitter WASM/query
  → 返回纯范围 token
  → React 创建安全 span
  → 未知语言、超限或失败时显示原始代码
```

视觉目标是保留 ZC-106 已完成的主题和三栏骨架，只收敛真实偏差：角色、空行、阅读 measure、控件尺寸、对齐边和响应式状态。不得借本任务重写 Interactive Core、改变 Agent 业务语义或新增静态占位按钮。

完整状态、interface、语法资产路由、组件尺寸和测试决策见 [ZC-107 方案设计](../designs/ZC-107.md)。

## 实施步骤

1. 先补充可复现测试，证明原生 `input`、composition、Enter、Shift+Enter、发送点击和 Controller dispatch 的现状；测试不得继续只调用 React handler 冒充浏览器输入。
2. 让 React 成为 textarea value 的唯一 DOM owner，移除命令式 value 写入；让 draft 本地变化立即发布，提交从 Adapter 当前 draft 读取，并补充 submitting、失败保留和防重复提交状态。
3. 建立 Web syntax Worker 与严格资产 catalog，按需加载仓库内 Tree-sitter WASM/query；扩展 bundle/server 的精确白名单路由和最小 CSP。
4. 将高亮结果渲染为 React text/span 节点，增加语言标签、复制按钮、大小上限、缓存、主题 token 和纯文本降级；保持 raw HTML、图片和非法链接的既有安全规则。
5. 修复 Timeline 的空 Assistant 行与 avatar 溢出，增加角色 header，收敛 User surface、长文 measure、Tool 组间距和代码/表格局部滚动。
6. 按 design 的控件层级调整 Brand、Topbar、Sidebar、Composer、Interaction、Utility：桌面紧凑、移动端触控目标放大，所有图标使用同一 Lucide optical weight。
7. 补齐 light/dark、1440×900/390×844、200% zoom、键盘、长文本、连续 Tool、超长代码和高亮失败测试；在 Tabbit 中完成真实输入与视觉抽查。
8. 更新用户/架构文档，运行 focused tests、build、typecheck、项目级检查和 open-code-review；高/中优先级问题修复后才能交给 ZC-105 固化 Browser E2E 与截图基线。

## 范围

- `packages/cli/src/web/application/adapter.ts` 的 draft / submit 纯表现状态与同步发布边界。
- `packages/cli/src/web/presentation/` 的 Composer、Markdown/code、Timeline、Thread、Topbar、Utility 与 CSS。
- `packages/cli/src/web/` 的 browser bundle、严格静态资源映射、syntax Worker 与 CSP。
- 语法资产生成脚本的 Web catalog 输出；复用现有本地 Tree-sitter 资产，不重新下载。
- Web Adapter、presentation、bundle/server、安全和真实浏览器 focused tests。
- `/web` 输入、代码高亮和布局行为的用户/开发文档。

## 非范围

- 不改变 Protocol、Python AgentHost、RunCoordinator、ControlLease、Handoff lifecycle 或 attachment 能力。
- 不改变 Slash Command、Model、Skill、MCP、Thread、approval/question 的业务语义。
- 不新增附件、上传、拖放、消息编辑、代码执行或远端图片。
- 不从 CDN、GitHub 或其它网络地址加载字体、图标、WASM、query 或高亮主题。
- 不引入第二套 Markdown parser，也不使用 `dangerouslySetInnerHTML` 或高亮器生成的 HTML 字符串。
- 不扩大到完整 Browser E2E fixture；最终跨进程自动化与四组基线仍由 ZC-105 完成。
- 不修改 TUI 视觉；Web 只复用 TUI 已分发的语法资产和语义 scope，不共享渲染组件。

## 验收清单

- [ ] Tabbit 中 textarea 可持续获得焦点并输入中文 IME、英文、空格、粘贴和多行文本；React rerender、Timeline 流式更新和 panel 开关不会清空或回退 draft。
- [x] Enter 发送、Shift+Enter 换行、Cmd/Ctrl+Enter 发送、composition Enter 不误发；点击发送只提交一次，失败保留原 draft 并显示可读错误。
- [x] active Run 时同一 action 位显示取消；readonly/leaving/connection error 时不可提交且说明原因，恢复后可继续输入。
- [x] 支持语言的 fenced code 使用本地 Tree-sitter scope 高亮；别名归一、light/dark token、语言标签和复制动作正确。
- [x] 未知语言、无语言、超出大小上限、Worker/WASM/query 加载失败时原始代码完整可读，不阻断其它 Markdown 或 Run streaming。
- [x] syntax Worker 和资产只能从固定 `/web/` 白名单读取；不接受路径穿越、任意文件名或远端 URL，CSP 只增加 WebAssembly 所需的最小权限。
- [x] 空的已结束 Assistant message 不渲染；Assistant avatar 不再承载 `Harness` 长文本，角色名称在独立 header 中可读。
- [x] Sidebar 去除重复标题；User/Assistant/Tool/Interaction 使用 design 指定的共享边、组内/组间间距和正文 measure。
- [x] 发送/取消、icon button、普通按钮和移动端操作遵守统一尺寸层级；所有目标至少满足 24×24px，390px 主要触控目标达到 44×44px，扩展 hit area 不重叠。
- [ ] 1440×900 与 390×844 的 light/dark 页面无根横向滚动、重叠、裁切或不可达主要操作；200% zoom 与 320px reflow 保持可用，代码/表格仅在自身容器横向滚动。
- [ ] Web focused tests、`bun run build`、`bun run typecheck`、`bun run test` 与 `bun run project:check` 通过；open-code-review 结论及复检证据写入任务。
