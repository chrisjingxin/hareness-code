## 背景

最终架构方案 §13（测试与质量门禁）与 §14（12 条验收标准 A-01~A-12）要求每个架构承诺都有可观察证据。现有 ZC-105（待认领）描述的 E2E scope 基于旧架构（Browser 直连 Agent attachment + host.control 转移），在 ZC-114 落地后流程已改变，必须重定 scope 后执行。

12 条验收（方案 §14）：

| 编号 | 验收项 | 主要归属任务 |
| --- | --- | --- |
| A-01 | CLI 一次运行只创建一个 InteractiveController | ZC-113 |
| A-02 | TUI/Web 均不直接解析 Agent Event，共享 Timeline reducer 唯一 | ZC-114 |
| A-03 | Browser 不创建 AgentClient/Controller，不连接 Python Host | ZC-114 |
| A-04 | Handoff 只改变 Presentation owner，Host owner 不变 | ZC-114 |
| A-05 | TUI→Web→TUI 后 Thread/Timeline/Run/Interaction/Catalog/Selection 连续 | ZC-114 |
| A-06 | dispatch 均返回 IntentOutcome，拒绝不清空 draft | ZC-110 |
| A-07 | interactive 对 ipc/react/opentui/dom/websocket 零依赖 | ZC-109 |
| A-08 | Presentation 统一消费 FeatureAvailability，不查协议 Capability | ZC-112 |

## 当前存在的问题

1. 各验收项散落在任务验收清单中，缺一个集中、可重复执行的验收矩阵与证据台账。
2. 架构测试（§13.2）目前只有 tests/tui、tests/web 的局部 regex 断言，缺少 interactive 零依赖（ZC-109 已建）、Browser 无 AgentClient、单 Composition Root、presentation-shared 纯净性等全量断言；且无工具化集成（§13.2 禁止仅靠目录白名单/正则字符串代表完整架构约束——需要把架构断言统一收口）。
3. ZC-105 的 Playwright E2E scope 描述旧流程（fragment attachment、host.control acquire/release、TUI 卸载重建），与 ZC-113/114 后的真实流程不符。
4. 仓库尚无 Playwright 依赖、E2E script 与浏览器 fixture（ZC-105 原样成立）。

## 为什么现在要修改

- 阶段 7 完成后，最终架构的所有能力已就位，必须用统一验收矩阵固化（方案 §13.3 端到端场景：TUI 新建 Thread → /web → Web 操作 → 返回 TUI → 状态连续 → 验证 Controller 未重建、Host holder 未转移）。
- 仓库完成定义要求任务完成前有 open-code-review 检视与可审计证据；集中验收矩阵是各任务证据的总闸门。

## 目标设计

### 1. 验收矩阵（tests/architecture-acceptance/ 或 scripts 驱动）

- 新增 `packages/cli/tests/acceptance/`：按 A-01~A-12 逐项建测试文件（A-01/A-06/A-07/A-08/A-12 为静态/单元级，A-02/A-03/A-09/A-10/A-11 为架构测试或 syntax 测试，A-04/A-05 为集成级）。
- 架构断言统一收口：把 tests/tui、tests/web 的 regex 断言迁移/合并为共享 helper（`tests/acceptance/arch-imports.ts`），并补缺项（interactive 零依赖、Browser 无 AgentClient/host.control、createInteractiveController 单调用点、presentation-shared 纯净、Web 无 dangerouslySetInnerHTML）。
- 每项验收记录命令 + 输出摘要（写入本任务 test_evidence）。

### 2. ZC-105 重定 scope

- 改写 `docs/developer/tasks/ZC-105.md` 的 scope/acceptance/references：按最终架构描述 E2E（WebUiGateway WS、UI token、state.replace/patch、intent/intent.outcome、handoff.state），删除 attachment/host.control 描述；状态保持待认领，完成证据并入本任务（ZC-105 作为本任务的交付物一并关闭）。

### 3. Playwright E2E fixture（承接重定后的 ZC-105）

- 依赖：固定版本 Playwright（`@playwright/test`），独立 script `test:web:e2e`（根 package.json），不读取真实 API Key。
- fixture：测试专用 CLI 启动入口（fake Agent 模式，参照 tests/gateway.integration.test.ts 的 HARNESS_ECHO/loopback 模式）→ 真实 Bun Web server + 真实 Browser。
- 场景分组：
  - smoke/parity：空首页首条消息、DOM/IME/Enter 发送、失败保留输入、代码高亮、Interaction approval/question、取消、Thread/catalog/command parity。
  - lifecycle：第二窗口拒绝、ready 超时、断线重连（state.replace 重同步）、active Run 下关闭、CLI exit 收敛、返回 TUI 后状态连续 + Controller 未重建（通过页面侧 marker 或 CLI 日志断言）。
  - security：UI token 单次/Origin 绑定、消息类型/大小/乱序 revision 拒绝、Web 页面无 Agent endpoint/token 泄漏（页面源码/console 断言）。
  - visual-a11y：1440×900 light/dark 与 390×844 light/dark 四组基线截图 + 键盘/ARIA 验收（沿用 ZC-106/107 的基线策略）。

### 4. 文档闭环

- `架构总览.md` 补"验收矩阵"小节（或引用本任务）；`docs/user/交互使用.md` 与 `故障排查.md` 按 ZC-114 流程核对更新；确认无 Harness Session 概念残留（grep 代码/文档/协议）。
