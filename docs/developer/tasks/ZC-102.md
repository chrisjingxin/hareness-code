## 背景

当前 `WebLauncher` 会建立 ThreadWatch、启动一个静态 Bun server 并直接打开带 attachment token 的页面。它没有表达一次 Web 接管的 identity 和状态，也无法区分第一个窗口、刷新、第二窗口、页面 bootstrap 失败和正常返回。

本任务在 CLI 侧建立 Web 生命周期深模块。它只协调 browser、attachment 和 Host holder，不代理 Agent JSON-RPC，也不持有聊天、Run 或 Interaction 业务状态。

## 当前存在的问题

- `/web` 依赖已有 Thread，不能从空首页启动。
- TUI 继续显示和接受输入，Web 只作为 watcher/第二输入源存在。
- 静态 server 没有 session path、精确 Host/Origin 校验和资源白名单。
- 没有第二窗口拒绝、ready timeout、正常“返回 TUI”或 CLI 主动 shutdown 协议。
- lifecycle 在浏览器 bootstrap 完成前断开时，没有 AbortSignal 关闭 Agent socket；已取得控制权的连接可能永久锁住 TUI。
- Web 清空当前 Thread 后，CLI 无法区分“没有 Thread”和“未提供更新”，归还时可能恢复旧 Thread。

## 为什么现在要修改

Web 页面必须先有一个可靠的宿主生命周期，才能安全接入完整聊天能力。把 timeout、窗口竞争和控制权恢复分散到 launcher、TUI React effect 和页面代码中，会形成无法整体测试的浅模块。

## 目标设计

新增 `WebSessionCoordinator`，对外只暴露 `open`、`snapshot/subscribe`、lifecycle 消息入口和 `close`：

```text
idle
  → opening：创建 session + attachment，启动页面
  → active：lifecycle accepted，Web acquire，页面 ready
  → returning：关闭/撤销 attachment，等待 Host owner
  → idle：TUI 恢复 lastThreadId 或明确空首页
```

浏览器与 Bun lifecycle WebSocket 只传递：

- `accepted`：第一个窗口获得当前 session；在此之前不能认证 Agent attachment。
- `ready`：Web 已 acquire 且应用初始化完成。
- `thread.changed`：字段为 `string | null`，`null` 明确表示空首页。
- `released`：Web 已请求归还；CLI 仍需查询 Host 确认。
- `shutdown`：CLI 退出、超时、第二窗口或非法 session。

任何 lifecycle close/shutdown 都必须触发 bootstrap AbortSignal，关闭 Browser AgentClient；CLI 同时 revoke attachment，并持续查询 `host.control.status`，只有 owner 恢复后才解锁 TUI。

## 实施步骤

1. 新增 `WebSessionCoordinator` 状态机和只读 snapshot；session ID 使用 256-bit 随机值，状态转换集中在一个 module。
2. 改造 `WebLauncher`：页面使用 `/web/s/<session-id>`，endpoint/token/attachment/thread 只进入 URL fragment，页面读取后立即清除。
3. 增加 lifecycle `accepted` 握手；第二 socket 在 attachment 认证前收到 `already-open` 并关闭。
4. 在 browser bootstrap 最早阶段注册 abort/close handler；timeout、普通 close 和 shutdown 都关闭 Agent socket，不能等 React mount 后再注册。
5. opening 失败或 65 秒未 ready 时 revoke attachment；正常/异常归还都等待 Host status 确认 owner。
6. 将 TUI 接入 coordinator snapshot：非 `idle` 时只渲染静态接管页，不订阅或镜像 Web 聊天；归还后通过 `threads.open` 恢复 nullable lastThreadId。
7. CLI `/quit` 或 Web shutdown request 顺序关闭 lifecycle、静态 server、AgentClient 和 Python Host。
8. 增加状态机、真实 loopback lifecycle、第二窗口、nullable Thread、timeout/abort、revoke 和关闭顺序测试。

## 范围

- CLI Web session identity、lifecycle channel、静态资源 server 和 TUI lock。
- browser bootstrap 的连接/中止协议，不包含页面业务 UI。
- Host 控制权确认后的 Thread 恢复。
- 本机页面 Host/Origin、CSP、no-store、no-referrer 和资源白名单。

## 非范围

- 不代理 Agent JSON-RPC、Event 或聊天消息。
- 不实现浏览器刷新恢复 active Run；刷新等同关闭当前 Web session。
- 不实现多个前台 Web 窗口或多项目 daemon。
- 不实现 Web 的 Thread、模型、Skill、MCP 具体界面。

## 验收清单

- [ ] `/web` 从空状态和已有 Thread 都能进入 `opening → active`，TUI 只显示静态接管页。
- [ ] 第二窗口在认证 attachment 前被拒绝，不能取得 token 或控制权。
- [ ] ready timeout 和 bootstrap 任意阶段断线都会 abort 页面连接、revoke attachment 并最终恢复 owner。
- [ ] active Run 下页面关闭会先取消并收敛该 Web Run，TUI 在 Host 确认前保持锁定。
- [ ] Web 报告 `thread_id: null` 后归还，TUI 回到首页；非空值通过 canonical `threads.open` 恢复。
- [ ] CLI 退出会关闭页面、server、attachment 和 Host，不遗留监听端口或后台任务。
- [ ] lifecycle 畸形帧、重复消息、过期 session 和终态错误均有回归测试。
