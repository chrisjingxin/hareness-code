## 范围

- 在 Model Picker 的确认流程增加明确、默认关闭的“同时设为后续新 Thread 默认”选择；也可由受 Registry 解析的等价参数触发，但不得把裸 `/model <profile>` 隐式升级为配置写入。
- 复用 ZC-071 的预览、CAS、来源/策略锁、完整 TOML 校验和原子写入服务，仅允许更新用户级 `models.default_profile`。TUI 不能拼接或直接编辑 TOML；写入请求、diff、日志与错误必须脱敏。
- 将当前 Thread 选择与默认更新拆为两个结果：当前 Thread 成功后即可等待下一次 Run；默认写成功只影响之后创建的 Thread；默认写失败保留当前 Thread 选择并给出可操作错误。
- 更新状态栏、Picker、`/status` 与用户文档，清楚区分“当前 Thread 下一次 Run”“未来新 Thread 默认”“已运行历史实际模型”。

## 非范围

- 不修改 Profile 的 endpoint、Header、API Key、Provider、能力、角色绑定、执行策略或项目配置。
- 不允许受 managed policy 锁定、来自环境变量/CLI/显式外部 `--config` 的默认值被静默写回用户 TOML；不实现跨设备同步或配置市场。
- 不实现 Agent/角色级默认模型、动态 Subagent 的默认模型编辑或运行中模型切换。

## 验收清单

- 仅选择模型时用户 TOML 字节不变；勾选默认并确认后，新的空 Thread 与重启后的新 Thread 使用新的默认 Profile，既有 Thread 继续从自己的最近选择恢复。
- CAS 冲突、managed lock、非用户来源、无效/不可用 Profile、权限/磁盘/解析失败均不破坏原文件、不泄漏秘密，并不撤销已经成功设置的当前 Thread 选择。
- Python 覆盖 Config Writer 的预览、锁、原子失败恢复和重启读取；TypeScript 覆盖确认/取消、双结果提示、焦点恢复和错误显示；协议、类型、用户/开发文档及项目级检查通过。
