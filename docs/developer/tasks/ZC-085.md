## 背景

当前生产执行路径已经固定为：

```text
AgentHost → RuntimePool → create_harness_agent() → DeepAgents graph
```

仓库中仍保留了几组为未来方向提前实现、但没有接入上述路径的代码。它们拥有完整类型、校验和测试，看起来像已经生效的领域能力，实际只在自己的单元测试中运行。

## 当前存在的问题

### 1. Agent catalog 没有生产 seam

`packages/agent/harness_agent/agent_catalog.py` 约 843 行，定义了 AgentDefinition、ExecutionPolicy 和 catalog 解析，但生产代码没有 import 或动态加载入口。当前主 Agent 仍由 `create_harness_agent()` 固定构建，Plugin Agent 也没有进入运行路径。

这意味着 catalog 的 interface 没有调用方。删除它不会把复杂度推回其他 module，符合 deletion test。

### 2. Unicode 安全实现没有生产调用方

`packages/agent/harness_agent/unicode_security.py` 约 568 行，只被对应测试使用。审批 DTO、Shell guard、路径 guard 和 MCP handler 都没有调用它，因此测试通过不能证明用户获得了 Unicode 风险保护。

### 3. ToolBatch 是另一套未启用的执行器

`packages/agent/harness_agent/concurrency.py` 中 `ToolBatch`、`partition_tool_calls()`、`execute_batches()` 和 `_execute_parallel()` 只在测试中使用。生产并发控制实际由 `concurrency_guard.py` 调用 `is_concurrency_safe()` 与 `AsyncRWLock` 完成。

两套并发模型同时存在，会让维护者误以为批执行器已经接管工具调度。

### 4. ThreadStore 存在字面重复实现

`get_model_bindings()` 与 `save_model_bindings()` 在 `thread_store.py` 中各定义了两次。Python 后一个定义会覆盖前一个定义，因此前一份代码和对应行级理解没有运行意义。

### 5. 测试正在固化不存在的产品能力

`test_agent_catalog.py`、`test_unicode_security.py` 和 `test_concurrency.py` 的部分用例只验证不可达 implementation。它们增加测试数量，却不能保护生产行为，还会阻止后续按照真实 seam 重新设计。

## 为什么现在要修改

- 后续模型绑定、Run lifecycle 和 Thread persistence 重构都会扫描这些 module；先删除伪领域可以显著降低错误依赖和 AI 导航噪声。
- 保留“已实现但未接入”的安全模块容易产生错误安全预期，比明确标记未实现更危险。
- 这些删除不需要产品决策、数据迁移或兼容 adapter，是其他 P0 前成本最低的基线清理。

## 目标状态

```text
当前生产需要
├─ concurrency.py
│  ├─ is_concurrency_safe()
│  └─ AsyncRWLock
├─ ThreadStore 当前有效方法
└─ create_harness_agent() 固定主 Agent

未来出现真实调用方
└─ 在真实 seam 上重新实现最小 Agent catalog / Unicode 检测 / 批执行
```

本任务不创建替代 module。删除后如果复杂度没有在生产调用方中重新出现，就说明这些代码原本没有产生 leverage。

## 实施步骤

1. 使用 production-only import/call 搜索确认目标没有反射、entry point 或动态字符串加载路径。
2. 删除 `agent_catalog.py`、`unicode_security.py` 及其专属测试。
3. 只从 `concurrency.py` 删除 ToolBatch 批执行路径；保留生产使用的安全分类和读写锁。
4. 删除 `ThreadStore` 中被后一定义覆盖的那组重复方法，并确认保留实现的行为测试仍通过。
5. 清理文档、类型 import 和测试 fixture 中对这些假设能力的引用。
6. 运行全量检查，确认 diff 中没有替代 abstraction 或用户可见行为变化。

## 范围

- 用生产 import 与调用链再次确认 `agent_catalog.py`、`unicode_security.py` 和 `concurrency.py` 中 ToolBatch 路径不可达后删除。
- 删除只验证这些假设实现的测试。
- 删除 `ThreadStore` 中重复定义的模型绑定方法。
- 删除过程中发现的同类无调用方 interface，但不得扩大为业务重构。

## 非范围

- 不实现 Plugin Agent、Unicode 审批提示或并发工具执行。
- 不改变 Protocol、数据库 schema 或用户可见行为。
- 不创建替代 abstraction；出现真实调用方后再设计 seam。

- [ ] `ThreadStore` 的模型绑定方法只剩一份有效实现。
- [ ] 全量 TypeScript 与 Python 测试通过。
- [ ] `git diff` 只包含删除和必要的引用清理。
