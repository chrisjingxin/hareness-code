## 服务的用户结果

本任务先关闭当前已经确认的 silent corruption 风险：模型不能再提交 unified diff，让 Harness
在 old/context 不匹配时仍按行号写成功。

## 当前问题

`packages/agent/harness_agent/tools/tools_file.py::_apply_hunks()` 根据 `old_start` 与带 `-`/
context 的行数直接替换切片，不比较这些旧行是否真的出现在目标位置。错误 patch 可能返回成功
并改错文件内容。

## 实施步骤

1. 增加最小回归 fixture，固定“hunk 行号指向 ccc、patch 却声称删除 bbb”会被现实现错误
   应用的事实；随后移除生产入口，不保留危险实现用于运行时。
2. 从 `create_harness_tools()`、`_BUILTIN_TOOL_SHAPES`、deferred tool catalog、工具风险/并发
   分类和 Capability 默认集合移除 `apply_patch`。
3. 删除 `tools_file.py` 中 unified diff parser/applier，只保留并收紧 `delete_file`；同步中文
   文件说明和测试名称。
4. 删除 Permission legacy mapping、审批规则和测试中对 `apply_patch` 的 canonical 期待；不
   保留 alias 或 fallback。
5. 更新用户/架构文档，明确现阶段修改已有文件只使用 `edit_file`，不宣称 Snapshot 已完成。
6. 运行文件工具、runtime、policy、approval focused tests，再运行 Agent 全量和项目检查。

## 明确不修改

- 不改变 DeepAgents 内置 `read_file/write_file/edit_file` schema。
- 不提前实现 ZC-131 SnapshotStore 或 MutationService。
- 不新增另一种 patch 工具名，也不通过 shell 包装 `patch` 作为替代。
