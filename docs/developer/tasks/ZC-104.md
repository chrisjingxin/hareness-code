## 背景

当前 Web 页面是约 200 行的直接 DOM 脚本，只能打开一个已有 Thread、发送消息并用浏览器 `confirm/prompt` 处理 Interaction。它声明 `run.multithread`，通过 ThreadWatch 展示 Event，缺少当前 TUI 的大部分工作流。

ZC-102 提供可靠的独占 handoff 生命周期，ZC-103 提供 Interactive Core interface。本任务只实现 Web Interactive Adapter 和 React DOM presentation，不再定义第二套 RPC、命令 dispatcher 或交互业务状态。

## 当前存在的问题

- Web 不能从空状态创建 Thread，也不能新建、恢复或切换 Thread。
- 模型、Skill、MCP、compact、status 和 Slash Command 不完整。
- approval/question 使用同步浏览器弹窗，无法呈现动态 decision、多问题、多选和反馈。
- Tool、Markdown、流式输出和错误状态展示过于简化。
- 页面没有明确的返回 TUI、active Run 禁止归还、移动端导航和浅/深色设计。
- 直接 DOM handler 容易绕过共享 command availability 和 controller invariant。

## 为什么现在要修改

在 lifecycle 和 Interactive Core 完成前扩展页面只会增加重复逻辑。本任务依赖两个 seam 后，Web 可以保持为轻量 Interactive Adapter，功能对齐由 `InteractiveController` 保证，页面工作集中于可用性和信息层级。

## 目标设计

```text
Browser event
  → Web Interactive Adapter 转换为 InteractiveIntent
  → InteractiveController
  → InteractiveSnapshot
  → React DOM presentation
```

Web 视觉参考 Codex/Claude 的工作台风格：桌面左侧 Thread 导航、中央紧凑时间线、底部 composer；移动端 Thread 使用抽屉。界面使用现有 `lucide-react` 图标、克制边框和小圆角，不使用营销式 hero、嵌套卡片或大面积装饰。

页面必须支持：

- 空首页第一条消息创建 Thread；
- Thread 新建、列表刷新、恢复和切换；
- 流式 Markdown/GFM、Tool 折叠、Run 状态和取消；
- 动态 approval/question 与反馈；
- 模型选择、Skill 选择/启停、MCP 查看/添加/删除；
- compact、status、help、version 和所有现有 Slash Command；
- 返回 TUI 与退出 Harness；active Run/Interaction 时禁止归还和切换 Thread。

## 实施步骤

1. 将 `packages/cli/src/web/app.ts` 改为 React DOM Interactive Adapter；transport/auth bootstrap 与页面组件分离，避免单文件同时拥有生命周期和所有 UI。
2. 通过共享 Controller 的 `dispatch/snapshot` 实现 composer、命令菜单和 Timeline；禁止 Web 自建 command switch 或直接解释 RPC 结果。
3. 实现桌面 Thread sidebar 与移动端 drawer；Thread 为空时显示可直接输入的工作区首页。
4. 实现 Markdown/GFM（禁用 raw HTML）、Tool、Interaction、取消和错误/断线状态。
5. 实现模型、Skill、MCP、status 面板；所有 capability、busy 和参数校验来自共享 snapshot/result。
6. 接入 ZC-102 lifecycle：ready、nullable `thread.changed`、return、shutdown 和 bootstrap abort。
7. 完成浅/深色 CSS、键盘焦点、ARIA、响应式稳定尺寸和长文本/长工具输出处理。
8. 增加 Interactive Adapter intent 映射与关键 presentation 测试；真实浏览器矩阵留给 ZC-105。
9. 更新用户交互文档，准确说明 `/web`、返回、关闭/刷新和运行中限制。

## 范围

- React DOM Web Interactive Adapter 和完整工作台 UI。
- 当前 TUI 已交付能力的 Web parity。
- 桌面/移动端、系统浅/深色、键盘与基本可访问性。
- Web Interactive Adapter/presentation 的 focused tests 和用户文档。

## 非范围

- 不实现 settings、权限编辑、远程登录、多租户或 daemon discovery。
- 不支持刷新后恢复 active Run，也不实现 Event replay。
- 不在 Web 中代理或复制 AgentHost、RunCoordinator 和 Command dispatcher。
- 不改变 TUI 已有产品语义；发现差异时修复共享 Controller。

## 验收清单

- [ ] Web Interactive Adapter 的所有聊天和管理动作都转换为共享 `InteractiveIntent`，没有平行 command switch 或业务 reducer。
- [ ] 空状态、Thread 新建/恢复/切换、流式消息、Tool、取消和完整 Interaction 可用。
- [ ] 模型、Skill、MCP、compact、status 和所有可用 Slash Command 与 TUI 行为一致。
- [ ] `//` 转义、未知命令建议、命令参数错误和 busy/capability 禁用与 TUI 产生相同 semantic result。
- [ ] active Run 或待处理 Interaction 时不能切换 Thread或返回 TUI，但仍可执行允许的只读命令和取消。
- [ ] 1440×900 与 390×844 下主操作可见、文本不重叠；浅/深色均有足够对比度和清晰焦点。
- [ ] Markdown 不执行 raw HTML，工具输出和用户输入不会注入 DOM。
