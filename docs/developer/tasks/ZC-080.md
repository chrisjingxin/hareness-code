## 范围

- 落地 ZC-081 已批准的 `AgentDefinition` 与 `ExecutionPolicyDefinition` schema。它们只描述未来由 Plugin 提供、可被内置主 Agent 动态派发的子 Agent：职责、Markdown 指令、输入/输出 JSON Schema、成功标准、默认 `model_profile`、`execution_policy` 和扁平 instruction fragments 均在 Agent 中声明；工具、文件、Shell、网络、隔离、审批与 delegation 边界只在 Policy 中声明。
- `main` 不是 AgentDefinition：它继续由 `create_harness_agent()` 和现有可信 TOML/代码路径构建，不能由 JSON、用户目录、工作区或 Plugin 覆盖。TOML `ModelProfile` 仍是模型与连接配置的唯一来源；不引入 `$default` 等 Agent 专用模型别名。
- Catalog 不自行扫描 `~/.harness/`、工作区或包内目录，只接受未来 ZC-041 Plugin loader 已完成信任校验后显式传入的 `PluginAgentSource(plugin_id, root)`。每个 Plugin 根目录内仅允许 `agents/*.json` 与配套 Markdown、`policies/*.json`、`instructions/*.md`、`schemas/*.json`；来源间 Agent/Policy ID 必须全局唯一，不做覆盖合并。
- 解析器必须校验 ID、引用、文件归属、symlink、JSON Schema、模型可用性和策略合法性；扁平 fragment 列表不支持嵌套引用，因此循环在结构上不可表达。非法项只产生脱敏诊断，不进入 catalog。
- 提供后端使用的只读 Agent/Policy catalog DTO、稳定内容指纹与纯 Policy 交集。ZC-038 后续将 managed/global envelope 接入该交集，ZC-015 再将父 Agent delegation envelope 和动态 `task` 接入实际 spawn。

## 非范围

- 不改变当前主 Agent Runtime、Prompt、模型选择、审批或 `task` 行为；不让 Agent catalog 指纹进入当前 root RuntimeProfile。
- 不实现 Plugin 安装、签名/信任验证、目录发现或热加载；ZC-041 负责验证并传入 Plugin 根目录。
- 不实现 Agent 定向 `/model`、Subagent 生命周期、执行树持久化、TUI `/agent`、固定 Workflow、Team、Mailbox、远端 Agent 或在线编辑。
- 不让 Agent/Policy 文件存放 API Key、Header、Provider endpoint、Shell Hook 或任意可执行代码。

## 验收清单

- 仅显式传入的合法 Plugin 根目录可生成 Agent/Policy/fragment/schema catalog；主 Agent `main` 不存在于该 catalog，且不存在用户、项目或包内目录扫描。重复 ID、路径逃逸、symlink、非法 JSON/Schema、丢失引用、不可用模型和非法 Policy 均被拒绝或忽略，并保持其他可用 Plugin 项。
- 目标 Agent 请求写文件、Shell、网络、审批豁免或进一步 delegation 时，Policy 交集不会超过调用方 envelope；所有交集和拒绝路径有 mock 单元测试。ZC-038 和 ZC-015 必须复用此入口，不能另建提权路径。
- 相同 catalog 产生相同 snapshot；Agent、Policy、Prompt 或 Schema 内容变化产生新 snapshot。诊断、DTO 与 snapshot 不暴露 Prompt 正文、凭据、完整 endpoint 或 Plugin 根目录路径。
- Python catalog/安全测试以及相关文档和项目检查通过。
