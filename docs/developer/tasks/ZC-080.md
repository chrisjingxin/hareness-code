## 范围

- 落地 ZC-081 已批准的 `AgentDefinition` schema 与目录发现：Agent 身份、目的、Markdown 指令、输入/输出 JSON Schema 引用、成功标准、默认 `model_profile`、`execution_policy` 和可复用 instruction fragments 均归属于 Agent；不再单独引入 Role 或 Persona 配置对象。
- 落地 ZC-081 已批准的 `ExecutionPolicyDefinition` schema：工具、文件、Shell、网络、隔离、审批与 delegation 边界只在 Policy 中声明。解析后的有效策略必须是全局/managed policy、父 Agent delegation envelope 与目标 Agent policy 的交集，任何子 Agent 定义都不能获得父 Agent 未授予的权限。
- 用户目录与可信项目目录分别发现 JSON 定义、配套 Markdown 和 JSON Schema；项目覆盖与同名冲突使用稳定规则。解析器必须校验 ID、引用、路径归属、循环 fragment、JSON Schema、模型可用性、策略合法性和来源信任；非法项提供脱敏诊断而不进入 catalog。
- 保持现有 TOML v1 的 `[models]`/ModelProfile 为模型与连接配置唯一来源。本任务不提前抽取 ProviderDefinition 或改变 endpoint/凭据契约；Agent/Policy catalog 的内容和文件指纹进入 Runtime Profile，实际解析摘要由后续 RunExecutionBinding 记录。
- 提供仅供后端和未来 TUI 使用的只读 catalog DTO/查询边界；动态 `task` 工具注册、Subagent 生命周期和 TUI `/agent` 选择不在本任务实现。

## 非范围

- 不实现固定 Planner→Executor、AgentWorkflowDefinition、Coordinator、Mailbox、并行 Team、远端 Agent、Agent 市场或 Agent 在运行中编辑自身定义。
- 不让项目定义在 ZC-037 的可信判定之前自动加载；不让 Agent/Policy 文件存放 API Key、Header、Provider endpoint 或任意可执行 Hook。
- 不变更当前主 Agent 的全局 execution/approval 实际行为，也不实现 Agent 定向 `/model` 覆盖。

## 验收清单

- 用户和可信项目的合法 Agent/Policy/fragment/schema 可按来源、ID 与完整指纹解析；重复 ID、路径逃逸、symlink、非法 JSON/Schema、丢失引用、循环 fragment、不可用模型和未可信项目均被拒绝并保持旧 catalog。
- 目标 Agent 请求写文件、Shell、网络、审批豁免或进一步 delegation 时，解析结果不会超过根 Agent/managed policy 边界；所有策略交集和拒绝路径有 mock 单元测试。
- 相同 catalog 可复用 Runtime，不同 Agent/Policy/fragment 内容产生新的 Runtime Profile；诊断、DTO、Profile record 与错误不暴露 Prompt 正文、凭据、完整 endpoint 或工作区外路径。
- Python 配置/发现/安全/RuntimeProfile 测试、协议/类型测试及用户和开发文档检查通过。
