## 背景

当前 DOM 名为 `desktop-workspace`，CSS 强制 `min-width: 1280px`。这使窄屏不是“体验较差”，而是核心内容物理不可达。本任务只解决布局状态与几何，不顺带重做 Timeline 或动效。

## 当前存在的问题

- 390px 视口实测根 scrollWidth 为 1280px，Conversation 从 x=280px 后开始，Composer 完全离开首屏。
- 1280px 打开 280px Sidebar 和 440px Dock 后，Conversation 内容约 512px。
- Sidebar 当前没有 open/close 状态；Dock 只有 open/width，不能表达 column/overlay/fullscreen。
- 200% zoom 会产生与窄视口相同的 reflow 问题，但现有结构没有降级路径。

## 目标设计

```text
viewport-set
  → wide：Sidebar + Conversation + 可选 column Dock
  → compact：Sidebar + Conversation，Dock overlay
  → narrow：Conversation，Sidebar/Dock 互斥 drawer；Code 可 fullscreen
```

Viewport 是 Web 表现状态，不进入 Interactive Core、Protocol 或持久化。精确断点与状态归一见 [ZC-124 设计](../designs/ZC-124.md)。

## 实施步骤

1. 在 Adapter 增加 `WebViewportMode`、Sidebar open 和 Dock presentation，并提供 `viewport-set/sidebar-open/sidebar-close` intent。
2. WebApp 用 `matchMedia`/ResizeObserver 把等效宽度映射为 wide/compact/narrow；事件只更新 Adapter 表现状态。
3. 重构 shell grid，移除根 `min-width`；为 Conversation 建立 640px 列式下限和局部滚动 invariant。
4. Compact 下把 Dock 变为右侧 overlay；Narrow 下 Sidebar/Dock 互斥，Code 使用 fullscreen，其他 Dock 使用 sheet。
5. 精简窄屏 Topbar，并保证返回 TUI、主题、Model、Approval 和退出仍能从 overflow 到达。
6. 为 viewport 迟到、宽度 clamp、互斥 open、Escape、状态保持和根 overflow 增加 focused tests。
7. 更新 Web 界面文档的桌面/窄屏行为。

## 范围

- `web/application/adapter.ts` 的 viewport/面板纯表现状态。
- `web-app.tsx`、WorkspaceSidebar、ContextDock 和响应式 CSS。
- 对应 adapter/presentation/browser geometry tests。

## 非范围

- 不改变业务 capability、Thread/Run/Interaction 状态。
- 不引入移动端专用业务组件；同一组件只改变 presentation。
- 不在本任务调整 Tool 分组、空态文案或动效。
- 不持久化用户布局宽度或 viewport。

## 验收清单

- [ ] 目标视口、320px reflow 和 200% zoom 无根横向滚动。
- [ ] Wide 列式 Conversation ≥640px，外围宽度变更会 clamp。
- [ ] Compact Dock overlay 不改变 Conversation 几何；Narrow Sidebar/Dock 互斥。
- [ ] Composer、Cancel、pending Interaction 和 scroll-to-latest 在所有模式可见可达。
- [ ] viewport 切换不清空 draft、Timeline、Tool 展开或当前 Run。
- [ ] focused tests、`bun run build`、`bun run typecheck` 通过。
