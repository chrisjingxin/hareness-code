## 背景

Harness 已经区分两个领域事实：

- `ThreadExecutionSelection`：当前 Thread 对下一次 Run 的可变意图。
- `RunExecutionBinding`：某次 Run 实际使用模型的不可变事实。

当前 JSON-RPC v3 的 `run.start` 可以携带 `model_selection`，SQLite 也保存了 requested selection、actual primary binding 和 Runtime Profile ID。但这条能力是分阶段叠加出来的，领域知识没有集中在一个 module 中。

当前调用链大致为：

```text
TUI threadModelSelection
  → run.start.model_selection
  → AgentHost._resolve_run_model_bindings()
  → ModelRouter / legacy ThreadModelBindings
  → AgentHost._resolve_runtime_profile()
  → ThreadStore.record_run_start(raw mappings)
  → run.started.primary_model
  → TUI actualModelProfile
```

## 当前存在的问题

### 1. 选择优先级由 Server 私有方法拥有

`AgentHost._resolve_run_model_bindings()` 同时解释：

1. 本次请求显式选择；
2. 最近 Run 恢复的 Thread 选择；
3. v5 legacy Thread 模型绑定；
4. 全新 Thread 的配置默认值。

这属于模型选择领域规则，却位于 transport/protocol implementation 中。任何非 JSON-RPC 调用方都必须复制或绕过这套规则。

### 2. 同一个概念存在多种表示

- `model_router.py` 使用 `ThreadModelBindings`。
- `server.py` 在 `ActiveRun` 上保存 `requested_model_selection`、`primary_model_binding` 等原始 `dict`。
- `thread_store.py` 的 `RunExecutionBinding` 仍把 selection 和 primary binding 暴露为 `dict`。
- Protocol 使用生成类型。
- TUI 同时维护 `threadModelSelection` 与 `actualModelProfile`。

调用方需要知道各字典字段、来源字符串和兼容分支，interface 几乎和 implementation 一样复杂。

### 3. 校验、脱敏和持久化构造分散

模型可用性由 `ModelRouter` 校验；Run binding 字段由 Server 拼装；SQLite 再用 `_validate_run_selection()` 与 `_validate_actual_primary_binding()` 二次解释。来源值如 `thread-primary`、`thread-recovered`、`legacy-binding`、`config-default` 也由 Server 手写。

新增或修正一种来源时，需要同时修改多个 module，容易出现“运行模型正确，但历史记录或 TUI 展示错误”。

### 4. legacy 兼容泄漏到当前路径

`_thread_model_binding_summary()`、`get_model_bindings()`、`get_runtime_profile()` 和 ModelRouter 的 record 转换都暴露给 Server。当前调用方必须理解 v4/v5 表结构，legacy 不再是 persistence implementation 的内部细节。

### 5. 测试依赖 Server private implementation

模型优先级、恢复和绑定测试需要通过 `AgentHost` 私有方法或大型 run.start setup 才能覆盖。测试不能直接表达“给定选择与历史，应该产生什么不可变执行事实”。

## 为什么现在要修改

- [ZC-089](ZC-089.md) 要提取 Run lifecycle；若模型解析仍属于 Server，新的 Run module 只能继续调用 Server private 方法或复制规则。
- 当前已经同时存在新 Run binding 与两代 legacy 记录，继续增加兼容分支会快速放大迁移风险。
- 多前端共享 Protocol 后，实际执行事实必须完全由 Python Core 确认，TUI/Web 不能各自推断。
- 这是纯领域计算为主的 in-process module，可以先建立稳定 interface，不需要新增远程 port 或依赖。

## 目标设计

建议建立一个模型与执行绑定 module，例如 `execution_binding.py`。具体文件名可调整，但 interface 必须保持小而类型化：

```python
class ExecutionBindingResolver:
    def resolve(self, request: ResolveBindingRequest) -> ResolvedExecutionBinding: ...
    def describe_thread(self, state: PersistedBindingState) -> ThreadBindingView: ...
```

`ResolveBindingRequest` 只包含已经读取出的领域输入：

- 请求中的 primary Profile ID；
- 最近 Run 的 `ThreadExecutionSelection`；
- 可选 legacy 模型绑定；
- 当前 `ModelCatalog` 与默认 Profile；
- 构造事实所需的 thread/run identity。

`ResolvedExecutionBinding` 至少包含：

- 类型化 `ThreadExecutionSelection`；
- 已解析且可用于 Runtime 构建的模型绑定；
- 类型化 actual primary model 与稳定 source；
- 可直接持久化的不可变 Run binding 值。

目标依赖关系：

```text
Config adapter ───────┐
SQLite adapter ───────┼→ ExecutionBindingResolver → RuntimeProfile builder
run.start adapter ────┘                           → Thread persistence
                                                  → Protocol event adapter
```

选择优先级、legacy 转换、可用性校验、source 和脱敏只在该 module 中出现。SQLite 仍由 `ThreadStore` 实现，不为唯一数据库另建 repository port。

## 实施步骤

1. 为 `ThreadExecutionSelection`、actual primary binding、source 和 resolved result 建立 Python 类型，禁止在 module interface 使用 `dict[str, object]`。
2. 将 `_resolve_run_model_bindings()` 的优先级和 `ModelRouter` 的兼容转换收进 resolver。
3. 将 `_validate_run_selection()`、`_validate_actual_primary_binding()` 的领域校验移到类型构造阶段；ThreadStore 只负责序列化、反序列化和损坏诊断。
4. 让 `_resolve_runtime_profile()` 只消费 resolved model binding，不再反向读取 Thread 或重新执行选择逻辑。
5. 让 `record_run_start()` 接收类型化 binding record，并在 SQLite adapter 内编码 canonical JSON。
6. 让 `models.list`、`run.started` 与 TUI 只消费同一类型化结果的 Protocol 投影。
7. 用表格化用例覆盖请求选择、最近 Run、legacy、默认、冲突、不可用 Profile 和损坏记录；删除等价的 Server private 测试。

## 范围

- 定义最小 interface，接收当前 Thread 选择、配置 catalog 和 legacy 持久化记录，返回已解析的 Runtime 输入与不可变 RunExecutionBinding。
- 将选择优先级、兼容映射、脱敏和绑定校验从 `server.py`、`model_router.py`、`runtime_profile.py` 与 `thread_store.py` 的调用方收进该 module。
- Protocol adapter 只做 wire 类型转换；TUI 不再推断实际执行模型。
- 迁移测试到 module interface，覆盖全新 Thread、已有选择、legacy 回退、冲突和脱敏。

## 非范围

- 不新增模型选择方式、Provider、Subagent 或 UI。
- 不删除 legacy 数据，不进行 SQLite 破坏性迁移。
- 不通过 Agent catalog 构建或替换当前内置主 Agent。

## 验收清单

- [ ] 模型选择与 Run binding 的状态转换只有一个生产实现。
- [ ] Server 不再拼装 RunExecutionBinding 原始 dict。
- [ ] TUI 展示只依赖服务端确认的实际绑定。
- [ ] Runtime Profile 与持久化事实消费同一个 resolved result，不会分别解析选择。
- [ ] legacy 表结构和 source 映射不泄漏到 Server 或 TUI。
- [ ] 新测试只穿过目标 module 的 interface。
