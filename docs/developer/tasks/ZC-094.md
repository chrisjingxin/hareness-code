## 背景

当前 `ConcurrencyGuardMiddleware` 在每张 Agent 图内部持有一个 `AsyncRWLock`：

- 只读工具获取共享读锁；
- 写工具和未知工具获取独占写锁；
- 需要 HITL 的工具为了避免审批打包死锁，会跳过锁；
- 审批通过后仍由 ToolNode 并行执行。

单图下这已经留下审批写工具并发缺口；多图后，不同 AgentEngine 的锁彼此不可见，即使两个 Executor 正在修改同一个工作区也不会互相阻塞。

## 当前存在的问题

### 1. 锁的作用域错误

竞争发生在工作区、worktree 或 sandbox，而不是编译图。AgentEngine A 的锁无法保护 AgentEngine B 访问的同一文件。

### 2. 审批不是并发安全保证

用户同时批准两个写操作，只表示都允许执行，不表示两者可以安全并行。当前代码把 HITL 工具直接交给 handler，可能产生覆盖和时序竞态。

### 3. Tool 分类与资源身份没有统一输入

`is_concurrency_safe()` 只按工具名和参数分类；MCP 或未来工具的副作用、目标 workspace 和隔离环境没有进入调度 key。

### 4. Agent Team 会放大问题

多个 Executor、Reviewer 与 Root 并行读取或写入时，图内锁会造成错误安全预期。没有跨图调度就不应开放并行 Agent 写同一工作区。

## 为什么现在要修改

- 这是当前单图生产路径已经存在的正确性问题，不依赖未来 Team 才成立。
- ZC-089 的 RunCoordinator 可以持有 Host 级调度依赖，避免 middleware 自建锁。
- 在 ZC-096 开放 pool-backed delegation 前必须提供跨 AgentEngine 的共享边界。

## 目标设计

建立工作区级调度器：

```text
WorkspaceExecutionScheduler
├─ workspace A
│  ├─ read leases：可并行
│  └─ write lease：独占
├─ worktree B：独立锁域
└─ sandbox C：按 provider/id 建立锁域
```

调度请求至少包含：

- execution ID；
- tool name；
- 已规范化副作用等级；
- workspace/worktree/sandbox resource key；
- 是否需要审批。

审批与执行顺序：

```text
收集 tool call
  → 需要时请求审批
  → 审批通过
  → 获取共享 read 或独占 write lease
  → 再执行工具
  → 释放 lease
```

锁不能跨等待用户审批持有。

## 实施步骤

1. 列出当前内置、Shell 和 MCP 工具的副作用分类；未知工具默认 write/exclusive。
2. 定义稳定的 execution resource key，避免用未规范化路径或模型输入作为锁 key。
3. 实现 Host/workspace scoped scheduler，并由 AgentEngine builder 注入共享引用。
4. 调整 ConcurrencyGuard，使它在审批恢复后的实际执行入口获取 scheduler lease。
5. 删除每图独立锁或把它降为共享 scheduler 的轻量 adapter。
6. 为 remote sandbox、worktree 和本地 workspace 定义明确锁域；无法确认是否隔离时不得并行写。
7. 增加跨 Profile、跨 Agent、审批后并发写、读写互斥、取消和异常释放测试。

## 范围

- 统一同一 Host 内的文件与 Shell 工具并发调度。
- MCP 工具没有可靠只读声明时按独占处理。
- 支持不同 worktree/sandbox 的安全并行，不实现自动创建 worktree。
- 保留 ToolNode 的只读并行收益。

## 非范围

- 不提供跨进程分布式锁。
- 不实现文件事务、自动 merge 或冲突解决。
- 不把人工审批当作锁。
- 不为每个工具建立独立调度 class。

## 验收清单

- [ ] 两张不同 AgentEngine 图写同一工作区时不会并行执行。
- [ ] 需要审批的写工具在批准后仍获取独占 lease。
- [ ] 多个只读 Agent 可以并行访问同一工作区。
- [ ] 不同隔离 worktree/sandbox 仅在资源 key 明确不同时并行写。
- [ ] 取消、异常和 AgentEngine 淘汰不会遗留 lease。
- [ ] 未知副作用工具默认使用保守调度。
