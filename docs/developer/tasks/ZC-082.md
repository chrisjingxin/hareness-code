## 范围

- 以当前 `create_harness_agent()` 构建的 Python 内置 `main` 作为固定 root；根模型继续按“Thread root 覆盖 → 当前 ModelRouter/TOML 默认与 legacy 回退”解析。`ThreadExecutionSelection` 不引入 `rootAgentId`，当前 Thread 不能用配置或 `/agent` 更换主 Agent。
- 将 ThreadStore 的 `harness_run_execution_bindings` 迁移为 ADR 定义的 `RunExecutionBinding`：每次 Run 创建 root execution，记录内置 root 身份、模型来源、Model/Profile 与当前执行配置的脱敏指纹、开始/结束时间及终态；允许 ZC-015 在同一 Run 追加 Plugin child execution。迁移 v6/v5 历史时只保留可恢复的 primary 事实，无法还原的字段必须标为 legacy/unknown。
- `run.started` 与终态事件继续返回脱敏 root 实际绑定；同一 `run_id` 的重试、事务回滚、取消和 sidecar 重启不得重复创建 root execution 或把未启动的 Run 标为完成。

## 非范围

- 不读取或注册 Plugin Agent、Policy、Prompt、contract，也不实现 `task` 的 Plugin Subagent 生命周期；这些由 ZC-041、ZC-080 和 ZC-015 处理。
- 不开放 `/agent`、`/model agent:<id>`、spawn 模型覆盖、固定 Workflow、Team、Mailbox 或远端 Agent。
- 不物化独立 Provider 配置或改变 TOML v1 的 endpoint、Header、API Key 和模型选择来源优先级。

## 验收清单

- 内置 `main` 的 `/model` 切换、恢复、legacy v5/v6 Run、幂等重试、取消、失败与正常完成均保持正确 root binding 和终态；历史 UI/DTO 不把当前选择伪装为历史实际模型。
- 根 execution 使用稳定的内置身份和当前执行配置指纹；Plugin catalog 文件变化不能改变 root Runtime 或 root binding。
- Python 覆盖 SQLite 迁移/幂等/终态、RuntimeProfile 与取消恢复；TypeScript 覆盖协议兼容和 root 实际模型校准；完成 protocol、typecheck、test 与项目检查。
