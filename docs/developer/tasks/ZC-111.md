## 背景

手动 `/compact` 表达用户明确的压缩意图，但当前 full 分支与自动/overflow 共用
`MIN_SAVINGS_RATIO=20%`。短 Thread 可能已经成功生成合法摘要，却因为只节省
少量 token 而放弃提交，并把 `savings_below_20_percent` 内部原因码直接显示给用户。

## 解决方案

```text
手动 /compact
→ 保留最近两轮并确定可摘要前缀
→ 用空摘要 + 必需包装构造理论最小投影
→ 最小投影也未变小：调用模型前 skipped
→ 调用摘要模型并完成现有安全校验
→ after < before：提交 full
→ after >= before：保持旧投影并 skipped
```

自动和 overflow 路径不变，仍使用 20% 收益门槛。micro 的候选、最近工具结果、
Artifact、摘要格式、原子组、运行态恢复和单事务提交规则均不改变。

## 验收清单

- [x] 手动 full 在 `0 < savings < 20%` 时提交 Summary、Artifact 和 full checkpoint。
- [x] 手动历史连空摘要包装都无法缩小时不调用摘要模型且不产生持久化行。
- [x] 手动实际摘要没有正收益时不改写上一份 latest-valid 投影。
- [x] 自动和 overflow 继续拒绝低于 20% 的最终收益。
- [x] TUI 将已知 skipped 原因映射为中文说明，未知原因不泄漏内部枚举。
- [x] 用户与架构文档明确手动和自动收益门槛不同。
