## 背景

当前 Harness 已经具备独立的 SkillRegistry、MCP 生命周期和静态 AgentCatalog，但用户不能把这些
能力作为一个 Plugin 整体安装、检查、停用或删除。运行模块如果直接读取任意外部目录，会把格式
兼容、文件系统安全、启停状态和执行生命周期混在一起，也无法证明一次 Run 使用的是哪一版扩展。

本任务先建立 Plugin 的可信输入边界：

```text
本地目录或 zip
  → 安全 staging
  → 格式识别和组件级校验
  → package/capability fingerprint
  → 内容寻址只读 store
  → registry 原子切换
  → 不可变 catalog 摘要
```

安装只表示“包已经进入本机 store”，默认不会把 Skill、MCP、Agent 或 Hook 注入正在运行的 Host。
后续任务只能从本任务发布的已启用 catalog 读取组件来源。

## 实施步骤

1. 定义不可变 Plugin metadata、component inventory、compatibility report、installed record 和
   catalog snapshot；协议摘要不得包含宿主绝对路径或 manifest 正文。
2. 实现 Agent Plugins 1.0 Adapter，离线校验根 `plugin.json`、固定 `skills/` 和 `mcp.json`，
   并读取 `com.za38.harness` 扩展目录的组件库存。
3. 实现 Claude Code Adapter，支持有 manifest 和 manifestless 的默认目录发现；当前不能执行的
   Hook、LSP、Monitor、workflow、channel、bin、settings 等组件必须显示为 unsupported，不能静默忽略。
4. 为本地目录和 zip 建立 staging：拒绝 symlink、hardlink、device、绝对路径、父目录穿越、
   文件/数量/总大小超限和解压炸弹。
5. 计算确定性的 package digest 与 capability fingerprint，按内容地址复制到用户级只读 store。
6. 用文件锁、revision、临时文件和原子替换维护 registry；install 默认 disabled，enable 必须携带
   当前 capability fingerprint，update 复用 install 的校验路径。
7. 在 Protocol v3 增加 `plugins.read/plugins.manage` 与 validate/list/inspect/install/
   set_enabled/remove RPC，Server 只调用 PluginManager，不解析外部格式。
8. 增加 Python 核心、安全和 Server contract 测试，并更新用户文档、架构文档和总体方案的当前状态。

## 范围

- 本地普通目录和 zip 文件。
- `user` scope 的内容寻址 store、持久化 data 目录和版本化 registry。
- Agent Plugins 1.0 与当前 Claude Code Plugin 的自动格式识别。
- 组件级 supported/adapted/unsupported/invalid compatibility report。
- 安装、启停、列表、详情和默认保留 data 的删除。

## 非范围

- 不连接 Git、GitHub、HTTP marketplace 或企业市场。
- 不执行 Plugin 中的 Skill、MCP、Agent、Command、Hook、LSP、Monitor 或脚本。
- 不实现 Plugin 依赖求解、签名验证、managed scope 或 project/local scope。
- 不把 enable 误称为用户已经授予具体文件、Shell、网络或凭据权限。
- 不实现 Agent delegation 或 Agent Team。

## 本次实现

- 新增 `harness_agent.plugins`：Agent Plugins 1.0、Claude manifest/manifestless、双 manifest
  Adapter 统一输出 `PluginDescriptor` 和逐组件兼容报告。
- PluginStore 对本地目录和 zip 执行私有 staging，限制链接、特殊文件、路径、数量、大小、深度和
  压缩比；package digest 同时覆盖相对路径、内容和可执行位。
- store 使用 `<source-id>/<name>/<digest>` 内容地址并收紧为只读；registry 通过文件锁、revision、
  fsync 和原子替换更新，损坏或篡改状态 fail closed。
- install 默认 disabled；enable 必须确认精确 capability fingerprint 并复核 store digest；remove
  默认保留 data，显式 `purge_data` 才删除。
- Protocol v3 新增 `plugins.read/plugins.manage` 和六个 Plugin RPC；Python Server 与 TypeScript
  AgentClient 只消费 canonical 管理接口。
- CLI 新增 `harness plugins validate/list/inspect/install/enable/disable/remove`，相对来源按 Host
  workspace 解析；管理结果不暴露来源、store 或 data 的绝对路径。
- 当前 Plugin 组件还不会进入 Run：Skill/MCP 报告为 `adapted/effective=false`，其他 Claude/Harness
  组件按实际情况报告 `unsupported` 或 `invalid`。

- [x] install 默认 disabled，错误 fingerprint 无法 enable。

- [x] remove 默认保留 Plugin data。
