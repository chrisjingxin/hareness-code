## 背景

CLI 已有不可变 `CommandRegistry`，帮助、补全、菜单、解析与执行都使用稳定 ID，但 Host initialize
仍返回空的 `agent_commands`。Plugin Adapter 能识别 Claude `commands/*.md` 和 portable Harness
extension 的 Command 路径，却把它们标为 unsupported。

本任务把 Markdown Command 视为一种“只能从命令入口显式调用的内部 Skill”：

```text
Plugin commands/*.md
  → PluginCommandSource
  → SkillRegistry 中的 user-only command record
  → initialize.agent_commands
  → CLI CommandRegistry snapshot
  → run.start(requested_skill + args)
```

这样正文仍由 Agent 端校验和按需读取，CLI 只处理类型化展示与调用信息。

## 实施步骤

1. 扩展 Plugin Skill source，区分普通 Skill 与 Command，并允许多段 canonical suffix。
2. 兼容 Claude Command 的可选 front matter；正文、digest、包边界和启动后篡改规则复用 Skill。
3. `PluginManager` 从同一个 enabled catalog 生成 Command source，单文件失败只形成诊断。
4. `SkillRegistry` 生成类型化 Agent Command 摘要；Plugin Slash 名包含 source/plugin namespace。
5. Protocol 将 `initialize.agent_commands` 从任意 JSON object 收紧为稳定结构。
6. CLI 根据 initialize 快照构建 `builtin + plugin` 的单一 `CommandRegistry`，冲突 fail closed。
7. Plugin Command Dispatcher 只提交 `requested_skill` 和原始参数，不执行 Plugin JS/Python。
8. 覆盖 portable/Claude、无 front matter、参数、菜单、帮助、builtin 冲突和坏项隔离测试。

## 非范围

- 不执行任意 Plugin 进程内模块。
- 不实现 Command 热重载，仍在下一次 Host 启动生效。
- 不让 Command 自行授予工具或跳过审批。
- 不实现 Agent/Team Command target；后续任务在同一类型化 action 上扩展。

## 验收清单

- [x] Claude 与 portable Plugin Command 可进入 initialize 快照。
- [x] CLI 菜单、解析、帮助与执行使用同一个动态 Registry。
- [x] Plugin Command 具有稳定 namespace，不能覆盖 builtin 名称或别名。
- [x] Markdown 正文只在 Agent 端按需加载，CLI 不接收正文和绝对路径。
- [x] 命令参数原样进入 requested Skill args。
- [x] 一个坏 Command 不影响其他有效组件。
- [x] enable/disable/update 只在下一次 Host 启动改变命令快照。

## 实现结果

- Plugin Adapter 将 Claude `commands/*.md` 和 portable Harness extension Command 标记为
  `supported/effective=true`。
- Command 复用 `PluginSkillSource` 和 `SkillRegistry`，但使用
  `plugin/<plugin-id>/command/<name>` ID、`kind=command` 和 `model_invocable=false`；普通 Skill
  列表与模型 Skill 索引不会混入 Command。
- Claude Command 可省略 front matter；存在 front matter 时读取 description、argument hint 和
  工具请求元数据。坏文件只写入 Plugin diagnostics。
- Protocol 的 `agent_commands` 已从任意 JSON object 收紧为生成的 `AgentCommand` 类型。
- CLI 从 initialize 结果构建 `builtin + plugin` Registry；菜单、帮助、解析和 Dispatcher 都使用
  这一个实例。
- Plugin Command Dispatcher 只生成 `submit-prompt + requestedSkill`，参数原样进入 `args`，正文与
  宿主路径不会跨进程。

版本影响：当前项目尚未正式发版，本任务不修改版本号或 Changelog。
