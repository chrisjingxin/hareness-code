# 安全与沙箱

Harness Code 默认在本机执行，与 Qwen Code 未开启 sandbox 时一致。`--cwd` 决定本机工作区：内置 `ls`、`read_file`、`glob` 和 `grep` 只能访问该目录内的文件；`write_file`、`edit_file`、`delete_file` 默认也限制在该目录内，工作区外写入按审批模式处理（见下文）。

直接文件工具必须使用工作区内的绝对路径。`glob` 和 `grep` 可以省略搜索目录，此时从工作区搜索；显式目录同样必须位于工作区内，文件匹配模式不能使用绝对路径或 `..`。Harness Code 会在工具执行前解析符号链接，因此工作区内指向外部的链接也不能用来读取外部文件。读取限制不能通过审批绕过。

工作区外写入按审批模式分流：`plan` 直接拒绝；`default`、`auto-edit`、`auto` 弹出审批框，用户批准（或命中显式 allow 规则）后才会真实写入工作区外的目标路径；`yolo` 不弹窗直接写入。工作区外读取在所有模式下都直接拒绝。`apply_patch` 不支持工作区外路径。

这不是操作系统隔离或完整沙箱：`execute`、MCP 工具和未来自定义工具仍可能具有各自的文件访问能力，并按其审批或企业策略执行。终端状态显示“本机执行 · 未隔离”时，请仅在可信开发环境中使用。

同一 Harness 进程中，访问同一工作区的多个 Agent 图会共享工具读写锁：只读操作可以并行，写入、未知工具和子 Agent 调用会等待前一个工具完成。审批只决定是否允许执行；批准后的写入仍会串行执行。不同工作目录通常由不同 Harness 进程承载，不会因此互相等待；两个独立进程同时操作同一物理目录目前不提供协调。

不要将 API Key、云凭据或其他秘密放在工作区中。模型 API Key 推荐通过环境变量提供；如必须使用明文 TOML 降级值，只能写入用户级 `~/.harness/config.toml`。macOS/Linux 上 Harness 会拒绝读取存在 group/other 权限的明文密钥文件；建议保持目录 `0700`、文件 `0600`。

## 审批模式

启动时的初始审批模式在用户配置 `~/.harness/config.toml`、显式传入的 `--config` 文件，或环境变量 `HARNESS_APPROVAL_MODE` 中设置；优先级依次为用户配置 < 显式配置 < 环境变量。当前项目目录的 `.harness/config.toml` 和 `.harness/config.local.toml` 完全不支持，检测到即要求迁移。

```toml
[approval]
mode = "default"
```

`auto` 模式可选配置 LLM 安全分类器：在 `[approval]` 中指定 `classifier` 为 `[models]` 中的某个 profile 名，Shell、删除等未被规则或确定性过滤器裁决的调用会先由该模型做两阶段安全分类，明确无害的自动放行，明确危险的直接拦截（不弹窗），拿不准的仍弹窗确认。分类模型建议使用小快模型；Harness 会以 10 秒超时调用且不重试。未配置 `classifier`、分类调用超时失败或结果无法解析时，一律回退为弹窗确认，绝不会因此自动放行。

```toml
[approval]
mode = "auto"
classifier = "small-fast"
```

运行中可以按 `Shift+Tab` 循环切换审批模式（`plan → default → auto-edit → auto → yolo`），composer 右下角实时展示当前模式。切换不影响正在执行的 Run，从下一次 Run 起由服务端按新模式强制策略；该选择只保留在当前会话，不写入配置文件，退出后重新启动恢复配置中的默认模式。

| 模式 | 文件编辑 | Shell、删除、子 Agent | 上下文压缩 |
| --- | --- | --- | --- |
| `plan` | 拒绝 | 拒绝 | 自动执行 |
| `default` | 每次确认 | 每次确认 | 自动执行 |
| `auto-edit` | 自动执行 | 每次确认 | 自动执行 |
| `auto` | 工作区内自动执行 | 自动安全判断；破坏性命令直接拦截，判断不可用时回退为确认 | 自动执行 |
| `yolo` | 自动执行 | 自动执行 | 自动执行 |

上表描述工作区内操作；工作区外写入的行为见本文开头：`plan` 拒绝，`default`/`auto-edit`/`auto` 弹窗确认，`yolo` 直接写入。

## Agent 与 Policy 文件

当前版本不从 `~/.harness/` 或项目 `.harness/` 读取 Agent/Policy 文件，主 Agent 由内置 Python 代码构建，不能被配置替换。后续只有经过安装与信任校验的 Plugin 才能提供可派发子 Agent；Plugin 资产不能包含 API Key、endpoint、Header、Shell Hook 或任意可执行代码，模型连接仍只能在用户级 `config.toml` 的 `[models]` 中配置。

`plan` 只允许 `ls`、`read_file`、`glob`、`grep`、`ask_user` 和 `write_todos`。写入、`execute`、`task` 以及未识别的未来 MCP 工具都会直接返回拒绝结果，不会弹出审批框。

Harness 还提供只读的 `/.harness/` 逻辑命名空间。它不是本机文件路径：只有 `read_file` 可以按页读取 Skill 正文、Skill 资源或本 thread 已归档的历史；`write_file`、`edit_file`、`ls`、`glob`、`grep` 和 shell 命令都会被拒绝。该路径不会泄露 Skill 的宿主目录或 SQLite 文件位置。

`yolo` 只关闭 Harness Code 自身的人工确认：工作区外写入也不弹窗直接执行，请仅在可信环境使用。它不会绕过 Shell 白名单、远端 sandbox provider 或企业安全策略；工作区外读取仍被直接拒绝。旧值 `ask` 会兼容为 `default`；空值或未知值同样安全降级为 `default`，TUI 会显示对应提示。

## 交互式配置修改边界

当前没有可直接编辑任意 TOML 的 `/config set` 命令。后续 Settings/Permissions Manager 仅能修改用户级配置中的默认模型、审批模式、执行后端和 AgentEnginePool 白名单字段；写入前会校验完整配置、并发版本和企业策略锁，失败时不会覆盖原文件。API Key、认证 Header、环境变量、模型服务地址和远端 Provider factory 始终不可通过交互界面修改。

如果环境变量、`--config` 或企业 managed policy 覆盖了某个字段，界面会显示不可修改原因。项目内 `.harness/config.toml` 即使被显式选择，也不能作为交互式写入目标。

启用 Shell 白名单的集成只接受可可靠解析的单一命令。管道、重定向、`&&` / `||`、分号、命令替换、反引号、换行和畸形引号都会在执行前被拒绝。绝对可执行文件路径必须以完整路径显式加入白名单，不能仅凭同名文件匹配。白名单限制的是启动的程序和 Shell 组合语法，不分析获准程序自身参数的业务语义，也不等同于命令沙箱。

## 启用企业远端沙箱

企业提供远端 sandbox 插件后，在用户配置 `~/.harness/config.toml` 或用户明确传入的 `--config` 文件中设置：

```toml
[approval]
mode = "default"

[execution]
backend = "remote"

[execution.remote]
provider = "corp"
factory = "harness_corp_sandbox:create_backend"
working_directory = "/workspace"

[execution.remote.params]
project = "your-enterprise-project"
```

也可以单次执行：

```bash
za38 --sandbox
HARNESS_SANDBOX=true harness
```

远端 provider 负责认证、工作区同步、网络策略和生命周期，并必须实现 deepagents 的 `SandboxBackendProtocol`。沙箱不可用时命令会失败，不会自动回退到本机执行。

`sandbox.params` 只传递非秘密 provider 参数；认证信息必须由企业身份机制或环境变量处理，不得写入 TOML。

当前不提供 Docker、Podman 或本机容器 sandbox。企业网络白名单由远端 provider 管理。
