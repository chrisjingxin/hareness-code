# Web 工作台

Web 工作台通过 `/web` 在浏览器中接管当前 Thread。它与 TUI 共用同一条 Timeline、Run、审批和 Composer 语义；本页说明 Web 端的视觉层级和外围操作。

## 主题与状态

- 页面使用暖中性画布加绿色强调：浅色是暖米色背景上的白色平面面板，深色由同一组主题 token 控制；切换入口是顶栏“返回 TUI”旁的单图标按钮（浅色显示月亮、深色显示太阳，图标表达点击后切换到的主题）。
- 绿色只用于当前选中、运行中、焦点和链接等交互强调；成功、等待、失败和取消仍使用各自的文字与图标语义。运行中与已完成同属绿色系，运行中额外叠加动画或文字（如“正在运行 · Esc 取消”），不只靠颜色区分。
- 顶栏的 Run 状态是最高状态层级，会显示“正在运行”“等待交互”“运行失败”等可读文案和状态点。状态来源于当前 Run，不由 CSS 推测。
- 顶栏的返回 TUI、主题切换和更多操作属于次级 chrome；更多菜单只保留帮助与退出入口。模型与审批模式不放在顶栏，而是作为 Composer 底部操作条上的下拉控件，贴近输入动作。

## 工作区外围

- 桌面端顶栏分两个区域：左侧是 Harness Code 品牌与在线状态，右侧是“返回 TUI”、主题切换和更多操作。顶栏不放工作区或运行时可切换的控件：当前工作区显示在左侧文件分区的标题上（文件夹图标加工作区名，悬停可见完整路径）。
- 三栏工作区中，左栏贴紧窗口左缘、右侧 Dock 贴紧窗口右缘，两栏从顶栏下缘一直延伸到窗口底部；栏间保持 `16px` 列间距，中间对话列上下保留呼吸内边距。左栏默认约 `296px`（可拖动 `220–480px`），右侧 Dock 默认约 `354px`（可拖动 `330–760px`）。中间内容列（工作项横幅、消息流、审批卡、输入框）固定居中：宽度封顶 `880px`，按 Dock 预留宽度计算——Dock 打开时用其实际宽度，Dock 关闭时用默认宽度（`354px`），因此把 Dock 拖宽后关闭，内容列会恢复默认宽度，重新打开仍保持拖宽后的宽度。开关或拖拽时内容列随轨宽整体平移过渡（约 200ms，系统开启“减弱动态效果”时瞬时切换）。拖动侧栏或 Dock 分隔条时按当前窗口宽度动态限制最大宽度，保证内容列不低于 `480px`。
- Composer 底部操作条承载两个下拉控件：左端是审批模式下拉（显示当前模式，点击就地切换；待处理交互或压缩中锁定，运行中仍可改下一轮档位），旁边是工作模式 chip；右端是模型下拉（发送键旁，显示当前模型，点击就地切换，菜单底部“管理模型…”打开右侧 Dock 的 Model 面板）。两个下拉都向上弹出，形态与行为一致。
- 左侧 Sidebar 是一个平面面板：Thread 与 Files 上下分区，中间的分隔槽显示一条细分隔线，可以拖动调整比例；未拖动过时 Thread 分区高度随内容自适应（短列表不会被截断），拖动后按显式比例固定。“新建 Thread”是分区标题里的次级图标按钮，不会压过当前 Run 或对话内容。
- 当前 Thread 使用浅绿色背景标识；未选中的 Thread 仅在 hover 时显示轻量背景。
- 对话时间线是扁平阅读流：每条消息由角色行（小头像 + 名称 + 时间）和左对齐正文组成，不使用气泡卡片；思考和审批条目用 1px 边框表达结构，不带投影。时间线不显示常驻滚动条；新消息到达时，视口贴底则自动跟随滚动到底，手动上滚阅读历史时保持位置不打扰——此时浮出中性「回到底部」按钮，若上滚期间有新内容到达，按钮升级为强调的「有新输出」，点击恢复跟随。
- 工具调用默认折叠为融入阅读流的单行：语义图标 + 动词标签（如“读取文件”“执行命令”）+ 主参数 + 状态 + 常驻展开箭头；点击后在引导竖线内展开两张同级卡片——“输出”卡片带头部条（标题、行数统计、一键复制按钮），超过约一屏时钳制限高并可点“展开全部”就地放开；“参数”卡片默认折叠成一行头，点开看美化后的 JSON。输出内容按工具类型结构化渲染：“读取文件”显示路径元信息与行号栏，“列出目录/搜索文件”显示带文件类型图标的条目清单，“查找内容”按文件分组显示行号与命中行；“编辑文件/写入文件”把实际变更渲染为红绿 diff 行（新增淡绿底、删除淡红底，头部显示 +N −M 统计）；“执行命令”渲染为终端块（顶部 $ 命令行 + 输出，头部显示 exit code，截断时有提示）；其余工具结果是 JSON 时自动美化缩进，否则按等宽纯文本展示。写类工具（写入/编辑/删除/执行命令）用暖色图标提示副作用，失败行用淡红底、左侧红条与“失败”文字徽章突出；原始工具名挂在标签的悬浮提示上。
- Context Dock 是右侧的平面单面板，用一层 tab 切换 Code、Model、Skills、MCP、Status 并可关闭；Help 从顶栏更多菜单打开。
- Sidebar、Dock、Thread、Files、Model、Skills、MCP 和 Status 的现有操作保持不变。打开/关闭面板不会改变 Thread 或 Agent 状态。

## 控件与可访问性

Web 控件使用统一的 compact、standard、field 尺寸和中性边界，圆角与阴影有固定纪律（阴影只出现在浮层、菜单和对话框）。必要的小号文字使用较深的 muted token，键盘聚焦显示 2px 绿色 focus ring（Composer 输入框以整卡描边变绿表达聚焦）；运行、等待、失败和取消不只依赖颜色区分。

Composer 的发送、取消、IME、Slash Command 和审批/问答行为见[交互使用](交互使用.md#web-工作台)。

## 文件变更审批

- `write_file`、`edit_file`、`delete_file` 的人工审批使用专用 Diff 卡，显示逻辑路径、操作和增删统计；
  Web/TUI 使用 Codex 风格的低饱和酒红/墨绿色整行背景、行号色带，并保留 `-`/`+` 标记。
- 可用宽度达到 760px 时默认左右对比，较窄时默认行内；当前审批内可用“左右 / 行内”手动切换。
- 删除和新增同时使用背景色与 `-`/`+` 标记，old/new 行号始终可见；长行不会静默省略。
- 支持的语言复用离线 Shiki Worker。未知语言、超限、超时或 Worker 故障只关闭语法高亮，不影响审批。
- Diff 仍受 200 行、16 KiB 预览上限约束；截断提示位于审批按钮之前，批准对应完整拟议变更。
- 工具参数默认折叠在“请求参数”中；非文件审批继续使用通用 description 和参数预览。
- 普通“拒绝”点击后立即提交，批准仍需选择后点击“提交”确认；“拒绝并反馈”需填写反馈后提交。
- 审批、问答与目录信任卡与对话内容共用同一居中内容列（宽度规则见“工作区外围”，封顶 `880px`）。Diff 预览区高度上限约 240px，超出内部滚动。
- 长审批卡整体仍限制在工作区剩余高度内并自身滚动；滚动 Diff 或审批卡不会把底部的审批按钮和 Composer 推出视口。
