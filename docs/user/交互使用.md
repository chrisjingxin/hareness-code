# 交互使用

启动 `za38`（源码开发阶段可用 `bun run dev --`）后，直接输入编码任务。Harness Code 会将流式文本、工具调用、审批请求和问题显示在同一 thread 时间线中。

企业 OpenTUI Core/React `0.4.3` 使用随 CLI 分发的离线 Tree-sitter parser 与语法查询渲染 Agent Markdown。标题、强调、列表、引用和 fenced code 会按终端样式显示；代码高亮不在运行时下载任何资源。

## 执行时间线

每次工具调用都是独立的历史事件。工具卡会显示本次调用的参数预览和实际结果；即使 Agent 连续调用同一个工具，先前结果也不会被后续调用更新。

需要审批或回答问题时，交互卡会停留在触发它的位置；完成后会显示已允许、已拒绝或已回答。思考、恢复执行和取消等当前状态只显示在时间线末尾，因此不会插入或覆盖已经完成的工具结果。

## 快捷键

| 快捷键 | 行为 |
| --- | --- |
| `Enter` | 发送输入 |
| `Shift+Enter` | 输入换行 |
| `/` 或 `Ctrl+P` | 打开本地 Slash Command 菜单 |
| `Esc` | 关闭命令菜单或取消当前运行 |
| `Ctrl+C` | 优先清空输入，其次取消运行，最后退出 |
| `Ctrl+O` | 展开或折叠工具详情 |
| `Shift+Tab` | 循环切换审批模式，见 [安全与沙箱](安全与沙箱.md#审批模式) |
| 空输入时 `↑` / `↓` | 回填历史提示词；没有历史时浏览 thread |
| 空输入时 `PageUp` / `PageDown` | 按半页浏览 thread |

`Shift+Tab` 按 `plan → default → auto-edit → auto → yolo` 顺序循环切换审批模式，输入框右下角实时展示当前模式并附有 `Shift+Tab` 快捷键提示；正在执行的 Run 不受影响，新模式从下一次 Run 起生效。选择器或命令菜单打开时 `Shift+Tab` 让位给浮层，不会误切换。

## 已实现的 Slash Command

- `/help`：显示命令说明。
- `/new`：创建新的 thread 并回到首页；当前任务仍在执行时会先显示确认框，确认后才请求取消。
- `/clear`：`/new` 的兼容别名。
- `/force-clear`：已废弃，仅提示改用 `/new`；不会再直接取消或清空当前 thread。
- `/compact`：在当前 thread 空闲时手动压缩模型工作投影。它保留最近两轮、将更早内容写入本机归档，并在没有足够历史或预计节省不足 20% 时不提交新投影。压缩不会删除 `/resume` 可见的完整 Transcript。
- `/status`：显示工作区、模型、执行后端与审批模式。
- `/version`：显示 CLI 版本。
- `/resume`、`/continue` 或 `/threads`：打开当前 project 的悬浮 thread 选择器。输入关键词过滤消息摘要，使用方向键或鼠标选中，按 Enter 恢复完整消息历史；Esc 关闭且不改变当前输入。正在执行或等待交互时不能切换 thread。
- `/model` 或 `/models`：打开模型 Profile Picker；`/model <query>` 会预填筛选。确认可用 Profile 后，当前 Thread 的下一次 Run 立即使用该模型，并自动尝试同步后续新 Thread 的用户级默认模型；Picker 会显示这项语义。已启动的 Run 不会被切换；不可用 Profile 不可选择。默认写入失败不撤销当前 Thread 选择，会显示安全原因；与旧 sidecar 协商时保留仅新 Thread 选择的兼容行为。
- `/skills`：在当前 thread 上打开可搜索的悬浮 Skill 选择器。输入关键词过滤目录，使用方向键或鼠标选中，按 Enter 后 Skill 会附到下一条消息；Esc 关闭且不改变当前输入。
- `/mcp`：查询并显示所有已配置 MCP 服务器的运行时状态，包括连接状态、已加载工具和错误信息。未配置时显示配置引导。
  - `/mcp add <name> <command> [args...]`：添加 stdio 类型 MCP 服务器，例如 `/mcp add filesystem npx -y @modelcontextprotocol/server-filesystem /tmp`。
  - `/mcp add <name> --url <url>`：添加 HTTP 类型 MCP 服务器；加 `--sse` 使用 SSE 传输。
  - `/mcp remove <name>`：删除指定 MCP 服务器。配置持久化到 `~/.harness/config.toml`，添加后自动尝试热连接。
- `/web`：仅在当前 thread 空闲时启动本机 Web 表现层。浏览器通过 `127.0.0.1` WebSocket 直连当前 Python Agent Host，并与 TUI 共享同一份 thread 历史、配置和 AgentEnginePool；Web 发起的新 Run 由 Web 独占审批、问答和取消，TUI 只观察相同事件。CLI 退出时 Web 连接同时关闭，刷新页面不会恢复进行中的 Run。
- `/settings` 与 `/permissions` 尚未提供界面。后续接入时只能通过受控预览和原子提交修改白名单配置，不能编辑任意 TOML、API Key、Header、环境变量或远端 Provider。
- 在 composer 输入 `/`：命令补全菜单同时显示 `skill:<canonical-id>`。筛选并选中任意 Skill 后，效果与 `/skills` 相同。
- `/quit` 或 `/q`：退出。

命令名不区分大小写，参数会原样传给对应命令。未知的 `/命令` 不会发送给 Agent，而会在本地提示可能的命令；若要向 Agent 发送以 `/` 开头的普通文本，请输入 `//`，例如 `//api/users 的路由在哪里`。

菜单会根据协商 capability 和当前运行状态隐藏不可用功能；例如未协商上下文管理时不显示 `/compact`，未协商 `models.read` 时不显示 `/model`，正在执行或等待交互时 `/compact`、`/resume` 和 `/model` 会说明不可用原因。协商 `models.select` 后，`/model` 可改变当前空闲 Thread 的下一次运行；若未协商 `config.write`，仍保留当前 Thread 选择，但未来新 Thread 默认值不会同步并会给出提示。

项目 `<workspace>/.harness/skills/<name>/SKILL.md` 默认生效，用户 Skill 位于 `~/.harness/skills/<name>/SKILL.md`（也兼容 `~/.harness/skills/local/<name>/SKILL.md`）。同名 Skill 不会互相覆盖，冲突时使用完整 canonical ID，例如 `project/review`。需要暂时停用时运行 `harness skills disable project/review`，重新启动 Harness 后生效。

命令行管理入口：

```bash
harness skills list
harness skills inspect project/review
harness skills enable project/review
harness skills disable project/review
harness skills trust project/review  # enable 的兼容别名
harness skills market --market enterprise
```

市场安装、更新和删除只调用企业 Provider 接口；未安装 Provider 时会返回明确诊断，不会访问公网。

`/tools`、`/agents` 和 `/remember` 尚未接入后端；请使用 `/resume` 恢复 thread。

## 恢复 Thread

运行 `harness --resume` 会直接打开与 `/resume` 相同的选择器。选择器只显示消息摘要、更新时间和消息数；内部 `thread_id` 不会显示，也不需要手动输入。恢复范围始终是当前 project，不能浏览或恢复其他 project 的记录。

Harness 将完整用户可见 Transcript、版本化 CompressionCheckpoint、LangGraph 执行缓存和 Context Artifact 存在用户目录的 `~/.harness/threads.sqlite3`。下一次运行的模型历史由“最新有效 CompressionCheckpoint + 之后的 Transcript”重新生成；LangGraph `messages` 只是单向刷新的执行缓存，不用来恢复完整 UI 历史。压缩不会删除已写入 Transcript 的历史；旧库只会把当时能证明的视图标记为 `legacy/incomplete`，不会伪造更早历史。目录权限为 `0700`，新建数据库权限为 `0600`；数据库只保存 project 规范路径的 SHA-256 指纹，不保存原始 project 路径。Harness 停止后，可以手动删除 `threads.sqlite3`、`threads.sqlite3-wal` 与 `threads.sqlite3-shm` 清理全部本地 thread。

## Run 上下文刷新

同一 thread 的每个顶层 Run 都会重新准备一份上下文快照。用户级 `~/.harness/AGENTS.md`、项目级 `<workspace>/.harness/AGENTS.md` 或受支持的环境描述发生修改、删除或新增后，下一次 Run 才生效；已经执行的 Run 继续使用启动时的快照，工具循环、重试和交互恢复都不会热切换规则。快照中的 AGENTS 和 Skill 索引只是低可信参考，不能增加真实的工具、Sandbox 或权限；快照 ID 会和本次 Run 的模型绑定一起保存，供本地审计。

刷新期间如果参考文件被替换、通过符号链接逃逸或无法形成一致读取，Run 会在首个模型调用和受理记录前失败，不会留下半套 Run。快照只保存确定性内容摘要和必要正文，并会脱敏常见凭据与宿主绝对路径。ZC-099 不扫描 Skill 热更新；当前进程已有的 Skill catalog 继续保持 immutable，热刷新属于后续任务。

模型配置、无头调用和配置查询见 [模型配置](模型配置.md) 与 [快速开始](快速开始.md)。
